# H-LSA 规模仿真压测与雪崩验证报告（T-0355）

> 交办方最担心的一条：*「尤其在节点多了、开发任务多了、repo 频繁改动的情况下，
> 不要造成整个系统的流量风暴和压力雪崩。」*
> 本报告只引用 `tools/lsa_loadtest.py` 的**仿真原始输出**（`.hive/raw-loadtest.json`），
> 不引用理论估算、不回填历史数字、不为好看调宽阈值、A/B 两个场景都报。

## 0. 结论速览

- **8 项 SLA 断言：7 项 PASS，1 项如实 FAIL（SLA-6 在 N=5 高频时统计边界越界）。**
  未通过项原样保留在 JSON 与本报告 §5，阈值一个都没改。
- **卡面完成标准 #3 点名的硬场景 `N=100 + 高频变更`：同步风暴峰值 12 ≤ 20，
  没有出现 >20% 的雪崩。** 1000 次连续状态翻转被压成 **5 条通告**（3 条 change
  LSA + 2 条汇总），最终状态 `v=999` 不丢。
- **空闲期**：B 场景 Gitea 请求 **0 次/节点/30min**（主控兜底 1 次），
  控制面带宽 **0.0176 ~ 0.4349 KB/s**（N=5~100），远低于 0.16.05 的 ~9KB/s 基线，
  且 A 现状同相位轮询是 **8.33 ~ 166.67 KB/s**，A/B 对比无回退。
- **规模收益**：idle 场景 Gitea 请求 A/B 比值随 N 单调放大
  **900 → 3600 → 9000 → 18000**（A∝N 盲轮询，B 单源 O(1)），
  「N 越大优势越明显」成立。

## 1. 复现方式与随机种子

执行环境：WIN10 / `C:\Python314\python.exe`（Python 3.14.7，pytest 9.1.1）。

| 5 | **B** | 1 | 0 | 64,780 | 0.017573 | 80 | 0 / 1 | 4.5 s |

读法：

- **B 的 Gitea 请求恒为 1**（主控启动兜底 1 次 `ls-remote`），与 N、M 都无关 ——

## 5. 8 项 SLA 断言逐项结果（阈值全部取自 `hive_lsa.SyncConfig`）

| # | 断言 | 阈值 | 实测 | 结果 |
|---|---|---|---|---|
| SLA-1 | 状态变更 → 全集群可见 max | ≤ 300 s | **279.5 s**（未收敛探针 0 个） | **PASS** |
| SLA-2 | 全量对账周期 1800s ±20% 且只发 digest | [1440, 2160] s；仅 digest/CSNP | 48 个 T2 事件，首轮 1840.0 s，周期样本 1540.6~2153.7 s，`full_state_transfers=0` | **PASS** |
| SLA-3 | B 空闲期 Gitea 请求 | 0 次/节点/30min；Leader 兜底 ≤1 | 12 个 idle 运行全为 0；主控兜底 1 | **PASS** |
| SLA-4 | 空闲控制面带宽 ≤ 基线，A/B 不回退 | ≤ 9 KB/s | B idle 峰值 **0.434924 KB/s**；A idle 最低 8.333333 KB/s | **PASS** |
| SLA-5 | 高频 + N=50/100：单节点 ≤64KB/周期、≤32 条 LSA/周期 | 65536 B；32 条 | 6 个大规格运行：峰值 **9694 B / 32 条** | **PASS** |
| SLA-6 | 同步风暴峰值 ≤ N × 20% | `floor(N*0.2)` | 35/36 个 B 运行达标；**1 个越界：N=5 高频 M=200，峰值 2 > 上限 1** | **FAIL（如实记录）** |

| SLA-8 | B 总流量 vs A 数量级下降且 N 越大优势越明显 | ≥10×；随 N 单调 | A/B = 900 / 3600 / 9000 / 18000（N=5/20/50/100） | **PASS** |

### SLA-6 的 FAIL：如实写清楚，不调宽、不隐藏

- **越界运行**：`B_N5_M200_high_seed20261114`，同秒内发起 pull 的节点数 **2**，
  而 `floor(5 × 0.2) = 1`。这是 36 个 B 运行中唯一一个越界。
- **原因**：N=5 时只有 4 个跟随节点，而「20% 上限」取整后只有 1；
  每个跟随节点按 `h.next_deadline(60s, ±20%)` 把补拉散布在 **[48, 72] s** 的
  24 秒窗口里，4 个独立样本仍有概率两两落进同一秒。这是**小 N 下阈值的统计边界**，
  不是 jitter 失效：同一运行的 A 现状峰值是 5（4 倍于上限），N=20/50/100 的
  B 运行全部达标，抖动确实把峰值压了下来。
- **卡面完成标准 #3 点名的 `N=100 + 高频` 场景**：实测峰值 **12 ≤ 20**（M=200）、
  0 ≤ 20（M=1000/5000），**没有 >20% 的雪崩**。
- **处置**：按卡面「未达标项如实记为 fail 并写明原因，不允许通过改阈值消掉」，
  JSON 的 `assertions[SLA-6].pass=false`、`reason` 完整保留；本报告不抹平、不调宽
  `SYNC_STORM_MAX_FRACTION`、不把小 N 运行从矩阵里删掉。若交办方要小 N 也严格达标，
  属协议层改进（例如把跟随节点补拉窗口按 N 拉长 / 引入二次抖动），应另开卡，
  **不是本压测卡改阈值**。

## 6. 震荡场景：1000 次连续翻转 → Flap Damping

同一个 `(repo, tid) = ("hive", "T-FLAP")` 连续 1000 次状态翻转（全部压在一个
`FLAP_WINDOW_S=60s` 窗口内），停止震荡后继续推进到抑制半衰解除：

| 指标 | 实测值 |
|---|---|
| 翻转次数 | 1000 |
| 发出的 change LSA | **3** |
| 发出的抑制期汇总（flap summary digest） | **2** |
| 通告总数 | **5**（远小于 1000） |
| `flap_suppressed` | 208 |
| `flap_recovered` | 1 |
| 合并窗口合并次数 | 790 |
| 最终 LSDB 条目 | 存在，`seq=3` |
| 最后一条补发 diff | `{"v": 999, "state": "s1"}` |
| **状态最终不丢** | **是**（`final_v=999`，`suppressed_keys=[]`） |

三条 FLAP 断言（通告数显著少于 1000 / 最终状态不丢 / 抑制确实触发并解除）全部 PASS。
这直接验证「拓扑一抖不能让全网同时重算、同时泛洪」：第 2 次连续翻转就把惩罚推到
`FLAP_SUPPRESS_THRESHOLD=2000` 进入抑制，之后只发汇总；停止震荡后按
`FLAP_HALF_LIFE_S=60s` 半衰衰减、受 `FLAP_MAX_SUPPRESS_S=300s` 兜底解除，
把累积的最终字段级 diff 合成 1 条 LSA 补发，状态不丢。

## 10. 已知边界与后续建议（不属本卡范围）

1. **SLA-6 小 N 统计边界**：见 §5。若要 N=5 也严格 ≤1，需要协议层给跟随节点
   补拉引入按 N 缩放的二次抖动，属新卡，不是调阈值。
2. **可见性 279.5s 接近 300s**：出现在 N=100/M=5000 高频，探针排在令牌桶队列尾部。
   实测仍达标，但余量只有 20.5s；若将来 M 再涨，建议单独观察队列等待分位数。
3. **模型参数**：`TASK_STATE_BYTES` / `STATE_JSON_BYTES_PER_CARD` 是显式标注的
   仿真参数，A 场景绝对字节数随它们线性缩放；A/B 的**比值、O(N) vs O(1) 结论**
   与这两个参数的选择无关。
4. **真实生产级带宽 / Gitea QPS**：本卡纯仿真不产生，标 `unavailable`；
   由 T-0356 集成回归与 T-0357 灰度观察在 dev 环境复核。
