## 背景

T-0310（控制面编排器）合入 main（25b5474）后，在 fb98（FreeBSD，有 AF_UNIX）上复跑：

```
python -m pytest -q tests/test_control_plane.py
1 failed, 56 passed
FAILED tests/test_control_plane.py::test_start_tolerates_busy_worker_socket
```

该用例要求：Worker socket 路径被别的进程占着时，`Plane.start()` 不抛异常，但要在 `status()["errors"]` 里留一条 `worker-sock: ...` 记账。

**根因不在 plane.py 的 try/except，而在 `hive_control/worker_sock.py` 的 `WorkerServer.start()`：**

```python
self._stop.clear()
self._unlink()          # ← 无条件删掉已存在的 socket 文件
listener.bind(self.path)  # ← 于是 bind 永远成功
```

`_unlink()` 是本意是清陈旧 socket，但它**分不清「陈旧」和「正被别的进程监听」**：直接把活着的路径删掉，自己 bind 到新 inode，于是既不抛异常、也无错可记，原监听者被静默架空（它的 socket 还在，但路径已经指向别人）。

这条用例在 deepseek-win 的机器上是 **skip**（Python 3.14 没有 AF_UNIX），所以它报「53 passed, 1 skipped」时说「唯一 skip 是平台能力缺失，与实现无关」——实际上这是**这条契约从未被真正执行过**，一到有 AF_UNIX 的机器就红。

## 要做什么

1. `WorkerServer.start()` 的陈旧判定：`_unlink()` 之前先探测路径是否仍有活监听者（`connect` 带超时；`ECONNREFUSED`/`ENOENT` 才算陈旧）。活着的就**不删**，让 `bind` 抛 `EADDRINUSE`，交给上层记账。
2. `Plane.start()` 的记账保持现状即可（已有 `except (OSError, AttributeError, NotImplementedError)`）——但要确认 `EADDRINUSE` 能走到 `_note_error("worker-sock: ...")`，别在中间被吞。
3. `tests/test_worker_sock.py` 补三条：
   - 陈旧 socket 文件（无监听者）→ 能正常接管；
   - 活着的监听者 → `start()` 抛错，且**不删**对方路径；
   - 路径不存在 → 正常 bind。
4. `tests/test_control_plane.py::test_start_tolerates_busy_worker_socket` 保持原断言不动（它是对的），改完应转绿。

## 不要做什么

- 不要为了让用例变绿而放宽 plane 的断言，或把该用例再 `skipif` 掉。
- 不改 `hive_control/plane.py` 里 worker-sock 之外的部分（T-0311/0312 正在动适配器与端到端不变量）。
- 不动 `hive_control/adapter.py`、`hive_cluster.py`（T-0311 的地盘）。
