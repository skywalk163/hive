## 背景

参考 reactive-agents 的 scoping 模型：`allowedTools` 是硬白名单，不在其中的工具在模型看到 schema 之前就被剪枝；`focusedTools` 是软聚焦，全量工具仍可调用但被聚焦的工具被高亮呈现。lightharness 已有 `src/预设.light` / `src/预设挂载过滤.light` 机制，这两个列表可以**通过 preset 或 profile 补丁注入，不需要改底层 registry**。

## 目标

1. 实现 `allowedTools`（硬白名单）：不在列表中的工具在进入模型 schema 之前剪枝；
2. 实现 `focusedTools`（软聚焦）：全量工具可调用，但聚焦工具在呈现时高亮/前置；
3. 两个列表均可通过 preset 注入。

## 关键设计取舍

**硬白名单只用于「锁死 surface」的场景**（如子代理只做 ctx 操作）。常规会话用 soft focus 即可——避免模型因为工具被剪枝而「编造不存在的工具名」。这一取舍要写进实现注释与卡面。

## 交付物

- `src/工具面装配.light`：两种可见性级别的装配逻辑
- `src/预设.light` / `src/预设挂载过滤.light`：preset 注入入口
- `tests/test_T0497_双级可见性.py`

## 验收判据

1. `allowedTools` 生效时，白名单外工具确实不出现在模型可见 schema 中；
2. `focusedTools` 生效时，全量工具仍可调用，聚焦工具呈现位置/高亮可验证；
3. 通过 preset 注入两种列表均生效；不注入时行为与现状完全一致（向后兼容）；
4. 既有工具面测试不回归。

## 红线

- 常规会话默认不得启用硬白名单（只允许显式 preset 开启）；
- 剪枝必须发生在 schema 构建前，不能先发给模型再撤回；
- 向后兼容：无 preset 配置时工具面与改动前一致。
