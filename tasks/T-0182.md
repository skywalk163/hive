> 来源：R164-T4 形态裁定登记的 **L-235**（缺陷账 §二十二五段式）。与 L-232（R163-A 已修「作为函数值」形态）同源不同投影。

## 背景

协程/闭包的**就地按名调用**形态：在 `异步 段落` 体内**直接按名**调用一个外层捕获了变量的内层段。

- 双腿对拍实测：原生腿 `同步就地=1`（拿不到捕获值）/ 转译腿 `同步就地=11`（拿到了）。
- IR 证据：直调点 `@_seg_f2(..., ptr null)`——env 恒传 null，所以内层读不到外层捕获变量。
- R163-A 只修了「把内层当函数值传递」的形态（L-232，自由变量登记为帧槽 + resume_0 解包），**不覆盖「就地按名直调」这条调用路径**。

## 要做什么

1. **先读缺陷账**：`docs/功能对标/语言缺陷账.md` §二十二 L-235 条目（五段式），确认现象/IR 证据/修法边界。
2. **定位直调路径**：在 `src/llvm/codegen_typed.py` 找到「异步段落体内按名直调内层段」的 codegen 分支（对比 L-232 已修的「函数值传递」分支），找到 env 传 null 的具体点。
3. **修法方向**（参照 L-232 已落地的 env 登记/解包/写回三件套，但作用到直调路径）：直调时把当前闭包 env 作为实参传入，而不是恒传 null。
   - 先在 FreeBSD 0.88 用最小探针复现 `同步就地=1`，修后转 `同步就地=11`。
4. **配最小回归用例**：`tests/unit/test_R164_L235_同步就地闭包.py`（新建），含双腿对拍 + 反跑有牙。
5. **反跑纪律**：直调点重新传 null → 探针立红；还原 → 转绿。
