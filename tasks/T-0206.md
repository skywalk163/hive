## 背景

Windows 上每 30 秒闪一次黑窗，根因不在调度，在 **spawn 方式**：

- 看板 `dashboard/serve.py::refresh_loop` 每 `--refresh-interval`（默认 30s）跑一次
  `hive status --json`；`hive.py:2837 cmd_status` 又**无条件**先 `fetch()`。
- 全仓 **29 处** `subprocess.run/Popen` 调用点，`creationflags` 只出现在 3 处
  （`hive.py:4206/5143`、`hive_cluster.py:3170`），而且都是 `DETACHED_PROCESS`。
  父进程没有控制台时，子进程（git 是 console 程序）会**自己新建一个可见控制台**
  —— 这就是弹窗，`DETACHED_PROCESS` 恰恰是帮凶。
- 所以哪怕真的执行 git，只要给子进程加 `CREATE_NO_WINDOW` 就不会有窗口。

## 要做什么

1. `hive_compat.py` 新增 `no_window_kwargs()`：Windows 返回
   `{"creationflags": subprocess.CREATE_NO_WINDOW}`，其他平台返回 `{}`；
   环境变量 `HIVE_NO_WINDOW=0` 时一律返回 `{}`（逃生阀）。
2. `hive.py::run()` 单点接入 —— 它已经是全仓唯一的命令出口（`git()`/`git_net()`
   都走它），改一处覆盖绝大部分调用。
3. `dashboard/serve.py::refresh_loop` 的 `subprocess.run(argv, ...)` 接入。
4. `hive_cluster.py::_git_rev` / `_remote_head` 的 `subprocess.run(["git", ...])` 接入。
5. `tests/test_no_window.py`（新）：**AST 扫描**全部生产模块，枚举
   `subprocess.run/Popen/check_output/call/check_call` 调用点，断言「除白名单
   （交互式 agent 拉起、`_spawn_background` 的 DETACHED_PROCESS）外，每个调用点
   都经过统一封装或显式带 no_window kwargs」。

## 不要做什么

- 不动调度架构、不动同步间隔（那是 T-0211）。
- 不给 `hive.py:5143` / `hive_cluster.py:3170` 的 daemon 拉起改标志：
  `CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` **互斥**，混用会起不来。
- 不给交互式 agent 拉起（`work` 里 Popen 的 agent 命令）加隐藏窗口——会吞掉
  人需要看的实时输出。
- 不顺手改 `git_net` 的超时语义。

## 完成标准

- `python3 -m pytest -q tests/test_no_window.py tests/test_core.py tests/test_dashboard_freshness.py` 全绿。
- **反证**：把 `run()` 里的 `no_window_kwargs()` 去掉，AST 判据必须变红（贴前后输出）。
- Windows 真机证据：`hive status --json` 期间枚举可见控制台窗口，**增量 = 0**
  （贴计数脚本与输出）。
- summary 里列出 29 个调用点里哪些走封装、哪些在白名单、为什么。
