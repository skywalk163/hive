## 背景

母文档 §6：增量 / 全量拉取、分页 100、配额（增量 10/s/项目，全量 1/60s/项目）、
人工拉取走独立队列。TCP 监听与上行共用一个端口。本卡实现协议服务端与客户端。

先读 `docs/控制面v0.5-实现约定.md` §2.4 / §3.5 与 D3/D15。

## 目标

实现 `hive_control/pull.py`：

1. `PullRetry(after_ms)` 异常。
2. `PullService(view, limits, clock)`：
   - `handle(req)` 返回响应行；校验 project / mode；
   - incremental：`watermarks` 逐条水位优先；没有则 `from` 当全局下界；
     返回 `version_key > 水位` 的条目，**包含 dna 条目**；
   - full：`from=null`，按 `(project, tid)` 排序，每页 ≤ `page_size`，
     每页以 `{"type":"page","page":K,"total_pages":T}` 开头；
   - 配额：按注入 clock 的滑动窗口；超限返回 `{"type":"retry","after_ms":...}`；
   - 并发调用线程安全。
3. `ControlTcpServer(bind, port, on_entries, pull, limits)`：
   - 监听 `0.0.0.0:port`，`port=0` 时暴露实际端口；每连接一个线程；
   - 首行 `type=="pull"` 走 PullService，否则按 entry 行调用 `on_entries`；
   - 响应以空行结束；坏行跳过不崩连接；连接空闲超时 `tcp_idle_timeout`。
4. `PullClient.fetch(host, port, req)`：连接、发送、读到空行；自动收全分页；
   遇 retry 抛 `PullRetry`；坏行跳过并计数。

## 测试（`tests/test_control_pull.py`）

- 250 条条目全量 → 3 页，客户端收全 250；
- 增量按逐条水位只返回新条目；
- 配额：第 11 次增量 / 第 2 次全量返回 retry，`after_ms>0`；
- 空变化返回空行且客户端得 `[]`；
- 同端口混合：先发 entry 行能安装，再发 pull 能响应；
- 坏 JSON 不崩连接。
