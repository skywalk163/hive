## 背景

上下文块装配族有多个语义高度重叠的工具（对应原 tool_20/21/22/23：选块 / 截断摘要 / 装配 / 装配报告）。模型在这几个之间容易选错，选错一次就是一轮校验失败。本卡聚焦这**一族**，落点在 `src/分块列表.light` 与装配相关逻辑。

## 目标

先判断这族工具的差异**主要是参数校验/后处理，还是执行路径本质不同**：

- **若差异主要是校验或后处理**：合并为一个 `ctx_assembly` 入口，把「选块 / 截断 / 装配」变成 `mode` 枚举参数。校验逻辑下沉到统一流水线，模型只做**意图选择**，不做**实现选择**。
- **若执行路径差异大到合并会破坏缓存或幂等性**：保留工具，但在 description 中显式写出**选择决策树**（「要 X 用 A，要 Y 用 B」），并把差异写进错误消息的 `suggestion` 字段（与 W3/T-0504 联动）。

实现前先做差异分析，把结论写进卡面评论，再选合并或决策树路线。

## 交付物

- 合并后的单一入口 **或** 带决策树的 description + suggestion 联动
- `tests/test_T0499_ctx装配合并.py`
- 一段差异分析结论（写进本卡的讨论或注释）

## 验收判据

1. 选定路线后，模型只需做意图选择即可命中正确行为；
2. 若合并：mode 枚举覆盖原有多工具的全部能力，无能力丢失；
3. 若保留：description 决策树 + 错误 suggestion 足以让模型一轮改对；
4. 既有装配相关测试不回归。

## 红线

- 不丢失原有多工具的任何能力；
- 若执行路径差异会破坏缓存/幂等，**必须走保留路线**，不得强行合并；
- 与 W3 错误契约（T-0504）的 suggestion 字段口径对齐，不另起一套。
