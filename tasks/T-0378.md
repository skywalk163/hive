# B 线：src/diagnostics 诊断码注册表

> 总纲：`docs/R222_语言×AI适配总纲.md`（hive 仓）。

## 背景

`src/diagnostics/registry.py` 和 `L1001–L5003` 这批码**现在都不存在**（此前有文档引用它们，
是口径漂移）。本卡负责从零建立这批码，**并且只建立码表和最小校验入口**，不改任何 parser 语义。

Agent 需要的不是「报错了」，是「错误码 + 位置 + 最小修复」。码表是这个能力的唯一事实源。

## 要做什么

1. 新建 `src/diagnostics/__init__.py` 与 `src/diagnostics/registry.py`：
   - 码区间约定：`L1xxx` 词法/关键字，`L2xxx` 语法/结构，`L3xxx` 类型与名字，`L4xxx` 语义与后端，
     `L5xxx` 工程与风格（lint 类）。
   - 每条码：`code` / `severity`（error|warning|info）/ `message`（中文，一句话说清人话）/
     `hint`（**最小修复建议**，可直接照做）/ `anchor`（这条码由谁产生：`cli` / `linter` / `parser`）。
   - 提供 `get(code)`、`all_codes()`、`format_diagnostic(code, file, line, col, extra=None) -> dict`。
   - 未注册的 code 必须抛 `KeyError` 而不是返回空（避免下游写出假码）。
2. `src/diagnostics/lint_bridge.py`：把 `src/linter/light_linter.py` 现有的规则（`E001`/`W001`/`E016`/`W016`
   等）映射到 `L5xxx`，**只做映射，不改 linter 行为**。
3. `tests/test_diagnostics_registry.py`：码唯一、区间合法、每条都有 `message` 与 `hint`、
   `format_diagnostic` 输出可 `json.dumps`、未注册码抛异常。

## 不要做什么

- 不要碰 `cli/light.py`（接线归 T-0382）。
- 不要改 `src/linter/` 的任何规则行为（D 线在改同一目录的 canonical 部分，冲突由 hive 串行）。
- 不要删旧规则码；一律「旧码 → 新码」映射表，向下兼容。
- 不要写「L9xxx」之类未定区间。

## 完成标准（verify 必绿）

- `PYTHONPATH=src python3 -m pytest -q -o addopts= tests/test_diagnostics_registry.py`
