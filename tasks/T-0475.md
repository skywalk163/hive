## 这张卡是给谁领的

**只给 `DESKTOP-6LFQUO8`（`http://192.168.0.100:8788`，仓在 `G:\dswork\duan-light-merge\hive`）的 agent 领。**

同一个仓库里还有 `T-0473`（IC6RTQ4）、`T-0474`（fb98） 两张同样结构的卡，
分别属于另外两台机器。**不要领不属于自己节点的卡**：先在本机跑

```bash
python hive.py cluster status
```

看「本机」那一行的节点名；对不上就说明这张卡不是你的，去领对的那张。

## 背景

0.16.09 修了两个租约 bug（`554cb2b` 心跳续租没写回节点记录、`4730460` 租约与
空闲心跳同为 5s 撞车）。**租约由主控签发**，所以只升级跟随者没用 —— 每个节点
都必须把自己的仓更新到 `0.16.09` 并**重启本机的集群进程**，新代码才会真的跑起来。

2026-11-25 09:24 实测：`IC6RTQ4` 还是旧代码（`uptime=45.93h`、租约 `4.9s`）；本机 `DESKTOP-6LFQUO8` 当时已是新代码。即便已是新代码，也要按本卡第 1 步自检确认，自检通过就不重启、直接记录。

手工重启过老版本的进程容易出问题（`cluster.pid` 缺失时 `restart` 会停在
「找不到 pid 文件」，然后 `start` 看到端口被占又什么都不做，看着像成功其实
没换代码）。所以这张卡要求**先自检、再决定是否重启、最后用 health 证实**。

## 本节点注意（平台差异）

Windows（win10）。本机是当前主控，重启会让主控权临时换到别的节点，
属正常现象；重启后要按 health 里 `leader` 字段指向的那台去验租约，
别按老地址验。

## 操作步骤（在本机执行）

### 1. 自检：本机是不是已经不需要重启

```bash
# 本机角色与本仓版本
python hive.py --version
git -C <本机仓路径> log --oneline -1
python hive.py cluster status
```

再问一次本机 health：

```bash
curl -s http://127.0.0.1:8788/api/cluster/health
```

**判定「无需重启」的条件（两条都要满足）**：

- 本仓 `HEAD` 已包含 `0.16.09`（`python hive.py --version` 输出 `0.16.09`）；
- 本机 `uptime_s` 小于 1 小时，且它当前认的主控下发租约 ≥ 10s。

若已满足：**不要重启**，直接跳到第 4 步写记录，结果为 `done`，
在记录里写明「已是最新，未重启」。

### 2. 同步代码

```bash
git -C <本机仓路径> pull --ff-only
python hive.py --version        # 必须显示 0.16.09
```

`--ff-only` 失败说明有本地分叉：**停下**，把现场（`git status`、`git log --oneline
HEAD..origin/main`）写进本卡留言，不要 `reset --hard` / `push --force`。

### 3. 重启本机集群

```bash
python hive.py cluster restart
```

- 启动闸会先对比本仓 `HEAD` 与 `origin/main`，落后就打印
  `⚠ 正在运行的 hive 落后远端 N 个提交` —— 看到它说明第 2 步没生效，回去重做。
- 若报「集群在运行，但找不到 pid 文件」：**说明老进程是旧版、没落盘 pid**。
  不要直接 kill -9。发 SIGTERM 让它优雅退出（它的信号处理里会
  `cluster.stop()`），确认端口不再响应后再 `cluster start`。
  Linux/FreeBSD 见清单第 2.6 节；Windows 用
  `Get-CimInstance Win32_Process -Filter "Name='python.exe'"` 找到
  `cluster serve` 的 pid，再 `Stop-Process -Id <pid>`（默认就是 TERM 语义）。

### 4. 用 health 证实（这一步是判据，不许跳过）

```bash
curl -s http://127.0.0.1:8788/api/cluster/health
```

要同时看到：

| 项目 | 要求 | 说明 |
|---|---|---|
| `uptime_s` | < 600（10 分钟） | 证明进程真重启了，不是报个成功 |
| 主控下发租约 | ≥ 10s | 新代码 15s；旧代码是 4~5s |

租约要看 **`leader_lease_until_epoch` 减去当前时间**，不是看本机自己的配置值。
若主控刚换过，以 health 里 `leader` 字段指向的那台为准。
