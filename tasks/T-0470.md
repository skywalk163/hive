# lightharness 工具根/worktree 支持：cd 守卫与读写路径解耦

## 背景（来自 T-0461 交接文档，实测）
代理在 worktree `/home/skywalk/.hive/wt/T-0461` 干活，但：
- bash 工具的 `越界正则`（`src/工具_bash.light:32`）只匹配**字面量** `cd /abs`、`cd ..`，代理发现 `W=/home/...; cd $W` 可绕过守卫——护栏被"合法绕过"，且这种绕法被当经验写进交接文档传递。
- `read_file/write_file` 的根是 `取根目录()`（`src/工具_路径安全.light:17`：`HARNESS_ROOT > 会话cwd > 当前目录`），固定在项目根 `/home/skywalk/dswork/lightharness`，够不到 worktree。代理只能用 bash cat/heredoc/python3 绕着写文件。

## 要做什么
- 工具根支持会话级工作目录覆盖：Web 请求 / CLI 可通过会话属性或参数指定工作根（如 `HARNESS_CWD` 或会话 cwd），bash/read/write/search 四个工具统一使用这个根；worktree 路径应作为合法根被接受（可配置白名单前缀，如 `~/.hive/wt/` 与项目根，避免任意目录逃逸）。
- cd 守卫升级：从"字面量正则"改为"解析后路径判定"——对 `cd $VAR`、`cd "带空格/变量"` 等间接形式，解析实际目标路径后按统一安全判定；既堵住绕过漏洞，又让合法 worktree 路径可以正常 cd（不再需要 `$W` 绕法）。
- 保持无 worktree 场景的既有行为（根仍是项目根，普通 cd .. 仍拒）。
- 相关文件：`src/工具_路径安全.light`、`src/工具_bash.light`、`src/工具_读文件.light`、`src/工具_写文件.light`、`src/工具_搜索文件.light`、`src/web服务器.light`（会话 cwd 透传）。

## 验收
- 新增 `tests/test_T0470_工具根与cd守卫.py`：
  - worktree 根设为会话 cwd 时，read/write 能读写该目录下文件，bash 能 `cd <worktree绝对路径>` 成功；
  - `cd $W`（W=worktree 路径）解析后判定为合法，不再靠绕过；`cd /tmp`、`cd ..` 越界仍拒；
  - 不设会话 cwd 时行为与旧版一致（回归 4 工具根目录测试）。
- `python -m pytest -q tests/test_T0470_工具根与cd守卫.py` 全绿。

## 不做什么
- 不放开到任意绝对路径（必须白名单/会话根约束）。
- 不改 T-0442 bash 修复的超时/stdin/退出码语义。
