## 背景

`docs/操作手册.md` 的标题编号已经乱了，翻起来很吃力（它是人和新 agent 了解 hive 的主入口）：

```
## 5. 分支与合并
### 5.2 audit        ← 5.1 呢？
### 5.3 paths 越界
### 0. 一条运维约定   ← 凭空冒出个 0
## 6.6 草稿          ← 顶层 ## 却用 6.x 编号，还夹在 §5 中间
## 6.7 验收强度
## 6.6 复盘          ← 6.6 重复
## 6.5 状态机        ← 倒着来
### 5.4 写命令的提交范围
### 5.1 hive land    ← 最重要的 land 排在最后
## 6. 租约与故障      ← 父章节出现在子章节之后
## 8.1 exec worker   ← 该是 ### 却写成 ##
```

四个 `## 6.x` 块物理上夹在 §5 的 `###` 之间，把 §5 拦腰截断；`6.6` 出现两次；`0.` 突兀。

## 目标

1. 整理成单调递增、层级正确、无重复的编号（内容不删不改，只调顺序与编号）：
   - §5：`hive land` 回到 **5.1**（audit 5.2 / paths 5.3 / 运维约定 5.4 / 写命令 5.5）；
   - 四个块移到 §6 之下，降为 `###` 并编为 **6.4 草稿 / 6.5 验收强度 / 6.6 复盘 / 6.7 状态机**；
   - `## 6. 租约与故障` 改名为「租约、故障与验收机制」，才装得下这些子章节；
   - `## 8.1` 降为 `### 8.1`。
2. **外部引用不能断**：`README.md` 引用 §5.1（hive land）与 §8（已知坑 gc），
   `CHANGELOG.md` 引用 §4.1 与 §8。所以 5.1 和 8 这两个编号必须保持原义 —— 这也是为什么
   要把 land 移回 5.1，而不是顺手把它编成 5.5。手册内部的 `§5.4` 引用同步改成 `§5.5`。
3. **加回归测试** `tests/test_docs.py`：解析手册标题，断言
   - 顶层 `## N.` 从 1 开始、严格递增、无重复；
   - `### N.M` 必须隶属于当前顶层 N，且 M 递增、无重复；
   - 支持 `N.M.K` 三级（如 6.1.1 重试熔断）；
   - `###` 不会出现在还没有 `##` 之前。
   这样以后谁再把编号写乱，测试立刻红。

## 红线

- **不改**手册正文内容（只调标题编号与块顺序，不动文字、不删段落）。
- **不改** `README.md` / `CHANGELOG.md` / `windows/README.md` 的既有章节引用
  （它们引用的 5.1 / 4.1 / 8 编号在本卡后仍然成立，所以不需要动）。
- **不引入** 任何第三方依赖。
- 测试只做静态解析，不联网、不改仓库状态。
