light 自己的报错文案在推荐一个**不存在的内置**：`切片下标检查` 抛 `TypeError` 时让人「请用 `整数()` 转换」，但 light 里没有 `整数` 这个函数，只有 `转整数`。用户照文案去调，撞的是「未定义」。

## 现场（2026-11-03，main @ 807f5e02a 实测）

```
stdlib/builtins.py 切片下标检查：
    raise TypeError('切片下标必须是整数，实际为' + 名 + ' ' + str(值) + '，请用 整数() 转换')
```

- `grep -nE "^def 整数" stdlib/builtins.py` → **无**
- `grep -n '"整数"' stdlib/builtins.py`（导出表）→ **无**
- `stdlib/内置核心转换.light:12` 导出的是 `转整数 转浮点 转字符串`；`:15` 是 `段落 转整数(文本)`
- 全仓 `stdlib/*.py|*.light` 里唯一带「整数」的定义是 `网络.py:278 整数转网络字节序`（不相干）

**来历猜测**：`整数` 是 lightharness 副本独有的名字（`scripts/sync_builtins.py` 里 `LH_ONLY = {"整数"}` 原样保留）。这句文案大概是按 LH 侧的习惯写的，落到 light 真源就成了「推荐一个自己都没有的函数」。

## 两条修法

1. **改文案**（推荐）：`请用 整数() 转换` → `请用 转整数() 转换`，零成本、不动内置面；
2. 真补一个 `整数`：要同步三副本（真源 / boot / LH）+ 原生腿能力清单，还得跟 `转整数` 划清语义，成本明显不划算。

选 1 就行；除非你判断对外 API 就需要 `整数` 这个名字。

