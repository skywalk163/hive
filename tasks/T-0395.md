# 会话级工作目录（后端）：全局设置降为默认值

## 背景（为什么需要这张卡）

上游 DSH 在新建会话时就能选目录，**目录是会话属性**。lightharness 现在只有一个全局目录：

- `src/web服务器.light:254` 的 `取会话` 把 `己.生效工作目录`（settings.json 的 `工作目录`，
  由 `POST /api/cwd` 写入并顺带 chdir 进程）当成**所有**新会话的 cwd；
- `POST /api/sessions`（`src/web服务器.light:1239`）只接受 `标题`，没有目录字段；
- 会话头信息里其实早有 `工作目录`（`src/会话.light:53/63`），`读入会话带策略`
  （`src/持久化.light:169`）也会从首行 `cwd` 还原——但新建路径从不写入用户选的目录，
  这条链路是死的。

后果：同一 lightharness 进程里所有会话共用一个根；想换项目只能去「设置」改全局，
而 `POST /api/cwd` 会 chdir 整个进程，正在跑的会话跟着漂。多项目并行根本做不了。

## 要做什么

1. `POST /api/sessions` 接受可选 `工作目录`：必须是存在且可读的目录（复用
   `解析工作目录` / `断言可用`）；非法返回 400 + 明确理由，**不写索引、不建空日志**。
2. `POST /v1/chat/completions` 惰性建会话时接受 `工作目录`：首条消息就把目录写进新会话
   头信息；未传则回退全局（旧行为完全不变）。
3. `取会话` 的目录解析顺序改为：请求目录 → 索引元数据 `工作目录` → 全局 `生效工作目录`
   → `HARNESS_CWD` → `当前目录()`。已有会话以**首行 cwd** 为准（`读入会话` 已实现），
   不要用全局覆盖。
4. `src/会话存储.light:186 新建会话(标题)` 增加工作目录入参，把 `工作目录` 写进索引
   元数据（`_index.json`）。旧索引没有该键 → 回退全局，**不做数据迁移**。
5. `GET /api/sessions`、`GET /api/sessions/current` 返回的元数据新增 `工作目录` 键；
   只增不改，侧边栏依赖的旧键形状保持。
6. 新增 `tests/test_T0395_会话工作目录.py`，至少覆盖：
   - 两条会话各自不同目录并发存在，路径安全各按各根（照 T-0180 的「反证」写法，
     旧实现下必须红）；
   - 重启（新 Hive 实例/重新读入）后会话 cwd 不丢；
   - 非法目录（不存在/是文件/相对路径）400，且索引里没有新会话；
   - 不传目录时回退全局，与旧行为一致。

## 不要做什么（红线）

- 不改 `POST /api/cwd` 的语义：它仍是「全局默认 + 进程 chdir」，UI 改造在下张卡。
- 不动 `HARNESS_ROOT` / `HARNESS_CWD` 的优先级（`T-0180` 的五条判据必须继续全绿）。
- 不改 CLI / MCP / 子代理的 cwd 逻辑，不顺手重构 `web服务器.light`（拆分是 T-0393 的事）。
- 不做目录浏览/最近列表 API（T-0396 再做）。
- 不动 `examples/` 期望输出，不顺手格式化。

## 完成标准

- 两个 verify 命令全绿；新用例在旧实现下必须红（否则是空判据，打回重写）。
- summary 贴出：两条会话 `GET /api/sessions/:id` 的 cwd、重启后 cwd、非法目录 400 响应体、
  `test_T0180` 全绿输出。
