## 背景

第三层要省掉「人工粘贴」：Hive 生成指令 → 脚本切窗口 → 粘贴 → 回车 → 回 Hive 标记已推送。
分工的要点是**只自动化派发，不自动化执行**：派发是确定性的（切窗口/粘贴/回车），
GUI 自动化在这里稳；执行仍由 agent 在自己的 chat 里完成。

前置 T-0184 已提供 `dispatch_prompt`（渲染文本与 `--json` 载荷）。本卡只写脚本与静态测试，
**真正的 CLI 子命令 `hive prompt` 由 T-0188 接线**；脚本按卡内固定的 CLI 契约调用，
契约不满足时脚本必须显式报错而不是静默失败。

### 固定 CLI 契约（T-0188 承诺实现，本卡按此写）

```text
python hive.py --dir <hive路径> prompt <T-xxxx> --agent <agent名> --format json
```

- 成功：stdout 是单个 JSON 对象（`payload["text"]` 为要粘贴的正文），退出码 0；
- 任务不存在 / 参数错：退出码非 0，stderr 有可读错误；
- 标记已推送（脚本第 5 步）：

```text
python hive.py --dir <hive路径> dispatch-mark <T-xxxx> --agent <agent名>
```

## 要做什么

### 1. `windows/dispatch-agent.ps1`

参数：

```powershell
param(
  [Parameter(Mandatory=$true)][string]$Task,
  [string]$Agent,
  [string]$Config = "$PSScriptRoot\dispatch-agents.json",
  [string]$HiveDir = (Resolve-Path "$PSScriptRoot\..").Path,
  [switch]$Apply,          # 不加就是 dry-run
  [int]$SendDelayMs = 800
)
```

流程（严格按序，任一步失败即中止且**不**标记 dispatched）：

1. 校验 `$Task` 形如 `T-\d{4}`；
2. 读配置表：`{ "<agent名>": { "window_title": "...", "hive_agent": "trae-win" } }`；
   未传 `$Agent` 时按配置顺序找第一个已打开窗口的 agent（找不到就报错列出候选）；
3. 调 `prompt --format json` 取 `payload.text`，UTF-8 解码（`[Console]::OutputEncoding` 显式设 UTF-8，避免中文乱码）；
4. `-Apply` 未给时：打印 `[dry-run]` 目标窗口标题、正文前 5 行、将要执行的 dispatch-mark 命令行，然后退出 0；
5. `-Apply` 时：用 Win32 `SetForegroundWindow`（`Add-Type` 内联 C# 或 `WScript.Shell.AppActivate`）激活窗口，
   **激活后用 `Get-Process | Where MainWindowTitle` 复核当前前台窗口标题与配置匹配**，不匹配则中止（防粘错窗口）；
6. 把正文放进剪贴板（`Set-Clipboard`），`Start-Sleep -Milliseconds $SendDelayMs`，
   发送 `^v` 再发送 `{ENTER}`（`WScript.Shell.SendKeys`）；
7. 调 `dispatch-mark`，退出码非 0 时打印警告并返回非 0（派发已发生，但账没记上，必须让人看见）。

硬性要求：

- 默认 dry-run；**不加 `-Apply` 绝不发送任何按键**；
- 配置表路径可覆盖，缺文件时用 `dispatch-agents.sample.json` 的形态报错提示，不内置任何窗口标题；
- 脚本里不许出现具体 agent 名/窗口标题字面量（除了示例配置）；
- 所有输出 `Write-Host`/`Write-Error` 中文 UTF-8 不乱码。

### 2. `windows/dispatch-agent.ahk`（AutoHotkey v2）

- 只做两件事：快捷键（如 `^!d`）调用 `dispatch-agent.ps1 -Apply -Task <选中文本或输入框内容>`；
  以及失败时的气泡提示（`TrayTip`）。
- **不得**在 AHK 里重新实现 JSON 解析、窗口匹配或标记逻辑——一切逻辑在 ps1。

### 3. `windows/dispatch-agents.sample.json`

示例配置（真实窗口标题留占位，不进真配置）：

```json
{
  "trae":  {"window_title": "<Trae 窗口标题片段>", "hive_agent": "trae-win"},
  "codearts": {"window_title": "<CodeArts 窗口标题片段>", "hive_agent": "codearts-win"}
}
```

### 4. `tests/test_dispatch_script_static.py`

静态断言（Windows/FreeBSD 都能跑，纯读文件，不执行脚本）：

1. ps1 含 `prompt` + `--format json` + `dispatch-mark` 三处调用；
2. ps1 的 `param` 块里 `$Apply` 是 switch 且默认未赋值（dry-run 默认）；
3. ps1 里 `SendKeys` / 发送按键的语句都在 `if ($Apply)` 分支内（用正则断言其前面最近的
   `if ($Apply` 守卫）；
4. ps1 里出现窗口标题复核（`MainWindowTitle` 或 `AppActivate` 返回校验）；
5. ps1 不含硬编码 agent 名（对 `trae-win|codearts-win|raccoon-win|dumate-win|doubao-win|workbuddyai-win` 断言只出现在示例配置或注释里，
   实现区不得命中）；
6. ahk 不含 `dispatch-mark` 与 `hive.py prompt`（逻辑不得重复实现）；
7. `dispatch-agents.sample.json` 可 `json.loads` 且每项含 `window_title` / `hive_agent`；
8. 三个文件均为 UTF-8（含中文注释时能被 `read_text(encoding="utf-8")` 读出）。

## 不要做什么

- 不修改 `hive.py` / `mcp_server.py` / `dashboard/` / `dispatch_prompt.py`（T-0184 / T-0188 的路径）。
- 不自动化「执行」环节：脚本发完回车就结束，不等 agent 回复、不读 chat 内容。
- 不写死窗口标题、不写死 agent 名、不把 token 写进脚本。
- 不在测试里真发按键（CI 无人值守，一定失败）。
