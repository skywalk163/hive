## 背景

0.5.0 加的 `hive mcp` 是**worker 视角**的：查卡、领卡、交活、放弃。够用，但闭环的另一半
——总控（合入、重试、关闭、分派）——还只能敲 CLI。意思是「agent 能自助干活」，
但「谁来当总控」仍然是人。

要让 hive 真的自己跑起来，总控这一侧也得能被 agent 调用。

## 目标

给 MCP 加 controller（总控）视角。

1. **角色开关**：`hive mcp --agent workbuddy --role controller`
   （或 `HIVE_ROLE=controller`）。不带 `--role` 就是现在的 worker 视角，行为不变。
2. controller 额外暴露的工具（**都是破坏性操作**，务必谨慎）：
   | 工具 | 作用 | 默认行为 |
   |---|---|---|
   | `hive_land` | 合入已完成的卡（依赖 T-0110 的 `cmd_land`） | **默认 dry-run**，`apply=true` 才真合 |
   | `hive_close` | 关闭一张卡（归档结果、删 claim/res 分支） | 直接执行 |
   | `hive_retry` | 重跑一张卡（清结果和租约） | 直接执行 |
   | `hive_assign` | 把卡指派给某个 agent | 直接执行 |
   | `hive_dispatch` | 跑一次自动分派 | **默认 dry-run** |
   | `hive_gc` | 回收过期租约 | **默认 dry-run** |
3. **安全约定**（这几条必须落实，不是可选项）：
   - **破坏性工具一律默认 dry-run**，工具描述里写明「先不传 apply 看计划」；
   - `hive_land` 遇到合并冲突时必须返回 error 并给出冲突文件清单，**绝不自动解冲突、
     绝不 force push**；
   - controller 也不许替别的 agent 提交/终止（复用 worker 侧那套归属校验）；
   - `initialize` 的 instructions 里要写明「你是总控，操作会改动 main」。
4. **`hive_whoami` 带上角色**：controller 视角下返回 `"role": "controller"`
   以及「待合并 / 待处理」计数（多少张 result=done 但 state!=done、
   多少张 conflict、多少张 lease 过期），让总控 agent 知道今天该干什么。
5. 测试（`tests/test_mcp.py` 里加）：
   - controller 起得来，工具清单包含 `hive_land`；
   - worker 视角起的服务**不含** `hive_land`（权限隔离要有明确的证据）；
   - `hive_land` 默认 dry-run 不动分支，`apply=true` 才合；
   - `hive_retry` 之后失败的结果被清掉。

## 红线

- 不改 light 等仓；不引入新依赖。
- worker 视角（不给 `--role`）的**工具清单必须一字不变** —— 现有 15 个测试是照着它断言的。
- 不许给 worker 视角加任何能改 main 的能力。
- 别动 `tasks/*.md`、`results/*.json`。
