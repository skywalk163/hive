# 选举安全：单票也可称主 + 失败即 3 秒连打（term 膨胀与脑裂来源）

## 一、现象（2026-11-09 实测，`cluster.log` 原文）

```
19:19:00 本轮选举未获多数：term=2047（1/3 票）
19:19:03 本轮选举未获多数：term=2048（1/3 票）
19:19:05 本轮选举未获多数：term=2049（1/2 票）
19:19:09 当选主节点：term=2050（1/1 票）
```

同样的四连击在 `19:20:22→19:20:31`、`19:21:59→19:22:13` 反复出现；
10 分钟窗口内 101 次 `election_started`、136 次 `term_advanced`、23 次 `leader_lost`。
term 从 11-08 的 637 涨到 11-09 19:24 的 **2060**。

## 二、证据锚

- `hive_cluster.py#L2112-L2117`：`_quorum_locked()` 在 `voters <= 1` 时**直接返回 1**。
- `hive_cluster.py#L1561-L1569`：节点 `dead_timeout=15s` 即被判 dead，退出票池
  （参数默认见 `#L110-L116`：`leader_lease=5s`、`election_min=3s`）。
- `hive_cluster.py#L2395`：`_start_election()` 每轮 `self.term += 1`。
- `hive_cluster.py#L2368-L2415`：失败后只受 `election_min`（3s）节流，无指数退避。
- `hive_cluster.py#L2175-L2195`：`preferred_leader` 命中时选举延迟为 **0**，每次最先抢跑。

## 三、为什么是缺陷

1. **安全**：多数票是 Raft 的全部安全性所在。`voters<=1` 返回 1 让一个被分区、
   看不到同伴的节点也能以 1/1「当选」，与另一侧的主节点并存 → 双主/脑裂。
2. **可用性**：失败不退避，每个节点每 3 秒 +1 term 连打，导致 term 单调膨胀、
   集群长期处于无主窗口，`leader_seen` 与 `leader_lost` 每隔几秒翻转一次。
3. 两者叠加：先靠连打把 term 抬高，再靠「同伴被判 dead」把 quorum 降成 1 当选。

## 四、修复方向（只改 `hive_cluster.py`）

1. `_quorum_locked()` 去掉 `voters<=1 → 1` 的退化：quorum 至少取「已知成员数的多数」，
   或取最近一次已知最大票池的多数；票池不足多数时**禁止自任 leader**，
   只能保持 follower/observer 并继续探测。
2. `_start_election()` 引入失败退避：`election_backoff = min(base * 2**n, max_backoff)`，
   base=3s、max=30s，带 ±20% 抖动；收到合法 leader 心跳或当选成功后重置 n。
3. `preferred_leader` 的零延迟只在「本节点能看到多数同伴」时生效，避免孤立节点抢跑。
4. 每次退避与拒绝当选都 emit 事件（`election_backoff` / `quorum_insufficient`），便于事后审计。

新增测试至少覆盖：`voters=1` 时不能当选；失败序列的退避间隔单调递增且封顶 30s；
收到 leader 心跳后退避重置；`preferred` 在孤立时不抢跑。

## 六、风险与边界

- 退避会让真实故障后的切主变慢（上限 30s），需在卡里给出可配置项与默认值。
- 不得为了「能选出来」而放宽多数判据；不得删除 `voters<=1` 分支却换成等价的隐式放行。
- **不改** 投票内容校验（`store_behind` 见 T-0295）、不改 `store` 层、不改 `hive.py`。
- 不改 `state.json` / 不改运行时配置；不动其它卡面与 agent 配置。
