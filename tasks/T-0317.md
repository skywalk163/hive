## 背景

缺陷 LP-D-002 有两半，评审把它列为 AI 友好的头号问题：

1. **归因错**：调用了未导入的 stdlib 函数（如 `子串位置`），报错却说「先定义变量」，新手/Agent 照做会越改越错。现在 `src/enhanced_errors.py` 的 `_STDLIB_NAME_TO_MODULE` 是**手写 50+ 项静态表**（第 180 行起），一定会随 `stdlib/*.light` 漂移。
2. **行号漂移**：`NameError` 的行号指向解析器内部状态，而不是实际出错的 token 行。

评审原话：「固定行号语义（报错指向实际出错的 token 行），这对人类调试同样是刚需。」

## 要做什么

1. 新建 `scripts/gen_stdlib_name_map.py`：
   - 扫 `stdlib/*.light` 顶层的 `导出 ...` 清单，生成 `src/stdlib_name_map.py`（`NAME_TO_MODULE: dict[str, str]`），文件头写明「生成物，勿手改，改 `scripts/gen_stdlib_name_map.py`」；
   - `--check` 模式：重新生成并与现有文件比对，不一致时打印 diff 摘要并 `rc=1`（CI/验收用）；
   - 过滤规则保留现状语义：**只收「必须显式导入」的名字**，全局内置（`分割字符串`/`长` 等）不收，否则会把「忘打括号」误报成缺导入。
2. 改 `src/enhanced_errors.py`：删掉手写表，改用生成表；`_stdlib_import_hint` 的返回文案保持不变（已有测试依赖它）。
3. 行号锚定（`src/enhanced_errors.py` + 必要时 `src/errors.py`）：
   - 运行时错误渲染时，行号取 traceback 中**用户 `.light` 栈帧**的 `lineno`，不得用解析器/生成器内部行；
   - 同一物理行被拆成多行逻辑语句时，映射回物理起始行；
   - 拿不到行号就写 0 并输出「行号未知」，**不许猜一个看起来合理的数字**。
4. `tests/test_error_anchor.py`，至少三个场景：
   - (a) 只调 `子串位置` 不导入 → 提示含「从 字符串处理 导入 子串位置」，且**不出现**「先通过『设』定义变量」；
   - (b) 变量名拼错（`打印(甲甲)`）→ 给拼写建议，行号 == 真实出错行；
   - (c) 真的未定义变量且不属于任何 stdlib 导出 → 不得误报「缺导入」。
   断言方式：跑真实的编译器/解释器入口取 stderr，正则解析 `行 N`，与源码行号比对。

## 不要做什么

- 不改 `cli/light.py`、不改 `src/diagnostics/`（T-0316/T-0318 的地盘）。
- 不改 `stdlib/*.light` 的导出；发现导出清单本身有问题，记录到 summary 另开卡。
- 不为通过测试而把测试文件名特判进产品代码。
