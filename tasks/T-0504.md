## 背景

模型调工具时「参数校验失败」的报错粒度决定能否一次改对。若只返回笼统的 `{"ok": false, "error": "参数校验失败"}`，模型只能反复试（3 次熔断）。现状是校验失败没有结构化字段说明「具体哪错了、该怎么改」。W3 要统一为结构化错误契约。

## 目标

把参数校验失败统一为可结构化呈现的 `ValidationError`，至少包含：

- `field`：出错字段路径（嵌套用点号或 JSON path）
- `reason`：类型错误 / 缺失 / 枚举越界 等分类
- `message`：人读消息
- `suggestion`：**可操作建议**（「类型应为 array」「枚举值只能是 a|b|c」「缺少必填字段 X」）

## 交付物

- `src/错误增强.light`：ValidationError 结构与构造
- 校验入口集成（`src/工具面装配.light` / `src/工具执行.light`）
- `tests/test_T0504_validation结构.py`

## 验收判据

1. 校验失败返回结构化 ValidationError，含 field/reason/message/suggestion；
2. suggestion 对典型错误（缺字段/类型错/枚举越界）可操作，模型据其一轮改对；
3. `tests/test_T0450_错误增强_v3_json_contract.py` 不回归；
4. 契约与 T-0451（失败可观测性）口径对齐，不另起 schema。

## 红线

- 不改变成功路径的返回结构；
- ValidationError 结构须与 W3/T-0505 的工具级/运行时错误契约**同族**，避免两套口径；
- suggestion 必须基于真实校验规则生成，不得硬编码误导信息。
