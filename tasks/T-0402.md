# 上下文压缩升级：对齐 DSH compaction（checkpoint 框架 + token 保留尾部 + 摘要钩子）

## 背景（先说三个现状，跟直觉不一样）

1. **自动压缩的代码在，但生产路径上永远不触发。** `src/代理.light:208-210` 只在
   `选项` 含 `"压缩配置"` 时才建 `压缩管理器`，而全仓 `src/` 里**没有任何调用方传入该键**
   （只有 4 个 `examples/` 传）。`src/web服务器.light:100/124` 构造了 `己.压缩管理器`
   却从不传给 `跑一轮`。→ web 路径下 `压缩管理器` 恒为 `空`，`检查并压缩` 一次都不会跑。
2. **前端「一键压缩」是空操作。** `webui/app.js:942` 把 `"/compact"` 当普通消息 POST 到
   `/v1/chat/completions`；服务端 `处理对话`（`src/web服务器.light:465-654`）不认命令，
   `"/compact"` 会原样进模型上下文。用户看到的 `%` 变化只是「又跑了一轮」的副作用。
3. **现有摘要不是 LLM 摘要，是字符串拼接。** `src/压缩.light:26 造摘要` 把
   `user/message` 与 `assistant/message` 拼成「用户: … 助手: …」加 `【压缩摘要】` 前缀；
   `src/压缩E5.light:64 生成摘要` 明确写着「未启用 LLM 摘要」的占位串。
   而 `src/压缩.light:129 造检查点消息` + `src/压缩配套.light:638 包摘要框架` **已经具备
   `<compacted-summary>` 框架能力，但生产路径没用**：`压缩到最近:57` 用的是裸 `造用户消息`。

DSH 的 compaction 三要素是：**LLM 摘要 + checkpoint 框架消息 + 按 token 保留尾部**。本卡补这三个。

## 要做什么

### 1) `src/压缩.light`（本卡独占）

- **改用 checkpoint 框架消息**：`压缩到最近:57` 把 `造用户消息([造文本块(摘要文本)])`
  换成已有的 `造检查点消息(会话对象, 尾号)`(129)，并给 `源序号表` 的来源标
  `{"kind": "compact-checkpoint"}` —— `src/会话引用深化.light:172/192/305` 已按该 kind 识别，
  前端 `Messages.addCompaction`(`webui/messages.js:472`) 也在等这个形状。
- **按 token 保留尾部**：现有 `压缩到最近` 只按**条数**（`保留条数` 10）。改成支持
  token 口径：优先用 `src/压缩配套.light:399 确定预算` 这类纯逻辑算「尾部保留到哪条」，
  条数口径作降级（两者都要留，配置二选一）。
- **摘要钩子（关键设计）**：`造摘要` 增加一个可选**注入式**摘要器
  `压缩造摘要(会话对象, 尾号, 摘要器 = 空)`：摘要器非空则 `等待`/调用它产出真摘要，
  为空则退回现有确定性拼接。**摘要器本身由调用方注入**——本卡不引入任何网络调用，
  也不在 `压缩.light` 里导入大模型客户端（它是纯逻辑模块，`examples/test_压缩*.light` 直接断言）。
- `检查并压缩`(109) 改成返回结构化结果（`{压缩了: 布尔, 原因, 裁剪条数, 压缩前token, 压缩后token}`），
  便于上层发事件帧。**保持向后兼容**：老调用按布尔用的地方（`代理.light:629`）仍能取到真值
  ——设计成「返回字典但上层判真值」或加一个新段落 `检查并压缩详情`，二选一，在 summary 里说明。

## 附注 A：「光明」写法禁令（照抄现状规避写法，成本最低）

- 段落一律块形式：**禁 `段落 X: 返回 …` 单行函数**（生成器缩进会累积）。
- 字典/列表字面量一律**单行**；嵌套字面量内不写 `\n`（用 `chr(10)`）；字面量不直接当实参先 `设` 变量。
- **单字变量名全禁**（`若 则 否 是 段 出 导 遍 对 跳 过 试 捕 抛 终 返 配 己 自 设 为 从 当 空 长 首 末 余 父 常 并 与 且 或 的 在 到 现 例 步 断 新 接 承 引 掷 跃 非 真`）。
- 标识符不得被关键字序列完全切分（`错误己` 会炸，`错误甲` 正常）；不用「为」字入标识符；
  避开含 `等待` 的标识符；成员名避开 `模/模型/模式/工具/事件/类型/原因/取/生成/新建` 等词根。
- 成员赋值一律 `设 己.X 为 …`（裸 `己.X 为 …` 会编成 `==`）。
- 缺键 `d[k]` 直接抛 `键错误` → 用 `字典获取(d, k, 缺省)` 或 `字典包含键` 守卫。
- `空` 是 `None` 不是 `""`，判空串写 `x != "" 且 x != 空`（照抄 `web服务器.light:452/522/527`）。
- `/` 是浮点除法，切片/下标前先 `整数()`。
- **段落名会与依赖模块内联后冲突**（`src/代理循环.light:10-12` 已记）：新模块段落统一加 2 字前缀
  （本批约定：`续`=目标续跑、`压`=压缩升级、`模`不许用→用 `式`、`队`=会话队列、`时`=会话细节）。
- 循环依赖用 `导入 模块` + `模块.段落()` 点号调用，不要 `从 X 导入 名`。
- 新模块名全仓唯一（`src/` 与 `stdlib/` 都要查）。
