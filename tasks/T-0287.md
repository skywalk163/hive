# Windows 垫片：sys.executable 路径带空格时 verify 假红

## 现象

用户名带空格的 Windows 机器（如本机 `PCbeta Tester`）上，凡是走垫片的 verify
（`true` / `test -f x` / `! grep` / 整数比较），**无论产物是否合格都记 failed**，
tail 是 `'<C:\Users\PCbeta>' 不是内部或外部命令`。

实际复现（T-0274 提交时踩到）：交付物 `docs/LH回灌流程.md` 明明存在，
`hive_submit` 的 verify 却 failed，退出码 1。

## 根因

`hive_compat.py:108` 的 `rewrite()`：

```python
def rewrite(cmd: str) -> str:
    text = str(cmd or "")
    quote = "'" if "'" not in text else '"'
    return f'{sys.executable} "{_self_path()}" run {quote}{text}{quote}'
```

`sys.executable` **没有加引号**。本机 `sys.executable` 是
`C:\Users\PCbeta Tester\.box-agent\...\python.exe`，含空格，被 `shell=True` 的
cmd.exe 在空格处截断：shell 把首 token `C:\Users\PCbeta` 当成可执行程序去找，必然找不到。

而同一条命令里 `hive_compat.py` 路径是**加了**双引号的——只有 `sys.executable` 漏了。
脚本路径 `_self_path()` 通常是仓内路径（`C:\dswork\hive\...`，无空格）所以没暴露；
但 `sys.executable` 落在用户家目录下，用户名带空格就必现。

## 复现取证

```bash
cd /c/dswork/hive
python -c "import hive_compat; print(hive_compat.rewrite('test -f docs/LH回灌流程.md'))"
# 输出：C:\Users\PCbeta Tester\.box-agent\...\python.exe "C:\dswork\hive\hive_compat.py" run 'test -f docs/LH回灌流程.md'
# 首个 token 被 shell 当命令 -> C:\Users\PCbeta -> 报不是内部或外部命令
```

对比：给 `sys.executable` 加双引号后本机实跑 rc=0（文件存在时返回 0）：

```bash
python -c "
import subprocess, sys
cmd = f'\"{sys.executable}\" \"C:/dswork/hive/hive_compat.py\" run \'test -f docs/LH回灌流程.md\''
print(subprocess.run(cmd, cwd='C:/dswork/hive-wt/T-0274', shell=True, capture_output=True).returncode)
"   # -> 0
```

## 修复方向

`hive_compat.py` `rewrite()` 里给 `sys.executable` 加引号，与 `_self_path()` 一致。
注意 `sys.executable` 在 Python 字符串里要写成 `f'"{sys.executable}"'`（直接插双引号），
而内层 `text` 的引号选择逻辑（`quote = "'" if "'" not in text else '"'`）保持不变。

**顺带检查**：`hive.py` 里凡是 `f'{sys.executable} ...'` 拼命令、且会被 `shell=True`
执行的地方，都可能有同样的空格问题，一并加引号（搜 `sys.executable`）。

## 边界

- 只改 `hive_compat.py`（必要时连带 `hive.py` 的同类拼接点）。
- 不改 POSIX 分支：`should_wrap` 在非 Windows 永远返回 False，POSIX 行为一个字节不动。
- 不要引入对 `shlex.quote` 的跨平台依赖（POSIX 用单引号、Windows 需双引号，语义不同，
  现有 `_win_single_quote_fix` 的思路更贴合，别破坏 T-0228 已处理过的 `|` 转义）。

## 验收

```bash
# 1. rewrite() 产出的命令首 token 不再被 shell 当独立命令
cd /c/dswork/hive
python -c "
import hive_compat, subprocess, sys, os
w = hive_compat.rewrite('test -f docs/README.md')
print('CMD:', w)
assert '\"' + sys.executable + '\"' in w or '\"' + sys.executable.lower() + '\"' in w.lower(), \
    'sys.executable 未加引号'
# 真跑：在临时目录建文件后应 rc=0
open('docs/.rc_probe', 'w').write('x')
r = subprocess.run(w, cwd=os.getcwd(), shell=True, capture_output=True, text=True)
os.remove('docs/.rc_probe')
print('rc =', r.returncode)
print('stderr =', (r.stderr or '')[:300])
assert r.returncode == 0, f'verify 假红：{r.stderr[:200]}'
print('OK')
"
```

## 为什么值得修

只要有一台 Windows 机器用户名带空格（`C:\Users\John Doe\...`），整张卡的验收就是
**假的 failed**，worker 反复重跑、租约白耗、看板飘红，而产物其实是对的。
T-0274 因此多跑了一整轮 retry 才发现要 `HIVE_COMPAT=0` 逃生阀绕过。
