## 一、LH-22　括号**外**续行不成立，报错却指向「缩进不正确」（P1）

```light
打印 "前半段"
    加上 "后半段"
```

实际报错：

```
位置: 行 3, 列 1
原因: 缩进不正确：这一行的缩进层级没有对应的语句块。请检查上一条语句是否以「：」结尾、或本行缩进是否多/少了一级。
```

括号**内**换行是合法的（`设 x 为 ("a" 加上 甲\n  加上 "b")` 能跑），括号外不行。
问题不在「不支持」，而在**报错把人往缩进上引**——对着改三遍缩进才会意识到是续行。

**期望（二选一，优先前者）**：
1. 支持「行首以运算符（`加上`/`并且`/`或者`/`乘`…）开头且上一行语法完整」时**自动续行**；
2. 或至少**换一条报错**：检测到上一行语法完整 + 本行以运算符开头，直接提示
   「疑似续行：请把整个表达式放进括号，或先落到临时变量」。

## 二、LH-18b　不支持反斜杠续行（P1）

```light
设 乙 为 甲 加上 \
  "b"
```

报错：`意外的标记: 「\」` + 后续 `缩进不正确`（一次抛多条，**第一条看上去完全不像真因**）。

**期望**：支持反斜杠续行；或明确在语法文档写「不支持 `\` 续行，请用括号」并让报错直接指向文档章节。

## 三、LH-12　报错只给调用点，不给异常链（P2）

异常发生在被调模块深处时，报错框高亮的是**调用点**，真因（`git push` 的 `fatal: ...`）埋在消息体里。
配合「异常被吞」的历史缺陷时尤其致命：看的人会去查调用参数，而真因在前面被吞掉的那一步。

**期望**：报错里带**最短异常链**（抛出点 → … → 调用点），而不是只有调用点。
若已有 `src/enhanced_errors.py` 的行号映射（L-061），在其上扩展即可，别重造。
