# 接线卡：cli/light.py 唯一 owner——把 A/B/C/D 的开关接上去

> 总纲：`docs/R222_语言×AI适配总纲.md`（hive 仓）。
> **本卡是 `cli/light.py` 的唯一 owner**：A/B/C/D 四张卡都不许改这个文件，全部由本卡一次性接线。
> 这样避免 4 个 worker 同时改同一段 200 行分派逻辑必然冲突。

## 背景

四张卡分别产出了 `spec/light.spec.json`、`src/diagnostics/`、`src/patch_engine.py`、`src/linter/canonical.py`。
它们都是纯模块。现在要让人（和 Agent）能用一条命令拿到它们，并且**全部支持 `--json`**。

现状（照抄，别猜）：
- `light ast`（2091 行）只有 `file` / `--backend`，**没有 `--json`**。
- `light check`（2101 行）只有 `file` / `--backend` / `--type-check` / `--no-type-check`，**没有 `--partial` / `--json`**。
- `light ai check`（2219 行）只有 `file` / `--run` / `--timeout`，**没有 `--json`**。
- `light spec` **不存在**。

## 要做什么

1. 新增 `spec` 子命令：`light spec [--json] [--check]`——`--json` 直接吐 `spec/light.spec.json`（内嵌不走文件读也行），
   `--check` 转发 `spec.build_spec --check` 的退出码。
2. `light ast` 增 `--json`（调 `src/patch_engine.ast_to_json`）。
3. `light check` 增 `--json`（诊断走 `src/diagnostics.format_diagnostic`）与 `--partial`
   （**只解析不要求整文件闭合**：允许一块一块送检，供 Agent 分段写；`--partial` 下遇未闭合块不 fail，返回 `partial: true`）。
4. `light ai check` 增 `--json`（含 `ok` / `stage`（词法|语法|类型|运行）/ `diagnostics[]` / `fix_suggestions[]`）。
5. `light symbols --json`（调 `symbols_json`）。`light patch --json <file> --edits <json>`（stdin 也支持）。
6. 新 `tests/test_cli_json.py`：每个 `--json` 输出都能 `json.dumps` 回环、字段齐全、rc 语义明确
   （error 诊断 → rc=1，warning → rc=0）；`--partial` 的未闭合输入不抛栈。
   用 `subprocess` 起真实 `cli/light.py`，别只测函数。

## 不要做什么

- 不要改任何既有开关的默认行为（`light check` 不带参数时行为必须与今天一致）。
- 不要动 `src/parser_*.py`、`stdlib/`、`src/linter/light_linter.py` 规则。
- 不要把 A/B/C/D 的实现逻辑复制进 `cli/light.py`（只允许薄转发）。
- 不要新增顶层 subcommand 之外的副作用（如自动写文件）。

## 完成标准（verify 必绿）

- `PYTHONPATH=src python3 -m pytest -q -o addopts= tests/test_cli_json.py`
- 手工冒烟四条（贴进 summary）：
  `python cli/light.py spec --json | head -c 200`、`python cli/light.py ast --json <某 .light> | head -c 200`、
  `python cli/light.py check --json <某 .light>`、`python cli/light.py ai check --json <某 .light>`
