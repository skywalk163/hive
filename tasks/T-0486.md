## 背景

T-0484 只产出「摘要指令 + 校验」的纯模块；真正让压缩变成模型摘要，还差**接线**：

- `src/代理.light:221` 只在 `选项["压缩配置"]` 存在时 `新建 压缩管理器(会话对象, 配置)`，
  `压缩管理器` 支持 `配置["摘要器"]`（`src/压缩.light:366`），但**没人传**；
- `src/web服务器.light` 构造 `压缩配置`（`压缩E5`）时只给窗口/阈值/保留条数；
- 结果是长任务压缩后只剩 `【压缩摘要】` + 原文拼接，`当前工作 / 下一步` 直接丢。

本卡把 T-0484 的指令接进一轮真实压缩，并保证**失败可回退、不中断本轮、不污染会话事件**。

## 目标

1. `src/代理.light` 构造处：
   - 若 `选项["压缩配置"]` 存在且其中没有 `摘要器`，且 `选项["模型摘要"] != 假`：
     注入 `摘要器 = 造模型摘要器(己.客户端对象, 己.会话对象, 己.选项)`；
   - `造模型摘要器` 返回闭包 `(会话对象, 尾号) -> 摘要文本`：
     - 取 `序号 < 尾号` 的表面消息（复用 `压缩.提取消息文本` 或等价只读函数）；
     - `压缩摘要器.造摘要请求(消息表, 旧检查点文本)` → `客户端对象.对话响应(请求, 选项, [], 空)`
       → `压缩摘要器.抽取摘要文本` → `校验摘要`；
     - 校验通过 → 返回摘要文本（只用八段正文，不加额外前缀）；
     - 校验失败 / 客户端抛错 / 返回空 → 返回 `空`（由 `压缩造摘要` 落回确定性分支）；
   - 摘要请求**不写入会话事件**、不计步数、不触发工具回调。
2. `src/压缩E5.light`：`压缩配置解析()` 增加可选键 `模型摘要`（环境变量
   `HARNESS_COMPACTION_MODEL_SUMMARY`，默认 `1`），只读，不改变其它默认。
3. `src/压缩.light`：`造检查点消息` 落事件时附 `摘要来源`（`model` / `deterministic`）与
   `摘要段数`（校验结果），供前端与判据读；不改既有摘要正文口径。
4. **不重试**：摘要失败一次即回退（DSH 也是单次；重试会把一轮拖死）。

## 红线

- 不改 `src/web服务器.light`（配置从 E5 读，web 层不需要知道摘要器）；
- 不改 `src/压缩摘要器.light` 的八段标题与规则（T-0484 契约）；
- 摘要请求不许带工具 schema、不许写 `request/header`；
- 不许在用户消息里出现「压缩」提示文本（DSH 要求 checkpoint 不被模型提及）；
- 不许 `git reset --hard` / `push --force` / `--no-verify`。
