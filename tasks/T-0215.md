## 症状

同一份源码、同一条 `light run <入口> -- 甲 乙`：

- 转译腿 `参数列表()` ⇒ `['甲', '乙']`
- 原生腿 `参数列表()` ⇒ `['<编译产物路径>', '甲', '乙']`（多一个 argv[0]）

## 根因

转译腿读 CLI 注入的环境变量 `LIGHT_USER_ARGS`（LH-05 修出来的口径）；
原生腿走 `src/llvm/runtime_typed.c:4426 dv_get_args`，它从
`dv_init_args(argc, argv)` 的 **argv[0] 开始**返回 —— 而原生产物是独立进程，
argv[0] 是它自己的路径。

## 影响

跨腿口径不一致（本账在这类差异上已经付过好几次学费）。
当前只差 1 个元素，但凡有人写 `参数列表()[0]`，换后端时就会**静默**取到不同的东西。

## 期望

两条腿的 `参数列表()` / `用户参数()` 返回**完全相同**的内容（都不含程序名）。

## 落点

- `src/llvm/runtime_typed.c`：`dv_get_args` 跳过 argv[0]（对齐 `sys.argv[1:]` 口径）；
- `src/llvm/codegen_typed.py:3416` 附近：`用户参数` 若尚未在原生腿接线，一并接上；
- `cli/light.py::_run_native`：确认 `--` 后的实参确实传给了产物（已做，别回退）。

## 验收

新增 `tests/unit/test_LH41_原生腿参数口径.py`：

1. 同一份源码分别用转译腿与原生腿跑 `light run <入口> -- 甲 乙`，
   断言两条腿的 `参数列表()` **逐元素相等**（含长度）；
2. `用户参数()` 在两条腿上也相等；
3. ⚠️ **必须同时改** `tests/unit/test_T6B_时间系统内建_原生腿.py:207` 的
   `assertGreaterEqual(int(got["N"]), 1)` —— 跳过 argv[0] 后无参运行 N 会变成 0，
   这条断言要改成 `>= 0`（或改成断言「不含程序名」）。**改断言要在卡里写明理由**，
   不许静默放宽。

## 边界

- 只动 argv 这一处 runtime + 原生腿接线。
- 若原生腿在CI 上跑不起来（无 clang），请在卡里写明「未能真跑」并给静态证据，
  **不要**用「编译过就算过」糊过去。
