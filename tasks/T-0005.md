# R95-B1：Job Object 杀树根治——实施方案文档

## 背景

Windows 本机全量跑 pytest 时，xdist worker 会被杀（KI-R94-01，已规避未根治）。
R95 backlog 的 B-1 是根治候选：把「全系统进程表 + PPID 链回溯」的杀树方式换成
Windows Job Object。你（执行 agent）的任务**不是改代码**，而是产出一份可供下个轮次
直接开工的实施方案文档。

## 必读材料（都在当前工作区里）

- `docs/known-issues/R95-backlog-job-object.md` —— B-1 的方案要点与验收标准（**验收标准要逐条对应**）
- `docs/known-issues/R94-xdist-worker-kill.md` —— KI-R94-01 的现象、探针数据、已采取的规避
- `stdlib/进程树.light` —— 现有杀树实现，重点看 `[R92-A-LEAK]` 两处兜底捕杀
  （约 619 行与 744 行）及其调用的 Toolhelp32 快照 / PPID 回溯逻辑

## 交付物

**只新增一个文件**：`docs/known-issues/R95-B1-实施方案.md`。
不要修改任何现有文件，不要动 `stdlib/` 下任何 `.light` 源码。

文档必须包含以下六节：

1. **现状与问题定位**：现有杀树路径的函数级清单（文件、段落/函数名、行号），
   说明 PID 复用下为什么可能误杀兄弟进程。
2. **Windows API 清单**：`CreateJobObject` / `AssignProcessToJobObject` /
   `QueryInformationJobObject(JobObjectBasicProcessIdList)` / `TerminateJobObject`
   各自的作用、调用时序、以及经 ctypes 调用的签名草案（参数类型、返回值）。
3. **与现有路径的共存/切换开关**：设计一个开关（如环境变量或配置项），
   新走 Job Object、旧走 Toolhelp32 可随时回退；说明默认值建议与理由。
4. **Job 嵌套与权限评估**：Windows 8 前不支持嵌套 Job 的影响、所需权限
   （`PROCESS_SET_QUOTA` 等）、与「进程已在别的 Job 里」时的行为。
5. **测试矩阵**：对应 backlog 的三条验收标准（单层/多层树 100 轮 0 漏杀；
   ≥25k 短命树 PID 复用压力下无关进程被杀数 = 0；全量 `-n 4` 低负载 3 轮无 node down），
   每条给出测试设计、轮次建议、判定口径。
6. **风险与回滚**：列出引入 ctypes 面的新风险、失败时的回滚步骤、
   以及「什么情况下应启用 B-2（创建时间闸门）而非继续 B-1」。
