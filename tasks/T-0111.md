## 背景

自举阶段 hive 是唯一在开发的仓，但并发被两层锁死了：

1. 全局只有 1 个 exec agent（`fb88-dsh`，`max_concurrency: 1`）；
2. T-0101 刚加的 `--max-per-repo 1` 又是**按 repo 计数** —— hive 就一个仓，
   等于所有卡强制串行。

方案文档「阶段 2」原本写的是「同时跑 3 张路径互斥的卡」。计数粒度对不上。
`_repo_loads()` 现在只看 `c.get("repo")`，不看卡具体改哪些文件。

## 目标

把同仓并发从「按 repo 计数」细化成「**按 paths 重叠计数**」：

1. 新增 `_paths_conflict(a_paths, b_paths)`：判断两张卡声明的 `paths` 是否可能打架。
   规则（保守优先，宁可不并行也别互相踩）：
   - 任一方 `paths` 为空 → 算冲突（未声明 = 可能改任何地方）；
   - 一方是另一方的父目录（前缀匹配，注意 `docs/` 与 `docs/a/`）→ 冲突；
   - 有交集 → 冲突；
   - 否则不冲突。
2. `_repo_loads()` 改造成 `_conflict_groups(cards)`：把在飞（`assigned`/`running`、
   且无结果）的卡按 paths 分成冲突组；新卡与**任一组内已有卡**冲突就不能派。
   `--max-per-repo` 语义改为「同一冲突组最多几张在飞」，默认值保持 1。
   **命令行参数名和默认值都别改**（`--max-per-repo` / `HIVE_MAX_PER_REPO`），
   向后兼容优先，只在文档里说明它现在是「同一 paths 冲突组」的上限。
3. `dispatch` 的跳过原因要写清楚：原来那句「同仓并发已满（hive 1/1）」改成
   「与在飞的 T-xxxx（paths 重叠：docs/）冲突」—— 让人一眼知道卡在谁身上。
4. 测试（`tests/test_core.py`，沿用现有夹具）：
   - `test_dispatch_paths_disjoint_parallel`：两张 paths 互斥的卡（如 `hive.py` 与 `docs/`）
     能同时派给两个 agent；
   - `test_dispatch_paths_overlap_blocked`：paths 重叠（如 `docs/` 与 `docs/a/`）的第二张被拦下，
     且跳过原因提到第一张的 id；
   - `test_dispatch_empty_paths_is_conservative`: 空 paths 的卡与任何在飞的卡冲突。

## 红线

- 不改 light 等仓；不改 fb5 runner；不引入新依赖。
- `hive dispatch` 的**默认行为别改**：`--apply` 才写、`--dry-run`/默认只看。
- 不要动 `abilities` / 能力匹配那部分逻辑（T-0101 刚做完，别一起搅）。
- 别把 `--max-per-repo` 改名；可以加别名，但老的必须继续能用。
