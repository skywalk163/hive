## 背景

母文档 §5.1 要求 Worker 上报不阻塞（I6）：serve 聚合 200ms、队列 4096、
满了优先丢 steady（G3）。本卡只做内存队列与聚合器。

先读 `docs/控制面v0.5-实现约定.md` §3.3。

## 目标

实现 `hive_control/uplink_queue.py`：

1. `UplinkQueue(capacity=4096)`：
   - `put` 永不阻塞、永不抛异常；`get(timeout)` 用条件变量；`qsize`；
   - 满时优先丢最旧的 `state=="steady"`；没有 steady 才丢最旧；
     `claimed/releasing` 等瞬态优先保留；
   - `stats()` 返回 `dropped_steady / dropped_transient`。
2. `Aggregator(sink, window=0.2, clock=...)`：
   - `submit` 只更新内存 `{key: entry}`，同 key 留版本大者，返回 <1ms；
   - 到窗口（按提交时间）或 `flush(force=True)` 时按 key 排序调用 sink；
   - `start/stop` 后台 flush 线程；stop 幂等并 flush 剩余；
   - `submit/put` 里不得有锁以外的等待、日志或 I/O。
3. 不依赖真实网络；所有时间可注入。

## 测试（`tests/test_control_uplink_queue.py`）

- 容量溢出：构造 4097 条，最旧 steady 被丢；全是 claimed 时丢最旧并计数；
- 同 key 聚合只留最大版本；不同 key 不合并；
- 窗口未到不 flush，force 立即 flush；
- 后台线程 start/stop 幂等；
- 1000 次 submit 平均耗时 < 1ms（Windows CI 放宽到 2ms，注释说明）。
