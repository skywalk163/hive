# T-0142 背景

T-0102 把 `win10`（`192.168.0.86`）接入了 hive，但那张卡的完成标准是「Windows 上跑通一张卡」，
实际只交到了「文档 + bootstrap 脚本」这一步，真机那一轮还欠着。

同时本机（HP Z620，Windows + 小浣熊客户端）已经具备闭环条件，但**还没证明过一次**：

- 身份 `raccoon-win` 已登记（`agents/raccoon-win.json`，manual / abilities=code,docs,verify /
  capabilities=gui,windows,linux / repo 只登记 hive）；
- `~/.box-agent/config/mcp.json` 里已有 `hive-raccoon-win` 条目，
  `python .../mcp_server.py --agent raccoon-win` 实测握手成功、`tools/list` 14 个工具；
- 但**还没有一次真实的「小浣熊通过 MCP 自己领卡、改文件、提交」**跑通过。

这张卡就是补这一环：先在本机（只需 Python + Git，不经 Windows 10 VM）把这套链路验一遍，
把实测结果沉淀进文档，之后再谈扩大产能。

# 要做什么

1. 开工前先手跑一遍 `verify`（`lessons.md` 纪律），确认两条命令在动手前是「该红的红」。
2. 在本卡 worktree 里改 `docs/MCP接入.md`，新增一节 **Windows 客户端接入（本机实测）**，
   覆盖以下实测事实（写不准就重新验，不要照抄本卡）：
   - 客户端配置为什么用 `mcp_server.py` 直起，而不是 `hive.py mcp`：在小浣熊这类用真实
     `python` 起 stdio 子进程的客户端里，`hive.py` 转发会多一层依赖；`mcp_server.py`
     与 `PYTHONPATH` 一起写进 `env` 时最省事。
   - 路径必须用正斜杠（`G:/...`），反斜杠在 JSON 里要转义、在 `args` 里容易写错。
   - `hive_whoami` 返回的 `hive_dir` 必须是 `~/.hive/clones/mcp-<agent>`，**不能是主工作区**；
     这是自检项（MCP 每次调用都会 `reset --hard origin/main`）。
   - 一个 agent 名在同一台机器别起两个 server；本机身份叫 `raccoon-win`，与 Linux chroot 的
     `raccoon` 是两个身份，别混用。
   - 重启客户端后工具才注册进来（热加载不保证生效），以及怎么自查「工具在不在」
     （`tools/list` / `hive_whoami`）。
3. 在文档里补一张**本机实测表**：把关键字段（`serverInfo.version`、工具数、`hive_dir`、
   `role`）如实填上，注明实测日期与 Python 版本。
4. 写 `.hive/summary.md`：做了什么、实测输出、哪些是没验的（比如「重启客户端后」这一段
   需要人配合，写清未覆盖）。
