# 跨腿口径不一致（L-262 / LH-41）

## 一、实测证据（light HEAD `8567a6588`）

```sh
# 转译腿（默认 --backend src）
printf '打印 转字符串(用户参数())\n' > /tmp/probe.light
python3 -m cli.light run /tmp/probe.light -- 甲 乙
# → ["甲", "乙"]  rc=0

printf '打印 转字符串(参数列表())\n' > /tmp/probe2.light
python3 -m cli.light run /tmp/probe2.light
# → ["/home/skywalk/dswork/light/cli/light.py", "run", "/tmp/probe2.light"]（宿主 argv，存量行为）
```

L-241（LH-05）的修复已生效：`light run <入口> -- 甲 乙` + `用户参数()` 拿到用户实参；
`cli/light.py run --help` 也写明了「未传 `--` 时 `参数列表()` 仍返回宿主 argv，存量行为不变」。

**本卡要修的是原生腿**：缺陷账 L-262 记录 `src/llvm/runtime_typed.c` 的 `dv_get_args`
从 `dv_init_args(argc, argv)` 的 **argv[0] 开始**返回，原生腿是独立进程，argv[0] 是编译产物自己的路径，
于是同一份源码在换后端时多拿一个元素。今天核到 `dv_get_args` / `dv_init_args` 在
`src/llvm/runtime_typed.c` 的 4518 行附近（`grep -n dv_get_args`）。

## 二、目标

1. 先**现场复现**：用 `--backend llvm-typed`（`native` 是它的一等别名）跑同一探针，
   拿到原生腿 `参数列表()` / `用户参数()` 的真实返回值，贴进结果。
   本机若无 clang / 原生腿起不来，**如实写「未能验证」，不许用转译腿结果冒充**。
2. 确认多 `argv[0]` 后改 `dv_get_args`，使其与 `sys.argv[1:]` 口径一致；只改这一处语义，
   不动其它运行时行为。
3. `tests/unit/test_T6B_时间系统内建_原生腿.py:207` 断言 `len(sys.argv) >= 1`，
   跳过 argv[0] 后无参运行会得到 0 —— 把这条改成 `>= 0`，或改成断言「不含程序名」，
   并在测试里加一条两腿对拍用例（能做原生腿的机器才跑，做不了就 skip 并写明原因）。

## 三、硬约束
