## 实测证据

```bash
$ git ls-remote https://gitcode.com/light-lang/registry
remote: <CH.00905403> The project you were looking for could not be found.

    https://github.com/skywalk163/light/raw/main/registry/registry.json

$ ls light/registry
# 空（仓库里没有 registry/ 目录）
```

而代码里：

```python
# src/lightpkg.py:41
REGISTRY_REGION_URLS = {
    'domestic': 'https://gitcode.com/light-lang/registry/raw/main/registry.json',
```

`--registry-url` 这个参数才有救 —— 而 R98 北极星写的是「零作者介入」。

# T-0262 · 默认 registry 源断链（选 B + C）

**结论：选 B —— 本卡未修复默认源可达性，只修了错误可读性**（卡面 B 要求的原话）。

## 实测（2026-11-07，A/B 实证，不只看状态码）
- `domestic` 原 URL：curl `200`，但 `Content-Type: text/html` + `<!DOCTYPE html>` SPA 页，`json.loads` 失败 → **HTTP 200 假绿**。
- 同域一个确定不存在的路径也回同样的 200 + HTML ⇒ 该域 raw 被 SPA 兜底，200 无判别力。
- `foreign` github raw：本机沙箱 curl `000`（不通）；卡面记录 404。
- A1 候选 `gitcode.com/skywalk163/light/raw/main/registry/registry.json` 同样是 200 + HTML 假绿；且该文件只会落在 task 分支，main 上须 land 后才可能有，而本卡禁止 land。
- 真跑默认路径实证：新诊断打印「…返回的内容不是合法 JSON（响应是 HTML 页面而非 JSON，属于 HTTP 200 假绿）…请用 --registry-url 指定，或设 LIGHT_REGISTRY_REGION=foreign 换源」，仍降级回内置表（packages=20），不阻断安装、不换 region。
