# 包管理器默认源两个都是死的

## 实测证据

```bash
$ git ls-remote https://gitcode.com/light-lang/registry
remote: <CH.00905403> The project you were looking for could not be found.
fatal: 无法访问 'https://gitcode.com/light-lang/registry/'：The requested URL returned error: 403
# RC=128

$ curl -s -o /dev/null -w "%{http_code}\n" \
    https://github.com/skywalk163/light/raw/main/registry/registry.json
404

$ ls light/registry
# 空（仓库里没有 registry/ 目录）
```

而代码里：

```python
# src/lightpkg.py:41
REGISTRY_REGION_URLS = {
    'domestic': 'https://gitcode.com/light-lang/registry/raw/main/registry.json',
    'foreign': 'https://github.com/skywalk163/light/raw/main/registry/registry.json',
}
DEFAULT_REGISTRY_REGION = 'domestic'
```

`src/package_installer.py:48-49` 是同一份硬编码（**两处重复定义，是隐患，见目标 3**）。

**后果**：`light install <包名>` 的默认路径 100% 失败。新用户必须先知道
`--registry-url` 这个参数才有救 —— 而 R98 北极星写的是「零作者介入」。

## 起点线索

- `src/lightpkg.py:38-60`：`resolve_registry_region()`，注释说「不做 geo-IP 探测，默认 domestic，
  foreign 必须显式指定」，**且明确「非法区域名抛 ValueError，不静默回退」**。
- `contrib/registry_git_tmpl/registry.json` 存在（2459 字节），是 R137 留下的种子模板。
- `tests/unit/test_R137_install_publish.py` 17 例全绿（我跑过，75.9s），
  其中 `:311` 有一条断言「交付物 registry_git_tmpl/registry.json 必须真的能被安装器读」。
  → **这些测试用的是本地文件桩，所以默认源死了测试也是绿的**，这正是它没被发现的原因。

## 目标（三选一，建议 A）

### A. 让默认源真的可用（推荐）

把 registry 内容落到**已经存在且可达**的地方。两条路：

**A1**：在 `light` 仓自己的 `main` 上建 `registry/registry.json`。
把 `contrib/registry_git_tmpl/registry.json` 的内容提交为 `registry/registry.json`。
然后默认源改成：

```python
'domestic': 'https://gitcode.com/skywalk163/light/raw/main/registry/registry.json',
'foreign':  'https://github.com/skywalk163/light/raw/main/registry/registry.json',
```

- 优点：不依赖「用户侧去新建一个仓库」，本卡自己就能闭环
- 缺点：registry 和编译器同仓，语义上不够干净（但比现在 100% 不可用强得多）

**A2**：维持独立仓方案，但**必须先由业主建仓**。
如果你选 A2，本卡只做：默认源改成一个**明确可达的占位**（见 B），并把待建清单写进文档。

### B. 默认源改成「内置兜底 + 明确报错」

如果短期建不了仓，至少让失败可读：

```python
REGISTRY_REGION_URLS = {
    # 内置兜底：编译器的核心包清单随仓发布，保证 install 至少能装上官方包
    'builtin': 'file',
    'domestic': 'https://gitcode.com/skywalk163/light/raw/main/registry/registry.json',
    'foreign':  'https://github.com/skywalk163/light/raw/main/registry/registry.json',
}
```

- `builtin` 走仓内 `contrib/registry_git_tmpl/registry.json`（已验证能被安装器读）
- 远端 404 时，**报错信息必须直说**：
  `「registry 源 <url> 返回 404。这通常是默认源失效，请用 --registry-url 指定，或设 LIGHT_REGISTRY_REGION=foreign 换源。已知问题见 docs/包管理器使用指南.md §默认源」`
- 不要静默回退到另一个 region（违反现有的「不静默回退」设计）

### C. 两处硬编码收口成一处（**无论选 A 还是 B 都要做**）

`src/lightpkg.py:41` 和 `src/package_installer.py:48` 现在是两份同样的 dict。
改成 `package_installer.py` 从 `lightpkg` import：

```python
from lightpkg import REGISTRY_REGION_URLS, resolve_registry_region
```

> 注意 `src/` 的导入路径惯例，先看 `package_installer.py` 里其它 import 怎么写的，照抄。
> 如果它已经有 `from .lightpkg import` 之类的相对导入，就按那个来，别自创。

## 红线

- **不能在代码里静默回退 region**。现有设计是「非法/失败就明确报错」，这个取舍要保留，改之前先读
  `src/lightpkg.py:38-60` 的注释。
- 不改 `test_R137_install_publish.py` 里那 17 条断言的**语义**。可以新增断言（比如「默认源 URL 必须能
  被 resolve 出来」），但不能为了让新行为通过而弱化旧断言。

- 不写 token / 密钥 / IP。
