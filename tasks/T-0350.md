# T-0350 H-LSA 协议核心模块（新建，纯标准库）

## 背景

要让「自动更新」与「低网络占用」同时成立，靠调几个 interval 是不够的，
需要一套**独立于传输层的状态传播纪律**：什么时候必须立刻发、什么时候只发摘要、
什么时候该退避、什么时候该把一堆变更合成一条、周期定时器怎么避免全网同时点火。

本卡新建 `hive_lsa.py`，把这套纪律做成**可单测、零网络、零外部依赖**的模块。
它不 import `hive.py` / `hive_cluster.py` / `hive_control`，也不碰 socket——
transport 由 T-0351 提供，上行由 T-0352 提供，落盘同步由 T-0353 提供。
**正因为它不依赖任何既有模块，本卡才能与第 1 批其余 5 张卡真并行。**

规范见 `H-LSA-协议设计-借鉴OSPF.md` §2（三档节奏）、§4（七道闸）、§5（指标）。

## 要做什么

1. **数据结构**（`hive_lsa.py`）：
   - `LSA`：`originator`、`area`（repo / cluster_id / project_tag）、
     `leader_epoch`、`seq`、`kind`（`change|digest|refresh`）、
     `key=(repo, tid)`、`diff`（字段级，不是整卡）、`digest`（sha256）、
     `ts`、`age`、`ttl`；
   - `LSDB`：内存摘要库 `(area, key) -> (seq, epoch, digest, head_sha)`，
     支持 `is_newer()` 幂等去重（旧/重复 LSA 直接丢）、MaxAge 老化（3600s，类比 OSPF）；
   - `SyncConfig`：所有常量集中、可注入（测试用 fake clock / fake random）。
2. **三档节奏的判定逻辑**（纯函数 + 可注入时钟，便于单测）：
   - `AGGREGATION_WINDOW_S = 0.200`（沿用 `Limits.aggregation_window`），
     `MIN_LS_INTERVAL_S = 5.0`（OSPF MinLSInterval）、
     `MIN_LS_ARRIVAL_S = 1.0`（MinLSArrival）、LSA Pacing 组步调；
   - `MULTICAST_BASE_S = 60.0`，无变更按 **NTP 式 2^n 退避**
     60→120→240→…→1800s，一有变更立刻回 60s（AIMD：加性增、乘性减）；
   - `LS_REFRESH_S = 1800.0`（OSPF LSRefreshTime），**只发 digest 清单**
     （IS-IS CSNP 式），不是全量状态；
   - **所有周期定时器强制 ±20% `JITTER`**，且 jitter 可注入以便测试边界。
3. **七道闸里的 4 道在模块内实现**：
   - 合并窗口：窗口内同一 `(area,key)` 的 N 次变更合成 1 条 LSA（字段级 diff 合并）；
   - **令牌桶**：每周期 ≤ `TOKEN_BUCKET_LSA=32` 条 / `TOKEN_BUCKET_BYTES=65536` 字节，
     超限排队合并、不丢状态但削峰；
   - **Flap Damping**（BGP 路由抑制）：同一 `(area,key)` 反复震荡时惩罚值指数上升，
     超阈值只发汇总并拉长间隔，恢复后半衰衰减；
   - **去重 / 分片**：`seq`+`epoch`+`age` 判新旧，单包 ≤ `MAX_PACKET_BYTES=1400`
     （对齐 `Limits.max_packet_bytes`），超出按 LSA 边界分片、不切半条 LSA。
4. **摘要与按需补拉**（最省流量的一步）：
   - `build_digest()` 产出 CSNP 式摘要清单；`on_hello()` 比对本地 LSDB，
     **digest 一致返回 `no-op`**（零 Git 流量、零 HTTP 请求），
     不一致或 seq 有缺口才返回 `pull_incremental` / `pull_full` 指令；
   - `head_sha` 单独作为一个字段，让 T-0353 判断「要不要连 Gitea」。
5. **公开 API** 保持小而稳定，供其余卡调用：
   `note_change()` / `tick(now)` / `on_hello()` / `build_digest()` /
   `merge_incoming()` / `should_pull()` / `sync_health()` / `status()`。
   所有函数不产生 I/O，不读写文件，不发起网络请求。
6. **`tests/test_hive_lsa.py`** 覆盖：合并窗口、MinLSInterval、MinLSArrival、
   令牌桶削峰、flap 抑制与恢复、2^n 退避与变更回弹、**jitter 必存在且落在 ±20% 区间**、
   摘要一致时 no-op、seq 缺口触发增量补拉、重复/旧 LSA 丢弃、1400B 分片不切半条、
   1800s 全量对账只发 digest、fake clock 下 30 分钟不产生任何全量状态传输。

## 不要做什么

- **不碰任何既有文件**（`hive.py` / `hive_cluster.py` / `hive_control/*` /
  `dashboard/*` 全部由别的卡持有），只新建 `hive_lsa.py` 与 `tests/test_hive_lsa.py`；
- 不 import 生产模块、不开 socket、不发组播、不连 Gitea、不读写 `~/.hive`；
- 不把全量状态体塞进摘要/Hello（这是 0.16.03 / 0.16.05 修掉的病根）；
- 不实现「每 N 秒全量同步」这类简单粗暴的兜底——T2 只发 digest；
- 不省略 jitter，不做「所有节点同一秒刷新」的定时器；
- 不为让测试通过而放宽阈值或改指标口径。

## 完成标准

1. `python3 -m pytest -q tests/test_hive_lsa.py` 全绿，用例数 ≥ 16，覆盖上述全部机制。
2. `hive_lsa.py` 只依赖标准库，`python3 -c "import hive_lsa"` 在不启动任何服务时成功。
3. 用 fake clock 跑 30 分钟空闲仿真：**0 次全量状态传输、0 次 Git 拉取指令**，
   只有 1 次 T2 digest 对账，且触发时刻带 jitter（不是整 1800.0s）。
4. 模块导出 `SyncConfig` 常量表，值与设计文档 §2 / §5 逐项一致，可被 T-0355 压测直接引用。
