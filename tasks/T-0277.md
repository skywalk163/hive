# 两条「编译器核心面」真缺陷（2026-11-07 现场复测，light HEAD `8567a6588`）

取证命令一律 `python3 -m cli.light run <探针.light>`，**用 light 自己的 CLI 与 `light/stdlib`**，
不要用下游项目自带的 stdlib 快照代跑（缺陷账「第三轮复测」因此错判过 4 条）。

## 一、复现与今天实测输出

```light
# 探针 A（L-257 新形态）：段落是两参，归约却报缺参
段落 求和(a, b):
  返回 a + b
打印 "BEGIN"
设 r 为 归约([1,2,3], 求和, 0)
打印 转字符串(r)
打印 "END"
```
→ **rc=1**，`错误: 类型错误 / 求和() missing 2 required positional arguments: 'a' and 'b'`，
stdout 只有 `BEGIN`。10/30 缺陷账 L-257 记的旧形态是「产物无 `import functools` → NameError」；
**今天形态变了**：`functools` 那条看起来已被后续轮次补上，但段落实参没按 `reduce(function, iterable, initializer)`
的口径发射。两条要一起收口，别只改其中一条。

```light
# 探针 B（L-239 同族的更普遍形态）：单行段落体 + 顶层语句
段落 加倍(x): 返回 x * 2
打印 "END"
```
→ **rc=0、零输出、零报错**。既不崩溃也不执行，属「静默空跑」。
对照实验：把段落体换成**换行缩进**写法后，后续顶层语句全部正常执行。
缺陷账「二十四」已登记 `异步 段落 …: 打印(...)` + `异步 运行` 的同类静默空跑（rc=0、零输出），
并注明「单行段落体是否属合法语法待裁定」；本探针说明**普通段落同样中招**，覆盖面比登记时更大。
