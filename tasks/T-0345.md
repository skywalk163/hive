# 接通约束解码，并把 V2 判据拆成「产品 / 能力」两列

> 依据：`~/dswork/LightPrism-整合路线v2-含train_openi方向-2026-11-14.md` §五 / §六 / §七，
> 与 `LightPrism-实战路线复盘与新思路-2026-11-13.md` A 组。
> **本卡不涉及 OpenI / V100 训练**（那是 T-0348，已按交办方要求后置）。

## 背景（都是实测，不是估计）

- `docs/Demo验收报告.md` §3：V2 = **0/20**，20 条抽样全是空格，`unique_chars=1`，
  **0 条带 `<CODE>` 标记**。
- `reports/训练报告.md` §5.2：训练流中空格占 **30.69%**（331,854 / 1,081,448 token），
  是最高频 token；50 步、loss 5.5–6.0 未收敛。
- 但 `src/lightprism/infer.py` 的 `PrismGenerator._apply_constraint()` +
  `src/lightprism/tokenizer.py:264 allowed_next()` **已经实现**结构状态机约束解码、
  checker 闭环、决策钉死、KV cache；而 `src/lightprism/demo/smoke.py:68` 走的是
  裸 `torch.argmax(last)`，一点没接上。
- 词表 `data/vocab_4096.json` 实有 **2900** 条、`headroom=1196`，但 `model.py`
  输出头是 4096 行；tied embedding 下这些空槽每步收 softmax 梯度却永远不是
  正确答案，是纯噪声。
- **关键纪律**：`train_openi.py` 文件头明确写了「约束解码的结构合法率必然接近 100%，
  属于假绿；判据 ③ 只用无约束贪心解码的裸结构合法率」。
  接通约束解码是**产品路径**，不是能力证据。

## 要做的事

### 1. 接通约束解码（不改公共语义）

- 新增 `src/lightprism/demo/infer_demo.py`（或等价入口），让 demo 的 `DemoVocab`
  与 `PrismGenerator` 的 `allowed_next` 状态机对齐，复用现有
  `_apply_constraint(logits, history)` 做 -inf 掩码。
- `scripts/demo.sh` / `make demo` / `lightprism chat` 走这条受约束路径。
- **不要**改 `src/lightprism/infer.py` 的公共行为，也不要动 `allowed_next` 的状态定义
  （全项目共享，动它另开卡）。

### 2. 空槽置 -inf

- 推理侧按 `data/vocab_4096.json` 的 `size=2900` 生成永久 mask，
  把 id ≥ 2900 且非 PAD/UNK 的槽位在 logits 上置 `-inf`。
- 做 ablation：接 / 不接 mask 各跑一次，报告 argmax 是否还塌到空格。

### 3. 评测：两列判据，不许合并

在 20 条真实任务 prompt（`data/sft/code_tasks.jsonl` 前 20 条）上重跑，报告**分别**给：

| 列 | 定义 | 归属 |
|---|---|---|
| 结构合法率（约束版） | 带成对 `<CODE>…</CODE>` / `<V:…>` 标记的比例 | **产品指标**，必然接近 100%，不算能力证据 |
| 无约束结构合法率 | 关掉状态机、裸 argmax 生成的结构合法率，按 `train_openi.check_structure()` 同口径复核 | **能力指标** |
| 代码段内合法率 | 抽出 `<CODE>` 内容跑 `light ai check --json`，全分母，空输出判不合法 | **能力指标** |

- 必须防住 `docs/Demo验收报告.md` §3.4 的已知盲区：`light ai check` 对空文件判 ok。
- 分母不许剔除截断 / 空输出；成功与失败样例都贴，不许只挑好的。
