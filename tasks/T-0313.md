## 背景

控制面要真正收到 Worker 状态，需要把 `hive.py` 的三处集群上报钩子接到 Unix socket。
母文档 §2：Worker 不直接发网络包，只写本地 serve。

先读 `docs/控制面v0.5-实现约定.md` §2.3 与 D5。

## 目标

改 `hive.py` 的 `cluster_publish_lease` / `cluster_release_lease` /
`cluster_publish_progress`（约 823-846 行）：

- 新增模块级懒加载 `_control_reporter()`，返回 `WorkerClient` 单例；
- 三个函数在原有 HTTP 上报之外，**best-effort** 把事件映射成 `StateEntry`
  交给 `report()`：
  - lease → `claimed`；
  - progress 的 state → `running` / `steady` / `released`；
  - release → `released`；
  - project 取 payload / card 的 repo，tid 取 task；
- 任何异常（导入失败、socket 不存在、队列满）都静默，不影响原返回值；
- `report()` 只入内存队列，不阻塞；控制面没起时不得增加可感知延迟。

## 测试（`tests/test_control_worker_hook.py`）

- monkeypatch `_control_reporter` 为假对象，断言三个函数各调用一次且参数正确；
- 控制面不可用时三个函数仍返回原 HTTP 结果、无异常；
- 映射表：lease / progress / release → 期望 state；
- 导入失败 / 构造异常时不影响原逻辑。
