# 基线归零：把 4 张卡的"没通过"一次性拆掉

> 触发：T-0370 / T-0371 / T-0372 / T-0373 的 verify 全部记 failed，但逐条复核后
> **没有一条是交付物本身不合格**。本卡只修"判据侧的债"，不改任何产品代码。

## 一、三条红的归因（已实测）

| # | 用例 | 为什么会红 | 性质 |
|---|---|---|---|
| 1 | `test_train_demo::test_decision_sequences_use_real_labels_only` | 断言 `len(rows) == 29`，T-0370 把 `data/runtime/decisions.jsonl` 扩到 241 条后必然红 | 快照写死 |
| 2 | `test_openi_v3_judge::test_label_coverage_surfaces_partial_coverage` | 断言 `has_err_validation is False`，T-0370 补了 25 条 ERR 正样本后必然 True | 把"当时的数据缺口"当成被测性质 |
| 3 | `test_acceptance::test_acceptance_main_exit_code_reflects_failures` | Linux 上通过，Windows 交付机上红（V7 在临时 ROOT 下判据入口缺失，退出码没反映） | 平台相关，待最小化 |
| 4 | `tests/test_kv_cache.py` 顶层 `import torch` | 无 torch 的机器收集期直接 ERROR，整轮 suite 记 rc=1 | 收集期硬失败（假红放大器） |

## 二、改法（不许降强度）

1. **#1 改成动态口径**：期望条数由日志里"带 `decision_tokens` 的记录数"现算，
   再叠一条 `>= 29`（T-0346 基线不回退）。不再钉 241 也不钉 29。
2. **#2 改成自造 partial**：从语料里挑 `PASS` 样本，现场组一个只有 1 个决策点的
   splits，断言诊断能标出"部分覆盖 + 无 ERR"。仍验证"诊断能报部分覆盖"，但不依赖仓库快照。
3. **#3 最小化复现**：先抓 Windows 上的 V7 分支（`verdict`/`detail`），确认是
   `entry_missing` 判 fail 还是 `blocked` 被算成 pass；若属后者，修 `exit_code` 聚合，不动判据。
4. **#4 加收集护栏**：`pytest.importorskip("torch")`，与 `test_model.py` 同口径——
   缺 torch 是环境缺依赖，不是代码红。

## 三、完成标准

```bash
PYTHONPATH=src python3 -m pytest -q tests/          # 无 torch 机器：0 failed（torch 用例 skip）
```

- 有 torch 机器上同样 0 failed（`#1` 的 `241` 与 `#3` 的 Windows 分支都要复跑）。
- 三条用例的断言强度**不得下降**：报告里逐条写"改前断言 / 改后断言 / 为什么仍然等价或更强"。
