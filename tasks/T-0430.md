## 背景

两个 MCP 相关 example 长期红，根因同一个：**断言「只装配 1 个 MCP 服务器」**，
而本机 `mcp.json` 实际配了 2 个（hive + lightmem）。

判据把「本机碰巧配了几个」当成不变量，于是：
- 机器上只有 1 个服务器的同事跑是绿的；
- 配了 2 个（正常使用场景）就红。

这是**环境耦合**，不是 MCP 功能坏了 —— 实测 2 个服务器都装配成功、31 个工具全部注册。

## 实测现状（2026-11-21，main c8153b1）

```
python 运行.py examples/test_mcp_prod.light
错误: Exception
  应装配1个服务器，实际: 2

python 运行.py examples/_probe_hive_mcp.light
错误: Exception
  MCP 挂载失败: {'已注册': [...31 个工具...], '服务器数': 2, '跳过数': 0}
```

注意 `_probe_hive_mcp` 的报错里 `失败数/跳过数 = 0`、工具全在 —— 装配本身是健康的，
只有「数量 == 1」这一条判断错了。

## 期望修法

把「数量」断言改成**与环境无关的不变量**，例如：

- `服务器数 >= 1`（至少要接上一个）；
- `跳过数 == 0`（没有服务器因为配置错误被跳过）—— 这条才是真正要守的；
- 断言「本用例注入的那台服务器」在 `已注册` 里存在（按名字定位，而不是按总数）。

如果这两个用例**本来就该测「只有一台」的装配路径**，那正确做法是给它们一个
**隔离的 mcp.json**（临时目录 + 显式注入），不要读宿主真实配置。

**不要**把 1 改成 2 —— 换台机器（0 台或 3 台）又红。

## 判据（全部必须绿）

```bash
python 运行.py examples/test_mcp_prod.light
python 运行.py examples/_probe_hive_mcp.light
```

反跑：
1. 在 `mcp.json` 里再加一台服务器 → 两条**应仍绿**（证明不再依赖总数）；
2. 把某台服务器改成坏地址 → 两条**应变红**（证明「跳过数 == 0」这条真在守）。
