## 背景

lightharness 当前工具面有约 160 个工具，名字多为 `tool_NN` 无语义编号或中文名，模型在调用前无法快速判断「某个能力在不在、属于哪个域」。`src/工具面装配.light` 是工具注册与装配的核心，`src/工具执行.light` 是执行管线。本卡是 W2（命名）/W4（可逆性）/W6（可观测性）三条线的**共同地基**，需优先落地。

## 目标

1. 在现有 registry 的注册接口上增加一个 `domain` 字段，取值如 `ctx` / `workflow` / `mcp_<server>` / `file` / `shell` / `session` 等。
2. 对现有全部工具做一次**批量回填**：优先基于工具名前缀或 description 关键词规则自动分类，人工只复核边界情况（例如 `工具_路径安全.light` 这类横切工具、MCP 透传工具）。
3. registry 支持按 `domain` 查询/枚举。

## 交付物

- `src/工具面装配.light`：注册接口新增 `domain` 字段 + 按 domain 查询能力
- 一个 `tool → domain` 映射（内联或独立数据文件，随实现定）
- `tests/test_T0496_domain字段.py`

## 验收判据

1. `tests/test_T0496_domain字段.py` 全绿，覆盖：每个工具都有非空 domain；按 domain 查询返回正确子集；未知工具缺省行为明确；
2. `tests/test_T0448_工具面装配.py` 不回归；
3. 原有工具的调用行为、wire 名不变——本卡**只加元数据，不改任何工具的可调用接口**。

## 红线

- 不改变任何工具的对外名称与参数签名；
- domain 是纯元数据，不得影响执行路径或工具剪枝；
- 回填规则要可复核，边界工具（横切、MCP 透传）单独标注理由。
