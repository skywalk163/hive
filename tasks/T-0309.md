## 背景

母文档 §2 / §7：Worker↔serve 唯一通道是 Unix socket；上报立即返回（I6/G1）；
通知非阻塞、满则丢（G2）。本卡实现服务端与客户端。

先读 `docs/控制面v0.5-实现约定.md` §2.3 / §3.8 与 D10。

## 目标

实现 `hive_control/worker_sock.py`：

- `WorkerServer(path, on_entry, limits)`：
  - start 前 unlink 旧文件；退出清理；`AF_UNIX SOCK_STREAM`；
  - 首行 `{"type":"worker","agent":...}` 注册；之后 entry 信封交给
    `on_entry(entry, agent)`；
  - `notify(owner_agent, message)` 只发给该 agent 的连接；非阻塞 `send`，
    `EAGAIN` / `BrokenPipe` 丢弃并计数；返回成功投递数；
  - 每连接读线程；坏行跳过；stop 幂等。
- `WorkerClient(agent, path, on_message=None)`：
  - `report(entry)` 只入有界内存队列（4096，丢最旧 steady）并返回；
  - 后台线程 connect / 重连 / 发送；服务端通知交给 `on_message`；
  - stop 幂等，退出前尽量 flush。
- 跨平台：Windows 用 `%TEMP%\hive-control.sock`（`Limits` 默认已提供）。

## 测试（`tests/test_control_worker_sock.py`）

tmp_path 下的 socket：

- 注册后上报能被服务端收到（agent 正确）；
- notify 只投递给对应 agent，另一个不收到；
- 客户端不读导致缓冲满时 notify 不阻塞、有 dropped 计数；
- 1000 次 report 平均 <1ms；
- 服务端重启后客户端自动重连（重试间隔可注入）；
- stop 后文件清理。
无 `AF_UNIX` 的平台 skip。
