## 背景

2026-11-25 凌晨修掉两个真 bug 并推到三端（`554cb2b`、`4730460`）：

- **坑 A**：`_adopt_leader_locked(refresh_lease=True)` 收到主控本人心跳时只续本机
  `leader_lease_until`，没写回 `nodes[leader]["lease_until_epoch"]`；维护循环那段
  「防御性收敛」又用记录里的旧值把本机租约压回去 → 每轮「续租→收敛回旧值→判过期→
  清空 leader_id→重新采纳」。清空走 `_emit_locked` **不写 cluster.log**，所以只看日志
  只看到「采纳主控」刷屏，看不到是谁清的。
- **坑 B**：`DEFAULT_LEADER_LEASE_S = 5.0` 与 `DEFAULT_IDLE_HEARTBEAT_S = 5.0` 相等。
  空闲时主控每 5 秒才发一次心跳，跟随者租约恰好 5 秒到期，网络晚几十毫秒就判过期。
  现改为 `max(默认值, 空闲心跳 × 3)` → 15s。

**问题**：这两处修复目前**只在 DESKTOP-6LFQUO8（win10）生效**。租约是主控签发的，
而当前主控是 fb98，它跑的还是旧代码，下发的 `leader_lease_until` 仍是 `now+5s`，
跟随者只能照收。实测证据（2026-11-25 03:1x / 05:1x 两次采样一致）：

| 节点 | 角色 | uptime | 下发的租约剩余 | 代码 |
|---|---|---|---|---|
| fb98 (`192.168.0.88:8788`) | **leader** | 41.4h | **4.9s** | 旧 |
| IC6RTQ4 (`192.168.0.101:8788`) | follower | 41.8h | 0.2s | 旧 |
| DESKTOP-6LFQUO8 (`192.168.0.100:8788`) | follower | 4.4h | 13.6s | 已修 |

`state.json` 的事件流是铁证：`leader_lost(主节点租约过期)` 与 `leader_seen`
一一配对（修前 55/54）。只要主控还是旧代码，这个配对就会继续产生。

各节点的工具仓路径（来自节点登记 `hive_dir`）：

- fb98（FreeBSD）：`/home/skywalk/dswork/hive`
- IC6RTQ4（win11）：`C:\dswork\hive`
- DESKTOP-2NRDKF0：`D:\dswork\hive`（当前 dead，可一并处理）

## 目标

1. **升级两个节点并重启各自的集群进程**，让 `4730460` 或其后的 main 生效：
   - fb98：`git -C /home/skywalk/dswork/hive pull --ff-only && hive cluster restart`
   - IC6RTQ4：`git -C C:\dswork\hive pull --ff-only`，然后 `hive cluster restart`
2. **重启前必须先看集群里有没有在跑的任务**：`hive status` / `hive cluster status`，
   有 `running` 的卡就先等或先 `hive block`，别把人家的活打断。
3. **重启顺序**：先 follower（IC6RTQ4），最后 leader（fb98）——
   先换主控会让集群短暂无主，先换跟随者影响面最小。
4. 升级后**实测确认**：主控下发的 `leader_lease_until_epoch` 减去当前时间应 ≥ 10s
   （旧代码是 5s），且 `state.json` 里新增的 `leader_lost(租约过期)` 不再成对出现。
5. 把这张清单沉淀成 `docs/cluster/节点升级清单.md`，把「节点仓路径 / 升级命令 /
   重启顺序 / 升级后怎么验」写进去，下次换代码不用再摸一遍。
