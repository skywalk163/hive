# 修复 make check 两项预存失败断言（V7 合入后的口径对齐）

## 背景

T-0341 已把 T-0335 的一键 demo 产物与 V7 复验证据合入 main（merge `7924855`，
三远端已对齐），`make demo` 3.827s / `make bench` 95.8 tok/s 实测通过。
但干净 clone 上 `make check` 仍 rc=1，T-0341 结果小结记录两项预存失败，
导致该卡第三条验收（`make demo` / `make bench` / `make check` 三个目标全绿）未达成。
本卡只处理这两项，其余不动：

1. `tests/test_acceptance.py::test_acceptance_main_exit_code_reflects_failures`（第 360 行）
   在 `tmp_path` 空目录上跑 `acceptance.main(["--only", "V7", "--json"])` 断言 `rc == 1`，
   现在实际 rc=0。`scripts/acceptance.py::check_v7` 用 `ctx.root / "Makefile"` 判断入口，
   而用例只 `monkeypatch.setattr(acceptance, "ROOT", tmp_path)` —— 需要核实
   `repo_root` 是否真的被隔离（默认参数在定义时绑定，可能没跟着 ROOT 走），
   即：是用例被工作区里的 Makefile 污染（夹具/实现问题），还是期望值过时。
2. `tests/test_openi_v3_judge.py::test_label_coverage_surfaces_partial_coverage`（第 344 行）
   `assert cov["has_err_validation"] is False` 实际为 True。`has_err` 由同文件测试夹具
   `_payload_vocab_rows()` 构造，`t` 是仓库根 `train_openi.py`（importlib 加载）。
   需定位是夹具语料/标签口径变更，还是 `train_openi.py` 的 label_coverage 实现回归。

`make check`（Makefile:50）依次跑全量 pytest、词表 `--check`、budget，除上述两项外无其它失败。
