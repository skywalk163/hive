## 背景

T-0187 的 Windows 派发脚本（`windows/dispatch-agent.ps1`）在真机上跑通了主链路（窗口匹配 → 激活 →
前台标题复核 → 写剪贴板 → `^v`+`{ENTER}` → `dispatch-mark`），但**真机验证同时挖出三处「会静默出错」的脆点**。
它们不是「能不能跑」的问题，是「跑坏了看不出来」的问题 —— 派发流水线的价值全在「账与实际一致」，
这三处都能让账说一套、实际另一套。

三条都是实测出来的（2026-10-28，Windows 10 19045 / PowerShell 5.1 / 真 AutoHotkey v2.0.31）：

1. **`SendKeys` 失败是静默的**。`WScript.Shell.SendKeys` 没有返回值，被拦时（UIPI、不同桌面、
   目标以管理员运行、受限会话）脚本照样打印「已发送」并继续 `dispatch-mark` —— 账上记了「已派发」，
   窗口里一个字符都没有。这是三处里最危险的一处：人看到「已发送」就不会再检查。
2. **`Set-Clipboard` 偶发抛异常**。实测撞到 `Requested Clipboard operation did not succeed`
   （`System.Runtime.InteropServices.ExternalException`）。剪贴板是全局单例，别的进程正开着它时就会抛；
   而 `$ErrorActionPreference = 'Stop'` 让脚本**直接终止**（exit 1，无 mark、无中文提示、只有一坨 .NET 堆栈）。
3. **`SetForegroundWindow` 在「调用进程不是前台」时返回 false**。实测连续三次 exit 3。
   AHK 触发的场景能成，是因为 AHK 刚收到热键、拥有输入权；换个触发方式（计划任务、别的脚本、
   从终端里跑但终端不是前台）就退化成「激活窗口失败」——而这不是真的失败，是缺 AttachThreadInput 兜底。

> 沙箱限制（写给下一位，省一次白跑）：本机受限会话里 `WScript.Shell.SendKeys` 对前台窗口**完全无效**
> （隔离探针实证：同样路径发 `XYZ`，目标文件一个字节没变），而 AHK 的 `Send()` 有效。
> 所以「按键真的落进窗口」这一步**必须在非沙箱的交互式桌面**上人工确认，pytest 里做不到。

## 要做什么

只改 `windows/dispatch-agent.ps1` 与 `tests/test_dispatch_script_static.py`（扩展既有静态断言）。
三件事，各自带一条新退出码。

### 1. 剪贴板写入重试（退出码 5）

新增 `Set-ClipboardText([string]$Text)`：

- 最多重试 5 次，退避 `150ms × 第几次`；
- 全部失败 → `Fail "写剪贴板失败（已重试 5 次）：<最后一条异常>" -Code 5`；
- **失败时绝不发送任何按键** —— 带着旧剪贴板去粘贴，等于往窗口里粘上一次的内容，比不发更糟。

调用点：第 6 步里把 `Set-Clipboard -Value $bodyText` 换成 `Set-ClipboardText $bodyText`。

### 2. 激活兜底：AttachThreadInput（退出码 3 语义不变）

`Set-WindowForeground` 改为：

- 先 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`；
- 不成立时 `AttachThreadInput(当前线程, 前台窗口线程)` → `SetForegroundWindow` → 解除 attach；
- 判定标准用 **`GetForegroundWindow() == 目标句柄`**，不要只看 `SetForegroundWindow` 的返回值
  （实测它会在窗口其实已经到前台时仍返回 false）；
- 仍不成立 → 保持现状 `Fail ... -Code 3`（语义与 T-0187 一致，AHK 的气泡分支不用改）。

### 3. 发送后回读校验（退出码 6）

新增 `Confirm-PasteLanded($Window, [string]$Sentinel)`，在 `{ENTER}` 之后、`dispatch-mark` 之前调用。
用 .NET 自带的 `UIAutomationClient`（**不加第三方依赖**）读目标窗口里第一个可读控件的文本
（`ValuePattern.Value`，退化到 `TextPattern.DocumentRange.GetText`），返回三态：

- **真**（读到文本且包含 `$Sentinel`）→ 打印「已确认正文落到窗口」，照常记账；
- **假**（读到文本但不含 sentinel）→ 说明按键去了别处或没生效 → `Fail -Code 6`，**不记账**
  （能确定没发出去，记账就是假绿）；
- **空**（UIA 不可用 / 控件不支持 / 读异常）→ 打印「未校验：本窗口不支持回读」，**照常记账**
  （记账失败会让人重复派发，比「未校验」更糟；但必须让人看见这句警告）。

`$Sentinel` 取任务号（正文里必然出现，如 `T-0184`），不额外往正文里塞标记。

## 红线

- ⛔ 默认仍是 dry-run：不加 `-Apply` 一个键都不许发（T-0187 的既有断言一条都不许放宽）。
- ⛔ 不引入第三方依赖 / 不要求装新软件（UIAutomation 是 .NET Framework 自带程序集）。
- ⛔ 不改 0/1/2/3/4 的既有语义；新增 5（剪贴板）、6（回读未命中）只加不改。
- ⛔ 回读只用**只读** API，不向目标窗口写任何东西，不切换焦点。
- ⛔ 不把 `SendKeys` 换成别的注入方式（AHK 的 Send 更可靠，但那会把逻辑漏到 AHK 层，违反 T-0187 的分工）。
- ⛔ 脚本仍须带 UTF-8 BOM、仍是中文输出（改完用 `head -c 3 | od` 复核 `ef bb bf`）。

1. `python -m pytest -q tests/test_dispatch_script_static.py` 全绿，且**新增断言至少 6 条**：
   - `Set-ClipboardText` 存在、有重试循环、全失败走 `-Code 5`；

   - `Confirm-PasteLanded` 存在、三态齐全（`-Code 6` 分支存在）；
   - 调用顺序正确：`Confirm-PasteLanded` 在 `SendKeys('{ENTER}')` 之后、`dispatch-mark` 之前；
   - 头部 `.NOTES` 的退出码表包含 5 与 6。
2. **反证（summary 逐条贴 A/B）**：把三条新分支分别注掉/改坏，对应断言必须红，还原后全绿。
3. **真机人工步骤（必须在非沙箱的交互式桌面上做，summary 贴终端输出）**：

   - 把一个不支持 UIA 回读的窗口设成目标（或临时让回读抛异常）：打印「未校验」且**照常记账**；
   - 剪贴板被占用时（可用另一进程持有剪贴板复现）→ exit 5，且**目标窗口里没有多出任何字符**。
4. 全量回归：`python -m pytest -q tests/test_dispatch_script_static.py` 与本卡无其它交集，说明即可。
