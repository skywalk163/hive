# lightplugin 去掉 `运行.py` 的 Windows 绝对路径默认值，让 `bash smoke.sh` 在 POSIX 上真跑

## 背景（T-0275 实测，2026-11-06 验收）

- 原卡：T-0276（lightplugin 补 LICENSE + smoke + CI），state=`done`。
- 原 verify 第 3 条 `bash smoke.sh` 在验收机（FreeBSD 15.1）实测：

  ```
  FAIL（5/5 全部失败，先卡在「找不到光明编译器」）
  SMOKE FAIL   rc=1
  ```

- 根因：[`运行.py`](../../lightplugin/运行.py) 的模块级默认值写死成 Windows 盘符路径：

  ```python
  # 运行.py:16-17（docstring）
  LIGHT_MERGE     光明编译器（语言本体）路径，默认 G:\dswork\duan-light-merge\light-merge
  LIGHTHARNESS    宿主项目路径，默认 G:\dswork\duan-light-merge\lightharness

  # 运行.py:26-27（默认值）
  LIGHT_MERGE = os.environ.get('LIGHT_MERGE', r'G:\dswork\duan-light-merge\light-merge')
  LIGHTHARNESS = os.environ.get('LIGHTHARNESS', r'G:\dswork\duan-light-merge\lightharness')
  ```

  POSIX 上没有 `G:\...`，模块级 `os.path.isdir` 检查（`运行.py:32-35`）直接 `sys.exit(1)`，
  5 个 smoke 用例全部失败。**Windows 上绿是因为那两个默认路径恰好存在 —— 假修。**

- 已证实的对照：同一份代码，把 `LIGHT_MERGE` / `LIGHTHARNESS` 显式指向正确的兄弟仓后，
  5 个 smoke 用例（`_lp001_verify`、`_lpd003_declared`、`冒烟A/B/C`）**全部 rc=0**。
  即：**路径解析是唯一阻塞点，smoke 内容本身是好的。**

- 平台命名差异（必须一起解决）：验收机上兄弟仓是 `/home/skywalk/dswork/light`，
  Windows 上是 `...\light-merge`；宿主仓两边都叫 `lightharness`。

## 目标

1. `运行.py` 默认值改为**从自身位置推导兄弟仓**，不再出现任何 Windows 盘符绝对路径：
   - 编译器默认：`ROOT/../light`，不存在时再试 `ROOT/../light-merge`；
   - 宿主默认：`ROOT/../lightharness`；
   - 保留 `LIGHT_MERGE` / `LIGHTHARNESS` 环境变量覆盖（优先级最高）。
2. 两个目录都找不到时，报错信息要指路（打印候选路径 + 提示可设环境变量），不要只 exit。
3. 同步 `运行.py:16-17` 的 docstring，删掉 `G:\...` 字样（否则静态判据不过）。
4. 不改 smoke 白名单与用例内容；不改 `smoke.sh` 判定逻辑。

## 红线

- 只改本卡 `paths` 内文件；不改其它卡与它们的 verify；不改 `agents/` 配置；不写 token / 密钥 / IP。
- 不许把环境变量写死进 `smoke.sh` 或 CI 来「绕过」——默认值本身必须在 POSIX 上可用。
- 不许放宽 smoke 白名单（不许把失败用例从 `PASS_LIST` 里删掉）。
- 不许在 `运行.py` 里保留 `G:` 字样的兜底。
