# 工具面装配表：预设过滤不再把 148 个已实现工具砍成 4 个

> 第一次接 hive？先读 `docs/AGENT快速上手.md`。

## 背景（实测，不是推测）

1. 真实会话里模型只收到 **4 个工具**：
   ```
   python - <<'PY'  # 扫 sessions/**/session.jsonl 的 request/header
   tools: ['bash','read_file','write_file','search_files']
   ```
2. 直接探装配面（今天 main 实测）：
   ```
   装配_standard=bash,读文件,写文件,搜索文件
   装配_ptc=bash,读文件,写文件,搜索文件
   装配_minimal=bash
   装配_brainstorm=读文件,搜索文件
   装配_无预设=…148 个工具…（SSH执行、待办添加、技能取用、网页抓取、派发子任务、
                 定时、交付、LSP、终端、沙箱裁决、运行Python脚本 …全在）
   ```
3. 根因两处，都在 `src/总入口.light`：
   - `工具名到叶子(名字)`（约 167 行）只映射 5 个名字：bash / 读文件 / 写文件 / 搜索文件 / 目标；
     其余一律 `返回 []`。
   - `预设保留工具(注册表, 预设标识)`（约 209 行）按「装配挂载集里有没有对应叶子」注销，
     于是**所有 lightplugin 工具与 MCP 工具在任何预设下都被注销**。
   （`工具名到叶子` 的注释里也承认：「lightplugin / MCP 工具：当前四预设无对应叶子，暂不挂载」。）

结果：lightharness 的 `standard` 预设只有 4 个工具，DSH 的 standard 有 ~15–20 个
（fs 读/写/编辑、fs-search、jobs、skill、goal、ask_user、todo、web、present、
subagent、workflow…）。这是「不如 DSH 好用」的第一大来源。

## 要做什么

新增 `src/工具面装配.light`（纯数据 + 纯函数，**不要碰 `src/总入口.light`**，
接线由收口卡 T-0456 统一做）：

1. `叶子映射(名字)` —— 返回该工具名对应的 DSH 叶子 id 列表，至少覆盖：
   - 现有 4 个：`bash` / `读文件` / `写文件` / `搜索文件`
   - `todo_write` → `tool-todo`
   - `ask_user_question` → `tool-ask-user`（含 `session_query` → `tool-session-query`，若上游无此叶子就落到 `tool-ask-user` 同组）
   - `search` / `网页抓取` → `tool-web`
   - `技能取用`/`技能列表` → `tool-skill`
   - `派发子任务`/`收集子任务结果`/`list_agents`/`send_message` → `tool-subagent`（fork 用 `tool-subagent-fork`）
   - `交付登记`/`交付列出` → `present`
   - `提醒注册`/`提醒列出` → `tool-schedule`
   - 作业族（T-0456 会新增）→ `tool-jobs`
   写不出叶子依据的名字必须**显式登记到「不上叶子表」**并在模块头注释写明理由。
2. `补充叶子(预设标识)` —— 返回该预设应额外保留的叶子集合（`standard`/`ptc`/`cordis`/`default` 为全集，
   `topdown`/`bottomup`/`lazy` 为全集减写工具，`brainstorm` 只留只读，`minimal` 只留 bash）。
3. `未映射默认保留(预设标识)` —— 布尔。`標準` 类预设返回 真（宁可多挂也不静默丢工具），
   `minimal`/`brainstorm` 返回 假（保持收紧）。
4. `装配报告(条目表, 预设标识)` —— 返回 `{保留:[…], 注销:[…], 未映射:[…]}`，
   供收口卡与文档打印「谁被留下了、谁被注销了」。
