## 一、LH-17　`后台执行` 钉死 PIPE，常驻进程写满管道后静默卡死（P0）

源码已确认：`stdlib/外部命令.py:236-237` 的 `subprocess.Popen(..., stdout=subprocess.PIPE, stderr=subprocess.PIPE)`，
**没有任何地方读这两个管道**。缓冲（Linux 64KB）写满后子进程阻塞在 `write()`：
`poll()` 仍是 `None`（"活着"），但再也不干活，**零报错**。

实测（探针，10 秒）：

```light
从 外部命令 导入 后台执行
从 时间管理 导入 睡眠
从 文件系统 导入 文件存在
设 脚本 为 "for i in $(seq 1 200000); do echo 0123456789012345678901234567890123456789; done; touch /tmp/done.flag"
设 句柄 为 后台执行(["sh", "-c", 脚本])
设 秒 为 0
当 秒 < 10:
  睡眠(1)
  秒 为 秒 加上 1
  如果 文件存在("/tmp/done.flag"):
    打印 "已写完"
    返回
打印 "10 秒后仍未写完 → 管道卡死（poll=" 加上 转字符串(句柄.poll()) 加上 "）"
```

实际输出：`10 秒后仍未写完 → 管道卡死（poll=空）`（9MB 都没写完，标记文件始终缺失）。

**期望**：
- 默认把 stdout/stderr 重定向到 `DEVNULL`（或调用方指定的文件），**不再默认 PIPE**；
- 确实要 PIPE 时必须是显式开关（如 `捕获输出 = 真`），并返回可读句柄，文档写明「不读会阻塞」；
- 向后兼容：`等待进程(句柄)` 现在靠 PIPE 取输出，改成 DEVNULL 后要保证「未开捕获输出」时返回空输出而不是崩。
- 建议再加一条运行期告警：子进程存活但输出未被消费超过 N 秒时提示（可选）。

## 二、LH-06　`执行命令` 没有 stdin 入参（P1）

签名仍是 6 参：`执行命令(命令, 捕获输出, 工作目录, 环境变量, 超时, 编码)`，没有 `标准输入`。
于是「把内存里的内容交给命令」的链路全断：`git hash-object -w --stdin`、`gpg --verify`、管道喂数据。

**期望**：`执行命令(..., 标准输入 = 空)` 透传 `subprocess.run(input=…)`；不传时行为不变。
**参考**：`stdlib/进程.py:进程运行(输入=)` 已有此能力，实现口径可直接对齐（注意 bytes/str 与 `编码` 参数的配合）。

## 三、LH-19　`工作目录 = ""` 是陷阱（P2，现状已比记录时好一档）

`执行命令(["pwd"], 真, "")` 现在**不再抛异常**，但返回 `返回码=-1` + `标准错误="命令未找到"`。
真因是 `chdir("")`（`FileNotFoundError` 被 except 兜住），**错误文案把人往"命令不存在"引**。

**期望**：`""` 归一成 `None`（"不指定"），与 `空` 同义。这是 stdlib 层归一化，代价极小。
（同类：`后台执行(..., 工作目录="")`、`进程启动(..., 工作目录="")` 一并归一。）

## 验收

新增 `tests/unit/test_LH17_后台执行管道.py`：

1. **不堵**：`后台执行` 起一个写 ≥1MB stdout 然后 touch 标记文件的子进程，10 秒内标记文件必须出现；
2. **不死**：子进程写满后 `poll()` 仍能正常返回最终返回码（不因管道卡死而永久 `None`）；
3. **兼容**：`等待进程` 在未开捕获输出时不崩；开了捕获输出时仍能拿到 stdout；
4. **stdin**：`执行命令(["cat"], 真, 空, 空, 空, "utf-8", 标准输入="甲乙")` 的 stdout 含「甲乙」；
5. **空串工作目录**：`执行命令(["pwd"], 真, "")` 返回码 0 且输出为当前目录（与传 `空` 等价）。
