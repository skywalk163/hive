# 编辑文件工具：把「整文件重写」换成唯一命中替换

## 背景

- DSH 的 fs 面是 **read / write / edit**（`packages/fs` + `tool-fs` 的 edit 命令），
  模型改一行只需要给 `old_string/new_string`。
- lightharness 目前只挂 `写文件`（整文件覆盖）。真实会话（`sessions/.../request/header`）里
  工具面就 4 个：`bash, read_file, write_file, search_files`。
  后果：改一行 = 重写整文件，输出 token 与上下文双重放大，长任务更容易撞压缩/步数上限。
- 纯逻辑其实已经在了：`src/字符串替换编辑器.light`（唯一命中 / 未命中 / 多命中 / replace_all），
  全仓只有 `src/文件系统工具.light` 导入它，**没有变成工具定义、也没被装配**。

## 要做什么

新增 `src/工具_编辑文件.light`（新文件；**不要改 `src/核心工具.light`**，接线归 T-0454）：

1. `造编辑文件工具定义(依赖 = 空)` —— 用 `工具.造工具定义` 造一个工具：
   - 名字 `编辑文件`；参数键用中文原名（与 `写文件` 同风格）：`路径`、`旧文本`、`新文本`、
     `全部替换`、`插入行`（可空）。
   - 描述里必须写清「旧文本必须在文件里唯一命中；要替换多处显式传 全部替换=真」。
2. `编辑文件处理(参数)` —— 走 `字符串替换编辑器` 的纯逻辑：读文件 → 唯一命中校验 →
   替换/插入 → 写回。错误返回 `造工具结果(消息, 真)`，文案要含**行号**与命中次数
   （照抄 `字符串替换编辑器` 现有错误文案，不要另造一套）。
3. 依赖注入：读/写文件用 `依赖` 里的回调（缺省退回 `文件系统.读取文件/写入文件`），
   这样测试可以完全离线跑，不用真盘。

## 判据（`tests/test_T0447_编辑工具.py`，新建）

用 `运行.py` 跑 `.light` driver（照抄 `tests/test_T0419_工具叶子拆分.py` 的进程级跑法）：

1. 唯一命中：`旧文本` 在文件里出现 1 次 → 替换成功，文件内容逐字正确；
2. 未命中：返回 `isError=真`，文案含「未找到」+ 行号口径；
3. 多命中且没传 `全部替换` → `isError=真`，文案含命中次数与行号；
4. `全部替换=真` → 全部命中被替换，计数正确；
5. `插入行=N` → 在第 N 行插入且不吞原行（N=0 与 N=总行数 两个边界都测）；
6. 工具定义形状过 `工具.校验工具定义形状` 且名单里叫 `编辑文件`；
7. **反跑**：把「唯一命中」判定改成「直接替换第一处」，用例 3 必须立红（summary 贴记录）。

## 红线

- 不改 `写文件` 行为；
- 不引外部依赖；不真改仓库里的源文件（测试用临时目录）。
