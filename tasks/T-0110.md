## 背景

闭环的最后一公里现在靠人。T-0101 的 result 早就 `done`、17 个用例全绿，代码却在
`task/T-0101` 分支上躺了两个小时，main 还是 0.4.0 —— 因为 `close` 只做「归档结果 +
删分支」，**根本不合并**。git log 里那 6 次 `chore: 复位 ready`、反复 retry，全是人工清场。

agent 一天能干 20 张卡，人一天只能合 5 张。不把这一步自动化，「在 hive 上协同各 agent
开发 hive 自己」就是空话。

## 目标

新增 `hive land T-xxxx`：把一张已完成的任务卡自动合入 main 并关闭。

1. **前置检查**（不满足就直接报错退出，不要硬来）：
   - 该卡有 `result` 且 `status == done`；
   - 该卡的 `verify` 在结果里全绿；
   - 任务卡 `state` 不是 `done`；
   - 依赖 `depends_on` 的卡都已 close（避免把半成品合进去）。
2. **合入**：在**代码仓库**里操作，不是在协调仓库：
   - `git fetch origin`，把 `origin/task/<tid>` 合进一个从 `origin/main` 新建的临时分支；
   - 优先 `--ff-only`；不能快进就试普通 merge；
   - **merge 冲突就立刻停下**：不要自动解冲突，把卡置为 `conflict` 状态（状态机由
     T-0113 引入；本卡先只做「报告冲突 + 给出冲突文件清单」，不写状态字段），
     打印冲突文件和后续步骤，退出码非 0；
   - 合入成功就 `push origin main`。
3. **收尾**：合入成功后再 `close`（归档 result 到 `results/<tid>.json`、删 `claim/`、`res/`
   分支），并在提交信息里带上 `land T-xxxx`。
4. **预演**：`hive land --dry-run` 只打印会做什么、会不会冲突，**不动任何分支**。
   默认行为自己定，但必须让「先看再动」成为习惯 —— 建议默认 dry-run，`--apply` 才真合。
5. **批量**：`hive land --all` 按优先级把所有「可合入」的卡依次合掉；遇到冲突就停下并
   报告，不要跳过继续合（后面的卡很可能建立在它之上）。

## 红线

- 不动 light 等其它仓；不改 fb5 runner 配置；不引入新依赖。
- **冲突绝不自动解**，也绝不用 `--force` 覆盖 main。
- `close` 的现有行为保持向后兼容（它现在不合并，加了 land 之后它**仍然**不合并）。
- 只在代码仓库里做 git 操作；协调仓库的工作区只能被 `commit_and_push` 改。
- 不要顺手改 `tasks/*.md`、`results/*.json`、`agents/*.json`（那是 T-0112 的事）。
