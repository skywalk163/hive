# 指令发现（AGENTS.md）：把已复刻的 agent-instructions 渲染成系统提示段

## 背景

- DSH 启动时会发现 `AGENTS.md` / `CLAUDE.md`（用户全局、仓库根、子目录多级），
  去重后注入系统提示。这就是「同一个模型在 DSH 里更懂这个仓库」的直接原因。
- lightharness 的 `src/智能体指令.light` 已经把纯逻辑复刻完了
  （候选组、`dshHome`/`agentsHome` 双全局根、`escapeProjectDisplayPath`、去重、渲染结构），
  但**全仓唯一消费者是 `src/推荐决策.light`**——系统提示里一个字都没用上。
  系统提示只有 `src/总入口.light:默认系统提示文本()` 那 3 条工具契约。
- 结果：模型永远不知道仓库的 AGENTS.md 写了什么。

## 要做什么

改 `src/智能体指令.light`（只增不改，别动既有导出语义）：

1. 新增 `发现指令(根, cwd, 配置 = 空)` —— 按现有纯逻辑算出命中文件表
   （用户全局 → 仓库根 → cwd 逐级向上 → 子目录），返回
   `{文件表:[{路径, 作用域, 字节数}], 去重数, 跳过:[{路径, 原因}]}`。
   IO 用注入的读文件回调（缺省 `文件系统.读取文件`），测试可完全离线。
2. 新增 `渲染指令段(发现结果, 上限字节 = 65536)` —— 产出可直接拼进系统提示的文本：
   - 每份文件一段：`## <显示路径>` + 正文；
   - 超 `上限字节` 时按文件粒度截断并追加「（已截断）」；
   - 转义沿用现有渲染约定（别把 markdown 结构破坏掉）。
3. 新增 `装配提示段(渲染文本, 通用契约文本)` —— 顺序固定：**项目指令在前、通用契约在后**
   （人写的仓库规矩优先级要高于系统默认那 3 条）。

## 判据（`tests/test_T0453_指令渲染.py`，新建，临时目录造假仓库）

1. 仓库根 `AGENTS.md` + `src/AGENTS.md` 两级 → 发现 2 份，作用域标注正确；
2. `CLAUDE.md` 与同名 `AGENTS.md` 同时存在 → 只留一份（按现有优先级），`去重数=1`；
3. 文件 > 上限 → 被截断且带「（已截断）」标记，输出总字节 ≤ 上限 + 标记长度；
4. `渲染指令段` 的段落顺序 = 发现顺序（用户全局 → 仓库根 → 子目录）；
5. `装配提示段` 输出里项目指令段的下标 < 通用契约段下标；
6. 空仓库（没有任何指令文件）→ 返回空文本，不报错；
7. **反跑**：把去重关掉，用例 2 立红。

## 红线

- 不改 `src/智能体指令.light` 既有导出（`推荐决策` 在用）；
- 不碰 `src/总入口.light` / `src/系统提示.light`（接线归 T-0454）；
- 文件读取必须可注入，测试不许读真仓库文件。
