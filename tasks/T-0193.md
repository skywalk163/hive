> 第一次接 hive？先读 `docs/AGENT快速上手.md`（agent 视角的接入指南）。

## 背景

agent land 合并一张卡后，**代码仓远端 origin/main 是最新的**（land_one 会先
`git fetch --prune origin` 再 merge、push），卡片状态也由 close 写进了协调仓 main，
主控看板 20 秒轮询就能显示 done。但**主控/开发机本机的代码仓主检出不会自动 pull**：
2026-10-28 T-0188 合入后，0.88（fb98）上的 clone 不跑 fetch 就看不到，主控机器
G 盘的主检出同样落后。现在靠人手动 `git pull`，多机多仓（hive / light /
lightharness…）时容易漏，会让人在旧代码上排查"为什么合了没生效"。

## 目标

1. **新子命令 `hive sync-repos`**：
   - 对主控本机登记的每个代码仓（`Hive.repos()` 的本机路径）逐一执行
     `git pull --ff-only origin`（或等价的 `fetch` + `merge --ff-only`）；
   - 每仓打印一行结果（已最新 / 快进到 <sha> / 落后但无法快进 / 远端不可达）；
   - **只快进、不自动解冲突**：ff 失败只列原因并跳过该仓，绝不用 `reset --hard`
     或 `--force`，本机未提交改动原样保留（复用 `_sync_for_commit` 的安全边界思路）；
   - `--json` 输出结构化结果；`--repo <name>` 只同步指定仓；
   - 网络类 git 操作走 `git_net`（带 HIVE_NET_TIMEOUT 超时），远端不可达明确报错。
2. **orchestrate 加 sync 阶段**：每轮在 doctor 之前调用同一实现
   （默认开启，`--no-sync` 可关）；sync 失败不中断整轮循环。
3. 测试 `tests/test_sync_repos.py`（≥6 用例）：已最新不报错、能快进、
   分叉时跳过且本地改动不丢、--repo 过滤、--json 结构、orchestrate 一轮内
   sync 被调用（可用 monkeypatch 或 fake 仓断言）。

## 红线

- 不改 `land` / `watchdog` / `dispatch` 的既有行为与退出码；
- 不自动解冲突、不用 `reset --hard` / `--force` / `--no-verify`；
- 不动 dashboard/、conflict.py、dispatch_prompt.py、dispatch_tracking.py、
  pending_matcher.py；
- 不引入第三方依赖（纯标准库 + git）；
- 不在本命令里做任何卡片写操作（sync 是只读同步，不是任务流转）。

## 验收

- `git show --stat HEAD` 只覆盖 `hive.py` 与 `tests/test_sync_repos.py`；
- `python -m pytest -q tests/test_sync_repos.py tests/test_core.py` 全绿
  （test_core 全量保持既有行为不变）；
- 手工演示：建两个本地 clone（一个最新、一个落后），跑 `hive sync-repos`
  后落后仓被 ff 快进、最新仓报"已最新"，分叉仓被跳过且报原因；
- summary 里贴真实运行的 `hive sync-repos`（含 --json）输出。
