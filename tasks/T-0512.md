## 背景

长任务中模型不知道本轮烧了多少 token、还剩多少预算，在「深挖 vs 收敛交付」之间判断不准。现状 `src/上下文.light` 已有 token 跟踪，`src/工具面装配.light` 已有工具预算（thresholdPct×contextWindow，listingMaxTokens）。本卡在**会话级**注入轻量预算信号，让模型在每轮看到「本轮用量 / 剩余额度」。

**前置**：T-0498（分层披露）就位，预算信号与工具折叠预算共用同一 token 估算逻辑。

## 目标

1. 每轮在系统注入或工具响应元数据中附加轻量预算信号：本轮已用 token、会话累计、剩余额度（基于 contextWindow 或预算阈值）；
2. 信号粒度可配：可选「每轮都注入」或「达到阈值时注入」（如超过 50%/80% contextWindow）；
3. 信号格式轻量（一两行），不占用过多上下文。

## 关键设计取舍

信号是**提示模型决策**的软信号，不是硬性熔断——模型据剩余额度自主选择深挖或收敛，不是到阈值就被强制终止。

## 交付物

- `src/工具执行.light` / `src/工具面装配.light`：预算信号计算与注入
- `src/上下文.light`：token 用量对接（复用现有跟踪）
- `tests/test_T0512_预算信号注入.py`

## 验收判据

1. 每轮（或达阈值时）注入预算信号，含已用/累计/剩余；
2. 信号基于真实 token 估算（复用 `src/令牌估算.light`），非硬编码；
3. 粒度可配（每轮 / 阈值触发），默认行为可验证；
4. `tests/test_T0449_执行管线.py` 不回归。

## 红线

- 信号是软提示，不是硬熔断，不得在达到额度时强制终止模型；
- 复用 `src/令牌估算.light` 现有逻辑，不另造估算；
- 注入开销要轻量，不得显著增加每轮 token 占用。
