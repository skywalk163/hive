# 根目录 155 个 md 里，145 个是过程文档

## 现状（实测）

```
$ cd light && git ls-files | grep -E '^[^/]+\.md$' | wc -l
155

# 按前缀分类
_R0xx_收口报告.md / _R1xx_A线交付报告.md 等   → 145 个
常驻文档（README/CHANGELOG/CONTRIBUTING/...） → 10 个
```

体积：**1.6MB**，全在仓库根目录。

后果：`ls light/` 出来 210 个条目，新人第一眼看到的是 `_R118_收口报告.md`、
`_R133_收口报告.md`… 一直到 `_R167_T4交付报告.md`。真正的入口文件被淹了。

### 根 ROADMAP.md 也有问题

```
$ awk '{print length}' ROADMAP.md | sort -rn | head -3
2613
1415
1056
```

**最长一行 2613 字符。** 那是 R167 那段把所有细节塞进了一个 `>` 引用块。
文件开头自己写着：

> 详细技术路线见 `docs/ROADMAP.md`；本文件只保留**对外可承诺**的部分。

但实际上没有遵守——`R147` / `R146` / `R167` 的历史快照全在里面。

## 起点线索

- `light/docs/归档/` **已经存在**，里面有 `R154_scratch归档`、`R157_探针归档`、`CI修复_P3P6事件` 三个子目录
  → 说明归档是这个仓的既有惯例，本卡只是把它执行到底
- `_archive/` 也在 `.gitignore` 里（`lightplugin` 用的是这个；`light` 用的是 `docs/归档/`）

## 目标

### 1) 建归档目录并搬文件

```bash
cd /home/skywalk/dswork/light
mkdir -p docs/归档/轮次报告
git mv _R*.md docs/归档/轮次报告/ 2>/dev/null
git mv _r*.md docs/归档/轮次报告/ 2>/dev/null
```

⚠️ **不要用 `mv`，用 `git mv`** —— 保留历史，后续 `git log --follow` 还能追。

### 2) 归档后加一个 README 说明

`docs/归档/轮次报告/README.md`：

```markdown
# 轮次报告归档

本目录存放 R118~R167 各轮的收口报告、并行任务书、分线交付报告。

**为什么归档**：这些是**过程留痕**，不是对外文档。堆在仓库根目录会淹掉
README / CHANGELOG / CONTRIBUTING 这些真正的入口（2026-11-06 时根目录 155 个 md
里有 145 个属于本类，占 1.6MB）。

**怎么找**：按轮次号。`_R167_` 是最近一轮（门禁假绿清零轮）。
**当前权威快照**：[`ROADMAP.md`](../../../ROADMAP.md) 顶部的「最后更新」段落。
```

### 3) 把根 ROADMAP.md 瘦身

保留结构：
- 当前版本
- 北极星
- 阶段（R96 / R97 / R98 的**结论性**进度，每条 1~2 行）
- 不在计划内
- 如何参与

**移除或外移**：
- 那段 2613 字符的 R167 巨块 → 挪进 `docs/归档/轮次报告/_R167_收口报告.md`（它本来就在那）
- R147 / R146 的历史快照段 → 同样已经在归档里，根 ROADMAP 只留一句「历史见归档目录」

目标：**根 ROADMAP.md 单行不超过 300 字符**，总行数控制在 120 行以内。

### 4) 检查内部链接没断

`light` 的 CI 有 `deploy-docs.yml`（mkdocs），如果 mkdocs 的 `nav` 里引了这些根目录 md，
搬走会 404。先查：

```bash
grep -n "_R1" mkdocs.yml 2>/dev/null
grep -rn "_R1[0-9][0-9]_" docs/*.md 2>/dev/null | grep -v "归档/" | head
```

有引用就把链接改成新路径。
