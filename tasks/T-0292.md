# hive_compat 支持 `bash <script>` / `python3 <script>`：治 Windows verify 平台假红

## 一句话

凡卡面 verify 写成 `bash ...` 或 `python3 ...`，在 Windows agent 上都必然 rc≠0，
与产物质量无关。T-0291、T-0261、T-0237 都栽在这上面，主控已经为 T-0261 / T-0289
人工改判过一次。这次把根因修掉，别再让每张 POSIX 卡都要人工捞一次。

## 现象与证据（都是实测，不是推测）

Windows agent 的 `hive_submit` 跑 verify 走 `subprocess(shell=True)` → `cmd.exe`：

```
'bash' 不是内部或外部命令，也不是可运行的程序     → rc=1
'python3' 不是内部或外部命令，也不是可运行的程序  → rc=1
```

T-0291 的 `results/T-0291.json`（`origin/res/T-0291`）里四条 verify 的 tail 就是
这个；第 4 条 `check_full_baseline.py` 因为脚本里显式做了环境检查，走的是 `exit 2`
+「找不到 bash：本判据要在 POSIX 上跑」。T-0261 的 previous_attempt 是同一签名。

本机 `bash` 只在 `C:\Program Files\Git\bin\bash.exe`，不在 PATH；Python 只有
`python.exe`，没有 `python3.exe`。`hive_compat.py` 的 `should_wrap()` 目前只认
`true` / `false` / `:`、`test -e/-f/-d/-r/-s/-x`（含 `! test`）、整数比较
`-eq/-ne/-lt/-gt/-le/-ge`，**不认识 `bash X` / `python3 X`**，于是整条原样丢给
`cmd.exe`。`evaluate()` 对未映射写法返回 2（`main()` 打印「不支持的写法」）。

## 目标

在 `hive_compat.py` 里给两类**命令前缀**加映射，让 Windows 上的 verify 能真正执行
POSIX 风格脚本，而不是换一台机器救火：

1. **识别**：`should_wrap()` 增加
   - `bash <script> [args...]`（也考虑 `sh <script>`，可只做 `bash`）
   - `python3 <script-or-args...>`
   
   只认「整条命令以该前缀开头」，且必须还有后续参数；`bash` 后面没东西不算。
   其它未知写法**照旧原样交给 shell**，绝不猜一个成功。

2. **定位可执行程序**（Windows 侧）：
   - `bash`：依次探测 `shutil.which("bash")`、Git for Windows 常见安装位置
     （`C:\Program Files\Git\bin\bash.exe`、`...\Git\usr\bin\bash.exe`、
     `C:\Program Files (x86)\Git\bin\bash.exe`）、`HIVE_BASH` 环境变量覆盖。
   - `python3`：映射到 `sys.executable`（当前跑 hive 的解释器），不要去 PATH 里碰运气。
   - 找不到时**明确失败**：打印可诊断的提示并返回非零（建议 2，与现有
     「不支持的写法」区分或复用），**禁止返回 0**。假绿比假红更贵。

3. **执行方式**：参数按 POSIX shlex 拆成 argv 列表，用
   `subprocess.run([exe, *args], cwd=..., **no_window_kwargs())` 直接调用，
   不经 `cmd.exe` 二次拼接引号（T-0287 已经证明 cmd.exe 的引号/空格会咬人）。
   保留 `stdin` 隔离与 `stdout/stderr` 捕获语义；沿用 `no_window_kwargs()`，
   别把 T-0206 修掉的黑窗带回来。
   退出码原样透传，不吞、不改；超时沿用调用方既有策略。

4. **平台边界**：非 Windows 不改变既有行为——`should_wrap()` 仍只在
   `os.name == "nt"` 返回 True；但 `python hive_compat.py run "<cmd>"` 这个
   **直接入口**要能在两种平台上执行新写法（POSIX 上用系统 `bash` / `sys.executable`），
   这样卡面 verify 在验收机和 Windows agent 上都能真跑、结果可比。

5. **回归锁**：`tests/test_compat.py` 补用例，覆盖
   - `bash X` / `python3 X` 的识别与执行（含带空格/引号的参数）；
   - 脚本不存在、命令返回非零 → 透传非零，不静默成功；
   - 找不到 bash 的模拟场景 → 非零且提示清晰；
   - 原有惯用法（`true` / `test -f` / `test -x` / 整数比较 / `rewrite()` 引号）
     行为一字不变；
   - `no_window_kwargs()` 仍被调用（Windows 侧不弹黑窗）。
   
   测试里模拟 Windows 请用 `unittest.mock.patch` 改 `os.name` / `shutil.which`，
   不要要求 CI 真装 Git Bash。

## 红线

- 不改 `hive.py` 的 verify 调度主流程；`should_wrap()` / `rewrite()` / `run` 的
  对外契约保持兼容（新增能力，不破坏既有调用）。
- **不许放宽判据**：不许把任何命令无条件映射成 `true`；不许对未知写法返回 0；
  不许吞掉子进程的退出码或用「跑不起来就算过」兜底。
- 不改任何任务卡的 verify 文本，不改 `agents/` 配置；不写 token / 密钥 / IP。
- 不动 T-0291 交付的 `tests/check_full_baseline.py`、`tests/baseline_allowlist.txt`、
  `tests/run_pytest.sh`（那三个文件是另一张卡的产物，本卡只把它们当被执行的样例）。
- 不引第三方依赖。

## 验收

在 **Windows agent** 上真跑（这是本卡要修的环境）：

```sh
python hive_compat.py run "bash tests/run_pytest.sh tests/test_run_stdin.py"   # 期望 rc=0
python hive_compat.py run "python3 -V"                                        # 期望 rc=0
python -m pytest -q tests/test_compat.py                                      # 期望 rc=0
```

三条全 `rc=0`。另外在 POSIX 验收机上同样跑一遍，确认 `should_wrap()` 仍为
`False`（不改写命令）、直接入口仍能执行 `bash ...`，没有回归。

`.hive/summary.md` 写清：探测到的 bash 绝对路径、两类命令的实测 rc、
「找不到解释器」的反证结果、原有惯用法回归条数。

## 影响面

T-0291（本次触发）、T-0261、T-0237 都因这个签名假红过；修完之后，卡面写
`bash ...` / `python3 ...` 的卡在 Windows agent 上不再需要主控人工改判。
