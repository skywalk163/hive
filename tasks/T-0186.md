## 背景

派发流水线的终局是「agent 自己定时来领任务」，不靠人在 chat 里说话。前提是 Hive 侧能回答
一个问题：**这张卡适不适合这个 agent**。现在 `dispatch` 是从「总控视角」往下派，
判定逻辑埋在 `Hive.cmd_dispatch` 里，agent 主动来领时拿不到同样的判定。

本卡把判定抽成**只读纯函数模块**，作为后续 `hive_list_pending --for-agent <id>`
与 MCP 工具 `hive_list_pending` 的唯一真源（接线在 T-0188）。**本卡不碰 `hive.py`**。

## 要做什么

新建 `pending_matcher.py`（纯标准库；可 import `conflict`，但不 import `hive.py`，无副作用），提供：

```python
def path_overlap(x: str, y: str) -> bool
def paths_conflict(a: dict, b: dict) -> bool
def explain_match(card: dict, agent: dict, *, cards: dict[str, dict] | None = None) -> dict
def match_tasks_for_agent(cards: dict[str, dict], agent: dict, *,
                          limit: int | None = None) -> list[dict]
```

### 1. 判定规则（顺序即优先级，与 `Hive.cmd_dispatch` 语义一致）

`explain_match` 返回 `{"matched": bool, "reasons": [<人话>], "score": int}`，逐条规则累积：

1. `state == "ready"` 且 `owner` 为空 —— 否则 `matched=False`；
2. `repo` 在 `agent["repos"]` 的键里 —— 不在则 False；
3. `agent.abillities/capabilities` 的并集覆盖 `card["needs"]` 全部标签 —— 缺一即 False
   （`agent` 里 `abilities` 与 `capabilities` 两个键都读，缺失按空列表）；
4. `agent` 是 verify 模式（`mode == "verify"` 或 `manual==False and mode=="verify"`）
   且 `card["paths"]` 非空 → False（验收 agent 不改代码）；
5. 依赖未完成（`depends_on` 里有卡 state 不是 `done`）→ False，reasons 里点名；
6. 与「in-flight 卡」（owner 有值或 state 在 assigned/claimed/running）`paths` 冲突 → 冲突的卡名进 reasons，
   **不判 False**，只扣分（打分见下）——因为审批权在 claim 时的租约，不在匹配阶段。

打分（用于 `match_tasks_for_agent` 排序，分值固定可测）：

- 基础 100；
- `priority`：`P1` +30 / `P2` +20 / `P3` +10；
- `needs` 与 agent 能力完全命中且 needs 非空 → +5（体现「专门对口」）；
- 每一条 in-flight 冲突 −40；
- `paths` 非空且全部在 `agent` 的 `worktrees` 同仓 → 不加分（不引入路径预算猜测）。

### 2. `paths_conflict(a, b)` / `path_overlap`

- 复刻 `Hive._path_overlap` 的语义：去空白、去尾斜杠、空串等于「任何地方」、父子目录互相覆盖。
- **双方都声明了非空 `locks`** 时走 `conflict._locks_conflict`（精确集合）；
  否则回退 `paths` 规则；任一方 `paths` 为空按冲突处理（保守）。
- 必须与 `Hive._paths_conflict` 行为一致：在测试里用 `hive.py` 的静态来源作对照
  （直接 `import` 不建议——请用参数化用例把同样的输入喂给本模块，期望值手工钉死，
  并在注释里注明对应 `hive.py` 的哪条规则）。

### 3. `match_tasks_for_agent`

- 返回 `[{"task": <card>, "score": int, "reasons": [...]}]`，按 score 降序、同分按任务号升序；
- `limit` 截断；同一输入必须同序（确定性）；
- 不做任何写操作，不判断租约、不 claim。

## 不要做什么

- 不修改 `hive.py`、`mcp_server.py`、`conflict.py`、`dispatch_tracking.py`（并行卡在改，禁止碰）。
- 不 `import hive`（避免运行时循环依赖与 `sys.argv` 副作用）。
- 不实现 claim / 租约 / 网络；本模块只回答「适不适合」。
- 不引第三方依赖。

## 完成标准

- 新建 `tests/test_pending_matcher.py`，至少 12 个用例，覆盖：
  1. 正常命中（repo + needs + ready）；
  2. repo 未登记 → 不匹配；
  3. needs 缺一个能力标签 → 不匹配，reasons 点名该标签；
  4. verify 模式 agent + 带 paths 的卡 → 不匹配；paths 为空 → 匹配；
  5. 依赖未 done → 不匹配并点名前置卡；
  6. 与 in-flight 卡 paths 冲突 → 仍匹配但 score 减 40；
  7. `path_overlap` 父子目录 / 尾斜杠 / 空串四种边界；
  8. `paths_conflict` 双方都写 locks 时按精确集合判（`src/a.py` vs `src/b.py` 不冲突）；
  9. 打分：P1 高于 P2、P3 最低；
  10. 排序稳定 + limit 生效；
  11. cards 含 blocked/assigned/done 卡时不进结果；
  12. 同一输入两次调用结果完全相同。
- `python -m pytest -q tests/test_pending_matcher.py` 全绿。
- summary 里贴出对本仓 `tasks/` 全量卡 × `agents/trae-win.json` 的匹配结果（真实运行）。
