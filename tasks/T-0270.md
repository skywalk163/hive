### 2) 补 smoke.sh

**注意**：`tests/跑全部.sh` 已经覆盖了完整测试，smoke 的定位不同：

| | `tests/跑全部.sh` | `smoke.sh`（新建） |
|---|---|---|
| 用途 | 完整回归，8 组 | 最小可验证：3 秒内判断「这套东西还能不能跑」 |
| 何时跑 | 交付前 | 每次 clone 后 / 每次改完 |
| 依赖 | 真 git、真 HTTP、SQLite | 只要能起 `运行.py` |

建议内容（不超过 40 行）：

```bash
#!/usr/bin/env bash
# lighthive 冒烟：3 秒判断「光明编译器 + 本仓 stdlib + 最小链路」还在不在。
# 完整回归见 tests/跑全部.sh（慢，起真服务）。
set -uo pipefail
cd "$(dirname "$0")"

fail() { echo "SMOKE FAIL: $*" >&2; exit 1; }

# 1. 编译器可用
python3 运行.py --help >/dev/null 2>&1 || fail "运行.py 起不来"

# 2. 最小程序能编能跑（不碰 git、不碰网络）
tmp="$(mktemp -d)"; trap 'rm -rf "$tmp"' EXIT
cat > "$tmp/min.light" <<'LIGHT'
打印("lighthive-smoke-ok")
LIGHT
out="$(python3 运行.py "$tmp/min.light" 2>&1)" || fail "最小程序跑不起来：$out"
echo "$out" | grep -q "lighthive-smoke-ok" || fail "输出不符：$out"

# 3. 单测（纯函数，秒级）
python3 运行.py tests/单测.light >/dev/null 2>&1 || fail "单测不过"

echo "SMOKE OK"
```

⚠️ **先读 `tests/跑全部.sh` 和 `tests/单测.light` 的实际调用方式**，别照抄我写的参数。
`运行.py` 的实际用法以其 docstring 为准（我看到的是 `python 运行.py src/主程序.light [参数...]`）。

### 3) 补 CI

最小 workflow，`.github/workflows/ci.yml`：

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

jobs:
  smoke:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      # lighthive 依赖同级目录的 light 仓（编译器本体）
      - name: 检出 light 编译器
        run: |
          git clone --depth 1 https://gitcode.com/skywalk163/light.git ../light \
            || git clone --depth 1 https://github.com/skywalk163/light.git ../light

      - name: 冒烟
        run: bash smoke.sh

      - name: 单测
        run: python3 运行.py tests/单测.light
```

**不要**在 CI 里跑 `tests/跑全部.sh` —— 它起真 HTTP 服务和集群，在 runner 上容易 flaky
（`跑全部.sh` 自己的注释都提到「退出码 137」的坑）。完整回归留给人跑。
