# A1：让 `light install` 的默认 registry 源真能取到包

> 承接 T-0262 的失败结论（该卡已 `shelved`，**不是「修好了」**）。
> 与 T-0262 最关键的区别：**T-0262 禁止 land，本卡允许、且必须先把
> `registry/registry.json` 合进 `main`** —— 文件只落在 task 分支时，任何 raw URL 都取不到。

## 一、现状（T-0262 实测，别重复踩）

- `src/lightpkg.py` 的 `REGISTRY_REGION_URLS` 两个默认值都是死的：
  - `domestic = https://gitcode.com/light-lang/registry/raw/main/registry.json` → 项目不存在 / 403；
    实测同域**任意不存在的路径也返回 `200 + <!DOCTYPE html>` SPA 页**，所以那个 200 是假绿，
    没有判别力，`json.loads` 必失败。
  - `foreign = https://github.com/skywalk163/light/raw/main/registry/registry.json` → 404。
    `github.com/<owner>/<repo>/raw/...` 不是 raw 文件地址（GitHub 的 raw 域名是
    `raw.githubusercontent.com`），这个 URL 本身就是写错的。
- 仓库里没有 `registry/` 目录，`_load_registry()` 只能静默降级到内置 20 包表。
- T-0262 实际只做了 B（错误诊断可读性）+ C（URL 字典单一真源），**默认源可达性没修**，
  而且它的代码提交没推到协调仓。那部分改动若要保留，请单独 review，不要混进本卡。

## 二、目标

`light install <包名>` 走默认路径时，能从一个**真实返回合法 JSON** 的 URL 拉到官方包表；
不再靠内置表静默兜底；拉不到时明确报错，而不是「HTTP 200 就当成功」。

## 三、要做的事

1. 在 `light` 仓新建 `registry/registry.json`：从现有内置表导出，结构至少含
   `"packages": [...]` 且非空，字段与 `_load_registry()` 的解析口径一致。
2. **先 land 再验 URL**：把该文件合进 `main`（本卡允许 land），确认所选 raw 地址真能取到。
3. 改 `src/lightpkg.py` 的 `REGISTRY_REGION_URLS` 两个默认值到实测可用地址，
   保留 `DEFAULT_REGISTRY_REGION` 的切换语义。地址自己实测选定，**不要照抄上面两条死链**；
   至少做一次反向对照：同域一个确定不存在的路径必须返回非 200 或非 JSON，
   以证明「200」在你选的域名上确实有判别力。
4. 同步 `tests/unit/test_R137_install_publish.py` 里 `test_11` 硬编码的两条旧 URL 断言：
   **改断言的期望值，不删断言、不放宽判据**。
5. `docs/包管理器使用指南.md` 更新默认源说明，以及「HTTP 200 ≠ 可达」的判别力边界。

## 四、验收判据与红线

- **最终判据由主控在 land 后复跑**（故意不进卡面 verify）：
  ```bash
  python -c "import json,urllib.request; u='<你选定的默认URL>'; r=urllib.request.urlopen(u,timeout=10); d=json.load(r); assert isinstance(d.get('packages'),list) and d['packages']; print('default-source-ok')"
  ```
  必须同时满足：HTTP 200、`json.load` 成功、`packages` 非空、响应体不是 HTML。
  T-0275 六仓总验收也会复跑这一条。
- 卡面三条 verify **全是离线标准库命令**，不依赖 `bash` / `pytest` / 出网。
  这是 11-08 三张异常卡（T-0261 / T-0262 / T-0267）的共同教训：
  verify 必须能在**接单那台机器**上真跑起来，否则一律交 `failed` 假红。
- 不许把 `except Exception: pass` 加回来；不许用改宽断言造绿灯；
  不许把 `registry/registry.json` 只留在 task 分支；不许把「改了错误提示」当成本卡完成。
