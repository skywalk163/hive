# 阶段 0：零模型确定性系统 + 决策 / 验证日志采集

> 依据：v2 整合稿 §三 / §四 / §八。本卡是整条路线的**数据生产环节**，
> 不训练任何模型、不涉及 OpenI / V100。

## 背景

方案一 §4.3 原本就规定：决策 token 的监督信号从 `light ai check` 验证日志、
lightharness 工具调用记录、实际编辑序列**自动导出**，不需要人工标注。
但这条一直没做，导致 `train_openi.py` 只能在 363 条空标签 SFT 上打转：
本机实跑 `--self-check` 得到决策密度 **0.083–0.096%**（方案要求 1–2%）、
决策点 test 覆盖 **1/7**、`err_tasks` 只有 **8 条**。
**缺的是监督信号，不是 GPU 或超参。**

先把不依赖模型的系统跑通，让它运行时自己产出这些日志。

## 要做的事

### 1. `src/lightprism/runtime/` 新模块（纯标准库 + light CLI）

```
任务文本 → 意图归一 / 检索（BM25 或关键词规则）
        → 选模板 / 积木（light ai snippets 占位符模板、lighting 积木、stdlib 模块）
        → 填槽 → 确定性展开成 .light 源码
        → light ai check --json
        → 真跑，比对预期输出
        → 不过则换候选 / 带诊断反馈重试 1–2 次
```

- 代码本体来自已验证模板，模型不参与生成。
- 允许零模型（纯规则检索）先跑通，报告里如实标注检索方式。

### 2. 决策 / 验证日志（本卡最重要的产出）

每次运行落一条到 `data/runtime/decisions.jsonl`，字段至少：
`task_id / template_id / decision_point / decision_option / validation_code / retry /
 checker_diagnostics / final_ok / elapsed_ms`。

- `<D:EDIT=FR/RW/PATCH>`、`<D:PLAN=...>`、`<D:RETRY=YES/NO>`、`<D:FIX=...>`
  从**实际发生的动作**映射，不许编造。
- `<V:...>` **一律取 `light ai check` 的真实返回**，不许模型自判、不许拿 `L0000`
  冒充具体错误类型（`reports/ERR样本覆盖.md` 实测 8 类里 7 类不可达，全回落 L0000）。
- 建议只保留可观测的 3 类：`PASS / RUNTIME / CHECKER_FAIL`。

### 3. 窄任务集与可执行判据

- `data/runtime/tasks.jsonl`：**20–30 个**窄任务（单函数 / 小 CLI / 文件处理 / 系统诊断），
  每条带**预期执行结果**。
- 判据是「`light check` 通过 **且真跑输出与预期一致**」，不是 checker exit 0、
  不是 loss、不是 JSON 精确匹配（`docs/Demo验收报告.md` §3.4：空文件也判 ok）。
- 按模板簇切分，全分母（截断 / 空输出按失败计入）。

### 4. 报告

`reports/零模型系统报告.md`：闭环可用率、每类任务条数、失败样例逐条贴、
决策日志条数与各决策点 / 验证码分布（有哪几类、各多少条、哪些没观测到）。

## 完成标准

- `python3 scripts/runtime_eval.py --tasks data/runtime/tasks.jsonl` 可跑，
  输出闭环可用率与失败明细
- `python3 -m pytest -q tests/test_runtime_system.py` 通过
- `data/runtime/decisions.jsonl` 非空，且每条 validation 可回溯到一次真实 checker 调用
- 报告含真实失败样例，不挑成功样例

## 禁止

- **不训练模型、不用别的模型批量生成样本**（T-0333 硬约束）
- 不编造决策日志；`<V>` 不许模型自判
- 不拿 L0000 冒充 SYNTAX / TYPE_MISMATCH 等具体码
- 不拿 checker exit 0 当分子、不剔除失败分母
- 不改 `docs/Demo开发计划.md`、不碰 `train_openi.py`、不上 OpenI / V100
