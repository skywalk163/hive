## 背景

`.gitattributes` 现有规则全部按**扩展名**匹配：`*.sh` / `*.go` / `*.md` / `*.yaml` …（都 `eol=lf`）。

但部署目录里有一批**没有扩展名**的文件，落在 `* text=auto` 兜底里：

| 文件 | 后果 |
|---|---|
| `deploy/logrotate.d/lightmem` | CRLF 会让 logrotate 解析失败（实测踩过） |
| `deploy/lightmem.service` / `deploy/lightmem-mcp.service` / `deploy/lightmem-watchdog.service` / `.timer` | CRLF 进 `/etc/systemd/system/`，systemd 里 `ExecStart` 行尾带 `\r` → 启动失败且报错很隐晦 |
| `deploy/cron.d/lightmem-watchdog` | 同 cron 解析问题 |
| `deploy/newsyslog.d/lightmem.conf` | FreeBSD 侧同类问题 |

现状实测（`git ls-files --eol`）：

```
i/lf  w/crlf  attr/text=auto   deploy/lightmem.service
i/lf  w/crlf  attr/text=auto   deploy/logrotate.d/lightmem
i/lf  w/lf    attr/text eol=lf deploy/platform.sh      ← 有 *.sh 规则，是对的
i/lf  w/lf    attr/text eol=lf scripts/lm-env-compact.sh
```

**索引里是 LF（没问题），但工作区检出成了 CRLF** —— 也就是说任何在 Windows 上
`git add` 这些文件的人，只要没注意就会把 CRLF 提上去。

另外 T-0417 发现 `deploy/logrotate.d/lightmem` **结尾还少一个换行**（末字节 `0x7d` 而不是 `0x0a`）。

## 目标

1) `.gitattributes` 增加**路径级**规则（放在现有 `* text=auto` 之后、binary 段之前），
   覆盖 `deploy/` 下所有无扩展名的部署文件，至少：
   `deploy/logrotate.d/*`、`deploy/newsyslog.d/*`、`deploy/cron.d/*`、
   `deploy/lightmem.service`、`deploy/lightmem-mcp.service`、
   `deploy/lightmem-watchdog.service`、`deploy/lightmem-watchdog.timer`。
   用 `text eol=lf`（不是 `text=auto`）—— 要的是**强制**，不是「看文件内容猜」。
   顺手把同类无扩展名文件一并覆盖（先 `git ls-files deploy | grep -v '\.'` 列全，别漏）。
2) 修正 `deploy/logrotate.d/lightmem` 的**末尾换行**（`printf '\n' >>` 之类即可，内容一字不改）。
3) 用一次性归一化把这些文件的**索引内容**统一为 LF 且无 CRLF
   （`git add --renormalize .` 后会看到预期内的 diff；若 diff 超出 deploy/ 范围，**停下来报告**，不要顺手改别的）。
4) 加一条可复跑的检查，让「以后再有人提 CRLF」能立刻发现。二选一（在卡里说明选了哪个）：
   - 塞进现有 `scripts/ci-linux-smoke.sh` 的一节（注意那是 E 线文件，改动要最小）；
   - 或新增 `scripts/check-eol-lf.sh`（POSIX sh，零依赖），并在 `deploy/README.md` 提一句怎么跑。

## 红线

- **不要碰 `*.sh` 等已有扩展名规则**（它们已经是对的，动了反而引入回归）。
- 不要用 `git add --renormalize .` 之外的手段批量重写工作区（尤其别用编辑器保存，那会带入本地换行）。
- 不要动 `.dumate/`、历史报告等无关文件。
- 索引归一化如果造成**语义变化**（二进制文件、png/docx 等）必须立即回退 —— 那些已经标了 `binary`，不该受影响。

## 验收要点

- `git check-attr eol -- deploy/logrotate.d/lightmem deploy/lightmem.service` 输出均为 `eol: lf`（不再是 `unspecified`）。
- `git ls-files --eol` 里上述文件 **w/ 不再是 crlf**（贴改前改后对照）。
- `deploy/logrotate.d/lightmem` 末字节 = `0x0a`。
- EOL 检查脚本（或 smoke 的新增节）在**故意造一个 CRLF 文件**时必须报红，删掉后复绿（反跑记录写进 summary）。
- `git show --stat` 的改动范围只在 `.gitattributes`、`deploy/logrotate.d/lightmem`、以及检查脚本/README；
  若出现别的文件，说明 renormalize 波及过头，必须交代清楚。
