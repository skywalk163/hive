# 修 `submit` 零改动误判：改动被 agent 自己提交后就「消失」了

> 来自 2026-11-08 收 T-0267 时实测。**先更正一个说法**：这不是
> 「`git rm --cached` 的 staged-only 删除不认」——`git status --porcelain -uall`
> 是认 `D ` 的。真正的原因在下面第二节，请按代码实证来做，别照着旧描述修。

## 一、现象

T-0267 第二轮（doubao-win，11:19）交 `failed`：

```
error = 零改动：结果没有任何 changed_files，判 failed；
        若为纯调查/台账类卡请在任务卡声明 allow_empty_diff: true
changed_files = []
verify = 3 条全 code=0（index-clean / readme-clean / sample-ok）
```

但成果齐全，实证：

```bash
git diff --name-only 3572848...origin/task/T-0267
# .gitignore / README.md / dashboard/live-status.json /
# dashboard/live-status.json.bak.20261028 / ... / status.json  （7 个）
```

最后靠主控手工 `cherry-pick` 两个提交才收口。任何 **manual / GUI agent 自己 commit 过**
的卡都会踩这个雷。

## 二、根因（对着代码看）

- `changed_files(wt)`（`hive.py:1530`）用的是
  `git status --porcelain -uall`，即**相对 HEAD 的未提交改动**。
- 产结果前有两处取它：`cmd_submit` 约 `:3571`、worker 约 `:5477`，结果直接写进
  `results/<tid>.json` 的 `changed_files`，并交给 `result_gate()`（`:1398`）判零改动。
- 而 worker 的手动模式收工判据（`hive.py:5449`）**明确把「HEAD 变了 —— agent 自己
  commit 过」当作完成信号**。两处语义打架：agent 一 commit，worktree 就干净，
  `changed_files` 返回 `[]`，闸门随之判 failed。
- 连带影响：`out_of_paths()` 同样只看未提交改动，**agent 自己提交的越界文件会漏检**。

仓库里已有正确口径：`result_diff_files(repo, base, head)`（`:1414`）用
`git diff --name-only base...head`（三点取 merge-base），land 侧的
`guard_land_self_consistency()` 已经在用它核对 `changed_files` 数量级。

## 三、修法方向（自己判断，写清取舍）

1. **不要直接改 `changed_files()` 的语义**：它还要服务 `stage_paths()` 与越界检查
   （只该 stage 未提交的东西）。新增一个「交付文件」口径，例如
   `git diff --name-only <base>...HEAD` 与 `git status --porcelain` 的**并集去重**，
   产结果时用它填 `changed_files` 并喂给零改动闸门。
2. `base` 从卡面 `base: main` 取；worktree 常是 detached、本地未必有 `main` 分支，
   要能回落 `origin/main` / merge-base。**取不到 base 时退回旧口径**，宁可保守也别把
   正常卡全判死或全放行。
3. 越界检查要不要一并覆盖「已提交文件」，自己权衡；改了就配回归用例，并在 summary
   里说明为什么。
4. 两条保护**不许改坏**（T-0205）：head 未推送 / 与远端不一致仍判 failed；
   `allow_empty_diff: true`、`paths` 为空的验收卡仍自动放行。

## 四、回归测试（新建 `tests/test_changed_files_committed.py`）

至少 4 例，用 `tests/test_result_head_guard.py` 的 `World` 夹具风格：

1. **复现本 bug**：agent 在 worktree 自己 commit 一个文件 → 结果 `changed_files`
   含该文件、`status=done`（修前应为 failed）。
2. 一个文件都没改 → 仍判 failed（零改动保护不能丢）。
3. 已提交 + 未提交混合 → 并集正确、无重复项。
4. `allow_empty_diff: true` 的验收卡仍放行。

同时**必须**跑通既有 `tests/test_result_head_guard.py` 与
`tests/test_submit_summary.py`（`guard_land_self_consistency` 的 head 一致性校验别动）。

## 五、verify 与红线

- 卡面 verify 用标准库包装 pytest（`sys.executable -m pytest`，自带
  `stdin=DEVNULL`），**不依赖 bash / grep / 外网**：11-08 那批异常卡全是 verify 与
  接单平台不匹配造成的假红。若接单机器没装 pytest，直接交还说明环境不满足，
  **不要改宽 verify、不要删测试**。
- 不许删 `result_gate`、不许放宽「零改动」、不许改坏 land 的 head 校验；
  不许把 `changed_files` 直接写成常量或「有 summary 就算有改动」来造绿灯。
- summary 里写清：改了哪几处、`base` 回落策略、越界检查是否一并调整、四条回归
  的实测输出、两个既有测试文件的通过数。
