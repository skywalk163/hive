## 背景

四层方案里这一期落地的是 L1（一键复制）、L2（dispatched 标记）、L3（自动粘贴脚本）、
L4 的 Hive 侧（agent 自领匹配）。代码级测试各自有卡，缺的是**串起来跑一遍**：
从看板复制一条指令，到 chat 里粘贴执行，到状态回落。

本卡只验收，**不改代码**（`paths` 必须为空，否则 dispatch 会跳过本卡）。

## 要做什么

在 Windows 实机上按顺序跑下面五步，把每一步的真实输出贴进 `.hive/summary.md`：

1. **L1 CLI**：`python hive.py --dir <hive> prompt T-0190` → 五段齐全、任务号与契约正确、中文不乱码；
   `--format json` 的输出能被 `python -m json.tool` 解析。
2. **L1 看板**：`python dashboard/serve.py --status dashboard/sample-status.json --port 8787` 起服务，
   浏览器打开，点某张卡的「复制派发指令」，把剪贴板内容贴进 summary 前 5 行；
   再确认表头有 `待分配 / 已推送 / 在跑` 摘要。
3. **L2 状态**：在**临时克隆**里跑 `dispatch-mark`（别污染主干）→ `status` 显示该卡 stage=dispatched、
   `dispatched_to` 正确；`dispatch` dry-run 不再把该卡列进候选（TTL 内）。
4. **L3 脚本**：`powershell -File windows/dispatch-agent.ps1 -Task T-0190`（dry-run）→ 打印目标窗口与正文前 5 行，
   **不发送任何按键**；再说明配置表里各 agent 的窗口标题片段是否与真机一致（不一致就只记录，不改卡）。
5. **L4 匹配**：`python -c "import json,pending_matcher; ..."`（或 `hive status --json` + MCP
   `hive_list_pending` 的实际调用）对 `agents/trae-win.json` 做一次匹配，贴出返回的任务号与 score。

## 不要做什么

- 不改任何代码、不改任何任务卡、不改 `agents/*.json`（发现问题写 summary，另开卡）。
- 不在主干仓库里跑 `dispatch-mark` / `take`（用 `/tmp` 或 `$env:TEMP` 下的克隆）。
- 不为了「让验收过」放宽 verify 命令。

## 完成标准

- 三条 `verify` 全绿（pytest 两组 + doctor）。
- summary 里五步各有可核对的真实输出（命令 + 关键行），缺一步视为未完成。
- 明确写一句结论：**这一期的派发链路上，哪一环还需要人、哪一环已经不需要人了。**
