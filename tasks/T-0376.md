# 0.88 排队跑测工具与基线入库（R222 前置）

> **所有 R222 卡都依赖这张**：它把「统一到 192.168.0.88（FreeBSD 15.1，12 vCPU）跑、并且排队」
> 变成仓内的可用工具，后面每张卡才有一条可复现的验收路径。
> 总纲：`docs/R222_语言×AI适配总纲.md`（hive 仓）。

## 背景

各 agent 的机器不一样（Windows 老机 / 云沙箱 / FreeBSD），同一份改动在不同机器上「红绿」不可比。
实测：0.88 上 light 仓全量 **28m57s / 18 failed**，本机 Windows 90s 且失败面不同 —— 同一份代码，
两台机器结论不同，这种「不可比」比慢更贵。

并发跑又会互抢 12 核。工具已在本机实测通过（3 组并发验证过排队、槽位自动释放），本卡把它固化进仓。

## 要做什么

1. 拷入 `tools/remote_ci.py`（同源副本 `G:/dswork/duan-light-merge/_tools/remote_ci.py`，
   两边内容必须一致）。工具自带：tar 快照（`*.sh` 包内转 LF、POSIX 分隔符）、
   远端 `mkdir` 原子抢槽、陈旧锁 4h 回收、`--list` 台账、`--jobs` 走 xdist。
2. 拷入三份文档并按本仓路径改写：
   - `tools/README_remote_ci.md`（用法/纪律/排障/前置条件）
   - `tools/baseline_0_88_light_merge.md`（18 条基线 + 耗时特征）
   - `docs/测试分级与远程跑测.md`（闸门：本地窄测 → 0.88 排队全量）
3. 工具里不得写死凭据路径：按候选顺序找 `.env`（`--env-file` / `LP_ENV_FILE` 可覆盖）。

## 不要做什么

- 不要把 `.env`、口令、token 写进仓。
- 不动 `src/`、`cli/`、`stdlib/`、`tests/`。
- 不给工具加第三方依赖（paramiko 只在跑远端时才 import，缺了要给清晰提示而不是崩）。

## 完成标准（verify 必绿）
