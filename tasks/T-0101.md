## 背景

分配现在是「needs + 负载」的粗粒度匹配：agent 能干什么、能碰哪些仓没有登记，
`agents/*.json` 里只有 `repos` 指向 light。本轮把分配规则收口，让它真的能用。

## 目标

1. `agents/*.json` 增加 `abilities: [code, ci, docs, verify, ...]`，`repos` 保留为白名单；
2. `hive dispatch --dry-run` 输出「派/不派」原因（能力缺失 / 仓不匹配 / 负载 / 依赖未就绪 / 人工优先）；
3. **同仓并发检测**：同一 repo 同一时刻最多 N 张 assigned+running（默认 1，可配），避免两个 worker 在同一个仓上互相踩 commit/push；
4. 现阶段所有卡 `repo: hive` 之外的，`dispatch` 拒绝并提示「非 hive 仓任务暂不派发」；
5. 全部落到测试：`test_dispatch_ability` / `test_dispatch_concurrency` / `test_dispatch_non_hive_rejected`。

## 红线

- 不改 light 等其它仓；不改 fb5 runner；不引入新依赖。
- 保持 `hive dispatch` 向后兼容：`--dry-run` 加字段可以，默认行为别改。

## 验收

`git show --stat HEAD` 覆盖 agents/ + hive.py + tests/；verify 全过。
