# lightharness MCP 配置发现与预设挂载断链整改

## 背景（来自 2026-11-25 只读诊断，完整证据）
`mcp.json` 配了 hive/lightmem 两个 HTTP MCP server；`mcp接线.light` 的挂载代码本身是好的（实测直接调用：2 服务器 / 31 工具 / 0 失败，格式归一化 `transport:"http"` → `类型=http` 也正确）。但生产路径三层断链，导致代理工具列表里没有 `hive_claim`/`hive_submit`：
1. **配置发现靠 cwd**：`取MCP配置路径()` 未设 `HARNESS_MCP_CONFIG` 时用相对路径 `mcp.json`；Web 进程 cwd 下找不到 → `文件不存在 → 静默 no-op`，无日志。实测 `组装注册表("","")` 在隔离 cwd 下 `MCP_TOOLS=0`；显式设 `HARNESS_MCP_CONFIG=<abs>` 后 `MCP_TOOLS=31`。
2. **预设过滤砍光**：`组装注册表(预设标识,...)` 在挂载 MCP 后调 `预设保留工具`；实测 `组装注册表("standard","")` 只剩 `bash,读文件,写文件,搜索文件` 4 个，31 个 MCP 工具全被注销。Web 服务端 `取注册表()` 对已知预设都会传预设标识，standard 会话必中。
3. **设计遗留**：`总入口.light:179` 注释写明"lightplugin / MCP 工具：当前四预设无对应叶子，暂不挂载（G5 后按模式新增）"——预设挂载集从没给 MCP 留入口。

## 要做什么
- 配置路径：不再依赖进程 cwd。默认用仓库/数据根下的绝对 `mcp.json` 路径（如由 `Web服务端.根` 或环境变量 `HARNESS_MCP_CONFIG` 显式给出）；找不到时在日志里明确打印"未找到 MCP 配置: <路径>"而不是静默。
- 预设过滤：给 MCP 工具（`mcp__*`）在预设挂载集中增加叶子/通配规则，使 standard/ptc/cordis 等预设保留 MCP 工具；或提供会话级开关（默认开），并保证 `hive_claim`/`hive_submit` 在 standard 下可见。
- 兼容性：无 MCP 配置、配置坏、单 server 失败时保持现有"不拖垮启动"的容错语义。
- 接线位置：`src/mcp接线.light`、`src/总入口.light`、`src/预设挂载过滤.light`（及必要的预设定义文件）、`src/web服务器.light`。

## 验收
- 新增 `tests/test_T0468_MCP挂载.py`：
  - 临时目录写 mcp.json（stdio echo server 用已有 test fixture 或内联 python 脚本），设 `HARNESS_MCP_CONFIG` 指向它，`组装注册表("standard","")` 后 `名单()` 含 `mcp__*`（至少 1 个）。
  - 不设环境变量但配置放在数据根时也能发现（具体发现规则由实现定，测试跟随）。
  - 配置缺失时日志含明确提示（断言 stdout 或返回结构）。
  - standard 预设下 MCP 工具不被 `预设保留工具` 注销。
- `python -m pytest -q tests/test_T0468_MCP挂载.py` 全绿。

## 不做什么
- 不改 MCP 客户端的 JSON-RPC/stdio 实现细节，只修发现与过滤链路。
