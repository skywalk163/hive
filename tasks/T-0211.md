## 症状

**静默产生错误结果**（本账最危险的一类）。把 ISO-8601 时间戳交给 `解析时间`：

```
解析时间("2026-10-30T15:00:00")                        ⇒ 空      ← 什么都不报
解析时间("2026-10-30 15:00:00")                        ⇒ 正常 struct_time
解析时间("2026-10-30T15:00:00", "%Y-%m-%dT%H:%M:%S")   ⇒ 正常
```

签名：`stdlib/时间管理.py:418 def 解析时间(时间字符串, 格式="%Y-%m-%d %H:%M:%S")`。

## 根因

1. 默认格式用**空格**分隔日期与时间，不吃 ISO 的 `T`；
2. 失败路径 `return None` 而**不是抛异常**。

## 影响

lighthive 的租约 / 超时 / 耗时统计全部走 ISO：解析得到 `空`
→ `时间加减(空, 分钟=180)` 也得 `空` → 后续所有比较都在跟 `空` 比，
**没有任何一行报错**。排查时会去看网络、看锁、看并发，唯独想不到「时间是空的」。

## 期望

1. `解析时间` 默认能同时吃 `2026-10-30T15:00:00` 与 `2026-10-30 15:00:00`；
2. **解析失败必须抛可读异常**（写明「文本 / 期望格式 / 实际不匹配在哪」），
   不要返回 `空` —— 返回 `空` 是把「格式不对」伪装成「没有时间」；
3. 另给一个**显式试探版** `试解析时间(文本, 格式 = 空)`：失败返回 `空` 不抛，
   让「我允许这里失败」在调用点可见。

## 落点

- `stdlib/时间管理.py`：`解析时间` 的格式容错 + 失败抛异常 + 新增 `试解析时间`；
- `stdlib/时间管理.light`：同名门面同步（若存在）；
- `stdlib/builtins.py` 若在 `__all__` 与内置名清单里登记了时间族，一并登记 `试解析时间`。

## 验收

新增 `tests/unit/test_LH37_解析时间.py`（`light run` 真跑）：

1. `解析时间("2026-10-30T15:00:00")` 返回非空，且 `格式化时间` 能还原回同一时刻；
2. `解析时间("2026-10-30 15:00:00")` 行为不变（存量）；
3. `解析时间("不是时间")` **抛异常**（断言「抛」而不是「返回空」）；
4. `试解析时间("不是时间")` 返回 `空` 且**不抛**；
5. 「静默」反跑：`时间加减(解析时间("2026-10-30T15:00:00"), 分钟=180)` 结果非空
   （修前这条是 `空`，能证明卡有牙）。

## 边界

- 只动时间解析这一族。`时间戳` / `格式化时间` / `时间加减` / `时间差秒` 的现有行为不许变。
