# 会话级任务队列：运行中「排队」与「插话」两种语义（纯逻辑）

## 背景（先说一个真实存在的并发 bug，本卡顺便把它堵住）

现在 `/v1/chat/completions` 是**同步一轮、无队列、无忙判定**：

- 非流式：`src/web服务器.light:578-582` 直接 `跑一轮`，HTTP 协程阻塞到整轮跑完。
- 流式：`造流式响应`(662) 起 `线程(后台跑一轮, 载具)`(675)，队列是**每请求一个**
  （`663 设 队列 为 新建 实时队列()`），不是每会话一个。
- 没有任何 `session → 队列` 或 `session → 忙` 的映射。

于是两个并发请求带同一个 `session_id` 会：`取会话`(295-314) 命中内存缓存拿到**同一个**
`会话` 对象（306-307）→ 各自 `保存前序号 = 长(会话对象.汇集全部事件())`(499) →
两个 `跑一轮` 并发往同一 `己.事件表` 追加（`src/会话.light:86-93`，**无锁**）→
事件序号交错 → 各自 `增量保存`（`总入口.light:237-246`）把同一批事件写两次（JSONL 重复行）。

用户可见现象：回答串台、历史重复、侧边栏消息数虚高、压缩摘要基于错乱的事件序。

## 两种插话语义（照 DSH）

- **排队式**：任务跑着时发新 prompt，不打断当前轮，等当前轮结束再执行。
- **插话式**：立刻把新 prompt 插入当前会话任务（DSH 有「插话发送」按钮）。

## 要做什么

### 1) 新增 `src/会话队列.light`（本卡独占，段落前缀 `队`）

**必须线程安全**：`web服务器.light:675` 的 `后台跑一轮` 在独立 OS 线程里跑，
而 HTTP 侧在事件循环线程 —— 跨线程共享状态必须加锁。
`src/实时流.light:19 类 实时队列` 已经示范了「`从 线程 导入 互斥锁` + `尝试/最终` 解锁」的写法，照抄；
**不要**用 `双端队列.light`（无锁，且是复刻件）。

接口（段落名一律 `队` 前缀）：

- `队建闸门()` → `{}`，全局单例由调用方持有。
- `队尝试占用(闸门, 会话标识)` → 布尔（原子：锁内判忙 + 置忙）。
- `队释放占用(闸门, 会话标识)`。
- `队是否忙(闸门, 会话标识)` → 布尔。
- `队入队(闸门, 会话标识, 项)` → `{"ok": 真, "位置": N}`（位置用于前端显示「排队中 1/2」）。
- `队出队(闸门, 会话标识)` → 项 或 `空`（队列空时返 `空`，**不要抛错**）。
- `队排队深度(闸门, 会话标识)` → 整数。
- `队入插话(闸门, 会话标识, 文本)` / `队取插话(闸门, 会话标识)` → 插话通道**与待办通道分开存**
  （语义不同：待办是「等这轮完再跑新一轮」，插话是「塞进正在跑的这一轮的下一步之前」）。
- `队清理会话(闸门, 会话标识)` → 会话删除时清理，防内存泄漏。

**必须有的护栏**：
- 待办队列**长度上限**（默认 8），超限时 `队入队` 返回 `{"ok": 假, "理由": "队列已满"}`
  而不是无限涨（DSH 也没有无限队列）。
- 插话通道上限（默认 4）。
- 任何接口在 `会话标识` 为空串时**返回安全默认值**（不抛错），因为服务端允许无 session_id 的首轮。

### 2) 新增 `tests/test_T0405_会话队列.py`

- 忙碌互斥：同一会话连续两次 `队尝试占用` → 第二次假；释放后可再占；
- 排队 FIFO：入 3 项出 3 项，顺序正确；深度随之变化；
- 队列上限：入到上限后 `ok` 为假且理由正确；
- 插话与待办**互不串**：入插话不影响待办深度，反之亦然；
- 空会话标识：所有接口返回安全默认值、不抛错；
- `队清理会话` 后深度归零、不忙；
- **真并发判据（关键，必须写）**：起 8 个线程同时 `队尝试占用` 同一会话，
  断言**恰好 1 个成功**（这是锁是否真的存在的唯一硬证据，不能用顺序调用糊弄）；
- **反证**：把 `队尝试占用` 里的锁去掉，第 7 组必须红（贴输出）。

## 附注 A：「光明」写法禁令（照抄现状规避写法，成本最低）

- 段落一律块形式：**禁 `段落 X: 返回 …` 单行函数**（生成器缩进会累积）。
- 字典/列表字面量一律**单行**；嵌套字面量内不写 `\n`（用 `chr(10)`）；字面量不直接当实参先 `设` 变量。
- **单字变量名全禁**（`若 则 否 是 段 出 导 遍 对 跳 过 试 捕 抛 终 返 配 己 自 设 为 从 当 空 长 首 末 余 父 常 并 与 且 或 的 在 到 现 例 步 断 新 接 承 引 掷 跃 非 真`）。
- 标识符不得被关键字序列完全切分（`错误己` 会炸，`错误甲` 正常）；不用「为」字入标识符；
  避开含 `等待` 的标识符；成员名避开 `模/模型/模式/工具/事件/类型/原因/取/生成/新建` 等词根。
- 成员赋值一律 `设 己.X 为 …`（裸 `己.X 为 …` 会编成 `==`）。
- 缺键 `d[k]` 直接抛 `键错误` → 用 `字典获取(d, k, 缺省)` 或 `字典包含键` 守卫。
- `空` 是 `None` 不是 `""`，判空串写 `x != "" 且 x != 空`（照抄 `web服务器.light:452/522/527`）。
- `/` 是浮点除法，切片/下标前先 `整数()`。
- **段落名会与依赖模块内联后冲突**（`src/代理循环.light:10-12` 已记）：新模块段落统一加 2 字前缀
  （本批约定：`续`=目标续跑、`压`=压缩升级、`模`不许用→用 `式`、`队`=会话队列、`时`=会话细节）。
- 循环依赖用 `导入 模块` + `模块.段落()` 点号调用，不要 `从 X 导入 名`。
- 新模块名全仓唯一（`src/` 与 `stdlib/` 都要查）。
