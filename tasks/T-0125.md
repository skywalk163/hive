## 背景

多 agent 系统跑起来后，worker 会死、会卡、会被删。现在有两处缺口：

1. **`cmd_gc`（hive.py:1614）只删过期的 claim 分支，从不把卡的状态退回 `ready`**。
   于是出现「卡停在 assigned/running、但 claim 分支已被 gc/崩溃清掉」的孤儿卡——
   没人会再领它，还一直占着 in-flight 并发额度，dispatch 永远绕开那台机器。
2. **worker 领取后从不刷新租约**（`lease_until` 只在 `claim()` 时写一次，hive.py:1792）。
   所以光看 `lease_until` 过期，分不清「worker 死了」还是「任务跑得久但还活着」——
   看门狗若据此回收，会错杀健康的长任务。

结论：看门狗要分两半做——先给 worker 加上**租约心跳**（活着的 worker 自己续租），
再看门狗才能放心地把「租约过期 / 孤儿 / 僵尸」的卡自动回收回 `ready`。

## 目标

1. **worker 租约心跳**（改 `Worker.run_task`，约 hive.py:1884-1960）
   - 用一个 daemon 线程，在任务运行的整段时间内周期性刷新 `claims/<tid>.json` 的
     `lease_until`（间隔 `max(5, lease_minutes//3)` 分钟）。
   - 刷新即把新 payload 提交到 `claim/<tid>`，**父提交必须是当前 `origin/claim/<tid>`**
     （`commit_file_to_ref(..., parent=f"origin/claim/{tid}")`），否则非快进会被拒
     （hive.py:319-348 的 claim 原子性约定）。
   - **best-effort**：整段包在 try/except 里，刷新失败只 log，绝不打断任务本身。
   - claim 缺失或 agent 不是自己 → 直接 no-op。
   - 用 `with self.lease_heartbeat(tid):` 包住 verify / manual 等待循环 / exec 三条分支。

2. **`hive watchdog [--minutes M] [--apply] [--json]`**（新增 `cmd_watchdog`）
   - `fetch` 后枚举 `IN_FLIGHT_STATES`（`assigned`/`running`）的卡。
   - 逐张判定（先 `res=result_info(tid)`）：
     - 有 res → `land_lag`（只 warn：有人该去 land 了），**不回收**。
     - `claim = claim_info(tid)` 为 None：
       - `state==running` → `orphan_running`（**回收**：claim 在跑着却没了）。
       - `state==assigned` 且 `assigned_at` 早于 `now-M` 分钟 → `orphan_assigned`（**回收**）；
         否则算「刚分派还没来领」，跳过。
     - `claim` 存在：
       - `agent` 没在 `agents/` 登记 → `zombie`（**回收**）。
       - `lease_until < now - M*60` → `stale`（**回收**）。
       - 否则健康，跳过。
   - 回收动作 `_reenqueue_ready(tid, reason)`（复用 `cmd_retry` 的 re-enqueue 核心，
     hive.py:1582-1612，但退回 `ready` 并清空 `owner`）：
     删除 `claim/<tid>` 分支 → 删归档 `results/<tid>.json` → `state=ready`、`owner=None`、
     `retries+1` → 卡 body 追加 `**watchdog 回收（<iso>）**：<reason>，回到 ready` →
     `commit_and_push`。
   - **默认 dry-run**（`apply=False`）：只打印每张候选 + 原因 + 汇总数量，不改任何东西，
     返回数量。破坏性行为一律要 `--apply`（与 gc/land 约定一致）。`--json` 给结构化输出。

3. **`hive doctor` 增强**（hive.py:1006-1083 附近）
   - 对 in-flight 卡补三类告警：无 claim（孤儿）、claim 的 agent 未登记（僵尸）、
     in-flight 但有 res（land_lag）。保留已有的「租约已过期」warn。

4. **（小）MCP 总控视角补 `hive_watchdog`**（mcp_server.py，复用 `hive_gc` 的接法，
   T-0123 的 controller 工具集），让总控 agent 也能触发看门狗。

## 红线

- **绝不回收有 res 的卡**——那是 land 的活，看门狗只 warn。
- **绝不误杀健康 worker**：靠心跳保证「活着的 worker 租约不过期」，看门狗只在
  claim 缺失 / agent 未登记 / 租约过期 三种明确死亡信号下回收。
- 回收必须**幂等且不丢历史**：追加 body 备注，不覆盖；重复跑 dry-run 无副作用。
- 默认 dry-run，破坏性只在 `--apply` 下发生。
- 只动 hive 仓（hive.py / mcp_server.py / tests / docs / CHANGELOG），不碰 light/lightharness。
