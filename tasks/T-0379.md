# C 线：AST 序列化 / 符号表 / 局部补丁引擎

> 总纲：`docs/R222_语言×AI适配总纲.md`（hive 仓）。

## 背景

Agent 改代码时最怕两件事：**读不出结构**（只能正则猜）和**只能整文件重写**（一改就带出无关 diff）。
`light ast` 现在只打印给人看的树，没有 `--json`；也没有「按节点路径替换一小块」的能力。
本卡把这三件事做成纯模块（不接 CLI），CLI 接线由 T-0382 统一做。

## 要做什么

1. 新建 `src/patch_engine.py`，提供三组纯函数（**不 import `cli`**，可被任何入口调用）：
   - `ast_to_json(source, file_label=None) -> dict`：节点树转 JSON（含 `kind`/`span`（行列）/`children`/`value`）；
     用仓里现有的 AST 构建路径（`cli/light.py` 里 `_ast_src` 同一后端），别自己写解析。
   - `symbols_json(source, file_label=None) -> dict`：导出面（定义的名字、导入、作用域、被引用次数）。
     命名口径要与 D 线 `--canonical` 一致（同语义一个名字）。
   - `patch(source, edits) -> str`：`edits` 是 `[{span:{start_line,start_col,end_line,end_col}, text}]` 列表，
     返回新源码；**必须拒绝**不交叠检查失败、越界、span 不闭合的编辑（抛 `PatchError`，附中文原因）。
   - `diff_summary(old, new) -> dict`：改了哪些行、涉及哪些符号，给 Agent 自检用。
2. `tests/test_patch_engine.py`：
   - `ast_to_json` 输出可 `json.dumps`、span 有序、叶子节点数 > 0；
   - `patch` 做单点替换、多点不交叠替换、拒绝交叠、拒绝越界；
   - `symbols_json` 对 `benchmarks/programs/` 下任一真实 `.light` 文件可用。

## 不要做什么

- 不要碰 `cli/light.py`（唯一 owner 是 T-0382）。
- 不要碰 `src/parser_*.py`、`src/linter/`、`stdlib/`。
- 不要实现「按自然语言改代码」——只做 span 级确定性替换。
- 不要引入新依赖。
