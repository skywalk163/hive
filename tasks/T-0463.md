# 语料导出器：stdlib + spec →（中文需求, 光明代码）配对数据

## 背景

新语言"AI 不会写"的根本原因是**训练分布里没有它**。这件事不能靠文档解决，只能靠数据。
现在仓里已经有最好的原料，但没被组织成训练格式：

- `stdlib/` 119 个 `.light` 模块，带「导出」清单与实现
- `spec/light.spec.json` 有 keywords / stdlib 签名（含 arity）
- `docs/AI编程指南.md` §五 有 6 个可复制的编程模式
- `examples/`、`demos/`、`tests/` 里有大量真实可跑片段

目标是产出**可直接发布**的配对语料：`(中文需求 → 光明代码)`，供 few-shot、RAG、continued pretraining、LoRA 四种用法。

## 要做什么

1. `tools/gen_ai_corpus.py`（纯标准库，CLI 可跑）：

   ```
   python tools/gen_ai_corpus.py --out build/corpus/ --min 500
   ```

   产出 `build/corpus/light_sft.jsonl`，每行：

   ```json
   {"id":"L-0001","prompt":"读取 data.txt 的第一行并打印","code":"从 文件 导入 读取文件\n...","level":"L1","source":"stdlib/文件.light","sha256":"..."}
   ```

2. **需求侧必须是人话，不许直接暴露函数名**：
   - 从 stdlib 的导出函数 + 参数名 + 模块中文名生成动词短语，再套 8–12 个句式模板（"把 X 写成 Y" / "读 X 的第 N 行" / "把列表按 X 排序后打印前 3 项"…）
   - 断言：`prompt` 里**不得出现** `code` 中出现的光明关键字或 ASCII 函数名（这是防"需求泄题"的关键测试）
3. **代码侧必须可验证**：抽样的条目要能被 `light check` 通过；抽不到的（依赖网络/文件系统的）标 `runnable:false` 并不进抽样池。
4. **确定性**：同一份输入跑两次，输出文件 **sha256 逐字节相同**；同时产出 `manifest.json`（条数、按 level/source 分布、生成器版本）。
5. `--stats` 打印分布表（四类 level × 五类 source），供发榜引用。

## 不要做什么

- 不把产物提交进仓（`build/` 已在忽略列表；只提交生成器与测试）
- 不联网抓数据、不调用任何模型 API
- 不生成"光明写光明的编译器"这类超长片段（>60 行的样本一律跳过）
- 不改 `stdlib/`、`spec/`、`docs/AI编程指南.md`

## 完成标准

- `tests/test_T0463_corpus.py`：
  - 跑两次，两次 `light_sft.jsonl` 的 sha256 相同
  - 条数 ≥500（`--min 500` 下）
  - 每条字段齐全且 `prompt` 不含 `code` 里的关键字/ASCII 标识符（抽样 50 条）
  - 抽样 5 条 `runnable:true` 的代码写入临时文件，`light check` 返回 0（本机无 `light` 命令时 `pytest.skip`，不许写成假绿）
  - `manifest.json` 能被 JSON 解析且分布总和等于条数
- verify：`python -m pytest -q tests/test_T0463_corpus.py`
