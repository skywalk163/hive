## 背景

T-0435 复核（`dswork/T-0435-复核报告-2026-11-22.md`）发现两处「显示态仍未收口」，

## 问题 1：租约覆盖漏了终态/交接态（T-0435 §3.1）

`hive.py` 的 `Hive.display_state()`：

```python
if claim and not res and state not in ("done", "blocked", SHELVED_STATE):
    state = "running"
```

白名单是旧 `cmd_status` 原样搬来的，只有 done/blocked/shelved。
后果：卡面是 `closed` / `conflict` / `needs_review`、有未过期租约、还没有结果时，
显示态被改写成 `running`。

- 对 `status` 是老行为；对 `task list` 是 T-0435 引入的新回归（原本显示卡面）；
- 与 `display_state` 自己的 docstring「搁置/挂起/冲突/待审 → 原样」直接矛盾；
- 可达路径：`cmd_close` 删 claim 分支失败只记日志继续；`_set_state()`
  （block/conflict/needs_review）根本不释放 claim。

修法：白名单改用同一份常量 `_DELIVERY_KEEP_STATES`。

## 问题 2：MCP 还有第四套推导（T-0435 §3.6）

`mcp_server.py` 的 `HiveMcp._rows()`：

```python
state = c.get("state")
if claim and not res and state != "done":
    state = "running"
```

比旧 status 还宽：连 `shelved` / `blocked` 都会被翻成 running；已 submit 的卡在
MCP 里仍显示 `assigned`。修法：改用 `Hive.display_state(c, claim, res)`，与 CLI 同源。

## 判据（可反跑）

1. 卡面 `closed`/`conflict`/`needs_review` + 未过期 claim + 无结果 → `task list` 与
   `status` 都必须显示卡面态，不能是 `running`；删掉 claim 后结果不变。
2. `HiveMcp._rows()` 对「assigned + done 结果」返回 `submitted`，对 failed 返回
   `failed`，对 shelved + claim 返回 `shelved`（不再 running）。
3. 回归：`delivery_state_table` / `card_state_wins` / `live_lease_without_result_still_running`
   全绿（后者要求 ready + 租约仍显示 running）。
4. 文档 §4.6 表格补 `needs_review`，并把「有租约无结果 → running」限定为
   ready/assigned/running 三态；MCP 那句「仍按卡面报 state」改成「已与 CLI 同源」。
