> 第一次接 hive？先读 `docs/AGENT快速上手.md`。
> 本卡修 **hive 自身的集群无法启动**，症状是「进程在跑」但其实是别人的进程，极具误导性。

## 背景：一个被复用的 PID 让整个节点起不来

2026-11-23 00:13 现场（Windows 节点 DESKTOP-6LFQUO8）：

```
G:\dswork\duan-light-merge\hive>python hive.py cluster start
[hive-cluster] 注意 G:\dswork\duan-light-merge\hive\config.json 存在但不会被读取
集群进程在跑（PID 1556）但暂未响应，不重复拉起。
若确实卡死：hive cluster restart
```

三条互相打脸的证据：

| 观察 | 事实 |
|---|---|
| `cluster.pid` 内容 | `1556` |
| PID 1556 现在是谁 | **msedge.exe**（11-22 07:29 启动，浏览器网络进程） |
| 本机 8788 | **没有任何监听**，`127.0.0.1:8788` 连接被拒 |
| 主控 192.168.0.88:8788 | 完全正常，`/api/cluster/health` 回 leader/term 正常 |

根因在 `hive_cluster.py`：

- `cluster.pid` **只存一个号码**，没有进程身份（启动时间 / 命令行 / 角色）；
- `_pid_alive(pid)` 在 Windows 上跑 `tasklist /FI "PID eq <pid>"`，**只要能查到同名号码就算活着**；
- `cmd_start` 见 pid 存在、health 不通，就打印「进程在跑但暂未响应」并 `return 0`，**永不拉起**；
- 更糟的是 `cmd_stop` / `restart` 会对这个号码直接 `os.kill(pid, SIGKILL)`——**会杀掉一个完全无关的用户进程**。这次只差没执行 stop。

进程为什么会死：11-21 22:54 起的 hived 在 23:17–23:19 连续报
`维护循环异常（继续）：MemoryError()`，23:19:55 之后日志直接断掉，进程没了，
pid 文件留了下来，号码随后被 Edge 复用。

## 目标（按优先级）

### 1) pid 文件升级为「身份记录」（必做）

写入 pid 时同时落身份，例如：

```json
{"pid": 1556, "started_at": 1795272875.6, "argv": ["hive.py", "cluster", "start"],
 "node_id": "DESKTOP-6LFQUO8-8a3bf94c", "version": "0.16.07"}
```

必须**向后兼容**旧的纯数字 `cluster.pid`：旧格式一律按「不可信」处理（不能因为号码存在就判定在跑）。

### 2) 判活改成三层，任何一层不符都算「陈旧」

1. 端口/健康探活：`/api/cluster/health` 短超时（≤5s）能回 `cluster_id`；
2. 进程核对：PID 存在，且命令行含 `hive.py` 与 `cluster`（或 `hived`）；
3. 启动时间核对：进程创建时间与 pid 记录里的 `started_at` 相差在容差内（如 5s）。

### 3) `start` 自愈：陈旧 pid 自动清理后继续启动

- 打印**一行可读证据**，例如：
  `检测到陈旧 pid：1556 现属于 msedge.exe，不是本节点 hived，已清理并继续启动`
- 清理后正常启动，不再因为一个号码挡住整个节点；
- 真在跑但不响应（身份匹配、health 不通）时，保留「不重复拉起」，但提示必须带上探活证据（端口状态 / health 超时）并指向 `cluster restart`。

### 4) `stop` / `restart` 安全：绝不击杀无关进程

- 只对**身份校验通过**的 hived 进程发信号；
- 校验不通过时只删 pid 文件并打印提示，**不调用 `os.kill`**；
- 这是本卡的最高优先安全项：当前行为等于「随时可能杀掉用户正在用的任意程序」。

## 红线

- 不改选举 / quorum / 租约 / store 同步语义；不动 store schema。
- 不引入第三方依赖，只用标准库。
- Windows 上启动子进程必须走现有 `no_window_kwargs()`（T-0206：不许闪窗）。
- 不 kill 任何未经身份校验的 PID；不写 token / 密钥。
- 只改本卡 `paths` 内文件；不动其它任务卡与 agents 配置。

## 验收

- 新增 `tests/test_cluster_pid_liveness.py`，至少覆盖：
  1. pid 文件指向一个**无关的存活进程**（测试里 spawn 一个 sleep 子进程，把它的 pid 写进 pid 文件）→ 判活必须 False，`cmd_start` 必须视为陈旧并继续（不 return 0）；
  2. 旧格式纯数字 pid 文件（无身份字段）→ 不可信，不得据此判定「在跑」；
  3. pid + 命令行匹配 → 判定在跑，健康不通时给出带证据的提示；
  4. `cmd_stop` 面对无关 PID → **不调用 `os.kill`**（monkeypatch 断言未被调用），只清 pid 文件。
- 测试不得真的拉起常驻 daemon、不得出网、不得写 state_dir 之外的文件；用 tmp_path。
- 现有 `tests/test_cluster.py` 的 stop / restart / startup 相关用例不得回归。
