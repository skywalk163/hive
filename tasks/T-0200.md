## 症状

没有「拿到子进程句柄 → 写一行 → 读一行 → 再写」的接口：

- `外部命令.执行命令` 是**一次性**的（给命令、拿输出、结束），连 stdin 入参都没有；
- `外部命令.后台执行` 返回 `Popen`，但 stdout/stderr 钉在 `PIPE` 且无人读（见另一张卡），也不能写 stdin；
- `进程.进程启动(捕获输出=真)` 只给 PIPE stdout，**没有 stdin=PIPE**，也没有读一行的封装。

于是所有**基于 stdin/stdout 的长连接协议**都做不了：MCP stdio、LSP、JSON-RPC over pipe、
交互式 CLI 驱动（`ssh` / `gdb` / `psql` / `fdisk`）。

lighthive 的 `hive llm --mcp` 因此只能退化成 in-process 后端——功能等价，
但「本进程确实是个真 MCP 客户端」这件事证明不了。

**补充事实**：`stdlib/伪终端.light` 有完整的 PTY（`写输入` / `读输出` / `是否存活` / `窗口大小调整`），
但 PTY 会掺进回显与 ANSI 转义，**不适合逐行 JSON-RPC**——所以这不是「已有等价物」，是真空缺。

## 期望

`stdlib/进程.py` 增加管道式交互句柄（名字建议 `进程会话` / `交互进程`）：

```light
设 会 为 进程会话启动(["python3", "mcp_server.py"], 工作目录 = 根目录)
会.写一行("{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"initialize\"}")
设 行 为 会.读一行(超时 = 10)      # 超时返回 空，不抛
会.是否存活()
会.终止()
```

要点：
1. `stdin=subprocess.PIPE`、`stdout=PIPE`，**行缓冲**（`bufsize=1`）；
2. `读一行(超时=)` 必须有超时，否则读端会永久阻塞（这是本缺陷最容易写出的翻版）；
3. 输出保持**原样字节/文本**，不做行内重排、不吞空行；
4. stderr **不能**接 PIPE 后不读（会把子进程写死）——默认并入 `DEVNULL` 或独立线程消费。

## 验收

新增 `tests/unit/test_LH20_管道交互.py`：起一个 `python3 -c` 的小 echo 服务（读一行、回一行），然后

1. **请求-响应循环**：连发 5 轮，每轮读回的内容与发出的一一对应（幂等、无串包）
2. **超时**：子进程故意不回 → `读一行(超时=1)` 约 1 秒返回 `空`，**不挂死**
3. **stderr 大流量**：子进程往 stderr 写 1MB 再回一行 → 仍能正常读回（证明没被 stderr 管道堵死）
4. **收尾**：`终止()` 后进程确实退出（`是否存活()` 为假），无僵尸
5. **真协议佐证**（加分项）：用它跑一次 MCP `initialize` 握手，断言拿到 `serverInfo`

## 边界

- 跨平台：FreeBSD/Linux 必过；Windows 若 `bufsize=1` 文本行缓冲行为差异，请在代码注释里注明并降级为自实现行切分。
- 这是**新能力**，不改既有 API 行为；`进程启动` / `进程运行` 的签名保持不变。
