## 背景

评审对「对中国人友好」的判断：不等于全中文。标识符用中文还是英文应由**项目规范**决定，而不是语言强制；L0 内核已冻结、L1/L2 双轨已覆盖教学与工程，下一步应在 **LSP 层**提供「标识符语言检查/建议」，帮团队保持一致，而不是在语法层做非此即彼的选择。

## 要做什么

1. 新建 `lsp/identifier_language.py`（纯标准库）：
   - 从源码里提取标识符：`设`/`段`/`类` 声明名、参数名、模块导入别名（用现有 lexer/token 流，别自己写正则硬啃）；
   - 语言判定：`zh`（含 CJK 且无拉丁字母）、`en`（纯 ASCII 字母数字下划线）、`mixed`（两者都有）；
   - `check(text, mode="any") -> list[dict]`，元素 `{name, line, column, kind, lang, severity, suggestion}`；
     - `mode="zh"`：`en` 名给 `info` 提示「本项目规范为中文命名」；
     - `mode="en"`：`zh` 名给 `info`；
     - `mode="any"`：不提示，`[]`；
     - `mixed` 一律 `warning`（如 `user名字`），并给出建议写法。
   - 配置读取：`light.toml` 的 `[lsp.identifier] mode = "zh"|"en"|"any"`，缺省 `any`（**默认不打扰**）。
2. 接入 `lsp/diagnostic_extension.py`：作为可选诊断源，配置开启才发；不改变现有诊断顺序、不改变已有诊断的 severity。
3. `tests/test_lsp_identifier_lang.py`：
   - 三种 mode 的判定矩阵（zh 名 / en 名 / mixed 名）；
   - 字符串字面量与注释里的中文**不误判**；
   - 中文标点、关键字本身（`如果`/`段落`）不当作标识符；
   - 性能粗测：1000 行源码 `check()` < 50ms（宽松，只防 O(n²)）；
   - 默认 `any` 下返回空列表。

## 不要做什么

- 不做自动重命名、不给 code action（不替用户改代码）。
- 不改 `cli/light.py`、不改 L1/L2 语法、不改 `src/` 编译器。
- 不把 `info` 升级成 `error`；任何情况下不得因命名风格让编译/诊断失败。
- 不引入 pygls 等第三方依赖。

## 完成标准

- `python -m pytest -q tests/test_lsp_identifier_lang.py` 全绿。
- summary 里贴三种 mode 对同一段示例代码的真实输出对比。
