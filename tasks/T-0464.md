# 收口接线：把 A–E 五个模块接成一条 agent 能走的闭环（唯一热点 owner）

## 背景

T-0457~T-0461 各自的模块都是"纯模块 + 判据"，**故意不碰热点文件**，好让它们七路并行。
本卡是 `cli/light.py` / `README.md` / `docs/AI编程指南.md` 的**唯一 owner**，负责真正接电——否则只是又一堆死代码。

实测的四个断点（2026-11-24）：

```
$ python -m cli.light 运行 x.light
light: error: argument command: invalid choice: '运行'      # 但 docs/AI编程指南.md 就是这么写的
$ python -m cli.light ai card | wc -c
1013                                                        # 700 字，标 v3.2
$ python -m cli.light ai check --json x.light | grep duration_ms
"duration_ms": 3899                                         # agent 一轮调 10 次 = 39 秒
```

## 要做什么

1. **接诊断**：`ai check --json` 的 `diagnostics` 里出现来自 `src/ai_pyisms.py`（D1xx）与 `src/ai_strict.py`（D2xx/ALIAS 等）的条目；`fixes` / `fix_suggestions` 必须是**可套用**的结构（含 span 与 replacement），不再是 hint 的复制。行/列/严重级与既有 `schema_version` 口径一致。
2. **加 `--strict` 开关**（`ai check` 与 `light check` 都要有，**默认关**，避免破坏存量 9981 条测试）：开时把别名/中文标点/省略类型作为 warning 输出，关时完全不影响现有输出。
3. **`ai card --level compact|standard|full`**：默认 `compact`，接到 T-0459 的三层生成器；`ai snippets` 保留。
4. **中文子命令别名**：`light 运行/检查/编译/测试/格式化` → 对应英文子命令。**选"加别名"而不是"改文档"**——文档已经对公众承诺过这套写法，改文档等于让每个读过文档的人继续踩。别名要出现在 `--help` 的说明里，且 `light 运行 x.light` 与 `light run x.light` 行为逐字一致（含退出码）。
5. **`--fast`**：`ai check --fast` 跳过运行检查与类型检查，只做语法 + 诊断。测出 P50 并**如实写进 summary**；目标是 <300ms，达不到就报实测值，**不许编**。顺带定位 3.9s 花在哪（import？类型检查？stdlib 扫描？）——这一段分析写进 summary，它比代码更值钱。
6. **文档一致性**：`README.md` 顶部 AI 段 + `docs/AI编程指南.md` 的首段，改成指向三层卡（`docs/ai/`）与 `AGENTS.md`；把 `light 运行` 与 `light ai check --json --fast` 的实测输出贴进去。**只改这几段**，不要重写 4.8 万字。

## 不要做什么

- 不改 `src/diagnostics/`（T-0457 独占）、`tools/ai_copilot/`（T-0459 独占）、`benchmarks/light_agent/`（T-0462 独占）
- 不重构 parser，不动 `src/code_generator.py`
- 不删任何现有子命令、不改默认行为（`--strict` 必须默认关）
- 不为了让测试绿而放宽既有断言
