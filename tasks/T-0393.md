# 拆分 src/web服务器.light（121KB 巨型文件）为关注点内聚的模块

## 背景（为什么需要这张卡）

`src/web服务器.light` 已 **121141 字节**，是本仓最大的 .light 文件。它承担了：
路由分发、静态资源、会话 CRUD、工具回放、审批、设置、jet-hub 网关、流式 SSE、
WebHook、MCP 桥接……几乎所有 Web 面职责都塞在一个文件里。维护成本极高：
- 改一个端点要在巨型文件里翻找，上下文负担重
- 并行开发同文件时冲突概率高
- 新功能无处安放，继续膨胀

## 要做的事（保守、分阶段，不许大爆炸重构）

1. **先摸清结构**：通读 `web服务器.light`，按「端点族 / 辅助函数 / 状态」划出
   6-10 个关注点边界（如：路由表、会话端点、审批端点、设置端点、静态资源、流式推流、
   WebHook、MCP桥接、工具回放、认证鉴权）。写一份 `docs/web服务器拆分方案.md`
   记录边界清单 + 每个函数归属 + 依赖方向（谁 import 谁）。**这一步先交，等主控评审后再动代码。**
2. **在不改变任何行为的前提下**，用「薄入口 + 子模块」方式逐步迁移：
   - 每迁移一个关注点，新建 `src/web_<关注点>.light`，`web服务器.light` 保留同名转发/导入
   - 每个迁移必须跑通对应端点的现有测试（examples 里有 test_web*/test_工作目录设置/
     test_会话导入导出 等），确认 rc=0 再进入下一个
   - 严禁一次性把整个文件打散——每步可独立回滚
3. **收口**：`web服务器.light` 最终降到 ~30KB 以下，入口只保留组装逻辑。

## 验收判据（必须全部满足）

- `python -m pytest tests/test_回归.py -o addopts=""` 全绿（全量 examples 无新增红）
- `python -m pytest tests/unit/ -o addopts=""` 全绿
- Web 真机冒烟：`python 运行.py examples/运行Web服务器.light` 能启动，浏览器打开有响应
- 流式推流链路不受影响（`tests/test_流式推流接线契约.py` 的 5 项契约断言仍通过）
- 拆分前后对外 HTTP API 行为完全一致（路径/响应形状/状态码不变）
- CHANGELOG 记录拆分与模块清单

## 风险提示

这是三张卡里**风险最高**的一张。若中途发现某个关注点耦合过深无法安全拆出，
允许只交「拆分方案文档 + 已安全拆出的部分模块」，把剩余留作后续卡——
**绝不许为了凑数硬拆导致行为回归**。宁可少拆，不可拆坏。
