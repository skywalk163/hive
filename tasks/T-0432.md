## 背景

`tests/unit/test_R221_增量清单.py::test_第四节候选表每行指到真实上游路径` 红：

```
候选表 16 行，超过 10 行大概率是凑数
assert 16 <= 10
```

这条判据守的是「文档里的候选表不能凑数」：行数太少（<5）说明没认真盘点，
太多（>10）大概率是把不相关的东西塞进来充数。

现在某份增量清单文档的第四节有 16 行，越过了上限。

## 期望修法（先判断「是不是真凑数」）

1. 打开被测文档，定位 `4. 纯逻辑候选表（B 路直接输入）` 这一节。
   ```bash
   grep -rn "纯逻辑候选表" docs/ | head
   ```
2. 逐行核对：**每一行是否都指向真实上游文件路径**（用例本身也在查这个）。
   - 若某几行其实是同一件事拆开写的 → 合并；
   - 若某几行不是「纯逻辑候选」→ 移到别节或删；
   - 若 16 行**都是货真价实**的候选 → 那就该改判据上限（并在卡里说明理由、
     给出「为什么这次不是凑数」的证据），而不是删内容凑数。

**红线**：不要为了让 assert 过而删掉真实的候选条目；也不要直接把 10 改成 20
了事 —— 判据的意图是防凑数，改上限必须给证据。

## 判据

```bash
python -m pytest tests/unit/test_R221_增量清单.py -q
```

反跑（二选一）：
- 若选择「瘦身文档」：把合并掉的那几行再加回去 → 应重新变红；
- 若选择「提高上限」：在卡里贴出 16 行逐条对应的上游路径清单，作为不是凑数的证据。
