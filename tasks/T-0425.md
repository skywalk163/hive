## 背景

T-0417 在 Ubuntu 24.04 真机上发现：quickstart（非 root）+ `sudo install.sh --systemd` **混跑**时，
`$RUN_DIR`（`_lightmem_run` 或 `/opt/lightmem`）被 root 重新创建，二进制与部分文件变成 `root:root`。
那次因为 `data/` 目录在非 root 阶段已存在才没炸。

**干净机器上先 `sudo` 跑一遍就会留下 root 属主的目录**，而两个 unit 是 `User=lightmem`（或
`--service-user` 指定的用户），于是 systemd 下写 sqlite 可能 500 / 只读失败。
这类故障表现在 `/healthz` 正常、写记忆才炸，非常难归因。

## 目标

1) `integrations/quickstart/install.sh` 在 `--systemd` 分支装完后，对 `$RUN_DIR` 做属主归一：
   `chown -R "$SERVICE_USER":"$SERVICE_USER" "$RUN_DIR"`（用户组缺省随主组），
   并对 `data/`、`logs/`、`$ENV_FILE`、`agent-tokens.json` 各自校正权限（目录 750 / env 600）。
   - 只在**确实以 root 运行**且 `--service-user` 非 root 时执行；非 root 运行时跳过并提示。
   - 幂等：重复跑不报错，不改变非 root 场景行为。
2) 混跑场景改成**有据可查**：在脚本输出里明确打印「本次以 whoami=… 运行，RUN_DIR 属主已归一到 …」，
   让下一次排查不用猜是谁建的目录。
3) 回归：把校验加进上一张卡的 `integrations/quickstart/envfile_test.sh`（或同目录新文件），
   至少覆盖：非 root 运行时**不**调用 chown；root + service-user 时**调用**了 chown 且目标正确。
4) `deploy/README.md`「已知坑」登记一条：不要先 sudo 后非 root 混跑；若已混跑，给出修复命令。

## 红线

- 不得对 `/opt/lightmem` 之外的路径做递归 chown（防误伤）；**必须先断言 `$RUN_DIR` 非空、非 `/`、在允许前缀内**。
- 不改 FreeBSD rc.d 路径行为。
- 不改变非 root（纯 quickstart）安装的现有语义。
- 不引入新依赖。
