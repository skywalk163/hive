## 背景

`src/mcp客户端.light:657` 的 `资源服务器系统提示段(名表)` 已经**逐字对齐上游**
（`## MCP resource servers` + 升序服务器名 JSON + 三个资源工具名），
但全仓**零消费者**：MCP 连上了、`mcp__*` 工具也在册（今天的 168 个工具里就有），
系统提示里却没有一句告诉模型「哪些 MCP 服务器可用、用哪个参数去取资源」。

DSH 的 standard 提示有 `mcp-resources` 段（`snapshots/session/mcp-resources-ptc`），
本仓这块只差一层接线。

## 目标

新增 `src/提示_MCP段.light`（纯文本模块，不启动、不连接 MCP）：

1. `MCP段文本(服务器名表, 工具名表)`：
   - 服务器名表为空 / 非列表 → `""`；
   - `服务器名表` 非空且三个资源工具**至少一个在场**
     （`list_mcp_resources` / `list_mcp_resource_templates` / `read_mcp_resource`）→
     输出 `资源服务器系统提示段(服务器名表)` 的原文；
   - 再补一行工具面：工具名表里 `mcp__*` 的条目按名升序，最多列 12 个，
     写成「已挂 MCP 工具：`mcp__fs__read`, …（共 N 个）」；无 mcp__ 工具则省略该行；
   - 资源工具**全部不在场** → `""`（不渲染一个用不了的工具名）。
2. `MCP段(服务器名表, 工具名表)`：别名。
3. 服务器名超过 40 → 截断 + `…`；总长 ≤ 800。

## 红线

- 不连接 MCP、不扫配置、不发请求：服务器名表与工具名表都由调用方传入；
- 不改 `src/mcp客户端.light` 的既有导出与 `tests/test_T0468_MCP挂载.py` 的断言；
- 不把 MCP **工具 schema** 塞进提示（schema 由工具面自己带）；
- 不改 `src/系统提示.light`、`src/总入口.light`（接线归 T-0487 / T-0489）；
- 不许 `git reset --hard` / `push --force` / `--no-verify`。

## 验收

`python -m pytest -q tests/test_T0481_MCP段.py` 全过：

- `(["fs","git"], ["bash","mcp__fs__read"])` → 含 `## MCP resource servers`、
  服务器名 `["fs","git"]` 升序、且含 `mcp__fs__read`；
- 服务器表空 → `""`；服务器表非空但资源工具全缺 → `""`；
- 只有 `read_mcp_resource` 在场 → 仍渲染服务器段（三个工具是「或」关系）；
- 13 个 mcp__ 工具 → 只列 12 个 + 「共 13 个」；
- 服务器名 60 字 → 40 + `…`；总长 ≤ 800。

反跑：①把资源工具全缺分支改成照样渲染 → 判据红；②服务器名不排序 → 升序红；
③把 mcp__ 工具行删掉 → 判据红。恢复后全绿。
