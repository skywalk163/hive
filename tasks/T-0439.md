## 背景

当前 lightharness 把 8 个预设平铺在同一张清单里，混了两类东西：

- **Agent 预设（4）**：`standard` / `cordis`（创造）/ `ptc` / `minimal`，对应 DSH 的 4 份
  `packages/bundle/web-app/presets/*.patch.yml` —— 差异在「挂哪些工具」。
- **工作方法（4）**：`topdown` / `bottomup` / `brainstorm` / `lazy`，对应 trae agent 的
  spec / plan / goal 一类工作流 —— 差异在「怎么推进」（控制流向 / 人机介入点 / 终止条件）。

现在 UI 与数据层都按 order 1..8 一条线排，用户看不出哪四个是工具组合、哪四个是方法论。
另外实测发现默认预算偏小：单轮 `最大步数 = 25`、目标续跑 `续默认最大轮数 = 8`，
多数真实任务在命中上限前还没收口。

## 目标（四件事）

1. **数据层分层**：`src/预设组合.light` 给每个组合条目加 `类别`（`agent` / `method`），
   新增 `预设类别(标识)` / `预设分组()` / `预设清单(类别="")`（默认空 = 全部，向后兼容）。
   `组合清单()` 仍是唯一真相，不另抄一份清单。
2. **UI 分层**：主输入区下拉、新会话面板、设置页「Agent预设」三处都按
   「Agent 模式 / 工作方法」两段呈现；**值仍是单个预设 id**，会话级切换语义不变。
   本卡不做「模式 × 方法」正交组合（会产生 8×4 组合面，另开卡），只做分类呈现。
3. **轮数上调**：`src/代理.light` 单轮步数默认 25 → 96，支持 `HARNESS_MAX_STEPS` 覆盖；
   `src/目标续跑.light` `续默认最大轮数` 8 → 64（单目标的 `maxGoalRounds` 仍可覆盖）。
   参考 DSH `packages/experimental/tool-ralph/src/index.ts:35` 的 `maxRounds` 默认 256；
   本仓一轮 = 一整轮对话，成本远高于 ralph 的单轮，故取 64 而非照抄 256，文档写明口径。
4. **文档与判据**：`docs/功能对标/模式规格.md` 增「分层」与「轮数预算」两节
   （**原 6 模式 × 7 小节结构与段序一字不动**，T-0406 判据不许破）；
   `docs/配置参考.md` 记 `HARNESS_MAX_STEPS`；`CHANGELOG.md` 记一条；
   新增 `tests/test_T0439_模式分层与轮数.py` 作为本卡判据。
