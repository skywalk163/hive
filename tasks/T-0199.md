## 症状

写错一个内置名，**编译期完全安静**，运行到那一行才炸。

```sh
$ python3 -m cli.light check /tmp/x.light
📄 检查文件: /tmp/x.light
✅ 语法检查通过，未发现错误。
━━━ 类型检查（级别: 表达式）━━━
✅ 类型检查通过
$ python3 -m cli.light run /tmp/x.light
错误: 名称错误
  name '临时目录' is not defined
```

内容就一行：`打印 临时目录()`。

光明的内置函数名是中文短语，命名空间大且没有补全，**极易「造词」**：
`去除空白`（对）vs `去空白`（错）、`最后索引`（对）vs `最后出现位置`（错）、`临时目录()`（根本不存在）。
更麻烦的是「Python 里是语法、光明里没有」的能力（列表切片 `截取列表`），写的时候完全不觉得缺。

## 期望

1. **`light check` 做静态名检查**：引用未定义的名字就报错，并区分四类来源
   （内置名 / `从 X 导入` 的名字 / 模块级段落 / 局部变量），便于一眼看出是「拼错内置名」还是「没导入」；
2. **`light builtins --json`**（或 `tools/内置名清单.py`）输出全部内置名，机器可读，
   让 AI 生成代码前先校验、让门禁用例能自动对拍文档；
3. 编译期（`run`/`compile`）也至少给**警告**，不要只有运行时炸。

## 二、LH-09　局部变量遮蔽**导入的段落名**时零告警，直接 UnboundLocalError（P1）

```light
从 环境 导入 主机名

段落 登记():
  设 主机名 为 主机名()      # ✗ UnboundLocalError
  打印 "登记: " 加上 主机名
```

编译期安静，`check` 也过，运行到那一行才炸：

```
错误: UnboundLocalError
  cannot access local variable '主机名' where it is not associated with a value
```

**关键的「差一步」**：编译器其实**已经有** `L-166 影子变量` 告警，写得很好（有行号、有成因、有修法）：

```
⚠ 编译警告（L-166 影子变量）：第24行 段落『断言等』内给『通过数』赋值，
  但模块级也存在同名变量且未在该段落内声明『全局 通过数。』…
```

**但它只覆盖「模块级变量被局部遮蔽」，不覆盖「`从 X 导入` 进来的段落被局部遮蔽」。**
检测成本极低（导入表已存在），收益是消灭一整类 UnboundLocalError。
这也是 LH-21 静态名检查的**同源工作**：两者都需要「按作用域查名字来源」，一次做掉。

**期望**：把 `L-166` 的覆盖面扩到导入名——段落体内出现 `设 <名> 为`，且 `<名>` 是本模块
`从 X 导入` 进来的名字时，同样发 `L-166` 告警（文案点明「导入名被局部遮蔽」）。

## 验收

新增 `tests/unit/test_LH21_未定义名.py`：

1. `打印 临时目录()` → `check` 退出码非 0，且报错文案含「临时目录」与「未定义/未知内置」
2. `设 甲 为 1` + `打印 乙` → 报未定义（局部变量也能查）
3. **不误报**（这条最重要）：正常程序 `设 甲 为 1` + `打印 甲` → 通过；

   段落定义在前、调用在后 → 通过
4. `tools/内置名清单.py` 输出的 JSON 里含 `打印`/`去除空白`/`是空`，且**不含** `去空白`（用真实清单对拍）

   而 `设 主机文本 为 主机名()` 这种正常写法 **不告警**（负向用例）

## 边界

- 静态名检查**最难的是不误报**：`从 X 导入` 的模块可能延迟解析，`builtin_map` 是调用点重定向，
  段落可以当值传参……**宁可漏报也不能误报**，误报会让全仓 `.light` 都跑不过 check。
- 上线前请用 `python3 -m pytest -q tests/unit/ -x` 之外的方式抽 20~30 个 `examples/*.light`、`demos/` 真跑
  `check`，确认零误报再交。
