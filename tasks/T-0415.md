## 背景
`.github/workflows/ci.yml` 只在 ubuntu-latest 跑 `go build/vet/test`，不测部署脚本；release.yml 虽构建 linux 二进制但无端到端。结果：`install.sh --dry-run`、profile 加载、双服务脚本在 Linux 上从不被 CI 验证。

## 目标
1) 新增 `scripts/ci-linux-smoke.sh`（POSIX sh，CI 友好）：
   - `sh -n` 检查 integrations/quickstart/install.sh、deploy/*.sh、scripts/*.sh；
   - `install.sh --profile solo --dry-run` 跑通（不写系统、不编译也行，dry 模式）；
   - profile YAML 语法校验（python3 yaml 或仓库现有校验）；
   - 若 T0 已合入：`LM_DRY_RUN=1 sh deploy/platform_test.sh`；
   - 若 A/B/C 已合入：systemd-analyze verify（容器无 systemd 时 skip 并明确打印 SKIP 原因，不算红）。
2) `ci.yml` 增加一步 `Run Linux deploy smoke`，调用该脚本；保留原 go 步骤不删。
3) 脚本输出统一 `PASS/FAIL/SKIP` 计数，末行给退出码（全 PASS 或仅 SKIP → 0，任一 FAIL → 1）。

## 红线
- 不改 release.yml 构建矩阵；不改端口口径。
- CI 里不得 `sudo`、不得写 /etc（dry-run 与静态检查为主）。
- 依赖 A–D 的项必须做「存在才测」的软开关，避免本卡先合入时 CI 红。

## 验收
- 本地跑 `sh scripts/ci-linux-smoke.sh` 贴 PASS/FAIL/SKIP 汇总。
- `git show --stat` 只覆盖 scripts/ 与 .github/workflows/ci.yml。
