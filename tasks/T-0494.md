## 背景

OpenI V100 两轮 + A 组 512 预算的实测结论是：**判据卡在数据，不在算力**。

- ③ 0.9091（50/55）、① C 0.6667 vs A 组 0.8889、② 差 4.3pp < 6.4pp 阈值；
- `verdict=incomplete`，三条门禁：`决策点只覆盖 1/7 个（['EDIT']）`、`探针 test 样本 9 条 < 30`、`train/test 模板簇重合 27 个`。

根因在代码里能直接看到：`train_openi.py::build_ids()` 在 `decision_policy=real` 下只认 `meta.category=="decision"` 且答案 JSON 里 `decision ∈ {FR,RW,PATCH}` 的样本，全库只产出 **36 个 `<D:EDIT=*>`**；`load_samples()` 只读 payload 的 `json_tasks / code_tasks / err_tasks` 三键。`data/runtime/decisions.jsonl` 里 **241 条真实决策**（6 个点的 `decisions` 字典、FIX 只在重试记录里、test 88 条、模板零重合）**从未进入训练**。

T-0370 补了数据，T-0493 已把快照对齐；本卡负责把它接进训练口径。

## 目标（可验收）

1. **payload**：新增 `decisions` 键。`scripts/embed_payload.py` 从 `data/unified/decisions.jsonl` 打包进 `_PAYLOAD_B64`；`_load_payload()` 的 `--data-dir` 分支读同名文件。旧 payload 缺该键时行为**完全不变**（向后兼容，不报错）。
2. **样本**：`load_samples()` 把每条决策记录转成一个样本——`task=task_text`、`steps[0].code=source`、`steps[0].validation=validation_code`、`steps[0].decisions=decisions`、`meta.template=template_id`、`_category="runtime_decision"`。字段缺失/验证码未登记要**报错**，不许静默丢行。
3. **标签**：`build_ids()` 的 `real` 策略改为「样本自带 `steps[0].decisions` 时原样注入每个点」，不再看 `category`；没有该字段才退回旧逻辑。注入前逐点校验 point/option 在词表里（`Vocab.point_token_ids` / `decisions`），非法直接报错。
4. **密度**：全量注入后实测 `decision_density`，必须 ≤ `DENSITY_MAX(0.02)`。超了用 **sha256 派生的确定性限量**（不是随机）每样本保留部分点，同时保证 7/7 点都有正样本、test 每点都有样本；实际密度与取舍写进报告。
5. **切分**：`--group-split` 下 `train_test_template_overlap` 必须 **0**，且是构造性保证（复用 `lightprism.runtime.splits` 的家族登记或等价的唯一归属），不许靠换 seed 试出来。
6. **门禁**：`points_with_test_labels = 7`、`n_test_decision_rows ≥ 30`、`overlap = 0` → `gated=false`。`verdict` 仍如实：①②③ 该 fail 就 fail，**不许为解除 gated 改判据**。
7. **探针**：test 行数与逐点覆盖能从 metrics 里读到；A 组外挂分类器的定义与训练集不动。
