> 来源：lighthive 记录 **LH-15（P2，stdlib 缺口）**。
> **2026-10-29 于 light HEAD `5e8d3ecb` 复测：`stdlib/socket.light` 只导出 6 个常量。**

## 症状

```light
从 socket 导入 SO_REUSEADDR   # 可以
从 socket 导入 SO_REUSEPORT   # 不存在
从 socket 导入 TCP_NODELAY    # 不存在
```

`stdlib/socket.light:47` 的导出行只有：

```
导出 socket AF_INET AF_INET6 SOCK_STREAM SOCK_DGRAM SOL_SOCKET SO_REUSEADDR
```

`stdlib/socket.light:70` 起是「零参取值段」形态（`段落 SO_REUSEADDR():`）。

影响：
- `SO_REUSEADDR` 够解决 `TIME_WAIT` 复用，所以只算不便；
- 但做高性能服务（多进程/多线程共享监听端口）绕不过 `SO_REUSEPORT`，只能 `导入 socket` 走 FFI；
- **另外**：记录里写的 `从 套接字 导入 ...` 在当前标准库里**没有这个模块**（只有 `socket` / `Socket.py`），
  名字对不上，会让照着旧记录写的人直接 ImportError。

## 期望

1. 把 `socket` 模块的常量**整组透出**：`SOL_SOCKET` / `SO_*`（至少 `SO_REUSEADDR`、`SO_REUSEPORT`、`SO_KEEPALIVE`、`SO_BROADCAST`）、
   `TCP_*`（至少 `TCP_NODELAY`）、`IPPROTO_*`（`IPPROTO_TCP` / `IPPROTO_UDP` / `IPPROTO_IP`）。
   常量不是行为，透出成本极低、收益明确。
2. 平台差异要**诚实**：`SO_REUSEPORT` 在 Windows 上不存在。
   取不到时不要静默返回值 `0`（会让 `setsockopt` 悄悄设错选项），应返回 `空` 或抛可读异常。
3. 明确 `套接字` 与 `socket` 的关系（要么补别名模块，要么在文档里写清「光明里叫 `socket`」）。

## 落点

- `stdlib/socket.light`（导出行 + 零参取值段）
- `stdlib/Socket.py`（Python 腿，若同名常量在此定义）
- 别动 `stdlib/外部命令.py`、`src/code_generator.py`（各有卡在改）

## 验收

新增 `tests/unit/test_LH15_socket常量.py`：

1. `从 socket 导入 SO_REUSEPORT, TCP_NODELAY, IPPROTO_TCP` 编译通过、运行不炸
2. 取值与宿主 Python 一致：`SO_REUSEADDR == socket.SO_REUSEADDR`、`TCP_NODELAY == socket.TCP_NODELAY`
   （用 Python 侧取真值对拍，别写死数字——不同平台不同）
3. `SO_REUSEPORT` 在**支持的平台**上能真用：起两个监听同一端口的 socket，第二个 `绑定` 成功
   （这是本卡的价值证明；不支持的平台 skip 并打印原因）
4. 取不到的常量返回 `空`/报可读异常，**不是 0**（负向用例）
