## 背景

T-0469 把工具面从 4 个救回来了，但**反向过头**：今天在主仓实测

```
[装配] 预设=standard 保留=168 注销=0 未映射=130
standard=168 工具     schema JSON=46,870 字符
ptc=168   topdown=168   lazy=163   brainstorm=27   minimal=1
```

168 个 schema 每轮全量发给模型（约 4.7 万字符），而系统提示只指导其中 15 个；
DSH 的 standard 工具面是 15–20 个。根因是 `未映射默认保留` 这层兜底：130 个没有
叶子依据的工具（lightplugin 74 个插件工具 + MCP + 内部编排件）被无条件保留。

同时 `tests/test_T0469_提示与工具面.py` 现在 **9 passed / 1 failed**：
`test_mcp工具与预设过滤共存` 断言 `MCP_无叶子=0`，实测为 1 —— `工具名到叶子`
给 `mcp__*` 返回了自身名当叶子，属于「硬塞叶子」，与 T-0468 的约定相反。

## 目标

1. `src/工具面装配.light` 新增**模型可见白名单**（声明式数据 + 纯函数）：
   - `基础白名单()`：standard / ptc / cordis / default / topdown / bottomup / lazy 共用的
     基础集，**20–30 个**，必须包含这 18 个（判据钉死）：
     `bash, 读文件, 写文件, 编辑文件, 搜索文件, job_start, job_output, job_kill,
     skill, web_search, web_fetch, present, todo_write, 目标, 派发子任务,
     收集子任务结果, 提问提交, 回答提交`；
   - `工作方法删减(方法)`：方法维**只能从基础集删**，不许加（topdown/bottomup/lazy 现有删减表沿用）；
   - `只读白名单()`：brainstorm 用，只含读/搜/问/网查类，**≤ 27** 且无写类/执行类；
   - `最小白名单()`：minimal，`bash` 一项；
   - `白名单(预设标识)` → 名表；未知预设抛错（复用 `是已知预设`）。
2. `src/总入口.light`：
   - `预设保留工具` 改为**白名单命中才保留**，未命中一律注销；删除 `未映射默认保留` 的兜底分支；
   - `工具名到叶子("mcp__*")` 改为返回 `[]`（MCP 不再硬塞叶子）；
   - MCP 工具的去留由显式开关 `HARNESS_MCP_TOOLS`（默认开）+ 白名单通配决定，
     保留时保留、注销时注销，都不进「无叶子」计数；
   - 装配日志从 `保留/注销/未映射` 改为 `保留/白名单外注销/未映射(应=0)`，
     并打印白名单外注销的名字（最多 20 个）。
3. `src/预设组合.light` **只允许新增只读查询**（如 `组合内工具名表`），
   **不改组合行表行数**（33 行是上游逐行对齐口径，examples 有断言）。
