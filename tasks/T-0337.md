# 补一批 ERR 类验证样本（真实诊断，9 码覆盖）

> 直接解锁 LightPrism 探针实验的门禁：现在 `validation` 全 PASS，9 类
> `<V:ERR=…>` 零正样本，导致 `verdict` 永远停在 `incomplete`。

## 背景（现在卡在哪，用数字说话）

`python lightprism/train_openi.py` 的覆盖诊断（2026-11-12，OpenI 与默认各跑一次）：

```
validation_codes_seen: ["PASS"]
has_err_validation: false
→ gate_blockers 必含「验证 token 只有 PASS，8 类 <V:ERR=...> 无正样本」
```

`data/sft/json_tasks.jsonl` 300 条、`code_tasks.jsonl` 63 条的
`steps[].validation` **全是 `PASS`**。真实归档 `~/.light/error_corpus/2026-11.jsonl`
也只有 **3 条**（`L0000`×2、`L3001`×1），远不够一批样本。

`src/lightprism/tokens.py::DIAGNOSTIC_TO_VALIDATION` 已把 23 个 `Lxxxx` 映射到 9 个验证码：

```
L0000→ERR=CHECKER_FAIL  L1001..L1007→ERR=SYNTAX / WARN=NON_CANONICAL
L2001→ERR=TYPE_MISMATCH L2002→ERR=MISSING_TYPE  L2003→ERR=TYPE_MISMATCH
L3001→ERR=RUNTIME       L4001→ERR=UNDEFINED_VAR L4002→ERR=IMPORT_FAIL
L5001→ERR=RUNTIME       L5002..→WARN=NON_CANONICAL
```

## 已知事实（本机 2026-11-12 实测，别重复踩）

`light ai check --run --json --no-corpus` 可用，但**大多数运行期错误都回落到 `L0000`**：

| 尝试的片段 | 实际诊断 |
|---|---|
| `设 甲 为 (`（括号不闭合） | `L0000` ✅ |
| `设 甲 为 [1, 2]` + `打印(甲[9])` | **`L3001`** ✅（唯一稳定复现的具体码） |
| `打印(甲)`（未定义） | `L0000`（stage=运行） |
| `设 甲 为 1 + "文本"` | `L0000` |
| `段落 加一(甲)` 无类型标注 | `L0000` |
| `从《不存在的模块》导入《甲》。` | `L0000` |

**结论：先做「可达性矩阵」，再决定每码能补几条。不许假设 9 码都随手可得。**

## 要做的事

### 1. `scripts/gen_err_samples.py`：诊断码可达性矩阵 + 真实样本生成

- `--check`：只探可达性，不写盘。对每个候选片段跑真实 checker，打印
  `code → 能否稳定触发（跑 3 次是否同码）→ 触发片段摘要`；
- 默认（写盘）：把可达码的片段批量生成样本，每个码**至少 5 条、目标 10 条**，
  且**每条片段内容不同**（不同变量名/不同上下文，不许同一段复制 N 份）；
- 必须调真实 checker：

```python
subprocess.run([sys.executable, LIGHT_CLI, "ai", "check", path,
                "--run", "--json", "--no-corpus"], ...)
```

`--no-corpus` 必须加：否则会往 `~/.light/error_corpus` 里灌测试垃圾。
`LIGHT_CLI` 通过 env `LIGHT_CLI` 或 `--light-cli` 传入，默认
`/home/skywalk/dswork/light/cli/light.py`，找不到就**明确报错并退出 2**。

### 2. `data/sft/err_tasks.jsonl`：样本格式与现有 SFT 完全一致

一行一个 `Sample`（能被 `lightprism.data.load_jsonl` 原样吃下）：

```json
{"task": "修复光明代码中的错误（L3001）：列表索引越界",
 "steps": [{"decisions": {"EDIT": "FR"},
            "code": "<完整可解析的坏代码，不是 ±2 行片段>",
            "validation": "ERR=RUNTIME",
            "validation_detail": "索引错误 列表索引越界（rt:2）"}],
 "meta": {"category": "err", "format": "code",
          "diagnostic_code": "L3001", "stage": "运行",
          "source": "light_ai_check", "generated_at": "2026-11-12T..."}}
```

- `validation` 必须是 `DIAGNOSTIC_TO_VALIDATION[code]` 的**查表结果**，不许手写；
- `code` 必须是**完整程序**（能再次跑出同一个诊断），不接受片段拼接；
- `validation_detail` 取 checker 的 `message`（截断 200 字以内）。

### 3. `scripts/embed_payload.py`：重建 `train_openi.py` 的内嵌 payload

这是个**现存缺口**：`train_openi.py` 的数据是 zlib+base64 内嵌的，但没有构建脚本，
现在改不了内容。要求：

- 读 `data/vocab_4096.json` + `data/sft/{json,code,err}_tasks.jsonl`；
- 重写 `_PAYLOAD_B64` 区块（保持 `r'''...'''` 形态与换行风格）；
- 打印每份数据的 `sha256`，与 `config.json` 里记录的 `payload` 一致；
- `--check` 模式只比对、不改文件（CI 用）。

然后让 `train_openi.py` 的 `_load_payload()` / `load_samples()` 支持 `err_tasks`：

- 内嵌路径：`payload["err_tasks"]` 存在则并入；
- `--data-dir` 路径：读 `err_tasks.jsonl`（不存在则该 key 为空，不报错）。

### 4. `reports/ERR样本覆盖.md`：诚实报告

必须有一张表：`验证码 × 可达性 × 条数 × 触发证据（checker 输出摘要）`。
不可达的码单列「未覆盖 + 原因 + 试过哪些片段」，**不许拿 `L0000` 冒充**。

### 5. `tests/test_err_samples.py`

覆盖：JSONL 能 `load_jsonl` 读回、每行 `validation` 与 `diagnostic_code` 查表一致、
不存在重复 `code` 片段、每个可达码条数 ≥5、`--check` 退出码语义、
`embed_payload --check` 在数据未变时返回 0。

## 完成标准

```sh
PYTHONPATH=src python scripts/gen_err_samples.py --check     # 打印可达性矩阵
PYTHONPATH=src python scripts/gen_err_samples.py             # 生成 data/sft/err_tasks.jsonl
python scripts/embed_payload.py --check                       # 内嵌数据与文件一致
python -m pytest -q tests/test_err_samples.py                # 全绿
python train_openi.py --self-check                           # has_err_validation 变 true
```

`--self-check` 的输出里 `validation_codes_seen` 必须**不再只有 `PASS`**（至少含
`ERR=RUNTIME` / `ERR=CHECKER_FAIL`，能触发几个算几个）。

## 禁止

- **不许手写 `<V:ERR=…>` 标签**。必须来自真实 `light ai check` 输出；触发不了就记未覆盖。
- **不许拿同一个片段复制 N 份**充条数；每条的 `code` 内容必须不同。
- **不许改 `data/vocab_4096.json` 的 9 个验证码**（码表已定，改要走新卡）。
- **不许改 `DIAGNOSTIC_TO_VALIDATION` 的既有映射**（`L3001→ERR=RUNTIME` 是实测纠错后的结果）。
- 不许把测试片段留在 `~/.light/error_corpus`（务必 `--no-corpus`）。
- 不要动 `train_openi.py` 除 `_load_payload`/`load_samples`/覆盖诊断以外的逻辑
  （v3.2 的判据与门禁刚校准过，见 `reports/探针实验_v2_评审_2026-11-12.md`）。

## 为什么这张卡值得单独做

当前 C 组探针准确率**恰好等于多数类基线**（分组切分 5/13=0.3846，
`reports/探针实验_v2_评审` 与第三次 OpenI 实测都是这个数）。补 ERR 样本不能直接
提升决策准确率，但能：① 让 `has_err_validation` 门禁过；② 让 `<V:ERR=…>` 有监督，
阶段二的「验证 → 重试」闭环才有数据基础；③ 给 `FIX`/`RETRY` 决策点提供因果依据。
