原生腿（llvm 后端）不认 `_light_builtin.原子写入` 这个模块点访问，导致 `文件系统` 模块**整体**被拒，所有从它导入的用例连坐变红。T-0241 归因时判为「越界」没治，本次单独开卡。

## 现场

- `stdlib/文件系统.light:137-138`：
  ```
  段落 原子写入(路径, 内容, 编码 = "utf-8", 权限 = 空):
    返回 _light_builtin.原子写入(路径, 内容, 编码, 权限)
  ```
  注释写明这是 native 边界，真身在 `stdlib/文件系统.py:原子写入`。
- `docs/原生腿能力清单.json` 里**没有** `原子写入` 条目 → 原生后端把它当未定义模块点 → 抛出
  `NotImplementedError: 未定义的模块点访问：原子写入` → `文件系统` 模块被拒 → 从它导入的用例全红。
- T-0241 在 Windows 实测（serial）：
  - `tests/unit/test_原生腿_R11C_数据高级.py::Test高级文件::test_O0_复制文件_对拍` → `1 failed, 28 passed`（约 371s）
  - `tests/unit/test_llvm_stdlib_readiness.py::Test真编译下界::test_下界模块当场编过` → `SUBFAILED(模块="文件系统")`，桶=明确拒绝（约 1366s）

## 两条可能的修法（自己判断，别硬塞）

1. **原生侧支持**：给原生后端补 `原子写入`（临时文件 → 设权限 → `os.replace`），并登记进能力清单；
2. **转译侧改写法**：`stdlib/文件系统.light` 别用 `_light_builtin.` 模块点转发，改成原生认得的写法（比如内联实现或走已登记的内置）。

选哪条都行，但要在 `.hive/summary.md` 里写清理由——「整模块被一个内置卡死」这个后果（连坐范围）比单条用例红严重得多。
