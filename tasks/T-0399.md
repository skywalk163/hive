# 对齐验收：新会话五件事 E2E + 文档/对标登记

## 背景

T-0395~T-0398 分别改了会话 cwd、新会话面板、会话模式/权限、附件/压缩入口。
单卡 verify 各自绿，不代表串起来能用：会话创建带目录 → 首条消息带 preset/权限/附件
→ 再切回会话恢复，这条链路没有任何一张卡单独负责。上游 DSH 的落地页能力要作为
**一个整体**验收，并登记到功能对标档案。

## 要做什么

1. 新增 `tests/test_T0399_新会话对齐.py`：用仓里既有的 web server 测试模式起真实服务，
   全走 HTTP：
   - `POST /api/sessions {标题, 工作目录}` → 200，`GET current` 的 cwd 正确；
   - 首条 `/v1/chat/completions` 带 `preset`、权限预设、`attachments` → 会话记录四键齐全；
   - 两会话不同目录 + 不同权限并发 → 路径安全与工具检查各自正确；
   - 触发压缩后会话仍可继续发消息；
   - 切回旧会话 → 模式/权限/目录恢复（API 层断言）。
   测试禁止依赖外网与真实大模型，用仓里 mock 服务/假响应。
2. UI 冒烟 checklist 落到 `docs/快速开始.md`（新建会话：目录/模式/权限/附件/压缩各一条，
   含预期现象与失败时怎么排查）。
3. `docs/API参考.md` 补：`POST /api/sessions` 新字段、`GET /api/cwd/check`、
   `GET /api/sessions/current` 新键；`docs/功能对标/对标清单.json` 增补条目
   （记住 `#编号` 只增不改，旧条目别重排）；`CHANGELOG.md` 一条。
4. 全量回归：`tests/test_回归.py` + `tests/unit/` 无新增红。

## 不要做什么（红线）

- 只改测试与文档，**不改业务代码**；发现 T-0395~T-0398 的 bug → 开新卡，不在这张卡里顺手修。
- 不引入浏览器自动化新依赖（Playwright/Selenium）；E2E 走 HTTP 层。
- 不动 `examples/` 期望值来「让回归变绿」。
- 不重排 `对标清单.json` 既有条目，不删旧编号。

## 完成标准

- 三个 verify 全绿；E2E 用例在「只完成 T-0395」的中间态下必须红（证明它真的串了链路）。
- summary 贴：E2E 输出、全量回归统计、文档 diff 摘要。
