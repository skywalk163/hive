# 把 T-0268 的归档计数判据改成跨平台真判（POSIX 130 是假红，Windows 145 是假绿）

## 背景（T-0275 实测，2026-11-06 验收）

- 原卡：T-0268（light：145 个 `_R*_` 过程文档从根目录归档 + ROADMAP 瘦身），state=`done`。
- 原 verify 首行：

  ```bash
  python -c "import pathlib; n=len(list(pathlib.Path('docs/归档/轮次报告').glob('_R*.md'))); print('archived', n); assert n>=140"
  ```

  - 验收机（FreeBSD 15.1，大小写敏感）：`archived 130` → `AssertionError`，`rc=1`。**假红。**
  - Windows 本机（NTFS，大小写不敏感）：`archived 145` → 通过。**假绿。**

- **假绿机制**：Windows 上 `pathlib.glob('_R*.md')` 的匹配不区分大小写，把 15 个
  `_r*_task_*.md`（任务书）也算成了「大写 R 的轮次报告」，才凑到 145；POSIX 上同一条
  命令只有 130。这不是搬迁没做完，是**判据口径被文件系统差异放大**。

- 实测现状（light 仓 HEAD `4c7b15a35`，T-0268 land 为 `33dbc22cf`）：
  - `docs/归档/轮次报告/` 共 146 个文件 = 大写 `_R*.md` **130** + 小写 `_r*_task_*.md` **15** + `README.md` 1
  - 仓库根目录 `.md` 共 10 个，`_R*` / `_r*` 残留 **0**
  - `ROADMAP.md`：**59 行**，最长行 **111** 字符（已瘦身）
  - 原卡 verify 自创建（`895d2b7`）到关闭（`15d2fd8`）未改动，不存在「改判据凑绿」。

## 口径裁定（本卡的核心，必须落到 verify 里）

1. **`_r*_task_*.md` 计入总数**。T-0268 正文明确写「根目录还有 15 个 `_r1xx_task_*.md`
   （任务书）…属于同一类噪音」，目标包含一并搬走。因此归档口径 =
   大写 `_R*.md` + 小写 `_r*.md` 两类之和。
2. **大小写敏感**。用 Python 字符串 `startswith`（大小写敏感，与操作系统无关），
   **不要再用 `glob`**：`glob` 的模式匹配在 Windows 上大小写不敏感，正是本次假绿根因。
3. **排除 `README.md`**：它是归档说明，不是过程文档。
4. 阈值取 **145**（实测定值 130 + 15），不再沿用原来的 140。

## 目标

T-0268 本身保持原样（state、verify 都不动，作为历史记录）。本卡负责：

1. 按上面的口径复核迁移结果；
2. 若仓库根目录仍有 `_R*` / `_r*` 残留，用 `git mv` 移到 `docs/归档/轮次报告/`
   （只移动，不删除、不改内容）；
3. 在 `.hive/summary.md` 写清：大写数、小写数、总数、根目录残留数、
   `ROADMAP.md` 行数与最长行。
