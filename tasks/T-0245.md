`.hive/summary.md` 是每张卡的 worker 在工作区里写的工作小结，它被 `git add` 带进 task 分支、随每次 land 覆盖 main —— 于是**每张卡都要在这一个文件上打一次冲突**。

## 现场（2026-11-03）

- `git ls-files .hive` → `.hive/summary.md`（被跟踪，且从 main 上看是「上一张卡的小结」）；
- `.gitignore` 里**没有** `.hive/`；
- T-0241 合并时就是撞在这里：`land` 报 `合并冲突（1 个文件）：.hive/summary.md`，只能人工取 main 版收场；
- 内容其实不丢：每张卡的小结已经归档在 `results/<tid>.json` 里，仓内这份纯属重复。

## 交付

1. `git rm --cached .hive/summary.md`（保留历史，不回写历史）；工作区文件可以留着，也可以删；
2. `.gitignore` 加一行 `.hive/`（连同 `.hive/task.md` 等 worker 中间产物一起挡掉）；
3. 在 `.hive/summary.md` 里说明：以后 worker 仍会写这个文件，但它不再进版本库。

## 判据

```
python -c "import subprocess,pathlib,sys; t=subprocess.run(['git','ls-files','.hive'],capture_output=True,text=True).stdout.strip(); g=pathlib.Path('.gitignore').read_text(encoding='utf-8'); sys.exit(0 if (not t and '.hive/' in g) else 1)"
```

## 注意

- **不要**顺手改别人的 `.gitignore` 既有规则，只加 `.hive/`；
- 历史里的 summary 不用清（`git log -- .hive/summary.md` 留着当档案）。
