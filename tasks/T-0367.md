## 上游语义（三条）

**#3 工作树清理判定**：归档 Session 时若①无未归档 Session 引用该目录、②创建者策略非只读、③Git 未见跟踪文件改动/未跟踪文件/
已初始化子模块/锁/分离 HEAD，则 `git worktree remove`（不带 force）。**被忽略的文件（如 node_modules）不保留**，
skip-worktree / assume-unchanged 的改动也不保留；含已提交内嵌仓库的目录 Git 拒绝删除 → 保留并报清理失败。分支与提交保留。
`retainOnArchive` 默认关；旧的检出目录没有 `plugin:worktree/created` 事件，不扫描。

**#16 终端清理失败**：`TerminalBackendCleanupError` 改继承 `TerminalError`（带 `CLEANUP_FAILED` 的 `HarnessError`），不再继承 `AggregateError`；
`name` / `spawnError` / `cleanupError` / `errors`（保持原顺序）不变，`errors` 变只读 unknown 列表；`cause` 是同样两个失败组成的聚合错误。

**#4 附件错误码**：`AttachmentError` 继承 `HarnessError`（`name` 与 `ATTACHMENT_*`、`INVALID_IMAGE`、`IMAGE_TOO_LARGE` 不变）。
失败 turn 的 `code` 从 `UNKNOWN` 变为具体附件码；工具逸出时 `tool/result` 记 `error:{name, code}`（此前没有该字段）。
捕获顺序：先 `AttachmentError` 再 `HarnessError`。旧日志的 `UNKNOWN` 与新码视为同一类失败。

## 语言坑（光明语言，2026-11 实测）

1. `导出 a b c` 行末不能加句号（报「无法识别的语法元素 '.'」）。
2. 字符串不解释 `\uXXXX`：写真实字符；串内引号写 `\"`。
3. 不支持匿名函数 `段落() 返回 x` → 用具名包装段落。
4. `设 f(x) 为 v` 非法；下标/成员赋值写 `表[位] 为 值`。
5. 变量名避开关键字尾巴（`合并为` / `等待` / `映射`）。
6. `写` 只吃字面量或已赋值变量。
7. 跨模块未捕获异常定位块会错位 → 断言用 `转字符串(异常值)` 比消息。
