## 背景

总控强调"需要更详细/全面的文档"。现在 hive 的概念散在多篇文章：`多机并行开发.md`（偏多机、
偏实操）、`操作手册.md`（人视角）、`AGENT快速上手.md`（agent 视角）、`任务卡模板.md`（写卡）。
缺一篇**把整条链路讲全、还能当排障手册**的"全景"文档，让新接的人先读这一篇就能建立全局图。

本卡产出 `docs/架构与排障全景.md`，把已有内容串成一张图 + 各组件职责 + 一张可检索的排障表，
不重复造轮子，而是引用既有文档的对应小节。

## 要做什么

在 `docs/架构与排障全景.md` 写文档，**必须包含以下小节（verify 会校验）**：

- `## 架构总览`：一张文字/ASCII 架构图——中心仓(Gitea) 的 `tasks/ claims/ results/` 是唯一真相，
  多机 worker 各自独立 worktree；点明四根支柱（中心仓唯一真相、claim 原子锁、worktree 隔离、
  land 串行合流）。可引用 `docs/多机并行开发.md` §1。
- `## dispatch`：分派怎么决定"派给谁"——`needs` 能力 + `repo` + `depends_on` + `paths` 冲突检测
  + `max_concurrency`；dry-run vs `--apply`；引用 `docs/多机并行开发.md` §4.2。
- `## worker`：exec/manual/verify 三种模式；单卡执行链路 `claim→prepare→执行→submit`；
  预留"内部并发"（指向 T-0161/T-0162 规划）。
- `## claim 与租约`：claim/<tid> git ref 的原子抢锁（`git push` 非快进即失败）；租约时长与
  续期 `hive_extend_lease`；MCP 与 cmd 的"先抢锁后 assign"对齐（T-0146/T-0147）。
- `## land 与合流`：`hive land` 串行合入、撞冲突只报不自动解、不 force push；`--apply` 才推
  main；引用 `docs/多机并行开发.md` §4.4。
- `## watchdog 与 gc`：租约过期回收、重试熔断（回收 3 次判 blocked）、`hive_block` vs `hive_abort`
  区别（引用 `docs/AGENT快速上手.md` §8）。
- `## 排障表`：一张表，列"现象 / 原因 / 处理"，覆盖 `dispatch` 不派、land 报本地仓不可用、
  卡一直 assigned、验收恒过、两台机改同文件、中心仓不可达等（综合 `docs/多机并行开发.md` §6
  与 `docs/AGENT快速上手.md` §6）。
