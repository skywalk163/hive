## 症状

两条都是「内置」该有的样子它都没有：

1. **`归约` 根本跑不起来**：`打印 转字符串(归约([1,2,3], 加倍, 0))`
   ⇒ `错误: 名称错误 / name 'functools' is not defined`。
2. **`映射` / `筛选` 返回 Python 迭代器**：`转字符串(映射([1,2,3], 加倍))` 打印
   `<map object at 0x…>`，`筛选` 同理 —— 不能 `长()`、不能下标、不能 `转字符串`。

## 根因

- `src/code_generator.py:668` 把 `归约` 映射成裸名 `functools.reduce`，
  而生成产物的序言只 import 了有限几个模块，**`functools` 不在其中**。
  同一张表里 `筛选`→`filter`、`映射`→`map` 是 builtins，所以只有 `归约` 漏网。
- `src/code_generator.py:5044` `_DATA_FIRST_BUILTINS = {'映射': 'map', '筛选': 'filter'}`
  直接发射 Python 内建。**LH-11（= L-245）修了 `反转`/`范围`，这两个漏了。**

## 期望

1. `归约(列表, 段落, 初值)` 能跑，返回归约结果；
2. `映射` / `筛选` 返回**列表**（与已修的 `反转`/`范围`/`枚举` 同一口径），
   可以 `长()`、可以下标、`转字符串` 出可读内容；
3. 两条都在**真跑**层面验收，不只是「生成代码里出现了 `reduce`」。

## 落点

- `src/code_generator.py` / `code_generator_unified.py`：`归约` 改成走一个自包含实现
  （推荐在 `stdlib/builtins.py` 或现有 runtime 里实现 `归约`，与 `原子写入` 同款：
  不依赖模块解析），或在产物序言里无条件 `import functools`；
  `映射`/`筛选` 包一层 `list(...)`。
- ⚠️ **不要在 `stdlib/builtins.py` 里新开顶层 `def`** —— 地板自举率用 ast 数该文件顶层函数
  当分母，`tests/unit/test_R158_地板证据窗口漂移.py` 会把「68/96」判红。
  要加实现请走 `_t5b_runtime.py` 那条通道（实现放外置模块 + `from import` 接线）。
