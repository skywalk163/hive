> **2026-10-29 于 light HEAD `5e8d3ecb` 复测：`--` 分隔符也不支持。**

## 症状

`.light` 程序根本读不到用户传给它的命令行参数。

```sh
python3 -m cli.light run x.light 甲 乙
# light: error: unrecognized arguments: 甲 乙
python3 -m cli.light run x.light -- 甲 乙
# light: error: unrecognized arguments: 甲 乙     ← `--` 也没被支持
```

而 `参数列表()`（`stdlib/builtins.py:327`）直接返回进程级 `sys.argv`，
`.light` 不是进程入口，是被 `light run` 加载执行的，那时 `sys.argv` 是 CLI 自己的。

## 期望

1. `light run <entry> -- 甲 乙`：`--` 之后的实参**原样**交给脚本，不经过 argparse；
2. `参数列表()` 在这条路径下返回这批用户实参（`['甲','乙']`）；
3. **不传 `--` 时维持现状**（返回宿主 argv），保证存量脚本不炸；
4. 文档写清 `参数列表()` 的两种口径，并给 `light run --help` 补一句 `--` 的用法。

## 落点

- `cli/light.py`：`run` 子命令的 argparse（用 `parse_known_args` 或 `argparse.REMAINDER`；
  注意 `run` 自身还有 `--backend` / `--stdlib-dir` 这类选项，**不能被 `--` 之后的实参污染**）
- `stdlib/builtins.py:327` 的 `参数列表()` 实现：读一个约定好的注入点
  （环境变量或模块级 `_用户参数` 均可），没有注入时回退 `sys.argv[1:]`
- 建议同时给一个**显式**的 `用户参数()` 别名，让「我要的是用户参数」在代码里可读

## 验收

新增 `tests/unit/test_LH05_用户参数.py`（用 `subprocess` 真起进程，别只 import）：

1. `python3 -m cli.light run <临时.light> -- 甲 乙` → 脚本打印的参数恰为 `['甲', '乙']`；
2. 同上但带 `--backend src` 之类选项时，选项不被吞、`--` 之后仍原样透传；
3. 无 `--` 时脚本不崩（退化为宿主 argv，断言「不抛异常」即可，不锁死具体内容）；
4. 参数含空格 / 中文 / 引号时原样到达（证明没被 shell 二次解释）。

## 边界

- **只动 `cli/light.py` 的 `run` 子命令 与 `stdlib/builtins.py` 的 `参数列表` 那一小块。**

## 三条过程中的硬约束（踩过才知道）

1. **不能在 `stdlib/builtins.py` 里新开顶层 `def`** —— 地板自举率用 ast 数该文件顶层函数当分母，
   `tests/unit/test_R158_地板证据窗口漂移.py` 的「68/96」会转红。所以 `用户参数()` 的实现放在
   `stdlib/_userargs_runtime.py`，`builtins.py` 用 `from import` 接线（`from import` 不产生
   FunctionDef，分母不变 —— 与 `_t5b_runtime.py` 同一条既有通道）。
2. **`src/keywords.py` 是 CRLF** —— 用 LF 写回会把整个文件 1444 行改掉。写回前先确认行尾。
3. **`scripts/sync_builtins.py` 只同步函数体**：`参数列表()` 的新函数体被搬进 lightharness 副本，
   但头部 import 不会自动跟过去，必须手工补（补完才不会 NameError）。
