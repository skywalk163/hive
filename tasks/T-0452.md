# 网页工具：把已复刻的搜索/抓取接成 web_search / web_fetch

## 背景

- DSH 有 `packages/web`：`web_search` + `web_fetch` 是标准预设的常驻工具。
- lightharness 里搜索/抓取的纯逻辑都在，但**没有任何消费者**：
  ```
  src/搜索提供商.light  → 造搜索工具定义(依赖)   （grep 全仓只有它自己）
  src/抓取策略.light    → IP 私网判定 / IPv6 剥括号 …
  src/真实抓取提供.light → 真实 HTTP
  ```
  真实会话的 4 个工具里自然也没有它们。
- 后果：模型不能查资料，只能靠 bash curl（Windows 上还没有 curl 的稳定姿势）。

## 要做什么

新增 `src/工具_网页.light`（新文件；**不要改 `src/总入口.light` / `src/核心工具.light`**）：

1. `造网页搜索工具定义(依赖)` —— 名字 `web_search`（DSH 同名），参数 `query`/`limit`（可选，
   snake_case 对齐上游），内部委托 `搜索提供商.造搜索工具定义` 的执行体；
   **缺 API key 时必须返回可读错误**（`isError=真`，文案点明缺哪个环境变量），不许静默空结果。
2. `造网页抓取工具定义(依赖)` —— 名字 `web_fetch`，参数 `url`；
   抓取前用 `抓取策略` 做准入（非 http(s) / 私网 IP / 非公网字面量一律拒绝并说明原因），
   正文超过 32KB 走溢出预览（`src/溢出.light`），并给出「已截断」标志。
3. `网页工具状态()` —— 返回 `{搜索: {可用, 原因}, 抓取: {可用, 原因}}`，供启动日志与 doctor 用。

## 判据（`tests/test_T0450_网页工具.py`，新建，全部离线）

1. 缺 key：`web_search` 执行返回 `isError=真` 且文案含环境变量名（不是空串）；
2. 有假 provider（注入返回固定结果表）：`web_search` 返回归一后的结果（title/url/snippet），条数受 `limit` 约束；
3. `web_fetch` 对 `http://127.0.0.1/x`、`http://10.0.0.5/x`、`file:///etc/passwd`、
   `ftp://x` 四类都拒绝且文案可读（走 `抓取策略`，不自己写第二套判定）；
4. `web_fetch` 对合法假响应：正文 > 32KB 时返回截断标志 + 预览，不吐全文；
5. 两个工具定义过 `工具.校验工具定义形状`，名字恰为 `web_search` / `web_fetch`；
6. **反跑**：把私网拒绝那一行删掉，用例 3 立红。
