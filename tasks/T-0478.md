## 背景

`src/技能目录.light` 已经实现 `发现技能(根, 额外目录表)` 与
`渲染技能清单段(技能表, 上限条数=50)`（引导行 + 每技能一行 `- 名字：描述`，
描述截断 80 码点、`技能清单.转义文本` 转义、超 50 条补省略行），但**全仓零消费者**：

- 唯一导入 `技能目录` 的是 `src/核心工具.light:31`，只用了 `发现技能 / 造技能工具定义`；
- `skill` 工具描述（`技能目录.light:192`）写着 *"The available skills and when to use each
  are listed in the system prompt skill section"* —— 系统提示里根本没有这一段，
  模型只能瞎猜名字；
- DSH 的 standard 提示有 skills 段（`snapshots/session/advanced-toolchain` 里可见
  skill 工具描述与清单协同）。

## 目标

新增 `src/提示_技能段.light`（纯文本模块，不读全局、不发网络）：

1. `技能段文本(技能表)`：
   - 空表 / 非列表 → `""`（不渲染段）；
   - 非空 → `渲染技能清单段(技能表, 50)` 的同一文案，并在首行后补一句
     「先看这里的名字，再用 skill 工具按名字取正文；不在清单里的技能不要编造」；
   - 描述截断与转义复用 `技能目录` 的实现，**不复制第二份**；
   - 总长 ≤ 1000 字符，超了按条数回退（45/40/30 逐档）。
2. `技能段(发现函数, 根, 额外目录表=[])`：调 `发现函数(根, 额外目录表)`，
   取 `发现["技能"]`，转 `技能段文本`；发现抛错 → 返回 `""`（技能面坏了不该拖垮一轮）。
3. `技能段在场(工具名表)`：`skill` / `技能取用` / `技能列表` 任一在场才算「技能面可用」，
   供 T-0487 决定是否挂该段。

## 红线

- 不改 `src/技能目录.light` 的既有导出与 `tests/test_T0451_技能目录.py` 的断言；
- 不改 `src/系统提示.light`、`src/总入口.light`（接线归 T-0487）；
- 不扫家目录 / 不扫 `~/.claude`：只认调用方传入的 `根` + `额外目录表`；
- 不把 SKILL.md 正文塞进提示（只放名字 + ≤80 字描述）；
- 不许 `git reset --hard` / `push --force` / `--no-verify`。
