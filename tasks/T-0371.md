# 翻译方向：恢复独立 `<PY>` / `<LIGHT>` 段标记，治 Python 段与光明段混淆

> 来源：`reports/训练报告_v2.md` §九-2 原文——
> 「**翻译方向仍弱**：#2 暴露「Python 段 / 光明段」混淆，两个 `<CODE>` 块的边界需要更显式的标记
> （例如恢复独立 `<PY>` / `<LIGHT>` 词表 token），这需要改词表，不在本卡范围。」
> 补强讨论稿：`LightPrism-整合路线v2-含train_openi方向-2026-11-14.md`。
> 事实源：`docs/词表预算.md`、`src/lightprism/vocab.py` 的 `DEFAULT_BUDGET`。

## 一、问题是什么

翻译任务的序列里，Python 源和光明目标各自包在 `<CODE>` 里。两块标签完全相同，
模型只能靠**位置**区分「这块是要读的」「这块是要写的」，训练时一旦长度或顺序有偏就串。
`训练报告_v2.md` 的 #2 样本就是这个失败模式的实证。

## 二、要做什么

### 2.1 词表加两个段标记（走既有预算机制，不许硬塞）

- 在 `TokenSpace` 里新增 **`<PY>`** 与 **`<LIGHT>`** 两个结构标记；放在 `reserved`
  槽位（1536，已定义「用于后续决策点、实验 token、特殊控制符」），
  **或**在预算表新增一个显式槽位——两条路都行，但必须满足
  `VocabBudget.problems()` 三条检查：
  1. 每槽位落在区间内（`l0_core` 仍精确 44）；
  2. **合计精确等于 65536**；
  3. 决策 token ≤ 预算 且占比 ≤2%。
- `tests/test_sequence.py::test_default_budget_sums_to_64k` 必须继续绿；
  新增用例钉住两个新 token 的 id 与「不占用决策/验证 token 额度」。

### 2.2 序列构造与训练/推理同步

- 翻译样本的序列改为 `<PY> … </PY>` `<LIGHT> … </LIGHT>`（或等价定长段标记），
  **训练构造与推理 prompt 必须共用同一函数**——这是 v3.1 踩过的坑
  （`scattered` 训练/推理不一致把判据③从 0.98 打到 0.48），必须有一条测试专门钉住。
- **向后兼容**：旧 checkpoint 与旧数据不能静默失效。方案二选一并写清：
  - (a) 新词表 `V=4096+2`，旧 checkpoint 直接不可加载 → 必须给出重建命令与影响说明；
  - (b) 复用 `reserved` 里未被使用的 id，旧 checkpoint 仍可加载，但旧序列含义变化。
  推荐 (a)，因为可比性更干净；若选 (b)，必须证明旧 id 在旧 checkpoint 里从未被训练过
  （`train_openi.py` 踩过「没作为输入 ≠ 没训练过」的坑）。

### 2.3 小规模对照验证（不下结论也可，但必须有数）

用 `configs/demo-3m.json` + 固定 seed，在**相同步数**下做两组对照（各 1 次即可）：

| 组 | 序列格式 |
|---|---|
| 基线 | 双 `<CODE>` 块 |
| 对照 | `<PY>` / `<LIGHT>` 独立标记 |

报告里贴：val loss 曲线末值、翻译方向测试集上的**结构合法率**（`light ai check` 真实跑，
全分母、空输出判不合法）、以及混段错误率（一次错误统计，定义要写清）。

> **注意**：3.4M 参数 + 当前数据量，一次对照结果**不足以证明**「新标记更好」。
> 结论口径只能是「方向性观察」，要写成 `inconclusive` 就得写 `inconclusive`。
