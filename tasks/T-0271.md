# lightmem 缺 CONTRIBUTING 和 SECURITY

## 现状

```
$ ls lightmem/{CONTRIBUTING,SECURITY,SUPPORT,CODE_OF_CONDUCT}.md
# 全部不存在

$ ls lightmem/{LICENSE,AGENTS.md,GETTING_STARTED.md,README.md}
lightmem/LICENSE
lightmem/AGENTS.md
lightmem/GETTING_STARTED.md
lightmem/README.md
```

有意思的是：**`lightmem` 在「怎么让 AI 读懂这个仓」这件事上做得比其它仓都好** ——
`AGENTS.md` + `GETTING_STARTED.md` 双入口，README 第一段就是：

> 你的 DeepSeek Harness / Trae / CodeArts / WorkBuddy / 小浣熊……各自失忆。
> lightmem 让它们**连到同一个记忆服务**…

但**缺了给人看的贡献指南**。一个真人开发者 clone 下来，不知道：
- 能不能改
- 改了怎么提
- 本地怎么跑测试（README 只说「编译/测试/运行在 0.88」，那是内网门禁机）

## 起点线索

这些内容**已经散落在仓里**，本卡的任务是**汇总**而不是新写：

1. `README.md` 已经写了大量红线，例如：
   - 「⚠️ 能力边界（R25-D 如实化）」那一段（Solo 档有/没有什么）
   - 第 415 行提到「按红线⑧脚本不自动 push，执行前需业主示意」
2. `docs/核心与外围边界_v1.0.md` 讲清了「哪些由本套件负责、哪些由部署方负责」
3. `kernel/` 是独立 Go module，顶层 `go build ./...` 会失败 ——
   `.github/workflows/ci.yml:1-20` 的注释解释得很清楚：
   > kernel/ 是独立 Go module…因此在仓库根直接 `go build ./...` 会去网络拉一个并不存在的版本而失败。
   > 所以所有 go 命令统一在 working-directory: kernel 下执行

   **这条是贡献者最容易踩的坑**，必须写进 CONTRIBUTING。

4. `roadmap.md` 里记着历轮红线（如「红线 2：本机仅编辑 + SSH/传输，禁止本机实跑」）

## 目标

### 1) `CONTRIBUTING.md`

必须包含这几节：

**a) 环境（最容易踩的坑放最前）**

```markdown
## 构建

⚠️ **`kernel/` 是独立 Go module，所有 go 命令必须在 `kernel/` 下执行。**

在仓库根直接 `go build ./...` 会失败（顶层 module 只 require 了 kernel v0.0.0，
没有 replace 到本地），报错看起来像「依赖拉不下来」，其实是路径问题。

正确的：
    cd kernel && go build ./... && go test ./...

依据：`.github/workflows/ci.yml` 的 `defaults.run.working-directory: kernel`
```

**b) 跑测试**

```bash
cd kernel && go test ./...          # 单测（729 个 Test 函数）
bash scripts/smoke.sh               # 冒烟（8369 字节，比单测轻）
```

> 先自己跑一次确认这两条真能跑（我没在本机跑过 Go 测试，只确认了文件存在）。

**c) 提 PR**

- 分支命名、commit message 惯例（看 `git log --oneline -20` 的实际风格照抄）
- **不要自动 push 到三个远端**：`scripts/push_all_remotes.sh` 的注释明确说
  「按红线⑧脚本不自动 push，执行前需业主示意」
- 说明「本仓 gitea 为主、GitHub 为镜像，两侧当前有分叉（见 T-0264 核验报告）」

**d) 红线**

从 README / roadmap 里摘，至少这几条：
- 只增不改 Schema 语义
- 不写 token / 密钥（`.gitignore` 里有一大段凭据类规则，说明这是血泪教训）
- 能力边界要如实写（README 里那段「⚠️ 能力边界（R25-D 如实化）」就是范例：
  明确写了 Solo 档**没有** jail / MAC / IPsec / KMS）

### 2) `SECURITY.md`

轻量版即可，但必须有：

```markdown
# 安全策略

## 报告漏洞

**不要开 public issue。** 发邮件到 <维护者邮箱>，或在 Gitea 提 private issue。

## 支持范围

本仓当前只有 `v0.1.0` 一个 tag，不提供多版本安全维护承诺。

## 已知的设计边界（不是漏洞）

以下是有意为之，报告前请先确认：

- Solo 档**没有** jail / MAC / IPsec / KMS（README「能力边界」段已声明）
- 默认监听回环；非回环监听且未配 token 时**拒绝启动**（`kernel/auth.go`，
  commit `30ff8e4`）—— 注意这个护栏**当前只在 gitea 侧，GitHub 镜像缺失**（见 T-0264）
- agent token 默认透传（`kernel/auth.go` 的零回归设计）

## 凭据

`.gitignore` 已覆盖 `agent-tokens.json`、`tokens.csv`、`*-token.txt`、
`.lightmem-secrets/`、`_lightmem_run/`。**提交前请 `git status` 确认没有这些文件。**
```

> 邮箱不知道就写「见 `git log` 里的维护者」或者留 TODO 并说明，**不要编一个邮箱**。
