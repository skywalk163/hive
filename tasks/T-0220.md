## 背景（现场复现，2026-10-30 夜）

T-0196 从 blocked 退回 ready 后，被 0.88 的 `orchestrate`（`--interval 180`）
**3 分钟内连派 3 次**给同一个 agent（`c91b92f` / `6c42de5` / `e6c8155`），
每次只写 `owner` + `state: assigned`，**不建 claim**；agent 也没去 claim
（store 里这张卡还是旧的 `blocked`，CAS 过不去）。结果卡停在
**「已分派无人领」**：面板显示「进行中」，实际没有任何人在跑，比留在 ready 更糟。

根因两条，都在代码里：

1. **TTL 对 dispatch 派出去的卡完全失效**。`_dispatch_ttl_minutes()`（`hive.py:1981`，
   默认 60 分钟）只在 `is_dispatch_candidate()`（`dispatch_tracking.py:122`）里
   按 `dispatched_to` / `dispatched_at` 判断；而 `_assign_local()`（`hive.py:2005`）
   只写 `state/owner` + `inbox/<agent>/<tid>.md` 的 `assigned_at`，**从不写这两个字段**
   → 卡一旦被 `unassign` 回 ready，立刻又是「没推过」的候选，下一轮 180s 就重派。
2. **没有「派发未领取」的快速回收**。现有兜底是 watchdog 的 orphan 回收
   （`_assigned_at()` `hive.py:3224` + `orphan_grace` 默认 45 分钟），太慢，
   而且不记「这次派发没人领」，下一轮照样派给同一个 agent。

## 要做什么

1. `_assign_local()` 同时写 `dispatched_to = agent`、`dispatched_at = iso()`，
   让 TTL 对 dispatch 也生效（unassign 后 60 分钟内不重复派同一 agent）。
2. 新增「派发未领取」回收（放在 `watchdog` 的 existing 回收分支旁边，**不要**
   混进租约回收逻辑）：
   - 条件：`state == assigned` 且**无 claim** 且 `_assigned_at()` 超过
     `HIVE_DISPATCH_UNCLAIMED_MINUTES`（默认 10）；
   - 动作：退回 `ready`、`owner` 置空、卡面 `dispatch_miss += 1`、
     追加一行 body 记录（谁派给谁、多久没领）；
   - 同时清掉 `inbox/<agent>/<tid>.md` 的残留（否则 agent 还会看到旧信号）。
3. `dispatch_miss >= 2` 的卡：**不再自动派**，转 `blocked` 并在卡体写明
   「连续 2 次派发无人领取，转人工」——避免无限拉锯。
4. store 模式下的**派发前校验**：若 store 里该卡的 `state` 与 Git 卡面不一致
   （典型：卡面 ready、store 还是 blocked），跳过并记一行日志，
   不要派一张 claim 注定失败的卡。

## 不要做什么

- 不动 `cmd_unassign` 的语义（人工退回必须无条件执行）。
- 不改 `orphan_grace` 的默认 45 分钟（那是「领了但死了」的场景，和本卡不同）。
- 不给 `dispatch` 加新的必填参数（默认行为要向后兼容）。
- 不碰 `run()`（T-0206 的地盘）和 `fetch()`（T-0216 的地盘）。

## 完成标准

- `python3 -m pytest -q tests/test_dispatch_tracking.py tests/test_orchestrate.py tests/test_dispatch_miss.py`（最后一个新文件）全绿。
- 判据（每条都要反证）：
  1. 派发后卡面必须有 `dispatched_to` + `dispatched_at`；删掉写入 → 红；
  2. 派发后 `unassign` → 该卡在 TTL 内 `is_dispatch_candidate() == False`；
     退回旧实现 → 红（这正是昨天的拉锯）；
  3. 造一张 `assigned` 且无 claim、`assigned_at` 在 11 分钟前的卡 →
     回收后 `state == ready`、`dispatch_miss == 1`、inbox 残留被清；
  4. `dispatch_miss == 2` 的卡 → 转 `blocked` 且不再出现在 dispatch 计划里。
- 现场回归：把 T-0196 类似的卡（ready、P0、有 agent 能接）放进 0.88 的
  orchestrate 跑两轮，**不得再出现「assigned 但无 claim」超过 10 分钟**；
  贴两轮 `dispatch --dry-run` 的 skipped 理由。
