# 光明：中文标识符含关键字被词法截断，「check 绿 / run 红」且报错名称错位

> 来源：lightharness 工具层改造（T-0442）期间在光明仓 `light-merge` 上实测发现（2026-11-23）。

## 现象

中文标识符里若**中间夹着关键字**（本例是 `定义`，`src/keywords.py` 的关键字表成员），未声明时会被词法切成前缀，运行时 `NameError` 报出的名字只剩前半段；而同一份文件 `light check` 完全通过。代理或人拿到的信息是「语法没问题」，跑起来却是「name '甲' is not defined」，排查方向直接被带偏。

最小复现（Windows，python 3.13，`light` 仓 main）：

```light
# k.light
段落 主():
  打印(甲定义乙)
  返回 0
主()
```

```text
python cli/light.py check _probe/k.light   → 语法检查通过 / 类型检查通过，rc=0
python cli/light.py run   _probe/k.light   → 错误: 名称错误  name '甲' is not defined   rc=1
```

实际源码里写的是 `甲定义乙`，报错说的是 `甲`，`^` 指在第 2 行第 8 列（`甲` 之后），不是完整标识符。

四组对照（同一台机器实测）：

| 源文件里的写法 | 前置声明 | 实际结果 |
|---|---|---|
| `打印(未甲)` | 无 | `name '未甲' is not defined`（正常） |
| `打印(甲定义乙)` | 无 | `name '甲' is not defined`（**被截断**） |
| `打印(未定义甲)` | 无 | `name '未' is not defined`（**被截断**） |
| `打印(未定义甲)` | `设 未 为 1` | `name '未定义甲' is not defined`（**又变成全名**） |
| `设 未定义甲 为 9` + `打印(未定义甲)` | — | 打印 `9`（**又能整体匹配**） |

最后两行说明同一串字符在不同上下文被切成了不同 token 序列——这是比「截断」更麻烦的不一致：声明处整体匹配，使用处按关键字边界切分，于是「能定义、不能用」，报错名字还随上下文变化。

## 期望行为（二选一，卡内定夺后写进文档）

1. **整体识别**：标识符优先贪婪匹配，只有整串不是任何关键字时才当标识符；`甲定义乙` 合法，`定义` 单独出现才是关键字。
2. **明确报错**：词法阶段就拒绝「标识符包含关键字」，报 `[词法错误] 标识符不得包含关键字「定义」`，带准确行列与修复建议（改名或加空格）。

无论选哪种，硬要求是：**`check` 与 `run` 必须同源**——不允许 `check` 绿、`run` 才炸；也不允许静默截断。

## 判据

新增 `tests/test_lexer_关键字边界.py`，至少 4 条：

1. `甲定义乙` 未声明 → `run`/编译产物的错误信息里出现的名字必须是完整 `甲定义乙`（或词法阶段明确报「标识符含关键字」，二者按上面选定的设计断言其一）；
2. `未定义甲` 未声明 → 名字完整，或明确词法报错；
3. 声明后使用必须一致：`设 未定义甲 为 9` + `打印(未定义甲)` → `9`，且 `check` 与 `run` 结论一致；
4. `check` 对上面任一「会被截断」的写法**不得**在「run 会失败」时仍报通过（check→run 同源断言）。

反证：把词法改回「关键字优先切分」→ 第 1/3/4 条必须真红；只改报错文案不改切分 → 第 3 条仍红。

回归：`python -m pytest -q tests/test_lexer.py` 与 `tests/test_lexer_关键字边界.py` 同时绿；ASCII 标识符、无空格分词（`docs/bug_fixes_compact_notation.md` 里那批用例）不得回退。
