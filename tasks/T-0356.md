# T-0356 dev 环境集成回归与 SLA 验收（第 2 批）

## 背景

第 1 批 6 张卡各管一段：协议核心（T-0350）、组播下行（T-0351）、心跳上行（T-0352）、
协调仓同步（T-0353）、看板（T-0354）、压测（T-0355）。它们文件锁不重叠、能并行，
但**「拼起来是否真的省流量、是否真的 5 分钟内可见、是否真的没碰生产」必须有人端到端验一遍**。

本卡是第 2 批串行收口，只在 T-0349 的隔离沙箱里跑，
是 T-0357 合入闸门的唯一前置依据。没有本卡的验收报告，T-0357 不许 unshelve。

规范见 `H-LSA-协议设计-借鉴OSPF.md` §5（指标表）、§7（隔离五条）。

## 要做什么

1. **串起全链路**：在 `HIVE_DEV_REPO=<开发副本>` 起的 dev 实例上，
   验证 `T0 变更 → LSDB → 组播摘要 → 子节点比对 → 按需补拉 → 协调仓 autosync → 看板横幅` 全链路通；
   `plane_available:true` 是硬前置（T-0351 的产出）。
2. **逐条实测 §5 的 8 项 SLA**，每项写「实测值 / 判据 / 通过与否」：
   - 子节点状态变更 → 总控可见 ≤300s（设计目标 ≤10s）；
   - 子节点状态变更 → 全集群可见 ≤300s；
   - 全量对账 1800s ±20%、只发 digest；
   - 稳态空闲 Git 请求 0 次/节点/30min；
   - 空闲控制面带宽 ≤ 0.16.05 基线（~9KB/s @3 节点）；
   - N=50/100 高频变更无同步风暴、≤64KB/周期；
   - 切主组播源 ≤1；
   - 0.16.03 / 0.16.05 六项回归全绿。
3. **隔离再核验**（T-0349 清单逐条打勾）：
   - 连续 3 次 `dev-cluster.sh restart` 后生产 `~/.hive/cluster/state.json`
     的 `term` / `leader_id` / `peers` 不变；
   - 看板 8787 仍 `cluster_id=hive`、生产卡面状态与结果台账未被改动；
   - 开发日志无生产地址 / 端口 / 生产组播组；
   - 生产协调仓那 7 个 M 文件 + 3 个未跟踪文件**内容与发布前完全一致**
     （用 `git status --porcelain` 前后比对）；
   - 生产常驻进程 PID 未变（未重启）。
4. **`docs/H-LSA-验收报告.md`**：数字表 + 每项判据 + 复现命令 +
   「未达标项清单」。**任一指标不达 → 整卡判 fail**，不许靠改阈值 / 改口径判绿，
   也不许把环境性失败顺手记成通过（T-0342/T-0344 的教训）。
5. **`tests/test_hlsa_integration.py`**：把上述可自动化的部分做成回归测试，
   供 T-0357 灰度后复跑。

## 不要做什么

- 不在生产实例上做任何验证，不连生产 Gitea（用开发副本的本地 bare 仓做 origin 替身）；
- 不改第 1 批各卡持有的文件（发现缺陷 → 记进报告并回派对应卡，不自己越界改）；
- 不提前 `unshelve T-0357`，不执行 `upgrade publish|apply|rollout`；
- 不重启生产进程、不 stash 别人文件、不跑 `doctor --repair`；
- 不把 `unavailable` 写成 `pass`，不编造实测数字，不放宽 SLA 阈值。

## 完成标准

1. 全链路打通，`plane_available:true`，`sync_health` 与看板横幅显示一致。
2. 8 项 SLA 有实测值且全部通过；未通过的明确列出并回派对应实现卡。
3. 隔离清单 5 条全部有证据（含前后 `git status --porcelain` 对比与 PID 记录）。
4. `tests/test_hlsa_integration.py` 全绿，验收报告可被 T-0357 直接引用。
