## 背景

宣传文档、阶段总结、能力打分报告、工作报告分散在 CSDN / 掘金 / gitcode 等多个渠道，信息密度高，但新来的开发者或 AI Agent 缺少**单一入口的「当前状态」页面**：

> Light 现在是什么版本 · 哪些能力已经稳定 · 哪些是实验性的 · 最小可用面是什么 · 下一个版本的目标是什么

仓库根目录目前**没有** `STATUS.md`（已确认）。

## 要做什么

1. 新建 `STATUS.md`，**≤100 行**，固定六个小节（顺序固定，便于机器校验）：
   - `## 版本与定位`：版本号（必须与 `pyproject.toml` 一致）+ 一句话定位；
   - `## 已稳定`：能力清单，每条注明验证方式（如「8489 用例 0 失败，最近一次全量：<日期>」）；
   - `## 实验性`：明确写「不保证 API 稳定」，列出已知限制；
   - `## 最小可用面`：链到 `docs/MVP_SURFACE.md`，五方向各一行；
   - `## 最近一轮变更`：≤5 条，带轮次号/日期；
   - `## 已知欠账`：链到缺陷账/`tests/ci_baseline_failures.txt` 等真实文件，不粉饰。
2. 统计口径必须写明：例如模块数写「`stdlib/*.light` 顶层模块 N 个（`ls stdlib/*.light | wc -l`）」，避免「109 模块」这类数字各说各话。
3. `README.md` 顶部（前 30 行内）加一行指向 `STATUS.md`，措辞：「当前状态与最小可用面见 [STATUS.md](STATUS.md)」。除这一行外不改 README 其它内容。
4. `tests/test_docs_status.py`：
   - 文件存在；总行数 ≤100；
   - 六个小节标题全部存在且顺序正确；
   - 版本号与 `pyproject.toml` 的 `version` 一致；
   - 文中引用的相对链接（`docs/MVP_SURFACE.md`、欠账文件）**目标存在**（MVP_SURFACE 若尚未合并则跳过该条并 warn，不误红）；
   - README 含指向 STATUS.md 的链接。

## 不要做什么

- 不写宣传语、不堆形容词、不承诺日期或路线图时间点。
- 不复制 `docs/AI编程指南.md` 的语法内容（那是另一份文档的职责）。
- 不改 README 其它段落、不改 CHANGELOG。

## 完成标准

- `python -m pytest -q tests/test_docs_status.py` 全绿。
- summary 里贴 `STATUS.md` 全文（≤100 行）与 `wc -l` 结果。
