# Go 参考实现：MiniLog 交叉对拍（第二 oracle）

> 前置：`benchmarks/light-lang-bench/`（commit `c7a6b3779` 已合入 `main`）已含
> Python oracle 与 53 例黑盒套件。本卡补**第二份参考实现**，用于排除「oracle 与用例
> 共享同一个 Python 心智模型」导致的同源错误（见 `06-design/评测方案修订版.md` §7.1）。

## 0. 为什么需要它（不可省的理由）

现有 53 例的期望值全部由 Python oracle 生成/校验过。如果用例作者与 oracle 作者
犯同一个语义误读（例如把「记录索引」误解成物理行号、把「UTF-8 字节序」写成
「按 rune 序」），Python oracle 会**照样全绿**，错误被带进最终评测。

Go 的价值不在「再写一遍」，而在于：

1. **独立执行模型**：Go 的 map 遍历是随机序 → 强制暴露「分组输出未排序」类错误；
2. **独立字符串模型**：Go 的 `string` 是字节序列、`range` 按 rune → 强制暴露
   「UTF-8 字节序 vs 字符序」的判据错误；
3. **无共享库**：`encoding/json` 与 Python `json` 在非法 JSON、大整数、转义上的
   行为不同 → 强制暴露规格里未写清的地方。
