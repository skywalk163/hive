## 背景

现在的 AI 路径是单向流水线：`light ai check` 只往控制台打文本，外部 Agent 没法消费。评审要求把它变成**闭环**：`generate → check → fix → re-check`，前提是 check 能吐出机器可读的诊断。

`cli/light.py` 第 1753 行起是 `ai check` 的实现，目前结果全部 `print()`；`[1/2] 语法检查` 这类进度行也混在 stdout 里。

## 要做什么

1. `light ai check <file> --json`：
   - stdout **只输出一个 JSON 对象**，不带任何前后杂字；所有进度/日志走 stderr（无 `--json` 时保持现有输出逐字不变）；
   - schema（`schema_version: 1`）：
     ```json
     {
       "schema_version": 1,
       "ok": false,
       "file": "demo.light",
       "backend_hints": [{"keyword": "类", "desc": "class 定义", "suggestion": "改用 --backend llvm-typed"}],
       "diagnostics": [
         {"code": "L4001", "severity": "error", "stage": "模块导入",
          "line": 7, "column": 5, "message": "…", "hint": "…",
          "fixes": ["…"], "candidates": ["子串位置"], "provisional": false}
       ],
       "duration_ms": 42
     }
     ```
   - `line` 未知时为 0，不许猜。
2. 退出码契约写进 `--help` 与 `docs/AI编程指南.md`：`0` 无 error 级诊断、`1` 有 error 级诊断、`2` 用法/文件错误。
3. 诊断来源：优先 `src.diagnostics.explain()`（T-0316）；未命中时 `code="L0000"` + `provisional: true`，**不要臆造具体码**。
4. `--json` 可与 `--run` 组合：运行失败进 `diagnostics`（`stage="运行"`），不让进程直接吐 Python traceback 到 stdout。
5. `tests/test_ai_check_json.py`（subprocess 跑真实 CLI）：
   - stdout 能被 `json.loads` 直接解析；
   - 三种退出码各一例；
   - 每个 diagnostic 必备字段齐全、类型正确；
   - 无 `--json` 时输出与改动前快照一致（快照文件放 `tests/fixtures/ai_check_text_baseline.txt`，只比对关键行，避免环境差异）；
   - `--json` 时 stderr 里能看到进度，stdout 里没有。

- 不改变 `light check` / `light type-check` 的现有行为与退出码。
