# 续训验证 3000 步是否为上限：到 5000 步，给出可复现的对比结论

> 来源：`reports/训练报告_v2.md` §九-1 原文——
> 「**没证明 3000 步是上限**：val 仍在 2.69 平台，继续加到 5000 步可能还有 0.05–0.1 的收益，
> 但本卡 6 h 预算内不做外推。」
> 本卡就是把这个「不做外推」补上：**只外推到 5000 步，不多不少**。

## 一、已知事实（照抄报告，不改）

| 项 | 基线值（3000 步，FreeBSD 长跑 2h23min） |
|---|---|
| train loss | 8.08 → 1.26 |
| val loss | 4.82 → 2.69（最低）/ 2.72（末） |
| 过拟合起点 | 未观察到（3000 步内） |
| 生成 | 4 条里 2 条 `ai check ok=true` |
| 配置 | `configs/demo-3m.json`，d=192 / L=6 / V=4096 ≈ 3.4M |

## 二、要做什么

1. **同一配置、同一 seed、同一数据，跑到 5000 步**（`--eval-every 100 --log-every 50`），
   继续用同一台机器，避免换机引入口径差。
2. 记录 **val loss 最低点出现在第几步**，以及 4500—5000 区间是否回抬（过拟合判据）。
3. 在**同一份固定测试集**上比 3000 步与 5000 步两个 checkpoint：
   - `light ai check` 结构合法率（真跑、全分母、空输出判不合法）；
   - 若 T-0370/T-0371 已合入，用同一套评测口径对齐（不另立口径）。
4. **给出明确结论**，三选一并写明依据数字：
   - `3000 步接近上限`（5000 步 val 收益 <0.02 且已回抬）；
   - `5000 步仍有收益`（val 最低点后移且收益 ≥0.05）；
   - `inconclusive`（预算内跑完但差异落在噪声内 —— 必须说明噪声估计方式）。

## 三、预算与纪律

- `timeout: 480` / `lease: 360`（对齐 T-0347 的训练卡规格）。
- **训练期间不要同机跑 bench**：`hive.py` 没有实现 `exclusive` 字段（v2 整合稿 §四已核实），
  只能靠派单时人工避让 —— 拿到卡后先确认目标机没有别的 lightprism 卡在飞。
- 跑不完就标 `blocked`，写明跑到第几步、卡在时间还是资源，**不交半成品冒充完成**。

## 四、交付物

- `checkpoints/demo-3m-5000/`（`train_log.json`；`model.pt` 按现有 gitignore 规则本地归档）
- `reports/续训5000步报告.md`（新建）：完整曲线、最低点、两 checkpoint 对比、结论与证据等级
- `tests/`：若有新增评测脚本，需带用例；**不改既有测试期望**

```bash
PYTHONPATH=src python3 -m pytest -q tests/      # 全绿
# 报告必须含：

```

## 六、禁止

1. 不改 `configs/demo-3m.json` 的模型尺寸（d/L/H/V）来做「更快收敛」；
   要改学习率必须同 seed 双跑对照，并在报告里单列。
2. 不改 `scripts/bench.py` 口径；3000 步与 5000 步的评测命令必须逐字相同。
3. 不拿 `≥200 tok/s` 未通过的历史事实做反转（T-0342 已裁定降级到 ~100 tok/s，不动）。
4. 不挑成功样例；生成结果全贴，失败的也贴。
