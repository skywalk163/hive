# T-0354 看板同步健康度与增量订阅

## 背景

交办方是在「hive 集群面板」上看到那句提示的。要让它彻底不再出现，
除了后端 autosync（T-0353），前端也得把「一句无差别的操作提示」换成
**同步健康度指示**，让运维一眼看出：是同步慢了、本地脏了、还是真的分叉需要裁决。

现状（`dashboard/`）：

- `app.js:8` `REFRESH_MS = 15000`，可选 5/10/15/30/60s，页面不可见时暂停；
- `app.js:1142` 那句横幅由 `state.tasks.some(t => t.local_stale)` 驱动；
- `serve.py` 每次请求重读 `status.json` + `Cache-Control: no-store`，
  `X-Snapshot-Mtime` 超过 10 分钟加 ⚠；
- `serve-dashboard.sh:21` 每 **20s** 跑一次 `status --json > status.json`；
- 已有 `/api/push` agent 主动上报加速通道（`serve.py:1092`）。

规范见 `H-LSA-协议设计-借鉴OSPF.md` §6（横幅语义升级）、§2（T1 摘要）。

## 要做什么

1. **横幅改造**（`dashboard/app.js`）：改读 `sync_health` 对象，分四种展示：
   | 情况 | 展示 |
   |---|---|
   | 同步正常 | 横幅隐藏，顶栏显示 `LSDB seq` / `最后同步` / `档位 T0/T1/T2` |
   | 同步滞后（T0/T1 未到） | 「状态同步中，已落后 N 条」+ 自动重试倒计时，**不叫用户去 pull** |
   | 本地有未提交改动 | 「本地有未提交改动，自动同步已跳过」+ 提示联系改动主人，不提供一键 pull 按钮 |
   | 本地与 origin 分叉 | 「分叉，需人工裁决」+ 具体 `head_sha` / `remote_sha` |
   **彻底删除「请执行 git pull（或 hive sync-repos）」这句无差别提示。**
2. **增量订阅**（`dashboard/serve.py`）：
   - `/api/status` 增加 `X-Hive-LSDB-Seq` 响应头与 `sync_health` 字段；
   - 支持 `GET /api/status?since=<seq>` 只回变更部分（对齐既有 `/api/cluster/wait?since=N` 长轮询思路），
     无变更时返回轻量 `304 / {"unchanged":true}`，避免 15s 全量重传；
   - **保留** `Cache-Control: no-store`、`X-Snapshot-Mtime` 10 分钟告警、`/api/push` 加速通道，
     不改 `POST /api/task` 的按钮 → CLI 写路径（看板只读是既有纪律）。
3. **落盘节流**（`scripts/serve-dashboard.sh`）：20s 节拍保留，但改为
   **仅当 `sync_health.seq` 变化时才重写 `status.json`**，避免 20s 一次全量序列化；
   节拍同样加 ±20% jitter（对齐设计文档 §4 第 6 道闸，别让多机看板同时落盘）。
4. **前端刷新策略**：保留 15s 自动刷新作为兜底档位，但优先走增量订阅；
   页面不可见时暂停的逻辑不变。
5. **`tests/test_dashboard_hlsa.py`**（Python 侧，断言渲染分支与 API 契约）：
   四种横幅分支各一条、`since` 参数无变更返回 `unchanged`、
   `X-Hive-LSDB-Seq` 存在、`no-store` 未被删、`sync_health` 缺失时**优雅降级**到旧 `local_stale`
   （滚动升级期间旧后端不能让看板白屏）。
   `dashboard/dev/hlsa_banner_test.js` 为可选 jsdom 前端测试，能跑就跑，不作为唯一判据。

## 不要做什么

- 不改 `hive.py`（T-0353）、`hive_cluster.py`（T-0352）、`hive_control/*`（T-0351）；
- 不删 `Cache-Control: no-store`、不改 `POST /api/task` 只读纪律、不让看板直接写 Git；
- 不把前端刷新压到 5s 以下、不做「每次刷新拉全量快照」的实现；
- 不把「本地脏」显示成「同步故障」，不提供会 reset 工作区的按钮；
- 不碰生产 8787 实例、不重启 `serve-dashboard.sh`（生产）、不改 `config.json`。

## 完成标准

1. 四种同步状态的前端分支全部有对应文案，旧的「请执行 git pull」字符串在
   `dashboard/app.js` 中**零命中**。
2. 无变更时 `/api/status?since=<seq>` 返回 `unchanged`，响应体显著小于全量快照。
3. 旧后端（只有 `local_stale`、无 `sync_health`）下看板不白屏，降级路径有测试覆盖。
4. `status.json` 在无变更的 30 分钟窗口内重写次数为 0（或仅 T2 兜底 1 次）。
5. pytest 全绿。
