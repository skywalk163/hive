## 背景

2026-11-26 08:40（+08:00）经 hived HTTP MCP（127.0.0.1:8790，hive 0.16.09）调
`hive_whoami`，协议握手正常，但工具返回 error 信封：

```
TypeError: can't compare offset-naive and offset-aware datetimes
```

## 根因

`mcp_cache.py` 的 `ReadCache.refresh()` 在 store 模式下，把 store 的 epoch 租约
转 ISO 串时手写了：

```python
claim["lease_until"] = iso(datetime.fromtimestamp(float(claim.get("lease_until") or 0)))
```

`datetime.fromtimestamp(epoch)` **没带 `tz=timezone.utc`**，产出 naive 本地时间；
`mcp_server.py` `_rows()` 里 `parse_iso(lease_until) < now()`（`now()` 是 aware），
naive 与 aware 比较直接抛 TypeError。

影响面：**只有走 hived HTTP（读缓存）的客户端会挂**（所有 MCP 读工具只要
`_rows` 扫到带租约的卡就崩，不止 whoami）；stdio 模式（cache=None）不触发，
所以 CLI `hive status` 一直没炸，问题被掩盖到今天。

## 修法

- `mcp_cache.py` 改用现成的 `hive.lease_until_iso()`（tz-aware、含脏数据兜底），
  删掉不再用的 `datetime` 导入；
- 新增回归测试 `tests/test_mcp_cache_lease_tz.py`：stub store 返回 epoch 租约，
  断言缓存里的 `lease_until` 能与 `now()` 安全比较。

## 验证
