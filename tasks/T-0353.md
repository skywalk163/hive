# T-0353 协调仓自动同步与 `local_stale` 语义升级

## 背景

交办方看到的那句提示，出处是 `dashboard/app.js:1142` 与 `hive.py:5589`：

> 本地协调仓落后 origin/main，卡面状态可能不是最新；
> 在协调仓执行 git pull（或 hive sync-repos）后刷新看板

判定在 `hive.py:5468-5476`：`cmd_status` 比较 `HEAD` 与 `origin/main`，
落后且非祖先就置 `local_stale`。设计理由见 `docs/状态一致性修复-2026-11-11.md:16`：
**「不擅自替用户 merge 脏工作区」**——这条理由是对的，**不能推翻**。

所以正确解法不是「让 status 每次都 pull」，而是：

- **干净工作区 + 可 ff-only → 自动同步**（交办方「它应该自动更新啊」）；
- **脏工作区 → 绝不 merge/reset**，只把横幅说清楚；
- 同步时机由 **T2 1800s ±20% jitter 兜底 + T0 事件触发**驱动，
  不是每次 `status`（20s 落盘一轮）都去连 Gitea；
- 「要不要问 Gitea」先看 T1 组播带来的 `head_sha`，只有 sha 不同才走
  `fetch_if_changed()` 的 `ls-remote` 前置比对（`FETCH_IF_CHANGED_TTL_S=10.0` 保留）。

**当前生产协调仓恰恰是脏工作区**（7 个 M 文件 + 3 个未跟踪文件，别人的在途产物），
这张卡最容易出事的地方就是为了消横幅去 reset 它——写死不许。

规范见 `H-LSA-协议设计-借鉴OSPF.md` §6（三态处置）、§2（T2）、§4 第 6 道闸。

## 要做什么

1. **三态判定**（`hive.py` 的 `cmd_status`）：
   - 用 `git status --porcelain` 判断工作区是否干净；
   - 干净 + `merge-base --is-ancestor HEAD origin/main` → **autosync**：`merge --ff-only`；
   - 干净 + 分叉（non-ff）→ 不自动 merge，横幅写清「本地与 origin 分叉，需人工裁决」；
   - **脏 → 跳过一切写操作**，横幅改为「本地有未提交改动，自动同步已跳过」，
     并给出可操作建议（先由改动主人提交/保存），**不做 merge / reset / checkout / stash**。
2. **节流器**：把 `fetch_if_changed()` / `sync-repos` 的触发统一交给 `hive_lsa` 的
   T2 / T0 节拍：
   - `LS_REFRESH_S=1800.0` **±20% jitter**，30 分钟一次兜底对账；
   - 收到 T0 触发 LSA 或 T1 组播 `head_sha` 变化时可提前同步，但受最小间隔约束；
   - `orchestrate --interval 60`（`scripts/master.sh`）每 tick 都 fetch 的旧行为要收敛，
     避免 60s 一次 `ls-remote` 打 Gitea；
   - 本地 `ls-remote` 结果 TTL 10s 缓存保留，不与组播判断冲突。
3. **`sync_health` 字段**：`status --json` 新增结构化对象
   `{"lsdb_seq", "last_sync_at", "head_sha", "remote_sha", "behind", "tier": "T0|T1|T2", "reason"}`；
   **保留 `local_stale` 布尔字段向后兼容**（旧看板 / MCP 缓存仍在读它），
   但看板改读 `sync_health`（T-0354 负责）。
4. **`hive_repos.py` 协同**：`sync-repos` 复用同一节流器与三态判定，
   `needs-confirm` / `missing` 的返回语义不变，不因为「自动」就替用户猜路径。
5. **`tests/test_status_autosync.py`**：
   - 干净 ff-only 场景：自动同步成功、`local_stale` 转 false、卡面读到新状态；
   - 干净分叉场景：不 merge、`behind` 被标出、给出人工裁决提示；
   - **脏工作区场景：断言 `git status --porcelain` 前后完全一致、无任何写操作**
     （这条是本卡最重要的回归）；
   - 30 分钟内不重复触发全量对账、jitter 落在 ±20%、T0 事件可提前同步、
     `local_stale` 旧字段仍存在、`--json` 输出可解析。

## 不要做什么

- **绝对不 merge / reset / checkout / stash / clean 生产协调仓的脏工作区**；
  不为消除横幅改动别人的 7 个 M 文件与 3 个未跟踪文件；
- 不改 `hive_cluster.py`（T-0352）、`dashboard/*`（T-0354）、`hive_control/*`（T-0351）；
- 不把同步周期压到分钟级、不取消 jitter、不让 `status` 每次都连 Gitea；
- 不用内存 LSDB 覆盖 Git 卡面；Git 仍是事实账；
- 不删 `local_stale` 字段（向后兼容）；不改 `sync-repos` 的路径解析优先级（0.16.06 刚修好）；
- 不重启生产常驻进程。

## 完成标准

1. 干净工作区下，模拟子节点 push 后 `status --json` 自动拿到新卡面，
   `local_stale=false`，**无需人工 `git pull`**，端到端 ≤300s。
2. 脏工作区下横幅文案变更但工作区字节级不变（测试用 `git status --porcelain` 前后比对）。
3. 30 分钟窗口内 `ls-remote` / `fetch` 次数 ≤1 次（Leader 兜底），
   且触发时刻带 jitter，不与其他节点整点对齐。
4. 全部 pytest 用例通过，`--json` 输出同时含新 `sync_health` 与旧 `local_stale`。
