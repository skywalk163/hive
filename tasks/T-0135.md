## 背景

raccoon 发现：`mcp_server.py` 的 `TOOLS` 列表里，`hive_block` 条目结束后直接跟
`"name": "hive_unblock"`，**漏了开头的 `{`**——三个 dict（block/unblock/abort）
被并成一个，同名 key 互相覆盖。后果：

- `hive_block` / `hive_unblock` 不在 `tools/list` 里 → GUI / LLM 客户端根本看不到
  这两个工具（MCP 契约上等于不存在）；
- `hive_abort` 反而活着（覆盖后的幸存者），所以表面看只是"少了两个工具"；
- handler 其实都在（`HANDLERS` 里 `t_block`/`t_unblock` 照常注册），知道名字直接
  `tools/call` 仍能调通——所以 CLI 一直是好的，坑只在 MCP 广告位。

这和 T-0123 踩过的「往 TOOLS 列表字面量插 dict 漏 `{`」是同一类坑，当晚只做了
「改完打印 len(TOOLS) 确认」的口头纪律，没有留回归测试，于是第二次踩到。

更糟的是 `tests/test_mcp.py` 的 `EXPECTED_TOOLS`（12 个 worker 工具）本来就没有
block/unblock，`assert names == EXPECTED_TOOLS` 把 bug 表面固化成了"预期"。

## 目标

1. `mcp_server.py`：把 107–140 行区间被并掉的 dict 拆回三个（block / unblock /
   abort 各带完整的 name/description/inputSchema）。不改任何 handler 行为。
2. `tests/test_mcp.py`：`EXPECTED_TOOLS` 补上 `hive_block` / `hive_unblock`
   （worker 视角修复后应有的 14 个）。
3. **加不变式测试**（治本）：`HANDLERS` 的每个工具名都必须出现在 `TOOLS`
   （按角色过滤后）里；`TOOLS` 每个名字都有 handler；`TOOLS` 里不允许重名；
   每个条目必须是 name/description/inputSchema 齐全的合法工具对象。
   以后谁再漏括号，这条例行测试立刻红。
4. `hive.py` VERSION 0.9.10 → 0.9.11；`CHANGELOG.md` 记 0.9.11 Fixed。
