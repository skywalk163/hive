## 背景

评审的核心判断：生态冷启动不取决于「有多少」（109 个 stdlib 模块、711 项原生能力），而取决于**一个真实项目用到的 20% 是否打磨到无摩擦**。要求定义「Light 生态最小可用面（MVP Surface）」，五个方向各配一个能 `git clone` 后直接跑通的完整示例，而不是片段。

## 要做什么

1. `docs/MVP_SURFACE.md`，五个方向逐个建表：
   `文件读写 / 网络请求+JSON / 进程管理 / 测试框架 / 包与模块引用`
   每行写：状态（`稳定` / `实验` / `缺失`）、入口 API（真实函数名，如 `读取文件` 而非 `读取`）、已知坑、示例路径、最近一次验证日期。
   - 状态判定要有依据：能在示例里跑通才算「稳定」；跑不通写「缺失」并留原因。
2. `examples/mvp/` 五个示例，每个 ≤60 行 `.light`，都能直接跑：
   - `01_file_io.light`：写临时文件 → 读回 → 逐行统计字数；
   - `02_http_json.light`：请求本机 `http.server`（测试内起）→ 解析 JSON → 取字段；
   - `03_process.light`：起子进程、拿退出码与 stdout，非零退出要能捕获；
   - `04_test_framework.light`：用语言自带测试能力写 3 个断言（含 1 个预期失败演示）；
   - `05_pkg_module.light`：`light pkg run` 或 `从 … 导入` 的跨模块调用。
   每个示例首行注释写清运行命令。
3. `tests/scenarios/test_mvp_surface.py`：
   - 逐个真跑（subprocess 调 `python -m cli.light run examples/mvp/xx.light`），断言 rc=0 且 stdout 含关键标记；
   - 网络示例在测试内起 `http.server`（随机端口），**不依赖外网**；
   - 不达标的示例用 `pytest.xfail(strict=True, reason="…")`，reason 必须指向 `docs/MVP_SURFACE.md` 的具体行——不许静默 skip。
4. `scripts/run_scenarios.py`：一键跑 5 个场景，输出 `场景 | 结果 | 耗时(ms)` 表格，任一失败 rc=1，`--json` 输出结构化结果。

## 不要做什么

- 不改 `stdlib/` 实现。发现坑只记录在 `docs/MVP_SURFACE.md` 并在 summary 里建议另开卡。
- 不引入第三方依赖（requests 等一律不用，用语言自带网络能力）。
- 示例不联网、不写用户目录（一律用 `tempfile` 语义的临时路径）。
- 不为了让示例跑通而给产品代码开特殊后门。

## 完成标准

- `python -m pytest -q tests/scenarios/` 全绿（xfail 必须 strict 且带原因）。
- summary 里贴 `scripts/run_scenarios.py` 的真实输出表格，以及五个方向的状态结论。
