## 背景

T-0237（`hive 加 smoke.sh`）的判据是 `test -x smoke.sh`。产物本身没问题（Windows Git Bash
与 FreeBSD 0.88 上 `sh smoke.sh` 都 4/4 通过，0.88 上 `test -x` rc=0），但 Windows worker
上 `hive submit` 记 **failed**：

```
code: 1
tail: 'test' 不是内部或外部命令，也不是可运行的程序
```

原因：`hive_compat.py` 的垫片正则只认 `test -e/-f/-d/-r/-s`（`[efdrs]`），
`-x` 不在内 → `should_wrap()` 返回 False → 原样丢给 `cmd.exe` → 必然红灯。
这和 T-0221/T-0222/T-0225/T-0228 是同一类浪费：产物合格，判据在目标平台上跑不了。

## 目标

1. `hive_compat` 支持 `test -x`（含 `! test -x`），Windows 上用 `os.access(path, os.X_OK)` 求值；
   POSIX 上的行为一个字节都不动（`should_wrap` 本来就只在 `os.name == "nt"` 时返回 True）。
2. 补单元测试：可执行/不可执行/不存在/取反四种情形，以及 `hive.verify_command` 必须把
   `test -x smoke.sh` 包成垫片调用，而不是交给 `cmd.exe`。
3. 更新 `docs/判据与平台.md` 的「垫片覆盖范围」一节，别让文档继续说只覆盖 5 个 flag。

## 红线

- 不猜成功：只有在明确映射到的语法上返回 0/1，未知写法仍然返回 2。
- Windows 上没有 POSIX 执行位，`os.access(X_OK)` 等价于「存在」——语义差异要在
  文档和注释里写清楚，不要假装 Windows 上能测出 exec 位。
- 不动 `hive.py` 的判定逻辑（`verify_command` 只是调用垫片）。

## 验收

- `python -m pytest -q tests/test_compat.py` 全绿（含新增用例）。
- 手工：`python hive_compat.py run "test -x /不存在的路径"` → 1；
  `python hive_compat.py run "test -x docs"` → 0。
- 落地后 T-0237 重新 submit 应变为 done（原先的验证码 1 是平台假失败）。
