## 背景

T-0477 把 standard 白名单从 168 收到 22（`基础工具名表` 20–30），并按
「白名单是唯一保留依据」重写了 `总入口.预设保留工具`：不在白名单里的工具一律注销，
MCP 工具靠 `mcp__*` 通配 + `HARNESS_MCP_TOOLS` 开关单独保留，不再因为「没有叶子依据」默认留下。

T-0469 的 `test_mcp工具与预设过滤共存` 仍写着老口径：

    assert int(kv['MCP_后']) == int(kv['MCP_前'])   # 过滤不许砍掉任何工具

实测 `MCP_前=162`、`MCP_后=24`（22 白名单 + 2 个假 mcp__ 工具），断言结构性失效——
**这个断言在 main 基线上就是红的**（`git stash` 掉别的改动后同样 `assert 24 == 162`），
不是某张卡引入的回归。它挡住了 T-0487 的验收（`hive_submit` 记 failed），也注定挡住 T-0488 / T-0489 的全量回归。

## 目标

只改 `tests/test_T0469_提示与工具面.py` 里 `test_mcp工具与预设过滤共存` 这一条函数体的断言口径，
把它换成「白名单收口之后仍然正确」的判据，driver 可同步微调（只加打印，不改其它 key 的口径）：

1. 删掉 `assert 后 == 前`，改为：
   - 从装配日志行解析 `[装配] 预设=standard 保留=(\d+) 白名单外注销=(\d+)`；
   - `assert 后 == 保留 + 2`（2 = 本探针手工挂的 `mcp__demo__echo` / `mcp__demo__add`）；
   - `assert 20 <= 保留 <= 30`（T-0477 的白名单规模口径）；
   - `assert 白名单外注销 > 0`（过滤真的发生了，别再回到 168 全量）；
2. 保留并在原意上加严：`MCP_echo在` / `MCP_add在` / `MCP_待办在` / `MCP_目标在` 必须为 True，
   `MCP_无叶子` 必须为 0；
3. 其余 9 条用例、其它 driver key、其它断言一律不动。
