# 787KB 运行时快照入库 + README 里有内网地址

## 现状（实测）

```
$ cd hive && git ls-files | grep -E 'status\.json|live-status|\.bak\.'
dashboard/live-status.json
dashboard/live-status.json.bak.20261028
dashboard/live-status.json.bak.20261029b
dashboard/sample-status.json
dashboard/status.json.bak.20261029
status.json
```

体积：

```
350K  dashboard/live-status.json
358K  status.json
合计 787K（含 3 个 .bak）
```

`.gitignore` 的现状（`:8-13`）：

```gitignore
dashboard/status.json          # ← 只忽略了这一个
dashboard/status.json.tmp*
dashboard/pushed-status.json
```

**漏了三个**：
1. 根目录的 `status.json`（不是 `dashboard/status.json`）
2. `dashboard/live-status.json`
3. 所有 `.bak.*` 快照

### 顺带：README 有内网地址

```
README.md:75   # git clone http://192.168.1.5:3000/skywalk/hive.git hive
README.md:130  - 默认 HTTP `8788`、UDP 发现 `8789`；跨网段用 `--seed 192.168.1.5:8788`。
README.md:403  远程看：`ssh -L 8787:127.0.0.1:8787 skywalk@192.168.0.88`
```

仓库是 **public**（`github.com/skywalk163/hive` + `gitcode.com/skywalk163/hive`）。
内网 Gitea 地址、内网 IP、内网用户名放在公开 README 里不合适。而且 `status.json` 里也有：

```
$ grep -oE '192\.168\.[0-9]+\.[0-9]+' status.json | sort | uniq -c
      2 192.168.0.86
      3 192.168.1.5
```

## 起点线索

- `dashboard/sample-status.json` 是**给文档/演示用的示例**（`dashboard/serve.py:79` 有
  `"/sample-status.json": ("sample-status.json", ...)` 路由），**这个要留**
- `dashboard/serve.py` 的 `--status` 默认指向 `dashboard/status.json`（已被忽略）
- README 里那 3 处内网信息，`192.168.1.5:3000` 是自建 Gitea，`192.168.0.88` 是门禁机

## 目标

### 1) 补 `.gitignore`

```gitignore
# 运行时快照（频繁覆盖、体积大、含内网拓扑，一律不入库）——T-0267
status.json
dashboard/live-status.json
dashboard/*.bak.*
```

要点：
- `status.json`（无前导路径）会匹配**任意层级**的同名文件，覆盖根目录和 `dashboard/`
- `dashboard/*.bak.*` 吃掉三个 `.bak` 快照
- **不要**加 `dashboard/sample-status.json` 到忽略列表，它是演示样例

### 2) 从索引移除（保留工作区文件）

```bash
cd /home/skywalk/dswork/hive
git rm --cached status.json dashboard/live-status.json \
    dashboard/live-status.json.bak.20261028 \
    dashboard/live-status.json.bak.20261029b \
    dashboard/status.json.bak.20261029
git commit -m "chore(T-0267): 运行时状态快照移出版本库 + 补 gitignore"
```

用 `--cached`：本机 `hive orchestrate` 和看板还在写这些文件（我看到有两个常驻进程
`hive.py orchestrate` 和 `cluster serve` 在跑），物理删掉会让它们报错。

### 3) README 脱敏

三处的处理建议：

| 行 | 现状 | 改法 |
|---|---|---|
| 75 | `# git clone http://192.168.1.5:3000/skywalk/hive.git hive` | 删掉这一行，或改成 `<自建 Gitea 地址>` 占位并说明「内网地址不公开」 |
| 130 | `跨网段用 --seed 192.168.1.5:8788` | 改成 `--seed <seed-ip>:8788` |
| 403 | `ssh -L 8787:...:8787 skywalk@192.168.0.88` | 改成 `ssh -L 8787:127.0.0.1:8787 <user>@<gate-host>` |

**保留**：端口号（8787/8788/8789）不算敏感，是产品默认值，留着。
**保留**：`gitcode.com` / `github.com` 的公网地址，那是给人用的。

### 4) 在 README 顶部加一句免责

如果 README 里以后还要写示例 IP，加一条约定：

> 文中 `<...>` 为占位符。本仓为公开仓库，请勿在文档中提交真实内网地址与主机名。

## 红线

- **不删 `dashboard/sample-status.json`**（演示路由在用）
- 不 kill 常驻进程（`orchestrate` / `cluster serve` 正在跑，杀了会影响看板）

- 不写 token / 密钥 / 真实内网 IP
