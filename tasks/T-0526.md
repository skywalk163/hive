## 背景

`T-0490`（commit `a1cec55`，2026-11-25）为「排队兜底」在 `src/web服务器.light` 的 `取队列闸门()`（约第 794–802 行）里起了一条兜底线程：

```
如果 己.唤醒线程 == 空:
  设 己.唤醒线程 为 新建 线程(排队唤醒循环, 己)
  己.唤醒线程.开始()
```

`排队唤醒循环`（约第 2931 行）是 `当 真: time.sleep(队唤醒周期秒/2s)` —— **没有退出条件**；而 `Web服务端.停止()`（约第 357 行）只做 `己.服务端.停止()`，**不停这条线程**。于是凡是走过流式/排队路径的 example 都会「断言全过、进程退不出」，在门禁里被 timeout 判红。

## 修法（择一并写清理由）

1. **加停止标志 + join（首选）**：`Web服务端` 增属性 `唤醒停止 等于 假`；`停止()` 里先置 `真`，再 `join`（带 3s 超时，禁止无限等）；`排队唤醒循环` 的 `当 真` 改成检查该标志，或把 `time.sleep(2)` 换成可被立即唤醒的 `线程().事件` 等待。
2. 若 `stdlib/线程.py` 的 `新建 线程` 支持守护标志，直接设守护线程（要确认进程退出语义真被拦住，不能只改注释）。

要求：`停止()` 可重复调用、未起线程时 join 为 no-op；不改排队兜底的业务语义（T-0490 的孤儿待办补拉仍要工作）。

## 必须补的回归判据
