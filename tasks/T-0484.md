## 背景

本仓的压缩**不是模型摘要**：`src/压缩.light:40 压缩造摘要(会话对象, 尾号, 摘要器=空)`
在 `摘要器 == 空` 时走确定性分支——把旧消息文本拼成 `【压缩摘要】\n…`，再由
`压缩配套.包摘要框架` 包上 `<compacted-summary>`。`压缩E5.压缩配置()` 只返回
`{上下文窗口, 阈值比例, 保留条数}`，**从不注入摘要器**；`web服务器` 也没有传。

DSH 的 compaction-basic 是专门的一次模型调用，末尾指令固定八段
（`packages/compaction/compaction-basic/src/summarizer.ts` 的 `COMPACTION_INSTRUCTION`）：
`Primary Request and Intent / Key Technical Concepts / Files and Code / Errors and Fixes /
Pending Jobs / Current Work / Next Step / Critical Context`，并明确要求：

- 保留精确路径、命令、报错串、标识符、数值、函数签名；
- 忠实保留用户纠正与显式指令；
- 不提及「这次是摘要请求 / 上下文被压缩过」；
- 已有旧 `<compacted-summary>` 时按**同结构合并**（真事实保留、陈旧丢弃）；
- 只输出 checkpoint 文本，不调工具。

本卡只做**纯模块**（不接模型、不接网络），把这份指令与校验落地；接线归 T-0486。

## 目标

新增 `src/压缩摘要器.light`：

1. `造摘要指令()` → 中文版八段指令（标题固定、顺序固定、`(none)` 空段占位、
   「保留原文事实」「不提及压缩」「只输出 checkpoint 文本」三条规则）。
2. `造摘要请求(消息表, 旧检查点文本="")`：
   - 复制 `消息表`（不原地改），末尾追加一条 `{"role":"user","content":[{"type":"text","text": 指令}]}`；
   - `旧检查点文本` 非空 → 指令里追加「先前检查点如下，按同结构合并：\n<文本>」；
   - 返回新消息表。
3. `校验摘要(文本)` → `{"ok": 布尔, "缺段": [标题…]}`：
   - 八个 `##` 标题必须全部出现且顺序与常量一致；
   - 缺任意一段 → `ok=假` + 缺段列表（供 T-0486 回退）。
4. `抽取摘要文本(块表)` → 把所有 `type=="text"` 的块拼接并 `去除首尾空白`；
   无文本块 → `""`。
5. `摘要指令字符上限()` = 4000；`八段标题()` 返回副本。

## 红线

- 不引网络、不调模型、不读文件系统；纯函数 + 常量；
- 不改 `src/压缩.light` / `src/压缩配套.light` / `src/压缩E5.light`（接线归 T-0486）；
- 八个标题是**契约**：中英对照固定在模块注释里，后续卡不许改名；
