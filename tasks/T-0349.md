# T-0349 前置：隔离开发沙箱与流量基线复现

## 背景

交办方明确要求「hive 的新代码先在开发环境里测试，不要干扰当前的 hive 集群，
因为当前的 hive 集群里有任务，一不小心就会导致整个开发工作的停滞」。

现场事实（2026-11-14 02:00 实测）：

- 生产协调仓 `~/dswork/hive` 有 **7 个未提交改动**（`hive.py` +261 行、
  `hive_compat.py`、`dashboard/app.js`、`dashboard/README.md`、
  `agents/doubao-win.json`、`scripts/freebsd/hive-cluster-run.sh`、
  `docs/判据与漂移.md`）和 **3 个未跟踪测试文件**，是别的在途任务的产物。
- `scripts/dev-cluster.sh` 已经做到了运行时隔离（8888 / `hive-dev` / `127.0.0.1` /
  `--no-discover --no-sync --no-store --no-mcp`），但 **L1 代码隔离和 L3 网络隔离还缺**：
  脚本第 29 行 `REPO_DIR` 写死为「脚本上级目录」，也就是**直接指向生产 `hive.py`**；
  组播组仍沿用生产 `239.255.42.1:47899`。
- 控制面当前 `plane_available:false`（装配缺陷，T-0351 修），所以现在开发实例
  即使误连生产组播组，生产也不会收到——但不能赌这个。

**本卡是第 0 批唯一前置**，产出后续 6 张实现卡共同引用的「开发副本路径 + 接入方式 +
流量基线分母 + 合入闸门清单」。不先做这一步，第 1 批任何一张卡都不许开工。

规范见本目录 `H-LSA-协议设计-借鉴OSPF.md` §7（隔离五条）与 §5（指标）。

## 要做什么

1. **建立独立开发副本**：默认 `~/dswork/hive-dev-src`，从当前 `origin/main`
   （`e0acfa6`）做本地 clone（建议 `git clone --local --no-hardlinks`），
   **不带生产工作区的任何未提交改动**。记录 clone 的 HEAD sha 与生成时间。
   若该路径已被占用，改用它处并在文档里写明确切值——后续卡一律引用文档里的值，不自己猜。
2. **改造 `scripts/dev-cluster.sh`（只改开发副本里的这份）**：
   - 新增 `HIVE_DEV_REPO` 覆盖项，使 `REPO_DIR` / `HIVE` 指向开发副本的 `hive.py`；
     不传时保持原行为（脚本上级目录），不改既有默认路径语义；
   - 开发实例组播组/端口改为可配，默认 `239.255.42.2:47900`
     （生产是 `239.255.42.1:47899`），并设 `project_tag=hive-dev`；
   - 保持 `8888` / `cluster_id=hive-dev` / `127.0.0.1` /
     `--no-discover --no-sync --no-store --no-mcp` / state_dir `~/.hive/dev-cluster`
     **全部不变**，这些是已验证有效的隔离参数。
3. **隔离自检 `tests/test_dev_cluster_isolation.py`**（纯 Python，可注入路径，不依赖真实网络）：
   - 断言开发实例配置里不出现生产端口 8787/8788/8789/8790、生产组播组
     `239.255.42.1`、生产 state_dir `~/.hive/cluster`；
   - 断言 `cluster_id == "hive-dev" != "hive"`；
   - 断言 `HIVE_DEV_REPO` 解析出的 `hive.py` 不在 `~/dswork/hive/` 下；
   - 提供 `assert_isolated()` 供后续卡复用。
4. **`tools/traffic_baseline.py`**：在 dev 环境采集本批优化前的**分母**，
   输出 JSON（可复现、带时间戳与参数），至少包含：
   - 心跳请求 / 响应平均与峰值字节（对齐 0.16.05 的 685B / 2.9KB 口径）；
   - `state.json` 落盘次数与字节 / 分钟；
   - 每 30 分钟窗口内的 `ls-remote` / `fetch` / `pull` 次数（**现状基线**）；
   - 空闲期与活跃期控制面带宽（3 节点估算，对齐 ~9KB/s 基线）。
   **不许填估算值当实测值**，跑不出来就明确写 `unavailable` 并说明原因。
5. **`docs/H-LSA-开发隔离与基线.md`**：写清
   (a) 开发副本确切路径与 HEAD sha；
   (b) 后续卡怎么接入（`HIVE_DEV_REPO=... scripts/dev-cluster.sh start`、
   verify 在哪个 cwd 跑）；
   (c) 基线数字表；
   (d) **合入闸门检查清单**（供 T-0357 使用）：生产 term 不变、看板仍 `hive`、
   开发日志无生产地址、无生产组播包、在途改动完好无损、备份位置。

- **不碰生产 `~/dswork/hive/` 工作区里的任何文件**（本卡改的是开发副本里的脚本副本）；
  不 stash / checkout / reset / merge 别人的未提交改动；
- 不重启 `service hive_cluster`、`master.sh`、`cluster serve`（生产 8788）、看板 8787；
- 不向生产组播组 `239.255.42.1:47899` 发任何一个包；
- 不改 `config.json` / `.env` / `agents/*.json` / `tasks/*.md` / `results/*`；
- 不跑 `doctor --repair`，不执行 `upgrade publish|apply|rollout`；
- 不把「生产未提交改动」复制或提交到开发副本——它们是别人的在途产物。

## 完成标准

1. `HIVE_DEV_REPO=<开发副本> scripts/dev-cluster.sh start` 起得来，
   `GET http://127.0.0.1:8888/api/cluster/health` 返回 200 且 `cluster_id=hive-dev`。
2. 连续 3 次 `dev-cluster.sh restart` 后，生产 `~/.hive/cluster/state.json`
   的 `term` / `leader_id` / `peers` **完全不变**，看板 8787 仍读 `cluster_id=hive`。
3. 开发集群日志里**没有任何**生产地址、生产端口、生产组播组字符串。
4. `tools/traffic_baseline.py` 产出可复现 JSON，字段齐全，缺失项如实标注。
5. 合入闸门清单逐条可勾选，且被 T-0357 直接引用。
