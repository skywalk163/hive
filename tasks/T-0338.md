# 补 lightprism chat 与 --format json 入口（V1/V3）

## 背景

T-0334 验收（`docs/Demo验收报告.md` §2/§4）判 V1、V3 未通过：计划书 §2 的判据入口
`lightprism chat --prompt "..."` 与 `--format json` 在 main 上都不存在——`cli.py` 只有
tokens / budget / map-check / parse / l0 / export / config 七个子命令。这不是模型能力问题，
是入口没实现，导致「能加载并推理」「JSON 模式」两条标准无法被验收。

## 目标

- `cli.py` 新增 `chat` 子命令：`lightprism chat --prompt "..." [--max-tokens N] [--ckpt PATH]`；
  - 复用 `lightprism.demo.smoke` 的 DemoGenerator（KV cache），不另写推理；
  - 默认 checkpoint 与 `scripts/demo.sh` 一致（`checkpoints/demo-3m/model.pt`）；
  - 缺 checkpoint 时给可读错误、**非零退出**（chat 是推理入口，没模型就是失败；
    与 demo.sh「缺 checkpoint 不算执行错误」的口径区分开，别混）。
- 增加 JSON 输出（`--format json` 或 `--json`），字段至少含 `text`/`tokens`/`tok_s`，
  且 `json.loads` 必能解析；空输出不许当成功（V2 的假绿教训）。
- `tests/test_cli_chat.py`：参数解析、JSON 可解析、缺 checkpoint 语义，用假生成器，
  **不依赖 torch 与真模型**。
- 用法写进 `--help`；`docs/Demo使用.md` 由 T-0341 统一收口，不在本卡改文档。

## 红线

- 不改 `scripts/bench.py`、模型结构、bench 口径；
- 不引入 torch 以外的新依赖；
- 纯 CLI 测试不得因缺 torch 就整体 skip。

## 验收

- `python3 -m pytest -q tests/test_cli_chat.py` 全过；
- `python3 -m lightprism chat --help` 退出码 0；
- 有 checkpoint 时 `--format json` 输出可被 `json.loads`（报告贴真实命令与输出）。
