# 前置：把两个仓登记进来 + 让至少一台能自动接活

## 背景（都是实测，不是推测）

我逐个读了 `hive/agents/*.json` 全部 15 份配置，现状是：

1. **15 台全是 `"mode": "manual"`，没有一台有 `"dispatchable": true`**。
   源码 `hive.py:2700` 附近：

   ```python
   mode = a.get("mode") or ("manual" if a.get("manual") else "exec")
   if mode == "manual" and not a.get("dispatchable"):
       blocked.append(f"人工优先（{name} 是 manual 模式）")
       continue
   ```

   所以 `hive dispatch --apply` 恒输出「没有可分派的任务」。你已经决定这轮人工分发，
   这条不影响本轮，但会一直卡住以后所有批次。

2. **`lighthive` 和 `lightplugin` 不在任何 agent 的 `repos` 里**。
   `hive.py:5784` 的 `draft_lint`：

   ```python
   elif not any(repo in (a.get("repos") or {}) for a in agents.values()):
       errors.append(f"repo {repo!r} 没有任何 agent 登记 —— 这张卡永远派不出去")
   ```

   这意味着 T-0270（lighthive 治理）和 T-0274（LH 缺陷账回灌）现在落卡也永远 `ready`。

## 目标

### 1) 给 `lighthive` / `lightplugin` 登记 repos

在**至少两台** agent 里补上这两条路径，建议 `workbuddy`（`host: fb98`，Linux，路径对）和
`fb88-dsh`（`abilities` 里已有 `code/ci/docs/verify`）。

`workbuddy` 补完应该长这样（只列变化部分）：

```json
"repos": {
  "hive": "/home/skywalk/dswork/hive",
  "lightharness": "/home/skywalk/dswork/lightharness",
  "lightmem": "/home/skywalk/dswork/lightmem",
  "light": "/home/skywalk/dswork/light",
  "lighthive": "/home/skywalk/dswork/lighthive",
  "lightplugin": "/home/skywalk/dswork/lightplugin"
}
```

Windows 机器上的 `repos` 路径是 `G:\...` 那种形态，**如果某台机器没有这两个仓的克隆，就不要给它加**
—— 加了会让 dispatch 把卡派过去，而那边 `git worktree add` 会直接失败。

### 2) 给一台开 `dispatchable`

只给**确实有常驻 worker 在收件箱接活**的那台加 `"dispatchable": true`。
从 `abilities` 看，`fb88-dsh` 有 `code/ci/verify/python/pytest`，是最像执行机的。

⚠️ **这一步需要业主确认**：`dispatchable: true` 会让 `dispatch --apply` 真的把卡派出去。
如果不确定哪台有常驻 worker，**只做第 1 步，第 2 步留着**，并在正文里写清楚为什么没做。

### 3) 顺手把踩坑写进文档

在 `docs/AGENT快速上手.md` 里补一小节「新仓接入三件事」：
- 在目标 agent 的 `repos` 里加路径（否则卡永远派不出去）
- 该机器要先 `git clone` 一份，`worktree` 是建在克隆之上的
- `manual` 机器要显式 `dispatchable: true` 才会被 `dispatch --apply` 选中

## 红线

- 只改本卡 `locks` 里那三个文件，**不要动 `hive.py`**（T-0261 正在改它）
