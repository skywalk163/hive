## 背景（现场实例：2026-11-20 T-0410）

hive 的 store 后端租约时长已由 T-0387（commit `88536cb`）修成「读卡面 `lease_minutes`」，
卡面没写才退回 `STORE_LEASE_MINUTES = 10`。但这次仍复现了 **10 分钟租约**：

- T-0410 发卡时卡面 `lease_minutes: 300`、`timeout_minutes: 180`（正确）；
- 17:44 agent `lightharness-fb98` 领取时，store 里的 claim `lease_until` 只到 17:54（**10 分钟**）；
- 卡面 `lease_minutes=300` 没生效 → 说明首领那一刻 store 里的 task 记录**没有 `lease_minutes` 字段**（或还是旧值），
  `store_lease_minutes_of(card)` 取到空，退回 10 分钟兜底；随后租约过期，卡被判 stale/running，
  而 0.88 leader 侧其实已是 ready —— 本机看板残留一份假「跑飞」快照。

根因判断（需本卡证伪/确认）：新卡 push 到协调仓 main 后，**store 的摄入（ingest）有延迟或条件**，
首领在 store 尚未摄入最新卡面（尤其 `lease_minutes`）时发生，于是用了兜底值。
`_ingest_missing_card` 只在 claim 抛 `no_task` 时补登记，补登记拿到的是基本信息，
未必带全 `lease_minutes`。

## 目标

1) **复现与取证**：在 store 模式下，构造「卡面有 `lease_minutes=300` 但 store task 记录缺该字段」的场景，
   调 `store_lease_minutes_of` / claim 路径，证明会退回 10（贴输出）。若无法复现，说明真实根因是别的，写清证据。
2) **修复（择一或组合，按取证结果定）**：
   - claim 前若 store task 的 `lease_minutes` 缺失/为 0，**先从 Git 卡面补读并更新 store task**，再算租约；
   - 或 `_ingest_missing_card` 补登记时把卡面完整字段（至少 `lease_minutes`/`timeout_minutes`）写进 store；
   - 或首领入口统一用「Git 卡面 lease_minutes 为准」，store 只做锁、不做租约时长的真相源。
3) **一致性兜底**：claim 成功后，回写确认 store claim 的 `lease_until` 与卡面 `lease_minutes` 一致；
   不一致则告警（log）并按卡面值纠正，避免再次出现「卡面 300、实际 10」。
4) **回归测试**：新增测试钉住「新卡 push 后首领立即领取也必须按卡面 lease_minutes 算租约」，
   而不是 10 分钟兜底；反证：退回旧逻辑该测试必须红。
5) **文档**：在 `docs/` 或 `CONTRIBUTING.md` 补一条运维须知：
   「新 push 的卡首领需确保 store 已摄入 lease_minutes；否则会退回 10 分钟兜底导致误判跑飞」，
   写清如何检查（`hive store` / 查 store task 字段）与如何规避。
