## 背景

本仓的权限与审批**只在工具层拦**：`src/权限.light`（预设全放行/按类别/全拒绝/自定义，
放行·审批·拒绝三类）与 `src/审批.light`（策略：询问/从不）都实现了，
但模型完全不知道自己的边界：

- 系统提示里没有一句「哪些操作会被拒 / 哪些要审批」，模型只能撞一次拒绝再改；
- `src/系统提示.light` 的 `上下文顺序常量表` 里 `SANDBOX_POLICY=110`、
  `APPROVAL_POLICY=115` 是照上游抄的，但唯一注册处是演示模块
  `src/互举接线.light:89`（`"沙箱：默认开启"` 一行），且 `渲染提示` 只拼节、不拼上下文
  —— 生产提示里这两条一次都没出现过；
- DSH 标准提示把 sandbox policy / approval policy 作为运行上下文注入（`CONTEXT_ORDERS`
  同值），模型知道「被拒不要换个写法重试」。

## 目标

新增 `src/提示_权限段.light`（纯文本模块，只吃标签，不复制判定逻辑）：

1. `权限段文本(权限预设标识, 审批策略)`：
   - 预设：`全放行` / `按类别` / `全拒绝` / `自定义`（用 `权限.是权限预设` 校验，
     未知 → `""`）；
   - `全放行` → 「文件与命令无需逐次确认」；
   - `全拒绝` → 「写盘与命令一律拒绝；需要时先说明原因，不要反复重试」；
   - `按类别` / `自定义` → 用 `预设按类别` 拿三类的类别名，渲染「放行：…；需审批：…；拒绝：…」
     （只列类别名，不列内部字段）；
   - 审批策略 `询问` → 补一行「需审批的操作会逐次询问，等待用户答复，不要跳过」；
     `从不` → 「本会话不询问审批；被拒绝即视为不可做」。
2. `权限段(权限预设标识, 审批策略)`：别名。
3. 沙箱拒绝口径（对所有含 bash/写类工具的会话追加一行）：
   「被沙箱/权限拒绝时，不要换措辞重试同一操作；说明原因，或改用允许的路径。」
4. 总长 ≤ 600 字符；未知预设或空策略 → `""`（不猜）。

## 红线

- 不调用 `权限管理器` 的真实判定，不复制放行/拒绝规则（只读预设标签）；
- 不改 `src/权限.light` / `src/审批.light` / `src/互举接线.light` 的既有断言；
- 文案里不出现内部字段名（`类别放行` / `通过` 这种），只出现用户能懂的说法；
- 不改 `src/系统提示.light`、`src/总入口.light`（接线归 T-0487 / T-0489）；
- 不许 `git reset --hard` / `push --force` / `--no-verify`。

## 验收

`python -m pytest -q tests/test_T0480_权限段.py` 全过：

- `("全放行","从不")` → 含「无需逐次确认」，且**不**含「逐次询问」；
- `("全拒绝","询问")` → 含「一律拒绝」与「逐次询问」；
- `("按类别","询问")` → 三类类别名都出现（放行/审批/拒绝各至少 1 个类别）；
- 未知预设 `("随便","询问")` → `""`；空策略 → 仍能给出权限部分（审批行省略）；
- 任何输出 ≤ 600 字符，且不含 `"审批策略"` / `"类别"` 这类内部键名（策略标签除外）。

反跑：①`全拒绝` 分支写成「尽量少做」→ 判据红；②未知预设返回 `"全放行"` 文案 → 判据红；
③删掉沙箱拒绝口径行 → 判据红。恢复后全绿。
