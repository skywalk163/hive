同一个病根在 hive 仓也要收拾，而且**治本点在 hive 自己的 worker 提交逻辑**：worker 提交时会把工作区里的 `.hive/summary.md` 一起带进 task 分支，于是每个代码仓的 main 都被这张「上一张卡的小结」反复覆盖，`land` 每次都撞同一个文件。

## 现场（2026-11-03）

- `hive` 仓自身也在跟踪 `.hive/summary.md`（内容就是 T-0237 的小结）；
- `hive.py:186` 的派发指令要求「完成后必须写 `.hive/summary.md`」——这个要求没问题，小结是小结；
  问题是**它被当成交付物提交**，而真正归档的地方是 `results/<tid>.json`；
- T-0241 在 light 仓就因此冲突（另开卡 T-0245 做 light 侧清理）。

## 交付（两件事）

1. **提交时排除**：worker 的提交路径不要包含 `.hive/` 下的文件（除非卡面 `paths` 显式写了它）。
   现有实现已经有「只提交该提交的文件」的收口（T-0114），这里是把 `.hive/` 明确排除掉；
   加一条回归测试：worktree 里放一个 `.hive/summary.md`，提交后分支上必须没有它。
2. **hive 仓自清**：`git rm --cached .hive/summary.md` + `.gitignore` 加 `.hive/`。

## 判据

```
python -m pytest -q tests/ -k "summary or hive_dir or submit" 
```
新增的回归测试必须真的跑「写 .hive/summary.md → submit → 检查分支树」这条链，不许只 `test -f`。
