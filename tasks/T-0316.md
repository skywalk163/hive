## 背景

> 本卡由原 T-0316（码表框架）与 T-0317（归因/定位）合并而来，T-0317 已作废（closed），内容逐条并入下方两个阶段。
> 合并理由：两卡同属「报错质量」一条链，阶段二的行号/归因提示要直接消费阶段一的 `Diagnostic`；改动面也不重叠（`src/diagnostics/` 是新建目录，`src/enhanced_errors.py` 是改造），一个 owner 串行做比两个 agent 并行 + 互相让路更省事，也避免「提示文案在两处各说一套」。

外部评审（DeepSeek，2026-11）把「报错质量」列为 AI 友好与人类友好的共同第一道门槛：AI 最怕模糊报错，一个「错误码 + 原因 + 候选修复」三元组，比任何语法糖对 AI 友好性的提升都大。

现状两块短板：

1. `src/errors.py` 的 `ErrorEntry`（约第 686 行）已有 `stage/message/line/column/fix_suggestions`，但**没有稳定错误码**，也没有机器可读的候选修复；`src/enhanced_errors.py` 的提示是散落的字符串。`docs/AI编程指南.md` 与 `docs/STDLIB_REFERENCE.md` 里记录了 14 个高频坑（缺导入、关键字冲突、类系统后端不兼容、列表索引赋值、`?:`、`&&/||`、段落实参数量、单行段落空跑等），但都只是自然语言。
2. 缺陷 LP-D-002 的另一半：调用了未导入的 stdlib 函数（如 `子串位置`）却报「先定义变量」，新手/Agent 照做会越改越错；`_STDLIB_NAME_TO_MODULE` 是手写 50+ 项静态表（`src/enhanced_errors.py` 第 180 行起），必然随 `stdlib/*.light` 漂移；`NameError` 的行号指向解析器内部状态而非出错的 token 行。

评审原话：「固定行号语义（报错指向实际出错的 token 行），这对人类调试同样是刚需。」

## 阶段一：Diagnostic 模型 + 14 条码表（原 T-0316）

1. 新建 `src/diagnostics/__init__.py`、`model.py`、`registry.py`，纯标准库。
2. `model.py`：`Diagnostic` dataclass，字段固定为
   `code / severity(error|warning|info) / stage / line / column / message / hint / fixes(list[str], ≤3) / candidates(list[str]) / provisional(bool) / docs`。
   - `to_dict()` 字段顺序稳定（JSON 可直接 diff）；`from_dict()` 可往返；
   - `line` 为 0 表示「位置未知」，序列化时保留 0，**不许编造行号**。
3. `registry.py`：
   - `Rule(code, title, pattern, stage, hint, fixes, candidates)`；
   - 内置 **≥14 条**，覆盖 AI 编程指南与 STDLIB_REFERENCE 的高频坑，码段约定：
     `L1xxx` 词法/语法、`L2xxx` 类型、`L3xxx` 运行时、`L4xxx` 模块/导入、`L5xxx` 后端差异；
   - `explain(message, stage=None) -> Diagnostic | None`：按正则命中返回；**未命中返回 None，不造兜底假码**；
   - `get(code) -> Rule | None`；
   - `to_legacy_entry(diag) -> ErrorEntry`，保证 `src/errors.py` 现有文本输出逐字不变。
4. `docs/错误码规范.md`：码段划分、字段语义、新增一条码的流程、兼容承诺（**码一旦发布不复用、不改变含义**）。
5. `tests/test_diagnostics_registry.py`：
   - ≥14 条规则，每条至少一组正例（命中）与反例（不命中）；
   - `explain()` 未命中返回 None；
   - `to_dict`/`from_dict` 往返相等；
   - 同一错误码在两条规则里重复 → 测试失败；
   - `to_legacy_entry` 转换后 `format()` 输出与直接构造 `ErrorEntry` 一致。

## 阶段二：归因与行号锚定（原 T-0317）

1. 新建 `scripts/gen_stdlib_name_map.py`：
   - 扫 `stdlib/*.light` 顶层的 `导出 ...` 清单，生成 `src/stdlib_name_map.py`（`NAME_TO_MODULE: dict[str, str]`），文件头写明「生成物，勿手改，改 `scripts/gen_stdlib_name_map.py`」；
   - `--check` 模式：重新生成并与现有文件比对，不一致时打印 diff 摘要并 `rc=1`（CI/验收用）；
   - 过滤规则保留现状语义：**只收「必须显式导入」的名字**，全局内置（`分割字符串`/`长` 等）不收，否则会把「忘打括号」误报成缺导入。
2. 改 `src/enhanced_errors.py`：删掉手写表，改用生成表；`_stdlib_import_hint` 的返回文案保持不变（已有测试依赖它）。
3. 行号锚定（`src/enhanced_errors.py` + 必要时 `src/errors.py`）：
   - 运行时错误渲染时，行号取 traceback 中**用户 `.light` 栈帧**的 `lineno`，不得用解析器/生成器内部行；
   - 同一物理行被拆成多行逻辑语句时，映射回物理起始行；
   - 拿不到行号就写 0 并输出「行号未知」，**不许猜一个看起来合理的数字**。
   - 若阶段一的 `Diagnostic` 已就绪，`enhanced_errors` 的提示应尽量走 `registry.explain()` 产出（code/hint/fixes 同源），但**不得改变本次要求外的既有文案**。
4. `tests/test_error_anchor.py`，至少三个场景：
   - (a) 只调 `子串位置` 不导入 → 提示含「从 字符串处理 导入 子串位置」，且**不出现**「先通过『设』定义变量」；
   - (b) 变量名拼错（`打印(甲甲)`）→ 给拼写建议，行号 == 真实出错行；
   - (c) 真的未定义变量且不属于任何 stdlib 导出 → 不得误报「缺导入」。
   断言方式：跑真实的编译器/解释器入口取 stderr，正则解析 `行 N`，与源码行号比对。
