# D 线：--canonical 归一规则 + 项目级文体锁定

> 总纲：`docs/R222_语言×AI适配总纲.md`（hive 仓）。

## 背景

`light.toml` 已经有 `[linter] style = "工程体"`，但「工程体」目前只是若干规则名，**没有「归一」能力**：
同一个语义有 8 类等价写法都被接受，Agent 每次都要选一次，选错就是 diff 噪音 + retry。
本卡加一条**可自动修复的 canonical 通道**：能归一的一律归一，归不了的降级为提示。

## 要做什么

1. 在 `src/linter/` 下新增 `canonical.py`（不改 `light_linter.py` 的既有规则行为）：
   - `canonicalize(source, style=...) -> (new_source, edits, skipped)`；
   - 先实现**确定性无风险**的几类：全角/半角标点统一、运算符中英文别名的 canonical 形态、
     `段落`/`函数`/`段` 的 canonical 选择、多余空格与行尾空白。每类给出 `code`（复用 `L5xxx`）与 reason。
   - `skipped` 记录「有歧义、不敢自动改」的位置，交给 Agent 判断（**不要硬猜**）。
2. `src/linter/cli.py` 增 `--canonical`（默认只报告差异，`--canonical --apply` 才写回；
   写回前必须输出将改的行数与片段，`--dry-run` 为默认行为）。
3. `light.toml` 增 `[linter] canonical = "报告"`（取值 `关` / `报告` / `写回`），CLI 参数优先。
4. `tests/test_linter_canonical.py`：
   - 幂等（`canonicalize` 两次结果相同）；
   - 对 `benchmarks/programs/` 里真实文件跑一遍，`--apply` 后 **文件语义不变**（AST 指纹同一）；
   - `--canonical` 不写回时文件 mtime/内容不变。

## 不要做什么

- 不要改 `src/linter/light_linter.py` 的既有规则判定（只新增模块 + 接 CLI 参数）。
- 不要碰 `cli/light.py`。
- 不要自动改「有歧义」的写法（宁可跳过，也不猜）。
- 不要改 `light.toml` 里已有的 `style = "工程体"` 值。

## 完成标准（verify 必绿）

- `PYTHONPATH=src python3 -m pytest -q -o addopts= tests/test_linter_canonical.py`
- `PYTHONPATH=src python3 -m src.linter.cli --help` 能看到 `--canonical`
