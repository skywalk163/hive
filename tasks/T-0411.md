## 背景
`deploy/lightmem.service` 目前只有 kernel 单服务（:18443），注释自称「非 FreeBSD/容器化用」，但 MCP 服务（:7444/:18444）没有 unit；`install.sh --systemd` 只装这一个 unit，且端口口径与 rc.d 混用风险高。Linux 用户要的是 kernel + MCP 双服务开机自启、依赖有序。

## 目标
1) 新增 `deploy/lightmem-mcp.service`（MCP 服务，端口跟 quickstart 7444 或 profile 声明，ExecStart 指向 `<prefix>/lightmem-mcp`），与 kernel unit 组成双服务：`After=lightmem.service`，`Wants=lightmem.service`。
2) 完善 `deploy/lightmem.service`：`User/Group=lightmem`、`WorkingDirectory` 用 `lm_prefix()` 口径、加固项（`NoNewPrivileges`、`ProtectSystem=strict` 需写白名单，`PrivateTmp`）、`Restart=on-failure` + `StartLimit*` 已有则核对。
3) `integrations/quickstart/install.sh --systemd`：装两个 unit、`daemon-reload`、`enable --now`；补 `--uninstall-systemd`（停服务+删 unit+reload）；幂等（重复跑不报错）；端口口径按 quickstart（7443/7444）， error 提示里区分 rc.d。
4) 复用 T0 `deploy/platform.sh` 的 `lm_service_install` 安装 unit，不自行写 cp/systemctl 判断。

## 红线
- 不改 rc.d 既有文件；不改 FreeBSD 安装路径。
- 端口口径不得混：systemd/quickstart=7443/7444，rc.d=18443/18444。
- `verify_requires`: 需 systemd 的机器（CI 容器无 systemd 时用 `LM_DRY_RUN=1` 验证脚本路径）。

## 验收
- 在 Ubuntu 24.04（或有 systemd 的机器）跑 `install.sh --profile solo --systemd --dry-run` 贴计划输出。
- `sh -n install.sh` + `systemd-analyze verify deploy/lightmem.service deploy/lightmem-mcp.service`（有 systemd 时）无错。
- `git show --stat` 只覆盖 deploy/ 与 integrations/quickstart/。
