## 背景

母文档 `docs/控制面v0.5-实现约定.md` §3.10：把控制面挂到 `hive cluster serve`
生命周期，并暴露 `/api/cluster/status` 与 `/api/cluster/pull`。

D14：只有 serve 入口开启，程序化 `Cluster` 默认关闭，避免 50+ 既有测试实例
抢 47899 端口。

前置模块（`hive_control/uplink.py` / `downlink.py` / `lease.py` / `pull.py` /
`worker_sock.py` / `view.py`）已在 main；`hive_control/plane.py`（T-0310 编排器）
尚未实现。适配器按 duck-typed 装配，plane 缺失时降级，并在 `.hive/summary.md`
里如实说明降级范围，不硬凑不存在的接口。

## 目标

1. `hive_control/adapter.py`：实现 `ClusterControlAdapter`
   - `__init__(cluster)`（duck-typed，不 import `hive_cluster`）；
   - `start()` / `stop()`（stop 幂等）；
   - `status() -> dict`：含 `multicast_mode`、`control_leader`、`control_epoch`、
     队列长度与计数；
   - `request_pull(body) -> (code, dict)`：返回 202 + `request_id`；
   - `pull_status(request_id) -> (code, dict)`：结果 / 进行中 / 404；
   - `peer_provider` 从 `cluster.nodes` 取 `url` 的 host + 控制端口，
     `local_agents` 从 `cluster._local_agents()` 取。
2. `hive_cluster.py`：
   - `Cluster.start()` 创建并启动适配器；`Cluster.stop()` 先停控制面；
   - 开关 `Config.control_plane`（内部属性，默认 False），只有 `hive cluster serve`
     入口置 True；为 True 时允许内部测试用 `control_limits` 覆盖端口/时序；
   - `GET /api/cluster/status` → `{"ok":true,"control":{...}}`；
   - `POST /api/cluster/pull` → 202 + `request_id`（体 `{"project":...,"mode":...}`）；
   - `GET /api/cluster/pull/status?id=...` → 结果 / 进行中；
   - 旧 `GET /api/cluster/state` 不动，可在 payload 里追加 `control` 摘要（向后兼容）。
3. `tests/test_control_adapter.py`：覆盖上述行为，重点验证 D14：程序化 `Cluster`
   默认不启动控制面、不占 47899；只有 serve 入口显式开启才启动；stop 会先停控制面。
