# 徽章显示绿，但 GitHub CI 实际是红的

## 现状

`README.md:3`：

```markdown
[![CI 门禁(本地生成)](docs/ci_badge.svg)](docs/ci_badge.json)
```

`README.md:10` 有一段说明：

> 上方「CI 门禁」徽章为**本地生成的动态徽章**（`docs/ci_badge.svg`，由 `tools/ci/gen_badge.py`
> 真跑测试后产出，读数见 `docs/ci_badge.json`）。历史权威快照为 0.82 门禁机的
> 7912 passed / 0 failed…实时 CI 跑在自托管 Gitea（`192.168.1.5`，`.gitea/workflows/ci.yml`）；
> GitHub Actions 的 `.github/workflows/ci.yml` 为对齐镜像，**尚未启用**，请勿据此判断实时状态。

但 `.github/workflows/ci.yml:1-10` 的注释说的是另一回事：

```
# ⚠️ 事实先说清楚（第七轮 E7 记账，T-0241 更正）：本棵 .github/ 树在 2026-11-01 之前
# 一次都没有执行过；`skywalk163/light` 远端启用后已真跑（run 41289797116，ubuntu 3.11，
# Unit Tests 12 failed + 7 errors），下面的结论不再只是「未验证的镜像」。
```

**矛盾点**：

| 位置 | 说法 |
|---|---|
| `README.md:10` | 「GitHub Actions 尚未启用，请勿据此判断」 |
| `.github/workflows/ci.yml:4-5` | 「已真跑，Unit Tests **12 failed + 7 errors**」 |

两个说法**同时存在于仓库里**，且 README 那个是更早写的，没跟着更新。

另外 `README.md:10` 里还有 `192.168.1.5` 这个内网地址（public 仓）。

### 还有一层问题

`docs/ci_badge.svg` 是 `tools/ci/gen_badge.py` 在**门禁机（0.82/freebsd）本地**跑出来的。
它的读数是 7912 passed / 0 failed。但：

- 那是**某一次本地跑**的快照，不是持续状态
- 徽章图片存在仓库里，永远显示那次的结果
- 任何人看 README 都会以为「现在也是绿的」

## 目标

### 1) README 第 10 行改成诚实描述

三件事必须说清：

1. 这个徽章是**哪台机器、什么时候**跑出来的（不是实时）
2. GitHub Actions 的**真实状态**（已启用、当前红/绿、红的原因）
3. 权威门禁在哪（自托管 Gitea）—— **但不要写内网 IP**

建议改成：

```markdown
> **CI 状态怎么看**（2026-11-06 核实）
>
> - **权威门禁**：自托管 Gitea（`.gitea/workflows/ci.yml`），判绿语义带基线豁免
>   （`tests/ci_baseline_failures.txt`，存量欠账不算新增红）。
> - **GitHub Actions**：`.github/workflows/ci.yml` 是**已启用**的对齐镜像。
>   最近一次真跑（run 41289797116）结果 **Unit Tests 12 failed + 7 errors**，
>   存量红见上方基线文件与 commit 注释，**不要据此判断代码质量**。
> - **上方徽章**：`docs/ci_badge.svg` 是 `tools/ci/gen_badge.py` 在门禁机上**本地跑一次**
>   生成的静态快照（读数见 `docs/ci_badge.json`），**不是实时状态**。
>   要看实时请去 Gitea / GitHub Actions 页面。
>
> 已知问题台账：[`docs/known-issues/`](docs/known-issues/)。
```

### 2) 去掉内网 IP

`README.md:10` 里的 `192.168.1.5` 删掉，改成「自托管 Gitea」。

### 3) 徽章图片加时间戳标记

在 `docs/ci_badge.svg` 里，或者在 `docs/ci_badge.json` 旁边放一个说明。
