## 背景

T-0534（语义名上线，已合入）把模型面 function.name 从 `tool_NN` 改成了语义线名（如 `workflow__todo_write`、`workflow__goal`、`web__search`、`shell__run`、`ctx__select_blocks`；fs 四件套仍是 read_file/write_file/search_files/edit_file）。调用侧 `回名` 仍能解析旧名（`todo_write` / `web_search` / `goal`），所以功能不致命。但 teleagent 在 T-0534 结果摘要的「遗留 / 风险」里明确写了：

> 系统提示正文（规划段/工具选择段）仍按旧名 `todo_write / web_search / goal` 说话；提示文案与 README / 快速开始 / API 参考 同步属后续工作（收口报告已把 README / 快速开始 / API参考 同步列为后续项）。

这会让模型看到的 function.name 与提示正文里的工具名对不上，属于文档/提示口径滞后。

## 目标

1. 把系统提示正文（规划段、工具选择段等所有出现旧名的地方）同步成 T-0534 的语义线名口径；旧名只在「兼容/别名」语境里保留说明。
2. 同步 README / 快速开始 / API 参考里相应的工具名文案，与系统提示一致。
3. 不破坏 `回名` 对旧名的解析（T-0534 的兼容语义），不改 `src/总入口.light` 的线名规则（那是 T-0534 已合入的口径）。

## 交付物

- 系统提示相关文件（含旧名的模板/文案，具体路径由执行者定位并写进 paths）
- README / 快速开始 / API 参考
- 新增/更新判据：断言系统提示与文档不再出现裸旧名 `todo_write / web_search / goal`（兼容说明段除外）

## 验收判据

- 相关 pytest 判据全绿（含新增的一条强验收）
- 模型面线名与提示/文档口径一致：提示正文里出现的工具名都能在 T-0534 的 `线名名单` 里找到
- 不引入 T-0534 已合入线名规则的变化

## 红线

- 不改 `src/总入口.light` 的线名转写/白名单等价逻辑（T-0534 语义）。
- 旧名解析（`回名`）能力必须保留。
