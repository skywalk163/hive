# plan 模式闭环：/plan 命令 + exit_plan_mode 工具 + 前端投影

## 背景

plan 是 T-0406 模式规格里的 6 个模式之一，但只落地了纯逻辑层：

- `src/计划模式.light` 有 `折叠计划模式` / `计划模式在末标题` / `投影初始/投影应用/投影视图`；
- `src/代理.light:444` 有 `设计划模式` / `是计划模式` / `计划模式拦写`（非放行工具直接记
  `tool/error` 并跳过）；
- 但**没有用户入口**：没有 `/plan` 命令；**没有出口**：没有 `exit_plan_mode` 工具；
  **没有前端投影**：`{active,pending}` 没进状态帧/UI。
  T-0406 的 `docs/功能对标/模式规格.md` 第 424 行仍把这三项写成"未落地（T-0407）"。

另有一个必须一起处理的隐患：T-0407 在 `src/web服务器.light:758` 给 **topdown 每轮**
设了 `计划模式=真`，而 `计划模式拦写` 会把所有非放行工具拦掉。也就是说 topdown 现在可能
默认就是只读的；引入 plan 模式时必须把"topdown 的计划树"与"用户主动进入的 plan 模式"分开，
不能让 topdown 默认被写拦截。

本卡把 plan 从"纯逻辑 + 一个标志位"补成可用闭环，语义对齐上游 plan-mode：
进入后只规划不执行；用户口头认可不算批准；必须通过 `exit_plan_mode` 提交计划才退出。

## 要做什么

1. **`/plan` 命令入口**（web 层命令面，与 `/goal`、`/compact` 同一条通道）
   - `/plan`（或 `/plan on`）：当前会话进入 plan 模式；
   - `/plan off`：退出（等同于用户切回普通模式），要落 `command/done` + `plan/mode(active=假)`；
   - 进入时落 `command/run`（name=`plan`、带 commandId、args）+ `command/done(kind=success)`
     + `plan/mode(active=真)` 事件，供 `计划模式.投影应用` 折出 `{active,pending}`；
   - 命令本身不喂给模型、不消耗轮次；未知参数回 400 用法提示。
2. **`exit_plan_mode` 工具**
   - 新增 `src/计划工具.light`（形状照抄 `src/目标工具.light`：`造工具定义` + `注册计划工具(注册表)`），
     提供工具名 `exit_plan_mode`，入参至少 `{plan: string}`（可带 `title`）；
   - 校验：plan 非空、能取到首个标题（复用 `计划模式.首个标题`）；空/空白 fail-loud；
   - 成功后：落 `command/done`（与进入时的 commandId 配对）、`plan/mode(active=假)`、
     计划正文事件（`plan/submitted` 或 `plan/update`，命名与前端契约一致），并把计划正文返回给模型；
   - **必须能在 plan 模式下执行**：`代理.计划模式拦写` 对该工具放行（按工具名白名单或
     `分类放行` 特判），其余写/改工具仍拦；不修这条会导致"进去出不来"。
3. **系统提示注入**
   - plan 模式激活时，把 `预设组合` 里 `plan-mode` 的 `section` 文案（或等价常量）注入本轮
     `系统提示文本`；文案要含三条语义：只规划不执行、口头认可不结束、必须 `exit_plan_mode` 提交；
   - 退出后不再注入。注入点与 T-0407 的 `模式系统提示` 拼接点一致，不新开第二条选项链。
4. **会话级持久化与隔离**
   - plan 状态必须由会话事件折出（`计划模式.计划模式在末标题` 或 `折叠计划模式`），不能只放进程内；
   - 两个会话，一个在 plan、一个不在，并发请求互不影响；切回旧会话时 `/api/sessions/current`
     与状态帧能恢复 `active`；服务重启后从 JSONL 重放仍能恢复。
5. **前端投影（最小可用）**
   - 状态帧/current 回 `plan: {active, pending}`；`webui/app.js` 渲染"计划模式"角标 + 计划正文面板
     （pending 时显示"待批准"）；`exit_plan_mode` 成功后角标消失、面板保留为已提交计划；
   - `webui/index.html` 加面板容器，`style.css` 加角标/面板样式；
   - 切会话、断线重连后从服务端状态重建，不靠本地记忆。
6. **修 topdown 语义冲突**
   - 把"topdown 的计划树"与"plan 模式写拦截"解耦：topdown 不因模式名自动进入 plan 模式的写拦截；
   - 增加回归：topdown（未执行 `/plan`）下写文件工具正常执行，不被 `计划模式拦写` 拦掉；
   - 若确需保留 topdown 的计划提示，只注入计划树提示文本，不置 `计划模式=真`。
7. **判据与文档**
   - 新增 `tests/test_T0420_计划模式闭环.py`：命令进入/退出、exit 工具成功与 fail-loud、
     拦截/放行、两会话隔离、重放恢复、topdown 不误拦写、前端源码契约（`plan` 面板/角标）；
   - 更新 `examples/test_计划模式.light`：补命令面与退出工具的端到端段落（原有纯逻辑断言不得放松）；
   - `docs/功能对标/模式规格.md`：plan 段从"未落地"改为"已落地（T-0420）"，写清入口/出口/投影；
   - `docs/API参考.md`：补 `/plan`、`/plan off`、`exit_plan_mode` 工具入参出参、`plan` 状态键；
   - `CHANGELOG.md` 一条。

## 红线

- 不破坏 `/goal`、`/compact`、排队/插话、统计细节的既有契约；`tests/test_T0407_收口接线.py` 必须仍绿。
- 不放宽 `计划模式拦写` 的语义：除 `exit_plan_mode`（及只读工具）外，写/改工具在 plan 模式下仍必须被拦。
- 不允许把"用户说'可以/同意'"当作批准；退出只能靠 `/plan off` 或 `exit_plan_mode` 成功。
- 不改权限四预设、不改 SSE 既有帧形状；新增帧只能加字段或新 `种类`。
- 不引第三方依赖，前端只用现有原生 JS。
- 不改 `examples/` 里与计划无关的期望值。
