## 背景
lightmem 当前部署件里 OS 判断散落各处：看门狗用 `service`/`fetch`、install.sh 用 `ss`/`sockstat` 分支、rc.d 硬编码 `/usr/local`。Linux 适配若各线各写一套 `uname`/路径/服务管理判断，必然漂移。

## 目标
1) 新增 `deploy/platform.sh`（POSIX sh 片段，可被 `.` 引入），冻结并实测以下接口：
   - `lm_detect_os` → freebsd/linux/darwin（基于 `uname -s`）
   - `lm_service_restart <name>` → systemd 走 `systemctl restart`，freebsd 走 `service restart`
   - `lm_service_install <src> <name>` → 按 OS 装 unit 或 rc 脚本
   - `lm_probe_port <port>` → 优先 `ss -ltn`，回退 `sockstat -4l`/`lsof`
   - `lm_prefix` → linux 输出 `/opt/lightmem`，freebsd 输出 `/usr/local/lightmem`
   - `lm_logrotate_install` → linux 装 `/etc/logrotate.d/lightmem`，freebsd 装 newsyslog.conf.d
2) 每个接口带 `LM_DRY_RUN=1` 时可只打印不执行（供 CI/验证用）。
3) 写 `deploy/platform_test.sh`：在 Linux 上逐接口跑一遍（DRY_RUN），断言输出形状正确；FreeBSD 接口可用 `LM_FAKE_OS=freebsd` 模拟分支。
4) 更新 `deploy/README.md` 增一节「platform.sh 接口契约」。

## 红线
- 不改任何 kernel Go 代码、不改 rc.d 既有脚本行为。
- platform.sh 必须 POSIX sh（`sh -n` 通过），不引入 bash 专属语法。
- 接口名/语义一旦冻结不得随意改；后续线只复用。

## 验收
- `sh -n deploy/platform.sh && sh deploy/platform_test.sh` 全绿（Linux 真机实测，贴输出）。
- `git show --stat HEAD` 只覆盖 deploy/ 下文件。
