# A 线：light.spec.json 权威表 + 抽取器

> 总纲（口径、基线、跑测纪律）：`docs/R222_语言×AI适配总纲.md`（hive 仓）。
> **本卡的产物是「事实」，不是「文案」**：表里的每一行都必须能从仓里代码/文件抽出来并自动校验。

## 背景

模型写光明代码最贵的不是「不会写」，是「不知道哪个名字/写法算对」：stdlib 有双轨三轨叫法、
关键字有教学体与工程体两套、同一语义有 8 类等价写法。没有一张机器可读的权威表，Agent 只能靠猜，
猜错就 retry。本卡把这张表做出来。

## 要做什么

1. 新建 `spec/` 目录（**仓内此前不存在**）与 `spec/build_spec.py`。
2. 产出 `spec/light.spec.json`，字段至少包含：
   - `version` / `generated_from`（生成它的 commit 或文件指纹，便于判陈旧）
   - `keywords`：L0 核心字与保留字，每项含 `字`、`作用`、`是否可作标识符`
   - `operators`：符号及其全角/半角、中英文别名（同一语义只允许一个 `canonical`）
   - `stdlib`：从 `stdlib/` 真实导出面抽（函数名、参数个数、是否返回、所属模块）
   - `syntax_forms`：等价写法族的 `canonical` 形态与 `accepted` 变体列表
   - `diagnostics`：占位 `[]`；若 `src/diagnostics/registry.py` 存在则自动填入（否则留空数组，别造）
3. `spec/build_spec.py` 支持 `python -m spec.build_spec`（写文件）与 `--check`（比对仓内现状，不一致退出非 0）。
4. `tests/test_spec_lockstep.py`：至少断言「stdlib 段每一项都在 `stdlib/` 里找得到」、
   「keywords 段与 parser 的真实关键字常量一致」、「同一语义的 canonical 唯一」。

## 不要做什么

- **不要猜数**。L0 核心字实测 44 个单字；`docs/分层语法设计_v4.0.md` §4.1 的「30 字」是旧口径。
- 不要碰 `cli/light.py`（CLI 接线归 T-0382，唯一 owner）。
- 不要碰 `src/parser_*.py` 语义。
- 不要写 `light.spec.json` 以外的东西到仓根。

## 完成标准（verify 必绿）

- `PYTHONPATH=src python3 -m pytest -q -o addopts= tests/test_spec_lockstep.py`
- `PYTHONPATH=src python3 -m spec.build_spec --check`
