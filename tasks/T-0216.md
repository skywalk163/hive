## 背景

看板每 30s 跑一次 `hive status --json`，而 `cmd_status`（`hive.py:2998`）第一行就是
`self.fetch()` → `fetch()`（`hive.py:1311`）→ `git fetch --prune origin`。
也就是说：**远端一个字都没变，也照样每 30 秒发一次网络请求**。

`_sync_one_repo`（`hive.py:2256`）同样先 `git fetch` 再比 `origin/main` ——
顺序反了，白跑一次网络。

`RepoSyncAgent` 里已经有 `_remote_head()`（`ls-remote`）这个正确工具，只是没用在
这两个热路径上。

## 要做什么

1. 新增 `remote_head(path) -> str`：`git ls-remote origin refs/heads/main refs/heads/master`，
   超时 10s，`GIT_TERMINAL_PROMPT=0`，失败返回 `""`。
2. 新增 `fetch_if_changed(path, ttl=10)`：
   - 先 `remote_head()`；与本地 **`refs/remotes/origin/main`** 比较（**不是 `HEAD`**）。
   - 相同 → 直接返回 `False`，**不启动 fetch 子进程**。
   - `ls-remote` 返回空/失败 → **回落无条件 fetch**（网络抖动不能让跨机卡消失）。
   - 10s 内重复调用只做一次 `ls-remote`（进程内按路径记 TTL，看板 30s 一轮、
     多仓时不至于 3×N 次往返）。
3. `cmd_status` 改用 `fetch_if_changed`；`_sync_one_repo` 改成「先比 `origin/main`，
   相同且 `HEAD == origin/main` 才 `up-to-date`，否则再 fetch + `merge --ff-only`」。
   安全边界（只快进、绝不 `reset --hard`）**不动**。
4. 新增环境变量 `HIVE_FETCH_ALWAYS=1` 强制回到「每次都 fetch」的旧行为（回退阀）。

## 不要做什么

- 不比 `HEAD`：本地落后但远端没动时，比 HEAD 会**永远跳过** fetch → 状态永久陈旧。
  这是这个改动最容易写错的地方。
- 不改 `HIVE_NET_TIMEOUT` 语义、不改 `merge --ff-only` 的安全边界。
- 不动 `run()`（T-0206 的地盘）。

## 完成标准

- `python3 -m pytest -q tests/test_status_git.py tests/test_sync_repos.py tests/test_core.py` 全绿。
- **反证**（三条都要贴前后输出）：
  1. 远端 SHA 未变 → `git fetch` 调用次数 **== 0**（改回无条件 fetch 必须红）；
  2. 远端 SHA 变化 → 调用次数 **== 1**；
  3. `ls-remote` 不可达 → 回落为 **1**（不能因为网络抖动让跨机卡消失）。
