## 背景

后端早就把节点信息备齐了：`Cluster.snapshot()`（`hive_cluster.py:1704`）里有
`nodes{id,name,url,port,electable,last_seen,last_seen_epoch}`、`alive`、`quorum`、
`term`、`leader`，`_node_status_locked()` 还能算出 `alive/suspect/dead` 三态。

但前端只渲染了一行文本（`dashboard/app.js:914 renderCluster`）：

```
集群：主节点 fb98；节点 2/2 在线
```

「哪台是谁、多久没心跳、各自在跑几张卡」全看不见 —— 排查「子节点是不是掉了」
只能去 SSH 敲 `hive cluster status`。

## 要做什么

1. 把 `#cluster` 从一行文本升级成**可展开面板**（点击展开，默认折叠）：
   - 头部：主节点 `名称 + IP:Port`（可复制）、`term`、`quorum`、集群 ID；
   - 节点表：名称 / 角色（leader·follower）/ 状态灯（alive 绿·suspect 黄·dead 红）/
     **心跳 age**（`last_seen_epoch` 换算成 `3s` `2m` `1h`）/ 当前任务数 / 版本；
   - 自己那一行加「本机」标记。
2. 状态灯阈值与后端对齐：用 `peer_timeout` / `dead_timeout` 的语义分档，**不要**
   在 JS 里另发明一套数字（后端没下发就在卡片上注明「按 15s/60s 估」）。
3. 当前任务数取 `/api/status` 里 `owner == 该节点名` 的在飞卡计数（前端算，不新增接口）。
4. 数据源继续用 `/api/cluster`，失败时保持现有「集群：未启动」降级，不报错、不弹窗。
5. 面板在 ≤768px 下退化成两列（名称 + 状态灯），不要横向滚动。

## 不要做什么

- 不新增后端接口（RTT/探活是另一张卡的事，本卡只用已有字段）。
- 不动 `/api/cluster` 的返回结构（其他脚本在读）。
- 不引入图表库 / UI 框架。
- 不改 `.topbar` 层级（T-0207 刚收口，别碰）。

## 完成标准

- `python3 -m pytest -q tests/test_dashboard_cluster.py tests/test_dashboard_freshness.py` 全绿。
- 新增断言：构造 3 节点快照（alive / suspect / dead 各一），渲染结果必须出现
  三档状态灯与 age 文案；把 age 计算删掉必须**红**。
- 截图：折叠态 + 展开态各一张（浅色），附在 summary。
- 手测：停掉一台节点的心跳（或 mock 一个 dead 节点），面板 30s 内变红。
