# 补 Web 流式链路的运行时 E2E 测试（当前只有 5 项静态契约断言，缺真跑）

## 背景（为什么需要这张卡）

`cbb395a`（Web Chat 真流式推送）刚合入。链路涉及：后台线程跑 agent → 增量回调投帧进
`实时队列`（`src/实时流.light`）→ HTTP 协程侧 `推流实现` 边取边发 chunked → 前端解析 SSE delta。
这是一条**异步边界很多**的新链路。

当前回归保护只有 `tests/test_流式推流接线契约.py` 的 5 项**静态**断言（钉死导入/载具键/回调实参）。
CHANGELOG 自己都写了「三处接线必崩」的历史——静态断言挡不住运行时顺序错乱、收尾帧缺失、
UTF-8 跨 chunk 分裂、队列线程安全问题。

## 要做的事

1. 为 `src/实时流.light` 写**独立单测**（放 `tests/unit/test_实时流.py`），覆盖：
   - `实时队列` 的线程安全 push/pop（多线程并发 put，逐条取，不丢不重）
   - `编码SSE帧` 的帧格式（`data: ...\n\n`，含 `event:`/`id:` 若支持）
   - `流块转增量帧` 对 OpenAI delta 形状的翻译
   - 收尾帧（统计 / 审批 / 会话 id / `[DONE]`）的构造与顺序
2. 补一组**真 HTTP SSE 端到端测试**（可参考 `examples/运行Web服务器.light` 的 mock 模式，
   不要依赖真实 API Key）：启动服务器 → 发 streaming 请求 → 逐帧读响应 → 断言：
   - 帧是边跑边到的（不是等整轮跑完一次性吐出）——可用 mock 大模型服务器的延迟验证
   - 收尾帧齐全且 `[DONE]` 在最后
   - 中途文本按语义分帧、无乱码（含中文/emoji 跨 chunk 场景）
3. 测试文件放 `tests/unit/`（Python 侧用 `test_support.py` 的 `run_light_source`）或
   `examples/test_流式推流E2E.light`（按现有惯例二选一，说明理由）。
