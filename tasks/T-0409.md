## 背景

2026-11-20 T-0406 首次提交被判 `failed`。第 1 条 verify（pytest）绿，第 2 条

    python3 -c "import json;json.load(open('docs/功能对标/对标清单.json'))"

报 `File "<string>", line 1 / import / ^ / SyntaxError` —— python 只收到 `import`。
**产物没坏**：同一条命令不经垫片改写、直接 `subprocess.run(..., shell=True)` 跑 rc=0；
本机 `hive.verify_command()` + `shell=True` 复跑则必现同样 rc=1，报错文本与 worker 提交时一致。

根因在 `hive_compat.rewrite()`：

    quote = "'" if "'" not in text else '"'
    return f'"{sys.executable}" "{_self_path()}" run {quote}{text}{quote}'

这条命令里同时有单引号（`open('…')`）与双引号（`-c "…"`），于是 `quote` 选 `"`，
而**内层 `"` 一个都没转义**，实际命令行是

    "...python.exe" "...hive_compat.py" run "python3 -c "import json; …""

cmd.exe 在第一个内层 `"` 处就截断了，`run` 只拿到 `python3 -c import`。

影响面：卡面 verify 里只要出现「双引号里再套单引号」的写法（`python3 -c "…open('…')…"`、
`git grep -q "x'y"` 一类），都会被判假红，而且失败形态和「产物坏了」长得一模一样 ——
这是 T-0225 / T-0228 同一类坑，只是这次触发点在 `rewrite()`（包装层），不在
`_win_single_quote_fix()`（改写层）。当前唯一绕过办法是卡面避开这种写法
（T-0406 已把判据换成 `python3 -m json.tool …`），治本在本卡。

## 目标

1. **`hive_compat.rewrite()` 产出的命令行必须能被 cmd.exe 还原成同一条原文**。
   验收口径是「还原」不是「看起来像」：`run` 收到的文本必须与入参文本逐字节相等。
   可接受的做法（任选，实现者定）：
   - 内层引号按 cmd 规则正确转义；
   - 或换一条不依赖嵌套引号的传递通道（例如把原文写进临时文件，`run --file <path>` 读回）；
   - 或含 `'` 时退到文件通道、不含 `'` 时保持现在的单引号包装。
2. 新增回归用例（Windows 生效，POSIX 上 `skipif`）：录入
   `python3 -c "import json;json.load(open('tests/…json'))"`，经 `verify_command()` 改写后用
   `subprocess.run(shell=True)` 真跑，要求 rc=0 且 stdout 是预期 JSON 片段。
3. 现有四类行为一个字都不能改：`tests/test_verify_command_quotes.py`（该换 / 不该换 / 多组引号 /
   内层含 `"` 且带元字符时保持原样）、`tests/test_compat.py`（`run` 剥一层单引号、`should_wrap`
   只在 nt 生效、`rewrite` 幂等、`HIVE_COMPAT=0` kill switch、非 Windows 原样返回）。

## 红线

- 不改 `_win_single_quote_fix()` 的既有语义（T-0225 / T-0228 的修法，动它会打红既有 66 条断言）。
- 不改 `verify_command()` 的 kill switch（`HIVE_COMPAT=0`）与非 Windows 分支（POSIX 一个字节都不改）。
- 不改 `_verify_verdict` / `_verify_strength` 的强弱判定口径（那是判据语义，另一件事）。
- 垫片必须纯标准库、Windows 原生可跑，不许引入 msys / git-bash / WSL 依赖。
- 不许在 `hive.py` 里给 `python -c` 这种写法开白名单绕过 —— 病在包装层的还原性，不在命令形状。
