# 零配置发现：AGENTS.md + llms.txt + SKILL.md

## 背景（实测）

```
$ ls AGENTS.md llms.txt SKILL.md mcp.example.json
mcp.example.json      # 0 字节
（前三个都不存在）
```

agent 永远不会"先读 README"。它进入一个仓库时，只会读**约定俗成的自动注入文件**：
Cursor / Codex 系列读 `AGENTS.md`，llms.txt 消费方读 `llms.txt`，WorkBuddy / Claude 的 skill 机制读 `SKILL.md`。

光明现在一个都没有，等于**默认所有 agent 都不知道有这门语言**——`light ai card` 再好也得先有人告诉它去跑。

## 要做什么

三个文件，合计 **≤12000 字节**（约 4k token），互不复制长内容，都用指针指向 `docs/ai/` 三层卡（T-0459 产出）：

1. **`AGENTS.md`**（仓库根）
   - 首屏 5 行：这是什么语言 / 一行 hello / 怎么跑 / 怎么查 / 改完怎么验
   - **6 条硬规则**（与 compact 卡同一份事实）：中文关键字、冒号必选、`print`→`打印`、`读取(x)` 是 stdin、读文件用 `读取文件`、块靠缩进
   - 「常用命令」小表：`light ai card` / `light ai check --json` / `light ai snippets` / `light 运行`
   - 「别做」清单：别用 `def/if/for/True`、别用 `&&`、别新增依赖
   - 「卡住了看哪里」：`docs/ai/README.md`、`docs/AI编程指南.md` §六、`light ai snippets`

2. **`llms.txt`**（标准格式：`# 项目名` + 一段摘要 + `## 链接` 列表，每个链接一行「- [标题](路径): 一句话」）
   - 只放**权威入口**：spec.json、AI 指南、stdlib 速查、L0 字表、bench

3. **`skills/light/SKILL.md`**（Agent Skill 格式）
   - 头部 frontmatter：`name: light` / `description:`（必须写清"什么时候该用它"）/ `when_to_use`
   - 正文：3 步工作流（读卡 → 写 → `ai check --json` → 按 fixes 改）+ 一个完整可跑示例 + 常见失败模式表

## 硬要求

- 三个文件里出现的**每个相对路径都必须真实存在**（测试用 `os.path.exists` 逐个校验）——这是防文档腐烂的关键
- 事实必须与 `spec/light.spec.json` 一致：抽查 L0 字数、至少 5 个关键字、至少 5 个 stdlib 函数名，与 spec 逐字比对
- 中文表述，短句，不写营销话术

## 不要做什么

- 不改 `README.md`（T-0464 的地盘，它只会在顶部加一个指针）
- 不改 `docs/ai/`（T-0459 的地盘，你只引用）
- 不把 4.8 万字指南内容搬进来；单文件超 6KB 就是错
- 不新增依赖

## 完成标准

- `tests/test_T0460_discovery.py`：
  - 三个文件存在、总字节 ≤12000、单文件 ≥500 字节（防空文件过关）
  - `AGENTS.md` 含 `light ai check --json`、`读取文件`、`打印`
  - `llms.txt` 首行以 `# ` 开头且含 `## ` 分节
  - `SKILL.md` frontmatter 有 `name` 与 `description`
  - **正文中所有反引号里的相对路径存在**（至少校验 `docs/`、`spec/`、`stdlib/` 下的路径）
- verify：`python -m pytest -q tests/test_T0460_discovery.py`
