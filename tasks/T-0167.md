## 背景

`hive doctor` 现在仍点名 4 张卡「只有弱验收」：T-0161、T-0164、T-0165、T-0166。
根因在 `hive.py` 的 `_verify_strength`（约 450 行）：判定刻意保守，只认
`pytest / unittest / npm test / go test / cargo test / make test|check / tox …` 这类
STRONG_TOKENS，而**混合管线按最弱一环算**（如 `grep x && pytest` 也算 weak）。

这 4 张卡的 verify 是 `python3 -c "import pathlib; … assert …"` —— 不含任何
STRONG_TOKEN，所以被判成 `weak`，`hive doctor` 据此告警"成果没被真正执行验证"。
（T-0162、T-0163 本来就是 `python3 -m pytest …`，已是 strong-pass，正常，不用动。）

注意：`doctor` 读的是**结果 verdict**（`results/<tid>.json` 里记录的 `verify_strength`，
close 时 `res/<tid>` 分支被删、结果归档进 `origin/main` 的 `results/<tid>.json`），
所以光改卡面 `verify` 不够，还得把 strong-pass 结果写回 `results/<tid>.json`。

   - `tests/test_docs_worker_parallel.py` → 验 `docs/design-worker-parallel.md`
   - `tests/test_docs_lock_model.py` → 验 `docs/锁与冲突模型.md`
   - `tests/test_docs_architecture.py` → 验 `docs/架构与排障全景.md`

   每个文件里用多个 `test_*` 函数断言：
   - 沿用各卡现有 `need` 列表的必备小节都得出现；
   - 更深一层校验（任选，挑能稳定过的）：``` 代码围栏配对、关键概念短语出现、
     正文中无 `TODO` / `待补` / `占位` / `xxx` 这类占位标记。
   断言要具体，别写成永远为真的废断言。

2. **把这 4 张卡的 `verify` 字段分别改成**（strong）：
   - T-0161 → `python3 -m pytest tests/test_docs_worker_parallel.py -q`
   - T-0164 → `python3 -m pytest tests/test_docs_lock_model.py -q`
   - T-0165 → `python3 -m pytest tests/test_docs_architecture.py -q`
   - T-0166 → `python3 -m pytest tests/test_docs_handbook.py -q`
   ⚠️ verify 必须是**纯 `python3 -m pytest` 调用**，不要前面加 `grep`/`echo` 之类
   （混合管线按最弱一环算，会变成 weak）；也不要写成 `python3 tests/foo.py`
   （没 pytest token，仍判 weak）。

3. **跑本卡自己的 verify 确认全绿**（这是 strong-pass）：
   `python3 -m pytest tests/test_docs_*.py -q`

4. **刷新 4 张已关闭卡的结果，让 doctor 闭嘴**（协调仓 bookkeeping，仅动 `results/*.json`）：
   卡已 close，`res/<tid>` 分支已删，结果在 `origin/main` 的 `results/<tid>.json`。
   重跑新强验收并把 strong-pass 写回：
   ```python
   import json, subprocess, sys
   from pathlib import Path
   tids = {"T-0161": "tests/test_docs_worker_parallel.py",
           "T-0164": "tests/test_docs_lock_model.py",
           "T-0165": "tests/test_docs_architecture.py",
           "T-0166": "tests/test_docs_handbook.py"}
   for tid, t in tids.items():
       p = subprocess.run([sys.executable, "-m", "pytest", t, "-q"],
                          capture_output=True, text=True)
       res = json.loads(Path(f"results/{tid}.json").read_text(encoding="utf-8"))
       res["verify"] = [{"cmd": f"python3 -m pytest {t} -q", "code": p.returncode,
                         "tail": (p.stdout + p.stderr).strip().splitlines()[-5:]}]
       res["status"] = "done" if p.returncode == 0 else "failed"
       tag = "升级为 pytest 强验收，strong-pass" if p.returncode == 0 else "强验收未过"
       res["summary"] = (res.get("summary", "") or "") + f"\n\n[re-verify] {tag}"
       Path(f"results/{tid}.json").write_text(
           json.dumps(res, ensure_ascii=False, indent=2) + "\n", encoding="utf-8")
       print(tid, "code=", p.returncode)
   ```
   然后只提交 results 文件到 main：
   `git add results/T-0161.json results/T-0164.json results/T-0165.json results/T-0166.json && git commit -m "results: T-0161/0164/0165/0166 升级为 pytest 强验收（re-verify）" && git push origin main`
   （`verify_strength` 是 `hive doctor`/`hive result` 读取时由 `_verify_verdict` 现算的，
   只要 verify 里是带 code=0 的 pytest 命令，就会是 strong-pass，无需手动写 strength 字段。）

5. **验收 doctor 干净**：`python3 hive.py doctor`，确认 T-0161/T-0164/T-0165/T-0166
   不再出现在「只有弱验收」告警里。
