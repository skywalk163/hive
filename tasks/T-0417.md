## 背景
A–F 六线各自交付后，缺一次 Linux 真机全链验收把碎片拼起来；本卡是收口卡，必须在 A–F 全部合入后做。

## 目标
1) 准备/确认一台 Linux 验收机（优先 Ubuntu 24.04；没有则用任一 systemd 发行版并注明版本/内核），记录 `uname -a` / `cat /etc/os-release`。
2) 全链走一遍：
   - `install.sh --profile solo --systemd`（non-root，装到 /opt/lightmem 或 _lightmem_run，按 A 线实际口径）；
   - 起 kernel + MCP 双服务，`systemctl status` 贴出来；
   - `curl /healthz` 200 + MCP `health`（用 lightharness 的 mcp__lightmem__lightmem_health 或原生客户端）；
   - 写一条记忆再召回（save→recall 闭环）；
   - 看门狗：人为停服务 triggers 重启（或 LM_DRY_RUN 验证），观察冷却防抖；
   - logrotate：`logrotate -d` + 手工触发一次轮转看文件滚动。
3) 产出 `_LM_Linux适配_验收报告.md`（落 lightmem 仓根）：环境、每步命令+退出码+输出摘要、PASS/FAIL 表、与 FreeBSD 0.88 的差异登记、遗留 TODO。
4) 交叉问题：若发现 A–F 线的接缝 bug，**在对应卡上留言**（hive_chat_post）并登记到报告，能在本卡小修的小修（paths 仅限 deploy/、scripts/、文档），涉及其它线文件面的退回对应卡。

## 红线
- 不破坏 FreeBSD 0.88 现网（本卡只在 Linux 验收机操作）。
- 不动 kernel 核心语义、不改端口口径。
- 报告里的每条 PASS 必须有真实命令与退出码，禁止臆造。

## 验收
- 报告含全链每一步的实测输出；save→recall 闭环有 memory_id。
- `hive doctor` 对本轮各卡无新增 error。
- 收口后在总任务书表格回填各卡实际编号与状态。
