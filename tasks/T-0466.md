# lightharness 上下文使用率显示准确率整改

## 背景（来自 2026-11-24 实测诊断）
Web GUI 顶部统计显示 `in 267680 out 26980 | 累计 605096 | 使用率 928%`，而同类 DSH 显示 15% 左右。只读诊断结论：
1. `web服务器.light:193` 的 `上下文窗口` 属性默认 32768，`构造` 用 `压缩配置()` 的 `HARNESS_MODEL_CONTEXT_WINDOW` 缺省 32768；而当前模型 `buddy/hy4flash-free` 的模型目录窗口是 1,000,000。分母用了陈旧默认值。
2. `web服务器.light:583` 使用率 = `(本轮总/窗口)*100`，其中 `本轮总 = 本轮输入+本轮输出`；`代理.light:779` 显示本轮输入是**一轮内所有 step/工具往返的累计**，不是"当前驻留上下文 token"，分子口径错误。
3. 前端 `webui/app.js:359 renderContextUsage` 不做封顶，`>95%` 标红，928% 显示为假爆满。DSH `contextOccupancy()` 是 `min(100, round(used/window*100))` 且用 provider 投影的当前占用。

## 要做什么
- 上下文窗口分母跟随当前会话模型的真实 `contextWindow`（模型目录/会话模型），不要用压缩阈值默认值；取不到时回退到保守值并在统计帧里标注来源字段（如 `窗口来源`）。
- 分子改为"当前上下文占用估算"：优先用模型侧上报的 `prompt_tokens`（最后一次请求的输入），不要把整轮 step 输入累加；若只能用累计口径，必须明确文档化并在 UI 文案说明，且封顶 100%。
- 前端 `renderContextUsage` 与统计条显示封顶 100%（超出显示 `>100%` 或 `100%+`，不再显示 928% 这种数字）；颜色阈值逻辑同步。
- 不触碰自动压缩的 token 估算口径（`估算token` = 文本字符/3），那是另一条独立逻辑。

## 验收
- 新增 `tests/test_T0466_使用率显示.py`：构造 本轮输入=267680、输出=26980、窗口=1000000，断言 `上下文使用率 ≤ 100` 且接近按新口径计算的值；构造窗口缺省场景断言取真实模型窗口；断言前端 JS 含封顶逻辑（文本断言）。
- `python -m pytest -q tests/test_T0466_使用率显示.py` 全绿。
- 手工：长任务跑一轮后 GUI 不再出现 >100% 的百分比。

## 不做什么
- 不改 `src/压缩.light`/`src/压缩策略.light` 的自动压缩触发逻辑。
