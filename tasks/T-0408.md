## 目标

1) **`GET /api/sessions/current` 带认证令牌时忽略 `?session=`**

   `src/web服务器.light` 的 `处理当前会话(令牌, 查询串)` 先看令牌绑定：
   ```
   如果 令牌 != "" 且 令牌 != 空:
     如果 己.令牌会话表.包含(令牌):
       设 标识 为 己.令牌会话表[令牌]
   如果 标识 == "":
     设 查询参数 为 解析查询参数(查询串)
     如果 查询参数.包含("session"): 设 标识 为 查询参数["session"]
   ```
   而 `己.令牌会话表[令牌]` 在**每次新建会话**时被覆盖
   （`处理新建会话` 末尾 `己.令牌会话表[令牌] 为 元数据["id"]`）。
   于是同一个令牌建过多个会话后，`?session=<旧会话id>` 永远返回最新那个。

   实测（FreeBSD 15.1，服务起在 `HARNESS_WEB_TOKEN=tok`）：
   ```
   POST /api/sessions {"标题":"A"}          -> S1
   POST /api/sessions {"标题":"B"}          -> S2
   GET  /api/sessions/current?session=S1    -> 返回 B（应为 A）
   GET  /api/sessions/current?session=S1    （不带 X-Auth-Token）-> 返回 A（正确）
   ```
   受影响调用方：`webui/app.js` 的 `refreshSessionTitle(id)` 用带令牌的
   `?session=<id>` 取标题 → 多会话下把标题刷成别的会话的。

   期望：**显式 `?session=` 应优先于令牌绑定**（令牌绑定只作为「没写 session 时」的兜底）。
   若这样改会动到 W2 契约（令牌=会话）的其它调用点，请在 summary 里说明取舍。

2) **落库的 `tool-result` 消息 `结果` 恒为空串**

   事件层（`<根>/legacy/<项目键>/<会话id>/session.jsonl`）的 `tool/result` 里正文是有的：
   ```json
   {"type":"tool/result","data":{"消息":{"content":[
     {"type":"tool-result","toolCallId":"c1",
      "content":[{"type":"text","text":"{\"内容\":\"OWN-CONTENT\",...}"}],"isError":false}]}}}
   ```
   但 `处理对话` 落库那段只扫顶层 `type == "text"`：
   ```
   如果 type(结果内容) == list:
     遍历 块 之 结果内容:
       如果 type(块) == dict 且 块.获取("type","") == "text":
         设 结果文本 为 结果文本 + 块.获取("text","")
   ```
   而顶层块的 `type` 是 `"tool-result"`，`text` 在**下一层** `块["content"]` 里，
   于是 `结果文本` 恒为 `""`，`工具名`/`调用id` 也没回填（恒空）。
   同一份逻辑在 `生成SSE` 里**写对了**（它会下钻一层取 `toolCallId` 和子块 `text`），
   落库路径没跟着改 → 两份实现漂移。

   期望：落库路径与 `生成SSE` 同口径（下钻 `content` 子块、回填 `toolCallId`），
   并顺带回填 `工具名`（用 `源序号` 关联 `tool/call` 事件，`生成SSE` 已有现成写法）。

3) **`会话存储.保存索引()` 的临时文件名固定，并发落盘互踩**

   `src/会话存储.light`：
   ```
   段落 保存索引:
     设 临时路径 为 路径连接(会话目录, 索引文件名 + ".tmp")
     写入文件(临时路径, 序列化JSON(己.索引))
     保存索引替换(临时路径, 索引路径)
   ```
   `保存索引替换` 有 5 次退避重试，但**重试的是 `os.replace(同一个 tmp)`**：
   线程 A 写完 tmp、rename 成功后，线程 B 的 tmp 已被 A rename 走，
   B 的 `os.replace` 报 `No such file or directory`，5 次重试全是同一个不存在的源文件
   → 抛「索引原子写失败，已重试 5 次」→ 该轮 HTTP 500「会话持久化失败」。

   实测（FreeBSD 15.1，同一服务进程两个线程各跑一轮对话）：8 次里 6 次红，
   且**双方轮流中招**（谁后 rename 谁红），不是固定一侧。
   线上形状：浏览器两个标签页同时发消息就可能撞上。

   期望：临时文件名带唯一后缀（`_index.json.<pid>.<线程id/随机>.tmp`），
   或对索引写入加进程内互斥锁（`互斥锁` 已在 `stdlib/线程.light` 导出），
   两者选一即可；顺带把「重试同一个已被消费的 tmp」这个反模式一起收掉。
   注意：**不要**改成「跳过重试直接抛」——R40 的 Windows `os.replace` 竞态修复
   依赖这层退避，别把那条修回去。
