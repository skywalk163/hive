## 背景

`tests/test_T0501_命名映射表.py::test_与真实注册表逐位一致` 常年红，但不是任何一张卡的回归：
它把 `组装注册表().名单()` 的长度与 §6 映射表的 160 条**硬等**，而注册表会随「挂了哪些插件 /
MCP」变化。实测三种环境：

| 环境 | 注册表条数 | 判定 |
|---|---|---|
| 干净 worktree / 只挂 lightplugin | 168 | 168 vs 160 红 |
| 本机主检出（lightplugin + MCP 桥） | 199 | 199 vs 160 红 |
| 未挂任何插件 | < 100 | 走 skip 分支 |

两处「多出来的工具」性质完全不同，但判据把它们混在一起：

1. **8 个团队 / 交付 / 会话工具**（`注册成员`、`分派团队任务`、`交付登记`、`交付列出`、`交付完成`、
   `交付关联`、`查询会话`、`装配团队面板`）——已全部登记在 `src/工具面装配.light` §3.9 的
   **`不上叶子表`**（A 类：无上游叶子，显式声明不映射），属**设计上就不进映射表**，不是漏登记。
2. **31 个 MCP 桥工具**（`mcp__hive__*` 18 + `mcp__lightmem__*` 13）——随各机 MCP 配置增减，
   本来就不该进基线映射表。

同时，前 160 位**逐位一致**（追加都发生在末尾，没有乱序），说明顺序契约本身是稳的，
坏的是「等长」这个判法。

## 目标

1. 把 `test_与真实注册表逐位一致` 从「长度相等 + zip 逐位」改成**两条互补判据**：
   - **正向（前缀一致）**：映射表 160 条必须按登记序作为注册表的**子序列前缀**出现，
     现名与域逐位相等（保持原有顺序契约，不放松）；
   - **反向（未登记清单）**：注册表里凡是**既不在映射表、也不在 `不上叶子表`、也不以 `mcp__` 开头**
     的条目，逐条点名判红 —— 这是新能力，专门抓「真·漏登记」，不能被上面两类豁免淹掉。
2. 在 `docs/工具命名规范.light.md` §6 补一段**豁免口径**说明：映射表的权威范围 = 基线 160；
   豁免源只有两个（`不上叶子表` 白名单、`mcp__*` 前缀黑名单），并写明理由与出处
   （`不上叶子表` 是 §3.9 的 A 类登记，不是本卡新造的清单）。
3. 判据在**挂了 MCP 与没挂 MCP 两种环境都绿**，且两种环境下都必须能抓到人为制造的漏登记。

## 关键设计取舍

- **不把 8 个团队工具塞进映射表**。它们是有意的「不映射」（无上游叶子），塞进去会连带反转
  T-0503 的红线判据（`注册名` 必须全 ASCII `/^[a-z]+\.[a-z0-9_]+$/`、`中文注册数 == 0`），
  还会牵动 T-0502 的别名 27 条基线与 T-0508 的分级表。要改它们的命名，是另一个决定，另开卡。
- **豁免源复用已有的 `不上叶子表`**（已从 `工具面装配` 导出），不新造第二份清单 ——
  两份清单一定会漂移。
- **`mcp__` 用前缀黑名单而不是枚举**：MCP 工具名由外部配置生成，枚举必然过期。
- **反向判据不能省**：如果只做「映射表 ⊆ 注册表」，那以后任何新增基线工具漏登记都会被静默放过，
  这正是本卡要修掉的那类假绿。

## 验收判据

1. `python -m pytest -q tests/test_T0501_命名映射表.py` 全绿 —— 且要在**挂 MCP** 与
   **不挂 MCP**（如 `LIGHTPLUGIN=` 指到没有 MCP 的目录）两种环境下分别跑一次；
2. 反证（务必在 summary 里贴证据）：临时把注册表里某条基线工具改名/删掉 → 判据**红**并点名；
   临时造一个 `我的新工具`（既不在表也不在 `不上叶子表`）→ 判据**红**并点名；
3. `test_T0502_改名与别名`、`test_T0503_中英混合治理` 不回归（这两条判据消费同一份 §6 数据）；
4. 判据里不得出现「数量不等就 skip」「`>=` 代替 `==`」这类放宽。

## 红线

- 不得为绿而放宽：`len(reg) == len(ROWS)` 这种全等断言可以去掉，但必须由上面两条判据补上同等甚至更强的约束；
- 不得改注册表本身（不为了对齐去删插件工具、不改 `组装注册表`）；
- 不得把 `不上叶子表` 的内容复制进测试当第二份名单 —— 判据必须从 `工具面装配` 导入；
- 判据要与环境无关：本机 199、干净 worktree 168、无插件 skip，三种情况给出**明确可读的结论**，
  不允许「碰巧过」。
