# 对标登记 + 新增《模式规格》文档（不碰 T-0399 独占路径）

## 背景

本批 5 张功能卡（T-0401~T-0405）会引入 4 种新模式（自上而下 / 自下而上 / 头脑风暴 / 懒人），
以及 goal/plan 两个行为型模式。这些模式在 DSH 里是 Agent Preset 的规格化产物，
有明确的「控制流向 / 人机介入点 / 终止条件」三维契约。lightharness **没有地方记录这个契约**，
下一个人接手只能靠读代码猜。

同时 `docs/功能对标/对标清单.json` 需要按现有口径增补条目（记住 `#编号` 只增不改，旧条目别重排）。

## 要做什么

### 1) 新增 `docs/功能对标/模式规格.md`

**这是本卡的主要产物**，一份可执行的规格文档，写清 6 个模式：

- **四个组合型**：`topdown` / `bottomup` / `brainstorm` / `lazy`
- **两个行为型**：`goal`（目标模式，落点 T-0401）/ `plan`（计划模式，落点 T-0407）

每个模式按统一结构写（缺一不可）：

| 小节 | 内容要求 |
|---|---|
| 触发方式 | 显式切预设 / prompt 意图路由，两者都写 |
| 进入条件 | 什么任务适合，什么任务不该用这个模式 |
| 控制流向 | 决策从哪发起、向哪传递；有没有中央规划器 |
| 人机介入点 | 哪个环节必须/可以引入用户，哪个环节一律不打断 |
| 输出形态 | 产物长什么样（计划树 / 结果集合 / 分层想法池 / 最小交付物） |
| 终止条件 | 正常终止 + 硬终止 + 预算上限，**三类都要写** |
| 实现要点 | lightharness 里的落点（文件/段落），以及**刻意的边界** |

特别要写清三条 DSH 规格里的硬约束（它们是判据，不是修辞）：

1. **自下而上**：去重与冲突检测必须放协调器，Worker 之间**不能互相看到输出**，
   否则会退化成隐式集中协调。
2. **头脑风暴**：发散阶段**禁止出现「这个想法好不好」的判断**；收敛阶段至少要有
   Devil's Advocate 与 Steelman 两个角色；「争议区」是刻意保留的，UI 层不得折叠。
3. **懒人模式**：进入代码层之前必须留下「方案层已穷尽」的依据（候选项目名 + 排除理由
   —— license / 维护停滞 / 集成成本高于自写）；且**预估自写行数 < 20 行时不触发检索**
   （否则为了少写代码反而更慢）。

还要写一节「**组合与切换**」：四个模式不做互斥四选一；模式状态默认**会话级、不跨任务持久化**；
模式内部可嵌套（自上而下执行某节点时局部切头脑风暴），但嵌套是执行层子 Agent 行为，
不改变顶层用户可见状态。

## 附注 A：「光明」写法禁令（照抄现状规避写法，成本最低）

- 段落一律块形式：**禁 `段落 X: 返回 …` 单行函数**（生成器缩进会累积）。
- 字典/列表字面量一律**单行**；嵌套字面量内不写 `\n`（用 `chr(10)`）；字面量不直接当实参先 `设` 变量。
- **单字变量名全禁**（`若 则 否 是 段 出 导 遍 对 跳 过 试 捕 抛 终 返 配 己 自 设 为 从 当 空 长 首 末 余 父 常 并 与 且 或 的 在 到 现 例 步 断 新 接 承 引 掷 跃 非 真`）。
- 标识符不得被关键字序列完全切分（`错误己` 会炸，`错误甲` 正常）；不用「为」字入标识符；
  避开含 `等待` 的标识符；成员名避开 `模/模型/模式/工具/事件/类型/原因/取/生成/新建` 等词根。
- 成员赋值一律 `设 己.X 为 …`（裸 `己.X 为 …` 会编成 `==`）。
- 缺键 `d[k]` 直接抛 `键错误` → 用 `字典获取(d, k, 缺省)` 或 `字典包含键` 守卫。
- `空` 是 `None` 不是 `""`，判空串写 `x != "" 且 x != 空`（照抄 `web服务器.light:452/522/527`）。
- `/` 是浮点除法，切片/下标前先 `整数()`。
- **段落名会与依赖模块内联后冲突**（`src/代理循环.light:10-12` 已记）：新模块段落统一加 2 字前缀
  （本批约定：`续`=目标续跑、`压`=压缩升级、`模`不许用→用 `式`、`队`=会话队列、`时`=会话细节）。
- 循环依赖用 `导入 模块` + `模块.段落()` 点号调用，不要 `从 X 导入 名`。
- 新模块名全仓唯一（`src/` 与 `stdlib/` 都要查）。

## 附注 B：测试写法（照抄 T-0395 / T-0398，不要自创）

- 主套路：`tests/test_T0395_会话工作目录.py` 的 `_run(src, tmp_path)` ——
  把一段光明驱动脚本写进 `tmp_path/driver.light`，`subprocess.run([sys.executable, 运行.py, 驱动])`，
  env 剔除 `HARNESS_ROOT`/`HARNESS_CWD` 并注入 `LIGHTPLUGIN`/`LIGHT_MERGE`（用沿祖先逐级找的 `_find_sibling`），
  子进程里 `打印("键=" + 转字符串(值))`，Python 侧按 `k=v` 解析成 `kv` 再逐项 assert。
- 前端断言：`tests/test_T0398_附件暂存契约.py` 的 `_read` + `_fn_body`（按函数头切片），
  **用「包含某串 / 相对顺序」断言，不要用「集合相等 / DOM 结构相等」**（并行卡会加东西，等价断言会假红）。
- 每个新 `webui/*.js` 必须加 `node --check` 兜底。
- verify 只跑本卡自己的测试文件，**不要跑 `tests/unit/` 全量**

  `python3 -m pytest -q tests/unit/test_R221_增量清单.py -o addopts=''` → 1 failed 属已知基线，忽略。
- `pytest.ini` 是 `addopts = --timeout=60 -n 4`；单卡调试要串行用 `-o addopts=''`（`-p no:xdist` 会报参数错）。
