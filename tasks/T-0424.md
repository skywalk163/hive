## 背景

A 线 `integrations/quickstart/install.sh:449` 用

```sh
( umask 077; printf 'LIMS_AGENT_TOKENS=%s\n' "$(cat "$TOKENS")" > "$ENV_FILE" )
```

把 `issue_token.py` 产出的 **~42 行美化 JSON** 原样写进 systemd 的 `EnvironmentFile`
（`$RUN_DIR/lightmem.env`）。systemd 的 `EnvironmentFile` 是**按行解析**的，只保留第一行 `{`，
于是 kernel 启动即 Fatal：

```
[boot] auth config: LIMS_AGENT_TOKENS: parse agent tokens json: unexpected end of JSON input
lightmem.service: Main process exited, code=exited, status=1/FAILURE
→ 重试 5 次 → Start request repeated too quickly
```

也就是说：**每个走 `install.sh --systemd` 的部署都会启动崩溃**，除非人工补跑规避件。

T-0417 已在 `scripts/lm-env-compact.sh` 给了**规避件**（压成单行 + 600 + 自检行数），
但那要求用户知道要先跑它 —— 对 `install.sh --systemd` 这条主线路径来说，这不成立。
本卡做**根修**：让 `install.sh` 自己写对的 env，规避件从此只是收尾工具而不是必经步骤。

## 目标

1) 改 `integrations/quickstart/install.sh` 的 systemd 分支（第 447–454 行附近）：
   写 `$ENV_FILE` 前把 `$TOKENS`（`agent-tokens.json`）**压成单行 JSON**再写，
   保持 `umask 077` + `chmod 600` 不变，token 内容不得改动（不得增删字段、不得改大小写）。
   - 优先零依赖做法：调用仓库已有的 `scripts/lm-env-compact.sh`（同一份口径，避免两处实现漂移）；
   - 若该脚本不可达（用户只拿到 `integrations/` 子集），退化为内联 `python3 -c 'json.dumps(...,separators=...)'`；
   - `python3` 缺失时**明确 fail**并给出可操作提示，绝不静默写出一份会崩的 env。
2) 写完后**自检**：env 行数必须为 1，否则报错退出（不 break 后续步骤）。
3) 新增回归 `integrations/quickstart/envfile_test.sh`（POSIX sh，零依赖）：
   - 造一份多行 `agent-tokens.json`，跑 install.sh 的 env 写入路径（或直接调用抽出的函数），
     断言产出 env **恰好 1 行**、首行以 `LIMS_AGENT_TOKENS=` 开头、解析回来与原始 JSON 等价；
   - 反跑：若压平被破坏（造一个多行输入强行走旧写法），测试必须**变红**（证明判据真的在测东西）。
4) `deploy/README.md`「已知坑」登记一条：env 必须单行（指向本卡修法，保留 `lm-env-compact.sh` 作为事后修复手段）。

## 红线

- 不改 kernel 核心语义、不改端口口径、不动 FreeBSD rc.d 既有文件。
- 不改 `scripts/lm-env-compact.sh` 的对外用法（它是已发布的规避件，只允许被调用）。
- 不改 `initialize`/token 往返语义：`agent-tokens.json` 一个字节都不改，只改「怎么塞进 EnvironmentFile」。
- 判据不得写成「grep 到某个字符串就算过」的弱验收：本卡判据要求真实产出并断言行数。
