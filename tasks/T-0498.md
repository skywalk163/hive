## 背景

160 个工具的 schema 全量 eager 进入上下文是固定开销大头。分层披露机制：核心工具 eager 全量；长尾工具按 tier 折叠（Tier 0 小目录全量 eager；Tier 1 显示「bridge + 分组清单」；Tier 2 仅名称；Tier 3 每组一行 `name: count`）。预算公式 `min(thresholdPct% × contextWindow, listingMaxTokens)`，默认 5% / 4–20K tokens。

**前置检查**：若已有等效的 tool-search / tool-disclosure 插件（如 DSH 系），本卡可退化为**配置项调优**（设 `thresholdPct`、core 常驻列表、`maxWarmTools`），不必从头实现。实现前先确认。

## 目标

1. 在工具面装配阶段计算每个工具的 tier；
2. 按 tier 决定进入模型上下文的形态（全量 schema / 分组清单 / 仅名称 / 每组一行）；
3. 提供一个 `tool_search` 桥，让被折叠的工具能在 1 轮内按需加载回 eager；
4. 预算用 `min(thresholdPct% × contextWindow, listingMaxTokens)` 控制目录本身的开销。

## 交付物

- `src/工具面装配.light`：tier 计算与降级装配
- `src/工具展示.light`：折叠/bridge 呈现
- 必要时一个最小 `tool_search` 桥工具
- `tests/test_T0498_分层披露.py`

## 验收判据

1. tier 计算符合预算公式，可给定 contextWindow 复算；
2. 被折叠工具通过 tool_search 能在 1 轮内加载为可调用；
3. 核心/常驻工具列表不被折叠；
4. `tests/test_R38_工具展示_token.py`、`tests/test_T0448_工具面装配.py` 不回归。

## 红线

- 折叠**不等于删除**：被折叠工具仍必须可被发现并加载，不得让模型把「折叠」误判为「不存在」；
- 预算阈值要有默认值且可配，不得写死；
- 本卡是 W5-B（提示词压缩 T5.3）的前置——分层披露未就位前，下沉工具参数键名省不了多少 token。
