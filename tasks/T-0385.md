# B 路：插件面板「共 0 个 / 不包含任何组件」异常修复

## 现象（用户报）
```
MCP桥接
v内置
异常
2 个工具
共 0 个
这个插件包不包含任何组件。
```
- 描述位「2 个工具」有数，计数位却「共 0 个」；
- 既显示「2 个工具」又显示「不包含任何组件」，自相矛盾。

## 根因（已定位）
1. `src/web服务器.light:1239-1257 处理获取插件面板()` 装配的包信息里把
   `"组件": []` **硬编码为空**，真实工具名放在 `"工具表": 行["工具表"]`；
2. `src/插件面板.light §4 造卡片()` **只透传 `组件`，把 `工具表` 丢弃**；
3. `webui/settings.js:667-690 渲染插件卡()` 只在 `卡["组件"]` 为空时
   **回退读 `卡["工具表"]`** 展示「工具清单（N）」；
4. 经 `造卡片` 之后 `工具表` 已不存在 → 前端两腿都空 →
   `组件计数文案([])` 返回「共 0 个」，组件/工具表都取不到 →
   落到 `文案组件空()` = "这个插件包不包含任何组件。"。

## 已落修复（本仓本地）
- `src/插件面板.light` `造卡片` 末尾补 `工具表` 透传（无该键则不出）；
- `examples/test_插件面板.light` 增 2j/2k/2l 三判据，已 PASS。

## 待完成（本卡范围）
1. **标签「异常」来源补齐**：`处理获取插件面板` 现在把 `"标签":[] "错误":""`
   硬编码，前端「异常」标签只能来自 `造卡片` 派生（`错误 != 空`），
   但当前装配链路从不写 `错误` → **用户截图里 MCP桥接 的「异常」标签实际无来源**。
   核对 `插件启停.列插件状态(根)` 是否产出每插件 `错误`；
   若无，按上游判定（pnpm 不可用 / 加载失败 / 启停失败）补真实来源。
2. **MCP桥接 被剔除的口径**：`生产挂载.light` 因与 MCP接线撞车
   把 MCP桥接 从 agent 工具表剔除；面板口径是
   「内置 75 个 = 76 − MCP桥接 − jet-hub」。在面板 UI 上对 MCP桥接
   补只读原因或隐藏，避免用户误以为异常。
3. **端到端判据**：现有 `test_插件面板.light` 只覆盖纯函数；
   需补一条 `处理获取插件面板` → MCP桥接 → 工具表 2 →
   前端渲染含「工具清单（2）」且不含「不包含任何组件」的装配级用例
   （可借 `examples/test_r110_e2e` 模式）。
4. 回归：`pytest tests/test_回归.py -q` 无新增红。
