## 背景

派发流水线要解决两类人肉损耗的第二种：**重复通知同一个 agent、漏掉某张待分配卡**。
缺的是卡面上的一个「已推送到哪儿」的显式标记。

本卡做 L1/L2 的状态机内核：新增 `dispatched_to` 语义（纯函数改 dict，不落盘、不碰 git），
把「待分配 / 已推送 / 已被领走 / 跑到一半」这几档统一成一套可判定的阶段。
**本卡不碰 `hive.py`**，字段真正写进任务卡、以及 `TASK_FIELDS` 白名单的改动在 T-0188。

## 要做什么

新建 `dispatch_tracking.py`（纯标准库，不 import `hive.py`，无副作用），提供：

```python
STAGE_PENDING = "pending"; STAGE_DISPATCHED = "dispatched"; STAGE_CLAIMED = "claimed"
STAGE_RUNNING = "running"; STAGE_DONE = "done"; STAGE_FAILED = "failed"
STAGE_CONFLICT = "conflict"; STAGE_BLOCKED = "blocked"

def board_stage(card: dict) -> str
def mark_dispatched(card: dict, agent_name: str, *, when: str | None = None) -> dict
def clear_dispatched(card: dict) -> dict
def is_dispatch_candidate(card: dict, *, dispatched_ttl_minutes: int = 60,
                          now: datetime | None = None) -> bool
def summarize_board(cards: dict[str, dict]) -> dict
```

### 1. `board_stage(card)` 判定顺序（先命中先返回）

1. `state in ("done", "closed")` → `done`
2. `state in ("blocked",)` → `blocked`
3. `state in ("conflict",)` → `conflict`
4. `state in ("failed",)` → `failed`
5. `state in ("running",)` → `running`
6. `state in ("claimed", "assigned")` 或 `card.get("owner")` 有值 → `claimed`
7. `state == "ready"` 且 `dispatched_to` 有值 → `dispatched`
8. 其它 `state == "ready"` → `pending`
9. 兜底 → `pending`（未知 state 不许抛异常）

### 2. `mark_dispatched` / `clear_dispatched`

- 返回**新 dict**，不改入参（`deepcopy` 语义）；不得删除其它字段。
- `mark_dispatched` 写 `dispatched_to=<agent>`、`dispatched_at=<ISO8601 秒级，带时区>`
  （`when` 给定时用它，否则用当前本地时区时间）；`agent_name` 为空或含空白非法 → `ValueError`。
- 已 `claimed`（有 owner）的卡再 `mark_dispatched` 不报错但**保留 owner**，只补 `dispatched_to`
  （历史事实：这张卡确实推给过谁）。
- `clear_dispatched` 把两字段置 `None`（不是删键），保证 `write_card` 序列化稳定。

### 3. `is_dispatch_candidate`

- 必须 `state == "ready"` 且无 owner；
- 无 `dispatched_to` → True；
- 有 `dispatched_to` 且 `dispatched_at` 在 `dispatched_ttl_minutes` 内 → False（刚推过，别重复推）；
- 超过 TTL → True（视为「推了没领，允许再推」）；`dispatched_at` 缺失或无法解析 → True。

### 4. `summarize_board(cards)`

返回：

```python
{"total": 7, "counts": {"pending": 4, "dispatched": 2, "claimed": 1, ...},
 "pending": ["T-0184", ...], "dispatched": ["T-0186"], "claimed": ["T-0183"],
 "by_agent": {"trae-win": ["T-0187"]}}
```

- 键按任务号排序；`counts` 只含有非零的阶段（不要塞一堆 0）。
- `cards` 支持 `{tid: card}` 也支持 `{"tasks": [...]}` 形态（后者按 `card["id"]` 取号）。
