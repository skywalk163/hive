# T-0352 旧 HTTP 心跳面增量 LSA 上行（不回退 0.16.03 / 0.16.05）

## 背景

交办方要求「如果子节点推送了新状态，总控要及时更新，5 分钟之内要更新一下」。

现有上行有三条并存通道：Git（事实账）、集群 HTTP 8788（心跳 / `/api/cluster/push`）、
看板 `/api/push`。**0.16.03（11-11）和 0.16.05（11-12）刚把「把状态同步当心跳发」
这个病根治完**，实测 3 节点 1.3MB/s → ~9KB/s（约 143×），改动包括：

- 空闲心跳 `DEFAULT_IDLE_HEARTBEAT_S=5.0`、活跃 1s；
- 改用 `sd`（progress+leases 的 sha256 内容摘要）判断要不要回全量，
  取代被误当跨机水位的本地自增 `generation`；
- 事件只回 `EVENT_WINDOW_S=10.0` 内、按 id 去重、上限 32 条；
- 节点表去掉 `agents`/`hive_dir`/`hostname`/`pid` 等大块静态字段；
- `ACTIVE_WORK_WINDOW_S=600.0` 让远期租约不再把心跳永久钉在 1s；
- `state.json` 落盘 1s → 5s、`http_json` 进程级 keep-alive。

本卡的任务**不是**重做同步，而是把这些「实质变化」转成 T-0350 定义的
**T0 触发 LSA**，并让心跳只捎带 `(seq, digest, epoch)` 摘要。
任何让全量 `progress`/`leases` 回流心跳的改动都判不合格。

规范见 `H-LSA-协议设计-借鉴OSPF.md` §2（T0）、§3（复用清单）、§4 第 2 道闸。

## 要做什么

1. **变更识别 → 触发 LSA**：在 `hive_cluster.py` 的实质字段变更路径
   （`_mark_dirty_locked` / 卡面状态、claim、进度、结果、lease 更新）上挂
   `hive_lsa.note_change()`，产出**字段级 diff**而非整卡快照；
   `_mark_touch_locked`（仅心跳 `last_seen` / 租约续签）**不得**产生 LSA。
2. **摘要升级**：把现有 `sd` 升级为带 `seq` / `leader_epoch` / `area` 的 LSDB 摘要，
   通过 `hive_lsa.build_digest()` 产出；**保留旧节点不带 `sd` 时走全量的兼容路径**
   （滚动升级不丢状态，0.16.05 已验证过这条纪律）。
3. **心跳载荷瘦身**：心跳请求/响应只带 `(seq, digest, epoch, area)`；
   摘要相同 → 空载荷；摘要不同 → 只回**增量 diff**，绝不回整份
   `progress` / `leases` / `nodes.agents`。对齐 OSPF「Hello 只保活 + LSA 单独泛洪」。
4. **T0 SLA**：状态变更到总控可见硬上限 **300s**（交办方要求），
   设计目标 ≤10s；聚合窗口 200ms、MinLSInterval 5s、jitter ±20% 全部由
   `hive_lsa` 决定，本卡只负责正确调用，不自己另写一套定时器。
5. **原样保留**（一个都不许动）：
   `DEFAULT_IDLE_HEARTBEAT_S=5.0`、`EVENT_WINDOW_S=10.0`、事件上限 32、
   `ACTIVE_WORK_WINDOW_S=600.0`、`DEFAULT_MEMBERSHIP_TTL_S=300.0`、
   `state.json` 5s 落盘节流、keep-alive 连接池、心跳不推进 generation。
6. **`tests/test_cluster_lsa_uplink.py`**：
   - 复跑 0.16.03 / 0.16.05 的 **6 项回归**（摘要稳定性、摘要相同/不同/旧节点三种响应、
     事件窗口、瘦身节点表、远期租约不钉死心跳、留言退避）；
   - 新增：心跳 `last_seen` 不产生 LSA、实质变更产生且仅产生 1 条字段级 diff、
     200ms 窗口内 N 次变更合并、心跳响应不含 `progress`/`leases` 全量、
     空闲 5s 不被 LSA 打破、旧节点兼容路径仍可用、300s SLA 在 fake clock 下成立。

## 不要做什么

- **不改 `hive.py`**（T-0353 持有）、不改 `hive_control/*`（T-0351 持有）、
  不改 `dashboard/*`（T-0354 持有）；本卡只碰 `hive_cluster.py` 与其测试；
- 不回退 0.16.03 / 0.16.05 任何一条优化，不把 `generation` 重新当跨机水位；
- 不在心跳里塞全量状态、不把事件窗口调大、不把空闲心跳改回 1s；
- 不新增常驻线程 / 定时循环（节拍复用既有心跳循环，省 CPU）；
- 不连 Gitea、不发组播、不碰生产 8788 实例。

## 完成标准

1. 6 项历史回归 + 新增用例全绿，`python3 -m pytest -q tests/test_cluster_lsa_uplink.py` 通过。
2. 空闲期心跳请求 ≤685B、响应 ≤2.9KB 量级（与 0.16.05 基线同档，不得变大），
   且 `events` / `progress` / `leases` 为空。
3. 一次卡面状态变更只产生 1 条字段级 diff LSA，200ms 内多次变更合并为 1 条；
   纯心跳 30 分钟产生 0 条 LSA。
4. 旧节点（不带 `sd`）仍能走全量兼容路径，不出现状态丢失。
