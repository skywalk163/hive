# verify 跨平台：python 前缀、变量赋值前缀、make 能力过滤

## 背景

T-0334 的 verify 写成 `PYTHONPATH=src python scripts/acceptance.py --all`，在 Windows
提交机上 100% 假失败：

- 部署版 `should_wrap()` 不认这种写法 → 原样交 `cmd.exe` → `'PYTHONPATH' 不是内部或外部命令`（实测 rc=1）；
- 若被包进垫片，`interpreter_command()` 只认 `bash`/`python3`，不认 `python` → rc=2。

T-0335 则是 Windows 没有 `make`，同样假失败。两起都不是产物问题，是平台口径不一致。
（T-0334 报告 §9.1 引用的 `env_prefix_command()` 在部署版 `hive_compat.py` 里并不存在，
本卡以本仓实际代码为准。）

## 目标

1. `hive_compat.interpreter_command()` 支持 `python`（映射 `sys.executable`，与 `python3` 同）；
2. 支持 `VAR=value ...` 赋值前缀（一条或多条）：Windows 上转成 `set VAR=value&& <rest>`
   或解析出 env 后 exec；POSIX 上原样不动。至少保证 `PYTHONPATH=src python x.py` 不再假失败；
3. dispatch：卡面 `needs: make`（或 verify 含 `make`）时只派给 capabilities 含 `make` 的 agent；
   agent 配置可显式声明无 make；
4. 回归测试覆盖以上三类，含一条「Windows 上不假失败」的用例（monkeypatch `os.name`）。

## 红线

- 不改 verify 的退出码语义：未知写法仍要**明确失败**，不许猜成功；
- 不在 POSIX 上改写命令一个字节；
- 不动看板与集群协议。

## 验收

- `python3 -m pytest -q tests/test_compat.py` 全过；
- 新增用例覆盖 `python`、`PYTHONPATH=... python`、`make` 过滤；
- `python3 hive_compat.py run "PYTHONPATH=src python -c 'print(1)'"` 在 POSIX 上退出码 0。
