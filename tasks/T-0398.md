# 输入区增强：空会话附件暂存 + 上下文用量/一键压缩入口

## 背景

- **附件**：`webui/app.js:77` 维护 `attachments`，`:1032` 的选择器把文件读成 dataURL，
  发送时随 `body.attachments` 上送（`:798`，服务端已有 `附件归一`）。但 `newChatState`
  与 `clearAttachments`（`:116`、`:785`）在新建/切换会话时直接清空。DSH 允许在空白页
  先挂文件再开聊——现在点一下「＋ 新会话」，刚选的文件就没了，容易白选一次。
- **压缩**：服务端已有完整实现：`src/压缩.light:67-121`（token 计量 + 阈值自动压缩）、
  `src/代理.light:628`（step 前自动触发）、`/compact` 斜杠命令
  （`webui/slash-palette.js:20`）。但入口藏在斜杠面板里，触发后 `app.js:203` 只加一行
  系统提示；统计帧里已有「上下文使用率」（`app.js:190-200`）却没有可见的压缩控件。
  DSH 把「压缩对话」做成了显眼入口。

## 要做什么

1. 新建会话（尚无 `session_id`）时点击「＋ 新会话」**不清空未发送附件**；chip 保留，
   首条消息发送成功后才清空。
2. 切换到**已有**会话时清空待发附件，并给一次中文提示（避免把 A 会话附件带进 B）；
   同会话刷新不清空（只保存在内存，不写 localStorage）。
3. 附件上限：数量（建议 20）与单文件大小（建议 10MB）超限时中文提示并拒绝该文件；
   服务端 400 时 chips 保留，可重试。
4. 输入区显示「上下文 xx%」+「压缩」按钮；点击弹确认（说明保留最近 N 条、旧消息进摘要），
   确认后走**现有** `/compact` 通道；压缩事件到达时刷新用量并给系统提示（复用现有
   `种类 === "压缩"` 帧，`:726`）。
5. `/compact` 面板项保留（双入口），文案与按钮一致。

## 不要做什么（红线）

- 不改 `body.attachments` 协议形状，不新增文件上传端点。
- 不在前端自造压缩算法，不改自动压缩阈值默认值（`HARNESS_COMPACTION_THRESHOLD` 等）。
- 不引第三方 UI 库；不把附件 dataURL 写进 localStorage（体积与隐私）。
- 不动 `messages.js` 的消息渲染契约（只加压缩/用量提示样式）。

## 完成标准

- 两个 `node --check` 通过；`tests/test_T0398_附件暂存契约.py` 覆盖服务端对
  `attachments` 形状的接收/归一与超限 400（前端行为用静态契约 + 手工冒烟）。
- 手工冒烟清单写进 summary：空白页挂 2 个文件 → 新会话 → 文件还在 → 发送后清空；
  已有会话间切换 → 清空且有提示；压缩按钮 → 确认 → 使用率下降/提示出现。
