# strict 检测器：把「同一语义多种写法」变成可判定的一条

## 背景

R222 盘点的成本结构里，**约 60% 的 retry 不是模型不会写，而是「同一语义有多种合法写法」的选择负担**：
`读取` vs `读取文件`、`如果` vs `若`、中文标点 vs 英文标点、L1 省略类型 vs L2 显式类型。

对人是渐进学习曲线，对 agent 是**多解空间**——它不是学语言，是在猜分布，每处"两种都对"都在推高猜错概率。

本卡只做一个**纯检测器**：给定源码，找出所有非规范写法，并给出机械可套用的替换。**不接 CLI、不改 parser、不写诊断码表**（那是 T-0457 和 T-0464 的地盘）。

## 要做什么

1. 新模块 `src/ai_strict.py`（纯标准库）：

   ```python
   @dataclass
   class StrictFinding:
       line: int; column: int; end_column: int
       kind: str          # 'ALIAS' | 'PUNCT' | 'TYPE'
       actual: str; expected: str
       replacement: str   # 该处替换后的文本（单个 token/标点级）
       message: str

   def check(source: str, *, canonical: str = "L2") -> list[StrictFinding]: ...
   ```

   分词用 `src/lexer.py` 的公开接口（token 带 `L行:C列`）。

2. 三类规则：
   - **ALIAS**：双字/别名 → L2 单字。至少覆盖 `如果→若`、`否则→否`、`遍历→遍`、`跳出→跳`、`跳过→过`、`返回→返`、`定义→设`、`并且→且`、`或者→或`，以及 `src/keywords.py` 里带同义关系的其它组。
   - **PUNCT**：中文标点 → 英文（`，：。；（）""` → `, : . ; () ""`）。
   - **TYPE**：L2 要求显式类型标注，`设 甲 为 10` 这类无标注的变量声明报 `TYPE`（只报，不给 replacement——类型靠人/agent 判断，别编）。

3. **规则表的唯一真相是 `spec/light.spec.json`**（`keywords` / `l0_core` / `operators` 字段）。不许手写第二份关键字表：spec 里没有的别名关系就跳过，并在 summary 里列出"因 spec 缺信息而跳过"的清单。

4. 幂等：对已经是 L2 的代码返回空列表。

## 不要做什么

- 不改 `src/diagnostics/`（T-0457 独占）
- 不改 `cli/light.py`、`spec/`、`src/lexer.py`
- 不做"自动修复写盘"，只返回结构化结果
- 不新增依赖

## 完成标准

- `tests/test_T0458_strict.py`：
  - L2 规范样本（单字 + 英文标点 + 显式类型）→ 0 条
  - L1 样本（双字 + 中文标点 + 省略类型）→ 三类都命中，且每条 `replacement` 非空（`TYPE` 除外）
  - 位置断言精确到列（用 `python -m cli.light tokens` 的输出交叉验证一次）
  - spec 读不到时抛明确异常，不静默返回空列表
- verify：`python -m pytest -q tests/test_T0458_strict.py`
