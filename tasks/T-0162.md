## 背景

见 T-0161。设计结论：worker 内部用 `concurrent.futures.ThreadPoolExecutor`（上限取
agent 的 `max_concurrency`），每个任务一个线程，各自独占 `prepare`/`run_task` 建出来的
独立 worktree。现有 `Worker.run_task`（hive.py 2567 行）一次只跑一张，要把"挑卡—派发—
收集结果"改造成能同时跑 N 张。

注意：本卡与 **T-0163** 都改 `hive.py`，但区域不重叠（本卡动 `Worker` 执行链路，T-0163 动
`Hive._paths_conflict`）。dispatch 按文件级互斥，同一 agent 不会同时领这两张；不同机器
的 agent 可并发做，最后 `land` 时若 hive.py 有冲突由总控解（通常不同函数不冲突）。

## 要做什么

1. 给 `Worker` 增加并发执行能力：新增 `run_tasks(self, tids, max_workers=None)`，
   用 `ThreadPoolExecutor(max_workers=max_workers or int(cfg.get('max_concurrency') or 1))`
   提交每张卡的 `run_task`；`as_completed` 收集结果并返回 `{tid: result}`。
2. 把现有"单卡"入口改造为调用 `run_tasks([tid])`，保持 `hive take`/`hive work` 的单卡行为不变。
3. 心跳按任务隔离：现有 `lease_heartbeat` 上下文（hive.py 2491/2503 行）须保证每个并发任务
   各自起一条心跳线程、退出时各自停；确认它本身就是 per-call 的（每次 `with` 一条），
   若是模块级单例则改成 per-task。
4. 日志隔离：每张任务线程写自己的 `state/logs/<tid>.log`，线程间不共享未加锁的可变状态
   （worktree 路径本来就 per-tid，重点守护共享的日志/计数）。
5. `scripts/start-worker.sh` 增加 `--max-concurrency N`（默认沿用 agent 配置），透传给 worker。
6. 新增 `tests/test_worker_parallel.py`：用 fake command 模拟 3 张卡、`max_concurrency=2`，
   断言"任意时刻最多 2 张在跑"且"3 张最终都完成"，覆盖限流与结果收集。

## 不要做什么

- 不要为了实现而把 `run_task` 拆得面目全非——保留既有分支/verify/submit 逻辑，外层加池。
- 不要改 `Hive._paths_conflict` / `conflict.py`（那是 T-0163 的地盘）。
- 不要动 `tasks/` 里别的卡；不要引入新的第三方依赖。
