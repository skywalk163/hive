## 背景

现状是「同一工具连续 3 次校验失败熔断并中止本轮」。熔断本身是保护，但熔断前模型应已从 T-0506 的 suggestion 得到可操作信息。本卡把熔断与反馈闭环对齐，并借鉴能力登记（`工具_能力登记.light`）在执行前的 schema 校验/反馈思路：在工具被调用前用其 schema 做一次轻量校验，提前拦截明显错误，减少熔断。

## 目标

1. 在执行前基于工具 schema 做轻量预校验，提前拦截明显参数错误（缺字段/类型明显错）；
2. 熔断计数与结构化错误联动：熔断时附上「已尝试几次、各自失败原因摘要」，帮模型判断改方案；
3. 熔断阈值可配，且在熔断消息中明确告知模型「应换方案而非继续重试」。

## 交付物

- `src/工具执行.light`：预校验 + 熔断计数 + 熔断消息增强
- `tests/test_T0507_熔断反馈闭环.py`

## 验收判据

1. 预校验能在工具真正执行前拦截明显参数错误；
2. 熔断消息含尝试次数 + 各次失败原因摘要；
3. 熔断阈值可配，默认行为与现状一致（3 次）；
4. `tests/test_T0449_执行管线.py` 不回归。

## 红线

- 预校验只能拦「明显错误」，不得引入误拦（合法调用必须放行）；
- 默认熔断阈值保持 3，改动需显式配置；
- 与能力登记机制复用，不另造一套 schema 校验。
