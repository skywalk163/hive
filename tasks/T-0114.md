## 背景

`Hive.commit_and_push()` 是「git add -A → commit → push」一条龙。协调仓库的工作区里
**但凡有别的未提交改动，都会被一起卷进这次提交**。

已经发生过一次真实事故：总控在写完 `mcp_server.py`（705 行）、`docs/MCP接入.md`、
`tests/test_mcp.py`、README/CHANGELOG 之后还没提交，跑了一次
`hive task new --id T-0110 ...`。结果这些改动全被塞进
`1dbe2a4 task: add T-0110 闭环最后一公里…` 这个提交里推了上去 ——
提交信息说的是「加一张卡」，实际内容是一个完整功能。

不是小事：协调仓库的 `main` 是审计记录（卡片、结果、租约全在上面）。提交信息一旦
和内容对不上，事后就没法靠 `git log` 回溯「这一步到底是谁干的、为什么」。

注意这跟 T-0112 是同一类问题的两面：T-0112 管的是 **worker 在 worktree 里** 别改越界文件，
本卡管的是 **总控在协调仓库里** 别把无关改动卷进来。两边都靠 `git add -A`，都该收口。

## 目标

给 `commit_and_push` 加「只提交该提交的」能力，并在所有调用点用起来。

1. 签名改成 `commit_and_push(self, message: str, paths: list[str] | None = None)`：
   - 给了 `paths` 就 `git add -- <paths...>`（可以多次给，也可以给目录）；
   - 没给就走现在的 `git add -A`（向后兼容，别一次性改出 regression）；
   - 加了 `paths` 之后仍然要判断「有没有东西可提交」，没有就跳过 push（现在的
     `diff --cached --quiet` 判断保留）。
2. 逐个调用点传上明确的文件清单（都在 hive.py 里，搜 `commit_and_push`）：
   | 调用点 | 该提交什么 |
   |---|---|
   | `cmd_task`（建卡） | `tasks/<tid>.md` |
   | `_assign_local` 之后的 assign / take / retry | `tasks/<tid>.md` + `inbox/<agent>/<tid>.md` |
   | `cmd_close` | `tasks/<tid>.md` + `results/<tid>.json` |
   | `cmd_gc` / `cmd_retry` 里撤归档 | `results/<tid>.json` |
   | `cmd_init` / `cmd_agent` | 目录级：`tasks/ agents/ inbox/ results/` |
   拿不准的就按「这次命令本该改什么」来列，宁可多列一个相关文件，也别漏。
3. **兜底告警**：没传 `paths` 的调用点（如果有的话确实该保留全量语义），
   日志里打一句 `commit_and_push 未指定 paths，将提交工作区全部改动`，
   让 `hive doctor` 也能报出来。
4. 测试（`tests/test_core.py`）：
   - `test_task_new_does_not_sweep_unrelated_changes`：
     在协调仓库工作区里手写一个无关文件（比如 `notes.tmp`），跑一次建卡，
     断言这次提交**不包含**它（用 `git show --stat HEAD` 看），
     而且它仍然是 untracked 状态；
   - 顺带断言建卡提交里**确实包含** `tasks/<tid>.md`。
5. `docs/操作手册.md` 里补一句运维约定：**跑 hive 写命令前先把自己手头的改动提交掉**，
   并说明现在已经有 paths 收口兜底。

## 红线

- 不改 light 等仓；不引入新依赖。
- 现有 32 个测试必须还绿。这是重构 `commit_and_push` —— 调用点有 8 处左右，
  漏一处就会让某个命令静默不生效，改完务必跑全量。
- 别改 `commit_and_push` 的返回值语义（`True`=提交了，`False`=没东西可提），
  有调用点依赖它。
- 别顺手改 `tasks/*.md` 或 `results/*.json`。

## 验收

`git show --stat HEAD` 覆盖 `hive.py` + `tests/test_core.py` + `docs/操作手册.md`；
verify 全过。

## 备注

验证自己改对了没有，最直观的办法：改完之后在协调仓库工作区里随便 touch 一个文件，
跑一次 `hive task new`，看它有没有被卷进去。
