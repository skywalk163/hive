## 背景

评审建议：把开发中暴露的每个语言报错自动归档成「光明报错数据集」，定期增量微调 `light-translator`，让它专门学会避开 Light 的已知暗坑，而不是泛泛做语言翻译。项目文档里已有这个思路，但没有落盘实现。

本卡只做**库与格式**，不接 CLI（接线在 T-0326），因此可以完全并行。

## 要做什么

1. 新建 `tools/ai_copilot/error_corpus.py`，纯标准库：
   - `record(diagnostic, source, context=None, root=None) -> dict`：追加一行 JSON 到 `<root>/YYYY-MM.jsonl`；
     默认 root = `~/.light/error_corpus`，可用 `LIGHT_ERROR_CORPUS_DIR` 覆盖；
   - 记录字段：`ts / code / message / hint / fixes / source_snippet(出错行 ±2 行) / source_hash(sha256 前 16) / lang_level / backend / light_version / hits`；
   - **去重**：同 `(code, source_hash)` 只保留一条，命中时 `hits += 1` 并更新 `last_seen`（写 `index.json` sidecar，避免全量重写 JSONL）；
   - `export_pairs(min_hits=1) -> list[dict]`：SFT 风格 `{"prompt": 代码片段 + 报错信息, "completion": 正确写法/修复步骤}`；
   - `summary(window_days=30, top=10) -> list[dict]`：`[{code, hits, last_seen}]` 按 hits 降序，字段名稳定（T-0320 要消费）；
   - `purge(before=None, dry_run=True)`：清理，默认只报告。
2. 脱敏：`source_snippet` 里去掉绝对路径、用户名、疑似 token（`[A-Za-z0-9_\-]{32,}` 打码）；文件路径只留 basename。
3. 并发安全：追加写用 `open(..., 'a', encoding='utf-8')` 单行一次写入；index 更新失败只 warn，不抛。
4. `docs/报错数据集.md`：格式说明、隐私边界（只存片段不存整文件）、清理方式、如何喂给 `tools/ai_copilot/` 的训练脚本。
5. `tests/test_error_corpus.py`（tmp 目录）：
   - record → 文件存在且每行是合法 JSON；
   - 同一错误记 3 次 → 只有 1 行、`hits==3`；
   - 脱敏：绝对路径/token 不出现在产物里；
   - export_pairs 结构正确；summary 排序正确、按窗口过滤；
   - 100 条并发追加后文件仍是 100 行合法 JSON（无半行）。

## 不要做什么

- 不联网、不上传、不发遥测。
- 不在 `light ai check` 主流程里默认写盘（T-0326 接线，且必须可关闭）。
- 不收集环境变量、主机名、用户名等标识信息。
- 不加第三方依赖（不引入 pandas/pydantic）。

## 完成标准

- `python -m pytest -q tests/test_error_corpus.py` 全绿。
- summary 里贴一段真实产物（脱敏后的 2 行 JSONL + 一条 export pair）。
