## 背景

用户要求把「小浣熊接入 hive」这一轮的实测结论落成文档，让其它 agent 能快速上手。

原计划只写一份面向 agent 的上手文档，但写作过程中产生了两类附加价值，一并落地：

1. **新文档 `docs/AGENT快速上手.md`**：现有《操作手册》是给人看的全量命令参考，
   《MCP接入》偏工具清单，缺一份"第一次接进来、照着做就能跑通"的入口。
2. **两个实测踩到的坑必须写进文档**，否则每个新 agent 都会再踩一次：
   - `--dir` 写在 `mcp` 子命令前面会被顶层同名参数吃掉、静默回退默认 clone
     （旧 README 的示例正是这种失效写法）；
   - MCP 启动与每次调用都 `reset --hard`，`--dir` 指向主工作区会抹掉未提交改动。

## 目标

- 新增 `docs/AGENT快速上手.md`：30 秒配置 → 身份自检 → 完整闭环 → 硬规则 →
  报错速查 → 一页速查，全部基于实测输出，不写推测内容。
- 修正 `README.md` 里会失效的 MCP 配置示例（`--dir` 位置），并在 §7 补小浣熊的现成配置。
- `docs/MCP接入.md` 新增 `--dir` 陷阱小节，并统一工具数量口径（消除 6/7 个的
  自相矛盾描述、以及过时的 12/19）。
- `docs/操作手册.md` 开头加一句导流，指向新文档（不动任何章节编号）。

## 红线

- 只动文档，不动 `hive.py` / `mcp_server.py` 的代码。
- 不动 `docs/操作手册.md` 的章节编号（`tests/test_docs.py` 盯着编号）。
- 工具数量、工具名一律以 `tools/list` 实测为准，不照抄旧文档。
- 文档里不写未经实测的行为。

## 验收

- `python3 -m pytest tests/test_docs.py -q` 全绿。
- 文档提的每个工具名都能在 `tools/list` 里找到（或明确标注为不可用并给出 CLI 绕道）。
- 文档引用的 CLI 子命令均存在。
