## 背景

列表页现在**全量**下发：`hive status --json` 把 `tasks/*.md` 全部解析一遍，
`dashboard/status.json` 已经 **362KB / 85 张卡（83 done）**，每 30 秒重写一次。
按当前增速，几百张卡时单次快照会到 1~2MB，看板首屏和 `status --json` 都会明显变慢。

`hive_store.py` 只有 `meta / tasks / claims / results / ops` 五张表（72-107 行），
没有任何「列表用摘要」的概念；详情（`verify` 的 tail、`result_summary`）也跟着
全量下发。

## 要做什么

1. **先出设计**（`docs/冷热分离与归档.md`，新文件，本卡交付物之一）：
   - 摘要表 `task_summary`：`id / title / state / repo / priority / owner /
     created_at / finished_at / summary_head / archived`；
   - 索引：`(state, finished_at)`、`(repo, state)`；
   - 热窗口可配 `HIVE_ARCHIVE_DAYS`（默认 14 天）；
   - 冷数据落 `tasks/archive/YYYY-MM/`（**只移动、不删除**，可 grep）+ 已有
     `results/<tid>.json`；
   - 详情懒加载契约：列表只回摘要，详情按 `id` 现取；
   - 回滚路径写清楚（`--restore`）。
2. **再落地**：
   - `hive_store.py` 迁移 v2（`PRAGMA user_version`，幂等：连跑两次 schema 一致）；
   - `hive_archive.py`（新文件）：`--dry-run`（默认）先出报告、`--days N`、
     `--restore <tid>`；
   - `hive status` 增加 `--summary`（只输出摘要字段）供后续接口复用。
3. 归档后 `status.json` 体积必须显著下降，且列表仍能查到该卡的摘要（`archived: true`）。

## 不要做什么

- 不删任何卡：归档 = 移动 + 打标，随时 `--restore` 能回来。
- 不改 `results/<tid>.json` 的既有结构（land/close 在写它）。
- 不动看板前端（列表分页是后续卡）。
- 不给 `tasks` 表加 `payload_json` 之外的新列而不写迁移（老库要能升级）。

## 完成标准

- `python3 -m pytest -q tests/test_store.py tests/test_archive.py`（后者新文件）全绿。
- 判据（都要反证）：
  1. 迁移幂等：连跑两次 `user_version` 与表结构一致；
  2. 归档 30 天前的 50 张卡后，`status --summary` 体积**下降 ≥ 50%**，
     且 50 张卡在摘要里都还在（`archived: true`）；
  3. `--restore` 之后该卡详情可读、`archived` 复位；
  4. `--dry-run` **不产生任何文件移动**（用目录快照前后 diff 证明）。
- 附归档前后 `status.json` 体积、`status --summary` 耗时的实测数字。
