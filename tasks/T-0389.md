# e2e 收录漏了 `mvp/02_http_json.light`：需要外部 HTTP 服务，任何机器都必红

## 背景

T-0383（R222 M 线收口）在 0.88 跑全量，发现两条用例三轮全量都红：

```
tests/e2e/test_e2e_chain.py::test_duan_run[mvp/02_http_json.light]
tests/e2e/test_e2e_chain.py::test_duan_compile_and_run_product[mvp/02_http_json.light]
```

失败原文：

```
AssertionError: duan run 失败 (mvp/02_http_json.light):
  [运行错误] 无法连接到 http://127.0.0.1:8765/mvp: [Errno 61] Connection refused
```

**Windows 本机同样 2 failed，可稳定复现**（不是 0.88 环境问题）。

来龙去脉：

- `examples/mvp/02_http_json.light` 由 T-0321（2026-11-10 21:24，`833ba145e`）引入，属于
  "生态最小可用面"的 5 个方向示例之一。
- 文件头注释自己写清了前置条件：

  ```
  # 运行：python -m cli.light run examples/mvp/02_http_json.light -- http://127.0.0.1:8765/mvp
  # 场景：请求本机 HTTP 服务 → 解析 JSON → 取字段。只访问 http://127.0.0.1，不联网。
  # 未给地址时默认 http://127.0.0.1:8765/mvp（测试会起随机端口的本机服务并用 `--` 传入地址）。
  ```

- 但 `tests/e2e/test_e2e_chain.py` 的候选集是**全量枚举**，且 `E2E_EXCLUDED` 里没有它：

  ```python
  EXAMPLE_CANDIDATES = sorted(
      p.relative_to(EXAMPLES_DIR).as_posix()
      for p in EXAMPLES_DIR.rglob('*.light')
      if p.relative_to(EXAMPLES_DIR).as_posix() not in E2E_EXCLUDED
      and p.relative_to(EXAMPLES_DIR).as_posix() not in EXPECTED_FAILURE_EXAMPLES
      and 'weather_app' not in p.relative_to(EXAMPLES_DIR).as_posix()
  )
  ```

- `_run_cli()` 也不传 `--`：

  ```python
  def _run_cli(args, cwd=None):
      result = subprocess.run([sys.executable, '-m', 'cli.light_unified'] + args, ...)
  ```

于是这个"需要外部服务"的示例被当成"应当自洽跑通"的示例，必然失败。
注意它不是本次 R222 改动引入的回归——`E2E_EXCLUDED` 里已经收了一批同类（`web_crawler/crawler.light`、
`todo_app/main.light` 等），只是漏了 `mvp/02_http_json.light`。

## 目标

二选一（按"这个示例要不要进 e2e 判据"决定）：

**方案 A（推荐，改动小）**：把它加进 `E2E_EXCLUDED`，并注明理由。
它和 `web_crawler/crawler.light` 属同一类（需要外部服务/网络端点），本来就不该进"自洽跑通"判据。

```python
E2E_EXCLUDED = {
    ...
    # 需要外部 HTTP 服务：示例默认连 http://127.0.0.1:8765/mvp，e2e 不负责起服务。
    # 与 web_crawler/crawler.light 同类。T-0321 引入时漏收（T-0383 收口发现）。
    'mvp/02_http_json.light',
}
```

**方案 B（改动大，覆盖强）**：给 e2e 加一个起临时本地 HTTP 服务的 fixture，并把地址用 `--` 传给 CLI。
这样示例能真正被端到端验证，但要处理端口抢占、服务生命周期、以及 `test_duan_compile_and_run_product`
里产物独立运行时的 `cwd`（现在传的是 `REPO_ROOT`）与参数传递。

如果选 B，`_run_cli` 需支持透传参数（现在签名只有 `args, cwd`），并且 `--` 之后的地址要能被
`用户参数()` 读到——这条链本身也值得一个回归用例。

建议先做 A 止红，B 单独开卡做增强。

## 红线

- 不要把示例文件本身删掉或改成"不联网的空壳"——它是 MVP 面子的可运行证明。
- 不要为了让 e2e 绿而把 `EXAMPLE_CANDIDATES` 的枚举范围缩小到某个白名单（会静默漏掉新示例，
  正是这次问题的成因之一）。
- 如果要给 `test_duan_compile_and_run_product` 加服务，注意它对产物是用 `sys.executable` 直跑，
  和 `duan run` 走的是两条链，两个用例都要覆盖到。
