## 背景

自举到第三批，exec 类任务从 ready 到 done 其实已经能全自动（worker 领卡→跑→写结果），但「分派」和「合入」这两步还得人工 drive：我手动 `hive dispatch --apply` 再 `hive land --all --apply`。T-0125 的看门狗又能自动回收死卡。三块拼起来，缺一个把它们串成循环的总控进程。

现状痛点：
- 每张卡都要人去点 dispatch / land，卡多了就漏；
- dispatch 只派 exec/verify agent，manual agent（如 workbuddy）的卡本来就不该全自动，属于预期内「留给人」；
- 看门狗的 `orphan_assigned` 回收目前读卡 body 的 assigned_at，但 `_assign_local` 实际写在 `inbox/<owner>/<tid>.md`，导致「分派了但 worker 一直没来领」的死卡永远收不回。

## 目标

给 hive 加一个「总控进程」角色——一条 `hive orchestrate` 命令，循环做 **看门狗回收 → 自动分派 → 自动 land → 体检**，替代人工 drive。让 exec 类任务从 ready 到 closed 全自动跑完，人只需要在 needs_review / 冲突 / 依赖外部资源等卡点介入。

## 需求

1. 新命令 `hive orchestrate`：
   - 每轮 tick 顺序：`watchdog --apply`（回收死卡）→ `dispatch --apply`（分派 ready）→ `land --all --apply`（合入完成卡）→ `doctor`（报告）。
   - 参数：`--interval`（默认 60 秒）、`--once`（跑一轮就退）、`--iterations N`（跑 N 轮退）、`--no-dispatch` / `--no-land` / `--no-watchdog` / `--no-doctor`（关闭某一阶段）、`--stop-file PATH`（文件出现即优雅退出）、`--dispatch-limit N`、`--max-land N`、`--watchdog-minutes N`（默认 180）、`--orphan-grace N`（默认 45）、`--json`（每轮打印 tick 摘要 JSON）。
   - 单轮内任何子步骤抛 `HiveError` 都 catch 住、记 log、继续下一轮，绝不整进程崩。
   - 安全默认：dispatch / land / watchdog 本就是 dry-run 才不落地，orchestrate 显式用 `--apply` 才真改，不引入新的破坏性开关。
2. 看门狗增强（配合总控）：`orphan_assigned`（state=assigned 但一直没 claim）按「分派后过了 orphan_grace 分钟」才回收；`_assigned_at` 改读 `inbox/<owner>/<tid>.md` 里 `_assign_local` 实际写的 `assigned_at`（目前读卡 body 是错的，导致这类死卡永远收不回）。新增 `--orphan-grace` 参数（默认 30，orchestrate 用 45）。
3. **不动 worker 自身循环**：worker 仍是各机器独立进程（自己的 `loop`）。总控只负责「脑」（分派+合入+回收），worker 负责「手」（执行）。两者解耦，便于推理和测试。

## 验收

- 新增 `tests/test_orchestrate.py`：
  - `test_orchestrate_once_dispatches`：`--once --no-land --no-watchdog --no-doctor` 能把一张 hive repo 的 ready 卡分派给注册的 exec agent（owner 被设置、inbox 信号生成）。
  - `test_orchestrate_once_lands_done`：`--once --no-dispatch --no-watchdog --no-doctor` 能把一张 done 卡 land 并 close（state=done、main 前进、claim/res 分支清理）。
  - `test_orchestrate_once_reclaims_via_watchdog`：`--once --no-dispatch --no-land --no-doctor` 能通过 watchdog 回收一张僵尸卡回 ready（清空 owner、+retries）。
  - `test_orchestrate_skips_fresh_assigned`：dispatch 后下一轮 watchdog 不回收刚分派的卡（orphan_grace 保护，刚分派的未被误杀）。
  - `test_orchestrate_iterations`：`--iterations 2` 跑满两轮后退，不无限循环。
  - `test_watchdog_orphan_grace`：orphan_assigned 在 grace 内不回收、超过才回收（分派时间从 inbox 文件读）。
- 全量 `pytest tests/ -q` 仍绿（不破坏现有 ~95 用例）。
- `hive watchdog --help` 出现 `--orphan-grace`；`hive orchestrate --help` 出现上述参数。

## 红线

- **不许把 orchestrate 作为 MCP 工具暴露**（会阻塞调用方）：MCP controller 那边保持由总控 agent 自己循环调 `hive_dispatch` / `hive_land` / `hive_watchdog`；本卡只在文档里说清「总控 agent = 跑 orchestrate 的进程 +（可选）带 controller MCP 的 LLM」。
- 不改变 dispatch / land / watchdog 的既有安全语义（dry-run 默认、不 force push、冲突不强制合入）。
- 不动 worker 的 `loop` / `run_task` 行为。
- manual agent 的卡不被 dispatch 触碰（这是 dispatch 既有的「人工优先」逻辑，保持）。
