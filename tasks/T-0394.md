# 补 fetch-deps.ps1：让 Windows 原生 PowerShell 用户免装 Git Bash

## 背景（为什么需要这张卡）

`README.md` 的「第一步：一键拉齐三仓」目前只有 `scripts/fetch-deps.sh`（Bash）。
Windows 用户被迫装 Git Bash：
```
& "C:\Program Files\Git\bin\bash.exe" scripts/fetch-deps.sh
```
这是不必要的入门门槛。本仓大量用户在 Windows（hive 里 10+ 个 win agent），
应该提供原生 `.ps1` 版本。

## 要做的事

1. 新建 `scripts/fetch-deps.ps1`，**功能对齐** `fetch-deps.sh` 的全部选项：
   - `--dir DIR`（PowerShell 用 `-Dir`，默认 `./lightharness-deps`，支持 `LIGHTHARNESS_DEPS_DIR` 环境变量）
   - `--mirror gitcode|github|<基址URL>`（`-Mirror`，默认 gitcode）
   - `--depth 1`（`-Depth`，浅克隆）
   - `--branch NAME`（`-Branch`，三仓共用分支）
   - `-NoPull` / `-NoRun`（已存在仓不更新 / 只拉仓不冒烟）
   - `-DryRun`（只打印不落盘）
   - 三仓 URL 覆盖环境变量：`LIGHT_REPO` / `LIGHTPLUGIN_REPO` / `LIGHTHARNESS_REPO`
2. **行为对齐**关键细节：
   - 克隆失败清掉半成品目录，可重复执行（已存在走 `git pull --ff-only`）
   - 校验三仓标志物：`light/src`、`lightplugin/集成`、`lightharness/运行.py`
   - 冒烟：`LIGHT_MERGE=<dir>/light LIGHTPLUGIN=<dir>/lightplugin python 运行.py examples/冒烟.light`，
     退出码 0 才算成功
   - PowerShell 输出用 Write-Host / Write-Error，退出码用 `exit $code` 正确传播
3. 更新 `README.md` 的「环境准备」段，加 PowerShell 原生用法（替换「必须用 Git Bash」的说法）。
4. 新增 `tests/unit/test_fetch_deps_ps1.py`（或在现有 smoke 测试中加），至少做**静态契约**：
   - ps1 文件存在、关键参数名齐全（`-Dir`/`-Mirror`/`-Depth`/`-DryRun`）
   - README 含 `fetch-deps.ps1` 用法
   - 若本机有 pwsh，则跑 `pwsh -File scripts/fetch-deps.ps1 -DryRun` 断言 rc=0

## 验收判据（必须全部满足）

- 本机若有 PowerShell（pwsh），`-DryRun` 实跑 rc=0 且打印的命令与 sh 版等价
- 静态契约测试全绿
- README 用法描述准确、无 Git Bash 强制依赖的遗留说法
- CHANGELOG `[未发布]` 段追加说明

## 环境说明

本机是 FreeBSD，**可能没有 pwsh**。这种情况下静态契约测试跳过 pwsh 实跑（不要硬装），
只保证脚本语法正确 + 参数对齐 + 文档更新即可。Windows agent 领这张卡时请务必实跑 `-DryRun`。
