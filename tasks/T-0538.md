## 背景

用户报告：这台 Windows 机器一启动 hive（dashboard + cluster），任务管理器里就会冒出几十个 `conhost.exe`（控制台宿主进程），关掉后又不断重新出现。实测确认如下：

- `dashboard/serve.py` 以 `--auto-refresh --refresh-interval 20` 常驻运行，`refresh_loop`（`dashboard/serve.py:711`）**每 20 秒**执行一次 `hive status --json --sync-health`（`serve.py:722`）。
- 该命令内部会调用多次 git（`ls-remote`、`cat-file --batch`、`show` 等）。Windows 上每个 console 子进程都会创建一个 `conhost.exe`。
- 代码里虽然统一走 `no_window_kwargs()`（`hive_compat.py:143`）传 `CREATE_NO_WINDOW`，但它**只隐藏窗口，不阻止 conhost 进程创建**。git 网络操作卡住（seed `192.168.0.88:8788` 不可达时）后代进程不退出，conhost 就不回收。
- 实测数据：2026-11-27 20:46–20:51 期间每分钟新增 12 个 conhost（每 5 秒一个，与前端自动刷新叠加）；峰值 71 个，其中 60+ 是父进程已退出的孤儿。清理后 12 秒内又新增 4 个。
- `hive_compat.py:147` 注释自己承认："看板每 30 秒刷新一次就闪一下黑窗"——说明这是已知现象但只做了表面处理。

同时发现另一个明确 bug：

- `dashboard/app.js:2279` 每 30 秒（`CI_MS=30000`）请求一次 `/ci.json`（`app.js:2330` `loadCI`）。
- 服务端 `serve.py:81` 把 `/ci.json` 列为静态文件，但 **`dashboard/ci.json` 文件根本不存在**，每次请求都返回 500。
- `~/.hive/logs/dashboard.err.log` 里已累积 **1727 条** `"GET /ci.json HTTP/1.1" 500 -`。

## 目标

1. **消除 conhost 堆积**：让 dashboard 的自动刷新（以及 `hive status` 的 sync-health 检查）在 Windows 上不再为每个 git 子进程创建残留的控制台宿主进程。
2. **修复 `/ci.json` 500**：让该接口在没有 CI 数据时返回合法的 200 JSON（例如 `{"ok":true,"jobs":[]}`），而不是 500；同时清掉已有错误日志刷屏。

## 要做什么

1. 在 Windows 上复现：启动 `hive dash start`（带 `--auto-refresh --refresh-interval 5`）并打开看板页面，观察 `Get-CimInstance Win32_Process | ? Name -eq conhost.exe` 的数量是否随时间增长；人为让远端 seed 不可达可稳定复现。
2. 修 `no_window_kwargs()` / `refresh_loop` 的子进程创建方式：研究 Windows 下 `CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` 的语义，找到既能捕获输出、又不分配（或能正确回收）控制台的方案。可考虑的方向（不强制）：
   - 使用 `STARTUPINFO` + `CREATE_NO_WINDOW` 并确保无孤儿后代持有控制台；
   - 让相关 git 调用走长驻连接或减少调用次数；
   - 为 `refresh_loop` 增加子进程超时后的强制清理（`/T` 杀进程树）。
3. 修 `/ci.json`：
   - 方案 A（推荐）：补一个默认 `dashboard/ci.json`（内容为空数据 JSON，如 `{"ok":true,"jobs":[]}`），并保证静态文件服务对其返回 200；
   - 方案 B：在 `serve.py` 中把 `/ci.json` 改成动态接口，无数据时返回 200 空 JSON；
   - 两种方案都要保证前端 `loadCI()` 能正常解析，不再 500。
4. 补回归测试：
   - `tests/test_no_window.py` 或新增测试，验证 Windows 下反复跑 `hive status --json --sync-health` 不产生持续增长的 conhost（可用 mock 或进程快照对比）；
   - 新增 `tests/test_dashboard_ci_json.py`，验证 GET `/ci.json` 返回 200 且 body 是合法 JSON。
