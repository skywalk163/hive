## 背景

T-0439 把 8 个预设分成了「Agent 模式（4）」与「工作方法（4）」，但两类仍是**互斥整套替换**：
选 `brainstorm` 就丢掉 `ptc` 的批量调用能力，选 `ptc` 就丢掉「只读发散」的约束。
下一步要把两维**正交化**：工具面由 Agent 模式决定，推进方式由工作方法决定，
并且补一个 `default`（默认）方法 —— 对应用户日常最常选的「标准 × 默认」。

## 目标（一张卡做完）

1. **两维模型**：`组合串 = 代理ID + "+" + 方法ID`，如 `standard+default`、`ptc+brainstorm`。
   4 代理 × 5 方法 = **20 个合法组合**；会话/请求里存的就是这个组合串（复用现有 `模式` 字段，
   不加会话库字段、不做数据迁移）。
2. **工作方法加 `default`**：`default` / `topdown` / `bottomup` / `brainstorm` / `lazy`（中文「默认」）。
   `default` 对工具面与提示面都**零改动**，`standard+default` 必须与旧 `standard` 逐项等价。
3. **工具面组合规则**：`组合行表(组合串) = 代理行表 − 方法删减`。
   方法**只做删减，不许新增工具**（topdown 的工具面删减集为空，差异全在提示/终止条件）。
   删减集必须写成数据（`方法删减(方法)`），不许在装配处写 if-else。
4. **行为面组合规则**：`模式系统提示(组合串) = 代理提示 + 方法提示`（顺序固定；`default` 为空，
   代理提示目前 4 个都为空 → `standard+default` 提示为空，与 T-0403 判据一致）；
   `模式终止条件/模式开关表(组合串)` 取方法维，`default` 回落原 standard 的默认值。
5. **兼容别名（不能静默改语义）**：
   - 裸代理 id → `代理+default`（4 个）；
   - 裸方法 id（旧 4 个）→ `standard+方法`（必须与旧版 8 预设行为等价）；
   - `default` 只作为方法 id，不单独出现在 `--preset` 的旧可用清单语义里（见判据 3）。
6. **UI 两下拉**：Agent 模式（4）× 工作方法（5，默认排第一），默认 `standard × default`；
   页面加载把组合串拆回两个下拉。设置页「Agent预设」只列 4 张代理卡，工作方法单独一组 5 张。
7. **CLI / Web**：
   - `--preset` 仍接旧值（含 4 个方法 id 的兼容拆分）；新增 `--method <default|…>`；
     两者都给时组合，只给 `--method` 时代理取 `standard`。
   - `/api/chat` 载荷支持 `preset`（可为组合串/旧 id）+ 可选 `method`；注册表缓存键必须是**组合串**。
   - 统计帧回报 `模式`（组合串）与 `方法`（方法 id），旧 `步数上限` 等字段不动。

## 验收判据（必须可执行）

1. **20 组合矩阵**：`组合矩阵()` 返回 4×5=20 个组合串，全部 `是已知预设()==真`；
   每个组合 `组合行表()` 非空、`组合统计()` 的展平后 = 插件行 + 1。
2. **等价性（主证据）**：`standard+default` 的行数/叶子集 == 旧 `standard`；
   `standard+topdown|bottomup|brainstorm|lazy` 的行数/叶子集 == 旧 4 个方法预设；
   `ptc+default / minimal+default / cordis+default` == 旧对应预设。
3. **别名解析**：`解析组合("topdown") == ["代理":"standard","方法":"topdown"]`；
   `解析组合("ptc") == ["代理":"ptc","方法":"default"]`；
   `解析组合("standard+default")` 原样；未知/乱序/空串/`+` 多个 → 报错或不合法，不静默回落。
4. **工具面删减**：`ptc+brainstorm` 叶子集里没有 `写文件`/`bash`/`pwsh`/委派组；
   `cordis+bottomup` 没有目标工具与提问工具；`minimal+topdown` 与 `minimal+default` 叶子集相同
   （topdown 不新增工具）；`default` 对 4 个代理的删减集为空。
5. **行为面**：`standard+default` 提示长 0；`standard+brainstorm` 提示头 `## 工作方式`；
   `模式终止条件("ptc+lazy")` 与 `模式终止条件("lazy")` 相同。
6. **CLI**：`--method` 出现在帮助；`--preset ptc --method lazy` 装配出组合；`--preset lazy` 等价
   `standard+lazy`；非法 `--method` 报错并列出 5 个合法值。
7. **Web/UI**：`/api/chat` 只给 `preset=ptc+brainstorm`、只给 `preset=ptc` + `method=brainstorm`、
   只给 `preset=ptc` 三种请求都落到同一组合；两个下拉默认 `standard`/`default`；
   localStorage 旧单值（如 `brainstorm`）升级后落到「标准 × 头脑风暴」。
8. **文档**：模式规格有 0.3 节与 20 组合表；CHANGELOG 有本条。

## 反证（写进 summary.md）

- `default` 的删减集塞进一条 `tool-ask-user` → 判据 2/4 立红；
- `解析组合("topdown")` 返回 `standard+topdown` 之外的组合 → 判据 3 立红；
- 注册表缓存键仍用 `preset` 裸值 → `ptc+brainstorm` 与 `ptc` 串味，判据 7 的等价请求立红；
- 删掉模式规格某段 `### 终止条件` → T-0406 第 0 组自检立红。

## 风险（写进 summary.md）

- 20 组合是**笛卡尔积**，不是每组合单独写行表；实现必须是「代理行表 − 方法删减」，否则维护成本爆炸。
- `brainstorm` 与 `ptc` 组合会得到「只读 + 批量工具」，语义上可行但没在真实任务跑过，先文档标注「未实测」。
- 旧裸方法 id 的提示/终止/开关必须与旧版等价，任何差异都要在 CHANGELOG 点名，不许静默。
