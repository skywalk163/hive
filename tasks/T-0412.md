## 背景
`deploy/lightmem-watchdog.sh` 用 `service "$SERVICE" restart`（systemd 机器可能没有 service 命令兼容层）和 `fetch`（FreeBSD 专有，Linux 无 curl 时失效）；只有 cron.d 形态，无 systemd timer。Linux 上要么看门狗失效，要么依赖 cron 未安装。

## 目标
1) 看门狗重启动作改用 T0 `platform.sh` 的 `lm_service_restart`（systemd→systemctl，freebsd→service）。
2) 探活回退链：`curl` → `wget -q -O /dev/null` →（仅 freebsd）`fetch`；Linux 无 curl 有 wget 也能工作。
3) 新增 `deploy/lightmem-watchdog.service`（oneshot）与 `deploy/lightmem-watchdog.timer`（每 2 分钟，`OnCalendar=*:0/2`，`Persistent=true`，`RandomizedDelaySec=10` 防抖）。
4) `deploy/README.md` 与 `deploy/cron.d/lightmem-watchdog` 注释补 Linux 安装法（`systemctl enable --now lightmem-watchdog.timer`）与 cron 法二选一。
5) 冷却文件目录用 `lm_prefix()` 口径（Linux `/run/lightmem` 或 `/var/lib/lightmem`，避免 `/var/run` 符号链接差异）。

## 红线
- 不改 FreeBSD rc.d 守护语义（daemon -R/-C）；看门狗是补充不是替代。
- 一次只重启本服务，不动其它实例。
- 只读探活 + 重启，不改配置/数据。

## 验收
- `sh -n deploy/lightmem-watchdog.sh` + 在 Linux 上用假 URL（`LIGHTMEM_READYZ_URL=http://127.0.0.1:1/readyz`）+ `LM_DRY_RUN=1` 跑一次，贴出「不 real restart、只打印」的输出。
- `systemd-analyze verify deploy/lightmem-watchdog.service deploy/lightmem-watchdog.timer`（有 systemd 时）无错。
- `git show --stat` 只覆盖 deploy/。
