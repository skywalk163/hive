# 根治 `run()` 后代进程持有 stdout PIPE 导致的挂死

> 来自 T-0261 人工复验的未闭环点（2026-11-08）。T-0261 已合入 `stdin=DEVNULL`，
> watchdog 从 `3/3 exit=124` 变成 `3/3 exit=0`；**但只解决了 stdin，没解决 stdout**。

## 一、现象（Linux 实测，不是 Windows 平台差异）

`tests/test_run_stdin.py::test_run_does_not_hang_when_child_spawns_grandchild`：

```
子进程 Popen 一个 sleep 30 的孙进程后立刻 print('parent-done') 退出
→ hive.run(..., timeout=10) 抛 HiveError「命令超时（10 秒内未返回）」
```

根因：`run()` 用 `capture_output=True`，stdout 走 PIPE；孙进程继承了管道**写端**，
`communicate()` 要等 EOF，写端被活着的后代握着就一直不返回。Windows 与 Linux 表现一致
（T-0261 的 summary 里判断「Linux 应能过」是错的，已实测证伪）。
目前在测试上打了 `@pytest.mark.xfail(strict=False)` 留证，**不是修好了**。

## 二、目标

1. `run()` 在子进程 fork 出长命后代时也不阻塞，且仍能拿到 stdout/stderr。
2. 删掉 `tests/test_run_stdin.py` 第二条的 `xfail`，恢复成严格断言（含 `< 5s` 耗时断言）。
3. 给出全量 pytest 的干净基线（见下）。

## 三、修法方向（自己验证，别照抄）

- 现成参照：`hive.py` 的 `cmd_dashboard` 那段已经用「stdout/stderr 走临时文件而不是
  PIPE」绕开同类问题，注释里写明了原因。可考虑把这套收口到 `run()`。
- 也可评估 `start_new_session=True` / `close_fds=True` / 进程组 kill，但必须说明
  对 `text=True` + `input` 二进制分支、Windows `CREATE_NO_WINDOW`、以及
  MCP stdio（`tests/test_mcp.py` 29 用例）没有回归。
- 有 `input` 的那一支目前没有 `stdin=DEVNULL`（`subprocess.run` 会自己设 PIPE），
  一并检查有没有同类后代继承问题。

## 四、验证

```bash
bash tests/run_pytest.sh tests/test_run_stdin.py      # 期望 2 passed，0 xfailed
bash tests/run_pytest.sh tests/test_watchdog.py       # 9 passed，exit=0
bash tests/run_pytest.sh tests/test_mcp.py            # 29 passed（stdio 不能坏）
bash tests/run_pytest.sh                              # 全量，贴用例数/失败数/耗时
```

前三条是卡面 `verify`（必须绿，且 `test_run_stdin.py` 要 `2 passed / 0 xfailed`）。
第四条全量**故意不进 verify**：当前 detached worktree + 无主集群环境下 900s 仍超时，
它是本卡要交付的「基线归因」，不是绿灯门槛；跑完把实测数字贴进 summary 即可。

- **全量基线要一并归因**：2026-11-08 在 detached worktree（`/tmp/t261`）+ 集群无主的
  环境跑全量，`HIVE_TEST_TIMEOUT=900` 仍 `exit=124`，进度到 93%，中间有 3 个 `F`、
  16 个连续 `E`。需要在**主仓 + 集群有主**的正常环境复跑，说清这些 F/E 是环境基线
  还是真缺陷；不要因为「本卡改的是 run()」就把它们算到自己头上，也不要装看不见。
- `tests/run_pytest.sh` 里写死了 `python`：部分 Linux/FreeBSD 只有 `python3`。
  顺手做成可探测/可覆盖（`${PYTHON:-...}`），但别破坏 Windows。
- verify 依赖 bash + pytest；**若接单机器没有这两个，直接交还/说明环境不满足，
  不要改宽 verify、不要删测试**（11-08 三张异常卡就是这么来的）。
