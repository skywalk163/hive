# lightharness 恢复工作区 bash 工具的 T-0442 修复（消除 30 秒硬超时/stdin 挂起）

## 背景（来自 2026-11-24/25 实测）
T-0442 已把 bash 工具修好并合入 main（HEAD `src/工具_bash.light` 里"超时"出现 23 次：可选 `超时` 参数 1~600 秒、stdin=DEVNULL、超时部分输出与说明、退出码透传、输出吞并修复）。但**当前工作区未提交改动把该文件覆盖成旧版**（"超时"只出现 2 次：30 秒硬超时、无 stdin 防护、无"等待终端输入"提示）。正在跑的 web 服务用的是旧版，导致：git push 等凭证提示静默挂到超时、长命令 30 秒被 SIGTERM、代理大量 bash 调用卡死；T-0461 交接文档记录 bash 最后多次返回"[命令已被用户停止]"，包括 `echo ok`。

## 要做什么
1. 先审计：`git diff HEAD -- src/工具_bash.light` 逐段列出工作区旧版相对 HEAD 修复版的所有差异，确认哪些是有意保留的本地改动、哪些是无意覆盖。
2. 以 HEAD 的 T-0442 修复版为准恢复 `src/工具_bash.light`，把确需保留的本地改动**手工移植**到修复版上（禁止直接 `git checkout --` 丢弃他人改动；移植前把旧版另存为 `docs/工具_bash_本地旧版_20261124.bak` 备查）。
3. 验证修复版在运行中的 web 进程生效：重启 web 服务（HARNESS_WEB_PORT=7788），跑一次 `sleep 31` 类命令确认返回含"超时"字样且不超过配置上限；跑一次需要 stdin 的命令确认立即失败并给出"等待输入"提示。
4. 逐条对照 T-0442 的 5 个缺陷（匹配行恒空/退出码误报 0/超时无提示/stdin 挂起/输出吞并）跑原验收：`python -m pytest -q tests/test_T0442_工具层缺陷.py tests/test_T0444_工具层缺陷.py -o addopts=''`（按仓库实际测试文件名）。

## 验收
- `src/工具_bash.light` 与 HEAD 修复版行为一致（T-0442 相关测试全绿）。
- 实测证据贴进 `.hive/summary.md`：超时命令输出、stdin 命令输出。
- 工作区其它未提交改动（webui、`代理.light`、`会话冷读.light` 等）保持原样，不冲掉。

## 不做什么
- 不改 T-0442 修复版的语义（超时上限 600、stdin DEVNULL 等）。
