## 背景

2026-11-23 已在 OpenI 调试任务（V100）跑通一次完整实验，结论 `verdict=incomplete`、
`evidence_level=partial_coverage`。基线数据（以下数字来自该次运行，不要重算）：

| 项 | 实测 | 说明 |
|---|---|---|
| 判据 ① 探针 | unknown | 门禁：只覆盖 1/7 决策点（`EDIT`），探针 test 9 条 < 30，模板簇重合 27 |
| 判据 ② C vs B | unknown | C=0.204、B=0.159，差 2 条，要求 ≥3 条 |
| 判据 ③ 无约束结构合法率 | **fail 0.8077** | 42/52，其中 6 条为截断（按 v3 口径计入失败） |
| 判据 ④ 密度/速度 | pass | 密度 0.0018、速度差 0.000 |
| 负对照 shuffle | 0.3333 | `< leak_threshold 0.7`，无标签泄漏 |

由此得到两个可执行判断：

1. ③ 的 0.8077 里有 6/52 是**生成预算不足导致的截断**（默认 `--max-new-tokens 384`），
   非截断样本的裸合法率约 42/46 = 91.3%，离 95% 差 2 条。这一半是解码预算问题，不必补数据就能测出来。
2. ①② 不可测是**数据门禁**问题（`gate_blockers` 三条），与 T-0370 同源，本卡不重复补数据。

另有一处口径不一致需要在本卡内定调：判据 ④ 的代码只判上限 `≤2%`，
但 `reports/零模型系统报告.md` 写的是"要求 1–2% 区间"。按区间口径，0.0018 属于**过低**，
而它之所以过低正是"只注入了 `EDIT` 一个决策点"——不能拿 ④ pass 当机制验证成功的证据。

## 要做的事

### 1. 脚本加固（`scripts/openi_run.sh`，只改这一处范围）

- `bg` / `run` 启动前**强制预检 CUDA**：不可用时直接中止并打印三条排查提示；
  确实要纯 CPU 跑必须显式 `LP_ALLOW_CPU=1`。现状是无提示回落 `--device cpu`，
  本次就是这么误判成"没跑起来"（显存 0 = CPU 在啃）。
- 新增 `status` 子命令，一条命令给全：进程是否存活（`pgrep -af train_openi.py`）、
  `nvidia-smi` 显存占用、最新日志头 3 行与末 5 行、`metrics.json` 是否生成。

### 2. 三次运行（每次一个 OpenI 调试任务名额，各自 `pack` 回传）

在仓库根目录执行，均不改预设、不改数据：

| 运行 | 命令 | 目的 |
|---|---|---|
| A | `LP_EXTRA="--max-new-tokens 512" LP_BUDGET_MIN=210 bash scripts/openi_run.sh bg` | 只看截断是否下降、③ 的分母变化 |
| B | `LP_EXTRA="--max-new-tokens 512 --eval-gen-samples 140" LP_BUDGET_MIN=210 bash scripts/openi_run.sh bg` | 让 ② 的"差 2 条"具备判别力 |
| C（可选） | 同 B，加 `LP_PRESET=small` | 若 B 仍 <95%，看是否容量问题而非解码问题 |

每次跑完必须记录 `metrics.json` 里的 `n_counted` / `n_truncated`，不要只看 0.8x 这个小数。

### 3. 失败归因（本地做，不需要 GPU）

解包 `lightprism_out/generated_samples.jsonl`，按 `truncated` 与 `structure_problems` 分两类统计：

- 截断样本：命中哪些任务类型、生成到第几个 token 断；
- 真非法样本（约 4 条）：缺哪个段（`<CODE>` 未闭合？`<V:…>` 缺失？），逐条列出任务原文片段（≤40 字）。

### 4. 判据 ④ 口径定调（二者之一，必须写进报告）

- **方案甲（改判据）**：`judge` 把 ④ 改成区间 `[0.01, 0.02]`，并同步 `tests/test_openi_v3_judge.py`
  的用例；本次运行按新口径会变 `unknown`（密度过低），报告里如实写。
- **方案乙（不改代码）**：明确声明 ④ 只卡上限，同时在报告注明"密度 0.18% 低于方案 1–2% 区间，
  属机制覆盖不足，不构成机制验证"。

不允许两个都不做、继续让 ④ pass 兼职"机制已验证"。
