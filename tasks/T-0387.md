# 0.88 全量假绿：dogfood conftest 把整个 session 都 skip 了

## 背景

T-0383（R222 M 线收口）实测发现：**不带任何参数的全量命令现在是假绿**。

```
python tools/remote_ci.py --repo . --tag any
→ 10531 skipped, 0 passed, rc=0, 145s
```

`rc=0`，看板上是绿的，但一条用例都没跑。现场 `192.168.0.88:/tmp/lp-ci/run-20261117-231942-T-0383-M`。

根因在 `tests/dogfood/conftest.py`（T-0322 于 2026-11-10 随 `5f72892b1` 入库）：

```python
def pytest_collection_modifyitems(config, items):
    if LIGHTHARNESS_DIR.is_dir():
        return
    print(f"\n{SKIP_TEXT}")
    marker = pytest.mark.skip(reason=SKIP_TEXT)
    for item in items:          # ← items 是整个 session 的，不是本目录的
        item.add_marker(marker)
```

`pytest_collection_modifyitems` 拿到的 `items` 是**整个 session** 的收集结果。0.88 的
`/tmp/lp-ci/` 下没有同级 `lightharness`，于是**全仓每一个用例**都被打上 skip。

基线 `run-20261117-091021` 是在 dogfood 入库之前抓的（该现场里没有 `tests/dogfood/`、`spec/`、
`src/patch_engine.py`、`benchmarks/light_agent/`），所以基线本身有效，坏的是"现在怎么跑全量"。

佐证：T-0382 的 summary 里已经撞到过 `25 skipped, rc=0`，当卡加了 `--ignore=tests/dogfood`
绕过去了，但没升级成全局问题。

## 目标

让 dogfood 的 skip **只作用于 `tests/dogfood/` 自己的用例**，不影响任何其它目录。

推荐做法（二选一，优先第 1 个）：

1. 在 `pytest_collection_modifyitems` 里按路径过滤：

   ```python
   items[:] = [i for i in items
               if Path(str(getattr(i, "fspath", ""))).resolve()
               .is_relative_to(HERE)]  # HERE = tests/dogfood
   # 或只 skip 属于本目录的：
   for item in items:
       if HERE in Path(str(item.fspath)).resolve().parents:
           item.add_marker(marker)
   ```

   注意 `is_relative_to` 需要 py3.9+，仓里 0.88 是 3.12，可以用；要兼容 3.8 就手写
   `HERE == p or HERE in p.parents`。

2. 或者别用 `pytest_collection_modifyitems`，改成在 `pytest_ignore_collect` 里对
   `tests/dogfood/**` 返回 True（收集期直接不收，连 skip 都不产生）。这一改法的副作用是
   `--ignore` 语义会变，需一并确认 `tests/dogfood/pytest.ini` 仍可用。

修完要保证两件事：

- 全量（不带 `--ignore=tests/dogfood`）能正常跑出 ~10000+ passed，不再是 10531 skipped；
- 单独跑 `pytest tests/dogfood/` 且无 lightharness 时，仍然是**该目录 skip** 而不是报错。

## 红线

- 不要为了让全量"看起来绿"而把 dogfood 从收集里整个删掉——它在有 lightharness 的机器上必须真跑。
- 不要动 `SKIP_TEXT` 的文案（其它地方有引用）。
- 不要改 `tests/dogfood/_dogfood.py` 的 `find_lightharness()` 候选顺序，除非有独立理由。
