## 背景

总控提的另一条提升方向：

> 提供更细粒度的锁声明方式（例如基于文件级的锁），让 dispatch 能更精确地判断冲突，
> 而不仅仅是目录前缀匹配。

现状：`hive.py` 的 `Hive._path_overlap`（1089 行）/ `_paths_conflict`（1099 行）只做
**目录前缀匹配**——`src/` 会覆盖其下一切，且任一方没声明 `paths` 就保守判冲突。这导致：
两张卡其实只分别改 `src/a.py` 和 `src/b.py`，但只要有人不得不声明 `src/`，dispatch 就认为
它们打架，无法并行。缺少"我精确改这几个文件"的语义。

本卡引入可选的 **`locks` 字段**（文件级锁声明），并据此做精确冲突判断，同时保持对旧
`paths` 的完全向后兼容。

## 要做什么

1. 新增 `conflict.py`，实现：
   - `_lock_matches(lock: str, other: str) -> bool`：支持三种声明
     - 目录前缀：`src/`（带尾斜杠）→ 覆盖 `src/` 下所有；
     - 精确文件：`src/a.py`（无尾斜杠）→ 仅该文件；
     - 简单通配：`src/*.py`、`**/test_*.py`（用 `fnmatch`）→ 命中即冲突。
   - `_locks_conflict(a_locks, b_locks) -> bool`：任一方锁与另一方任一锁匹配即为冲突；
     两方都声明了 `locks` 才走这个精确逻辑。
2. 改造 `Hive._paths_conflict`（hive.py 1099 行）：
   - 若两张卡**都**声明了非空 `locks` → 调 `conflict._locks_conflict`；
   - 否则保留现有目录前缀逻辑（向后兼容，旧卡行为不变）。
   - 把 `_path_overlap` 仍可保留给旧路径用，不删除。
3. 新增任务卡字段语义文档片段（放 `conflict.py` 顶部 docstring 或 `docs/锁与冲突模型.md`
   由 T-0164 统一写，本卡只保证代码与 `locks` 字段可解析——`card()` 读 frontmatter 已通用，
   无需改解析器）。
4. 新增 `tests/test_conflict.py`，至少覆盖：
   - `src/a.py` vs `src/b.py` → **不冲突**（精确文件互不相干）；
   - `src/` vs `src/a.py` → **冲突**（目录覆盖文件）；
   - `src/*.py` vs `src/a.py` → **冲突**（通配命中）；
   - 两张卡各声明 `{src/a.py, tests/x.py}` 与 `{src/b.py, tests/y.py}` → **不冲突**；
   - 一方有 `locks`、另一方 `paths` 为空 → **保守冲突**（回退旧逻辑）。

## 不要做什么

- 不要破坏 `_paths_conflict` 对"未声明 paths = 冲突"的保守默认。
- 不要删 `Hive._path_overlap`，旧 `paths` 仍依赖它。
- 不要动 `Worker` 执行链路（那是 T-0162 的地盘）；本卡与 T-0162 都改 `hive.py` 但区域不重叠。
- 不要引入新第三方依赖（标准库 `fnmatch` 足够）。

## 完成标准

  `test_dispatch_paths_overlap_blocked` 等既有用例（旧逻辑应仍通过）；
- summary 说明 `locks` 字段用法与和旧 `paths` 的兼容关系。
