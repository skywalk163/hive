# 75 个测试临时文件被提交进仓库了

## 现状

```
$ cd lightharness && git ls-files | grep -c '_unit_tmp_'
75

$ git ls-files | grep -vc '/'          # 根目录入库文件数
90
```

**根目录 90 个入库文件里，75 个是 `_unit_tmp_<pid>_<hex>.light`。** 占比 83%。
合计 338KB。真正的文件只有 15 个。

`.gitignore` 里**没有 `_unit_tmp_` 规则**（我 grep 过，无匹配）。

## 为什么不能直接 `git rm`

`tests/unit/test_启动配置.py:23` 有这行：

```python
name = f"_unit_tmp_{os.getpid()}_{uuid.uuid4().hex[:6]}.light"
```

它是**每次运行现生成新名字**（pid + uuid 随机后缀），所以：

- 已入库的那 75 个**不是**它要读的输入，只是历史运行留下的垃圾
- 但它生成的路径**就在仓库根目录**（没有 `tmp_path` 隔离），所以每次跑测试都会往根目录扔一个
- 这解释了为什么数量会一直涨

**要同时做两件事**：清历史垃圾 + 堵住源头。只清不堵，下次跑测试又会脏。

## 起点线索

- `_unit_tmp_` 文件都在仓库**根目录**（`lightharness/_unit_tmp_*.light`），不在 `tests/` 下
- `.gitignore` 已有 `tmp_*` 规则和 `tmp_persist/`，但**没有 `_unit_tmp_*`**（前缀是 `_` 不是 `tmp_`，所以没命中）
- `tests/unit/test_启动配置.py` 目前是 1 个测试文件，请先读全文再改

## 目标

### 1) 补 `.gitignore`（先堵源头）

在现有 `tmp_*` 附近加：

```gitignore
# 测试临时文件：tests/unit/test_启动配置.py 会在仓库根目录生成
# _unit_tmp_<pid>_<uuid6>.light，跑一次留一个（T-0266）。
# 历史上有 75 个被误提交，清理后不许再进。
_unit_tmp_*.light
```

### 2) 让测试写到临时目录（根治）

把 `test_启动配置.py` 里生成文件的路径从「仓库根目录」改成 `tmp_path`：

```python
def test_xxx(tmp_path):
    name = f"_unit_tmp_{os.getpid()}_{uuid.uuid4().hex[:6]}.light"
    target = tmp_path / name       # ← 关键：不再污染仓库根目录
    ...
```

如果这个测试**确实需要**在仓库根目录跑（比如被 `运行.py` 的相对路径逻辑约束），
那就退一步：用 `try/finally` 保证删除，并在 summary 里说明为什么不能挪。

> 判断依据：先看这个文件里的 `name` 变量后面怎么用的。如果只是给某个函数传个路径参数，
> 大概率能直接换 `tmp_path`。如果读了 `运行.py` 的 cwd 相对行为，就得谨慎。

### 3) 清历史垃圾

```bash
cd /home/skywalk/dswork/lightharness
git rm --cached _unit_tmp_*.light      # 只从索引移除，保留工作区文件
git commit -m "chore(T-0266): 移除 75 个误入库的测试临时文件 + 补 .gitignore 规则"
```

**用 `git rm --cached`，不要用 `git rm`。** 原因是：这批文件在本地可能还有测试会扫到，
先只从索引摘掉，确认测试全绿后再决定要不要删磁盘文件。
如果确认无引用，第二轮再 `rm` 物理文件（可选，不强制）。

### 4) 验证测试仍然通过

清掉之后必须确认 `test_启动配置.py` 还能跑 —— 因为它生成的文件名是随机的，
理论上不依赖历史那 75 个，但要**实际跑一遍证明**。
