# 前端：错误帧/结束原因可见 + 「继续」不再掉进无底队列

## 背景（都是实测/代码可查的）

1. 服务端会往 SSE 里投两类**失败帧**：
   - `web服务器.light:2617`：`["error": {"message": …, "type": "driver_error"}]`
   - `web服务器.light:2624`：`save_error`
   - `web服务器.light:2676`：后台线程异常兜底
   但 `webui/app.js` 的 `readStream.handleFrame`（1176-1237）只认
   `session_id / 种类=会话|统计|压缩|计划|审批请求|工具调用|工具结果 / choices`，
   **没有任何 `json.error` 分支** → 驱动失败在界面上表现为「什么都没发生、流结束」。
   这与用户报的「任务停止，再输入继续也没反应」在症状上完全一致。
2. 结束原因不可见：`turn/end` 的 `种类`（`completed/max-steps/max-tokens/aborted/error`）
   不落统计帧（`src/会话细节.light:时补统计字段` 只补耗时/速率），
   前端 `renderStats` 也就没法提示「这轮是撞了步数上限 / 输出上限」。
3. 本地排队也会吞消息：`sendMessage` 在 `streaming===true` 时只 `enqueueLocal`
   （`app.js:1311-1315`），而 `flushLocalQueue` 只在 `setStreaming(false)` 里触发（`1120`）。
   一旦 `streaming` 因为「流没收到 [DONE]」「fetch 挂住」而卡住，之后每条「继续」都只进本地队列。
4. 压缩提示是纯视觉（`showCompactionNotice` → `Messages.addCompaction`），
   不重置 streaming、不 flush 队列、不给「继续」按钮。

## 要做什么（只改 `webui/`）

1. **错误帧渲染**：`handleFrame` 增加分支——
   `if (json && json.error) { addSystem("驱动失败：" + (json.error.message||…), true); setStatus("down"); return; }`
   形如 `{"error": {...}}` 与 `["error": {...}]` 两种都要覆盖。
2. **结束原因提示**：读统计帧新字段 `结束原因`（由 T-0453 提供，四值闭集）：
   - `max-steps` → 提示「本轮达到步数上限（N 步），已暂停。发送「继续」或 /goal 可接着跑」+ 显示一个「继续」按钮（点了就往输入框塞「继续」并发送，复用 `sendMessage`）；
   - `max-tokens` → 「本轮输出被截断」；
   - `aborted` → 「已中止」；
   - `error` → 走第 1 条。
3. **streaming 自愈看门狗**：`setStreaming(true)` 时启动计时；若 30s 没有收到任何帧
   **且** reader 没结束（服务端挂住/连接半死），前端必须：收口当前气泡 → `setStreaming(false)`
   → flush 本地队列 → 给一条系统提示「连接可能已断开，可重发」。判据要能用假时钟驱动。
4. **压缩提示不阻塞**：压缩帧到达后不改变 streaming/队列状态（现在也没改，但要有判据钉住），
   并在提示文案里补一句「本轮结束后发「继续」即可接着做」。

## 判据（`tests/test_T0452_前端可观测.py`，新建）

本仓没有 jsdom，就用**手写最小 DOM 桩 + node 跑真实文件**（新姿势，别引依赖）：

1. `node --check webui/app.js`、`node --check webui/messages.js` 全绿；
2. 静态契约：`handleFrame` 内必须存在 `json.error` 分支、必须消费 `结束原因`、
   `setStreaming` 必须挂看门狗（用正则/子串断言，反跑能变红）；
3. 行为测试（node 脚本 + DOM 桩，由 pytest 起 `node` 跑）：
   - 喂一帧 `{"error":{"message":"boom","type":"driver_error"}}` → 出现 `.sys.error` 气泡且文本含 `boom`；
   - 喂 `{"种类":"统计","结束原因":"max-steps","步数上限":96}` → 出现提示且含「步数上限」，并出现「继续」按钮；
   - 置 `streaming=true`，假时钟推进 31s、无任何帧 → 自动 `setStreaming(false)` 且本地队列被 flush；
   - 喂 `{"种类":"压缩"}` → 出现压缩提示，且 `streaming` 状态不变；
4. **反跑**：删掉 `json.error` 分支，用例 3a 立红。

## 红线

- 不引 npm 依赖、不改构建；DOM 桩自己写在测试里；
- 不改服务端帧形状（`结束原因` 字段名以 T-0453 为准，两边必须一致）；
- 不动既有 `种类` 帧的渲染契约（工具卡/审批/会话绑定）。
