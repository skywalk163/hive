## 背景

DSH 提示里有一整套「多智能体与长任务」纪律，本仓 T-0469 只有一句
「子代理：彼此独立、可以并行的子任务交给派发子任务」。缺的是最容易出错的那几条：

- 并发：DSH 要求独立委派**在同一条 assistant 消息里一起发起**，并发上限 8，
  只等结果时**结束回合**而不是 sleep/轮询，给最终答案前必须收齐结果；
- goal：`complete` 只在目标真的达成时调；`blocked` 要**同一阻塞条件连续 3 轮**才允许标，
  并在 `blocked_reason` 写具体条件（难度大 / 还有活 不算 blocked）；
- workflow：**只在用户明确要求工作流/大规模编排时**才用，1–2 个委派用普通子代理；
- 并发写：bash、格式化器、生成器会**无冲突检测地覆盖**并发编辑，整合者必须 review
  最终 diff 并跑相关测试。

本仓今天的真实形态：`派发子任务 / 收集子任务结果` 都在册，`目标` 也在册，
但提示里没有这些边界，长任务很容易「一边跑一边空转」「goal 永远 active」。

## 目标

新增 `src/提示_协作段.light`（纯文本模块，按在场工具裁剪）：

`协作段文本(工具名表)` 输出「协作与长任务」段：

1. `派发子任务 / subagent` 在场 → 三条：
   - 「彼此独立的子任务在**同一条消息里一起发起**；只等结果时结束本回合，不要 sleep 或轮询」；
   - 「给用户最终答案前，必须收齐本任务需要的子任务结果」；
   - 「并发上限按工具定义（DSH 口径 8），不要超过」；
2. `目标 / goal` 在场 → 两条：
   - 「`complete` 只在整件目标真的达成时调；仍有活就保持 active」；
   - 「`blocked` 要同一阻塞条件**连续 3 轮**才标，并写清具体卡点；难度大不算 blocked」；
3. `工作流提交 / workflow` 在场 → 一条「只在用户明确要求工作流或大规模编排时用；
   一两个委派用普通子代理」；
4. `bash` 在场（并发写风险）→ 一条「bash / 格式化器 / 生成器可能覆盖并发编辑；
   整合者要 review 最终 diff 并跑相关测试」；
5. 一条都没命中 → `""`；总长 ≤ 1200。

## 红线

- 不改 `src/子代理核心.light` / `src/子智能体.light` / `src/代理团队.light`；
- 不写死除 DSH 对齐值 8 之外的并发数字；若工具定义另有上限，文案要写「按工具定义」；
- 不承诺本仓没有的能力（没有 `subagent_fork` / `list_agents` 就不许提）；
- 不改 `src/系统提示.light`、`src/总入口.light`（接线归 T-0487）；
- 不许 `git reset --hard` / `push --force` / `--no-verify`。

## 验收

- 含 `工作流提交` → 出现「仅显式要求」；

③无工具时仍输出全部段落 → 「只有 bash」判据红。恢复后全绿。
