## 一、LH-08　`是数字` 映射到 `是数值`（P0，命名事故，静默错）

```light
打印 转字符串(是数字("1"))   # 假
打印 转字符串(是数字(1))     # 真
```

`builtin_map` 里 `是数字` 指向「判数值类型」，而 `stdlib/builtins.py` 里另有一个同名的「判单个字符是不是数字」，
从源码根本调不到。写错名字**不报错，只是永远返回假**——lighthive 的 `像整数()` 曾因此恒假。

**期望**：源码 `是数字` → 判字符；判类型的那个只用自己的名字 `是数值`；`是数字符` 作为等价别名保留。
并在缺陷账标注为「命名层不兼容变更」，在 CHANGELOG 里写清迁移口径。

## 二、LH-07　没有「试探型转换」，且 `字符串全数字` 进不了源码（P2）

- `转整数("x")` 直接抛异常，不能拿来「试一下」；缺 `试转整数(文本, 默认 = 空)` / `试转浮点(...)`。
- **新发现**：`字符串全数字` 登在 `stdlib/builtins.py:1895` 的 `__all__` 里，但源码写 `字符串全数字("-3")` 报
  `name '字符串全数字' is not defined`；`从 字符串处理 导入 字符串全数字` 也失败（未导出）。
  → 「在 `__all__` 里」不等于「源码可达」，这类假登记要一并揪出来。

**期望**：`试转整数` / `试转浮点` 可用（转不了返回默认，不抛；支持正负号与前导空白）；
`字符串全数字` 在源码可达（或从 `__all__` 里撤掉——二选一，别两头不一致）。

## 三、LH-02　`是空(空列表)` 为假，且两份文档口径相反（P1）

```light
是空(空)    # 真
是空("")    # 真
是空([])    # 假   ← 与 docs/AI编程指南.md §2.1「空列表为假」相反
是空({})    # 假
```

`docs/空值语义规范.md` 定义成「null 或空串」，`docs/AI编程指南.md §2.1` 写「空字符串、空列表、空字典、0 均为假」。
**实现跟了前者，文档两头都在用** —— 查文档得到什么答案全看运气。

**期望**：以 `空值语义规范.md` 为准（**不改 `是空` 的语义**，避免存量翻车），
另加宽口径 `皆空(值)`（null/""/空列表/空字典 都算空）并在 AI 编程指南里点名推荐。
本卡只加函数；文档改动另有一张卡，别抢。

## 四、LH-03　`字典获取` 无法区分「缺键」与「值为空」（P1）

```light
设 典 为 {"owner": 空}
字典获取(典, "owner", "无主")   # 空，而不是 "无主"
```

hive 的任务卡在未分派时**显式写 `owner: null`**，「没填」和「填了空」在业务上是一回事，
现在每个取值点都得自己补判空。

**期望**：保留 `字典获取` 的 Python 语义（有人需要区分），**另加** `字典取值(典, 键, 默认)`：
缺键**或值为空**都返回默认。两个函数在文档里写清分工。

## 五、LH-11　`去空白` 不存在；`反转` 返回迭代器（P1，文档第一个函数就红）

| 文档/记录写的 | 实测 | 真名 |
|---|---|---|
| `去空白(s)` | NameError | `去除空白(s)` |
| `反转(列表)` | 返回 `list_reverseiterator`，`是列表` 为假 | 需 `列表(反转(x))` |
| `枚举(列表)` | `长(枚举([1,2]))` 抛异常 | 可遍历，`长()` 不行 |
| `范围(a,b)` | `长(范围(1,5))` = 4 **已可用** | —（这条已修，别再动） |

**期望**：`去空白` 补成**真实存在的别名**（成本最低、收益最高，文档第一个函数照抄即红）；
`反转` 直接返回列表（`是列表` 为真）；`枚举` 至少让 `长()` 可用，或明确在文档写「不可 `长()`」。

## 六、LH-14　没有「UTF-8 字节长度」，自己写 HTTP 必踩（P1）

`长("中文")` = 2，UTF-8 编码后是 6 字节。HTTP 的 `Content-Length` 必须按字节算，
按字符算会让客户端「等超时」或「截断在半个汉字上」——**症状是卡住而不是报错**，会被误判成网络问题。

- 没有内置 `字节长度`；
- `从 编码 导入 字节长度` 存在，但 `字节长度("中文")` 返回 **1**（明显不是 6），语义存疑，需核。

**期望**：内置 `字节长度(文本, 编码 = "utf-8")`，返回该编码下的真实字节数；
顺手把 `编码.字节长度` 的语义在文档里写清（它现在大概是「十六进制串对应的字节数」，名字撞车）。

## 七、LH-04　`排序列表` 没有 key 参数，而文档写着有（P1）

```light
段落 取编号(卡):
  返回 卡["n"]

排序列表([{"n":3},{"n":1}], 假, 取编号)   # 第三参不存在 → 报错
排序列表([{"n":3},{"n":1}], 假)           # TypeError: '<' not supported between dict and dict
```

内置签名是 `排序列表(序列, 反向=False)`，**没有 key**；而 `docs/AI编程指南.md` §2.8 明确写着
`排序(列表, 键 = 按年龄)`，§错误13 又说「不支持 lambda，用段落」。
「按字段排序」是任务队列的刚需（hive 的 dispatch 要按优先级+编号排），没有 key 又没 lambda 就只能手写排序。

**期望**：`排序列表(序列, 反向 = 假, 键 = 空)`，`键` 接收一个**段落**（光明里函数可作参数，实测可行，
比支持 lambda 更契合语言风格）。
