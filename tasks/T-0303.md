## 背景

母文档 §3 要求带宽感知、非抢占、确定性的 Leader 选举；落地契约见
`docs/控制面v0.5-实现约定.md` §3.2 与 §4 的 D2/D10/D11/D12。
共享骨架 `hive_control/config.py`（ControlConfig / Limits）、
`hive_control/model.py`（StateEntry）已落在 main；本卡只写选举状态机与带宽探测。

Hello / LeaderHeartbeat 的 payload 由本模块生成，传输在 T-0310（plane）装配。

## 目标

新增 `hive_control/election.py`，按契约实现：

- `SelfInfo(router_id, node, address, port, priority, interface_mbps)`；
- `BandwidthProbe`：`interface_mbps()`（Linux SIOCETHTOOL/ETHTOOL_GSET，
  失败 None）、`router_id(address, hostname)`（确定性）、
  `factor(reference_mbps)`（自身/参考；无效→1.0）；
- `Election`：`observe(message, source=None)` / `tick()` / `hello()` /
  `heartbeat()` / `leader_id` / `leader_epoch` / `is_leader` /
  `reference_mbps` / `peers()` / `status()`；
- 比较顺序 `priority` → `bandwidth_factor` → `router_id`，都大者胜；
- `priority==0` 不参选，仍可被选/被承认；
- 启动先 Waiting `waiting_interval`；期间收到 `leader_declaration=true`
  立即承认，不竞选；Waiting 结束仍无 Leader 时存活节点中排名第一者发
  `declare`，其余等它的声明/心跳；
- **非抢占**：现任 Leader 心跳有效时，排名更高也不发起；
- 心跳超时 `heartbeat_timeout`（6s）→ `leader_lost`；
  新 Leader epoch = 已知最大 epoch + 1；
- 参考带宽 = 存活节点（含自己）`interface_mbps` 最大值；单节点/全未知时
  自身值或 None，系数回落 1.0；`bandwidth_unavailable` 只记一次日志；
- Hello 间隔 2s、邻居 6s 过期（D11）；所有时间由注入 clock 驱动。

新增 `tests/test_control_election.py`，用 FakeClock 覆盖：Waiting / 声明 /
确定性排序 / 非抢占 / 心跳失效与 epoch 单调 / 邻居过期 / 带宽回落 /
payload 形状 / 畸形与回环报文。
