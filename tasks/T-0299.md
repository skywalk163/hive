# 选举协议修复（P0）：禁止 1 票自封、按 priority 推举、同优先级随机退避、health 不被长操作卡死

## 一、现场证据

- Mac 日志：`23:32:00 term=2327（1/1 票）`、`00:10:24 term=2340（1/1 票）`、
  `00:27:09 term=2343（1/1 票）`；fb98 日志：`00:09:43 term=2339（1/1 票）`、
  `07:24:55 term=2700（1/1 票）`。多台机器都出现过「一票当选」。
- fb98 日志 `07:26:43` 之后直到 `07:56:06` 才有下一次选举（30 分钟空窗）；
  同期 `sync: hive ...` 反复出现，fb98 上有 git 进程在跑。
- 停机排查时，fb98 的 `/api/cluster/health` 5s 超时，而 `/api/cluster/status`
  0.01s 返回 404（HTTP 线程正常）→ 集群锁被长操作占住，`snapshot()` 拿不到锁。
- 关键参数：`heartbeat=1s`、`peer_timeout=4s`、`leader_lease=5s`。任何
  5 秒级阻塞都会同时满足「无主」和「同伴全死」，于是 quorum 退化为 1。

## 二、代码位置

- 选民/多数：[hive_cluster.py#L2303-L2313]，只收 `status=="alive"`。
- 选举拉票：[hive_cluster.py#L2700-L2703]，`peers` 也只从 alive 选民取，
  quorum=1 时根本不发投票请求。
- 延迟/优先级：[hive_cluster.py#L2337-L2360]，priority 只产生 50ms 级排队差，
  没有「值高者直接为主」。
- 租约过期触发选举：[hive_cluster.py#L2962-L2964]。

## 三、目标语义（用户明确要求）

1. **priority 不同**：最高的那个节点直接为主，其他节点不竞争、直接投它/承认它；
   最高者自己 0 延迟发 CLAIM。
2. **priority 相同**：随机退避（参考以太网 CSMA/CD），谁先发出 CLAIM 谁为主；
   撞车（同 term 多个 CLAIM）就再随机退避一轮。
3. **只有两人参与且投票僵持**：随机退避重试，先 CLAIM 者胜。
4. **选民集合用成员表**：已知 electable 节点（含 suspect/dead，带较长
   membership TTL，或持久化），quorum=多数；已知成员 >1 时**禁止 1 票当选**
   （单节点集群 / 显式 allow-single 除外）。
5. 保留「不抢占在位主控」；租约过期后按 1–4 立即重选。

## 四、范围

- P0（本卡必须完成）：
  - 成员表/quorum 修复：不再按 4s alive 过滤掉已知成员；成员>1 时 1 票不能当选。
  - 选举向所有已知 electable 节点拉票（含 suspect/dead），没有多数就放弃并退避重试。
  - priority 不同 → 最高者直接 CLAIM，其他节点投它；priority 相同 → 随机 backoff，
    先 CLAIM 者胜，撞车再退避。
  - 两人僵持时的随机重试路径。
  - **解除阻塞**：git sync / store / 外部 HTTP 等长操作不得持有集群主锁；
    `/api/cluster/health` 走无锁缓存快照；选举/心跳线程不被同步任务拖住。
    在 election_started / 心跳超时日志里带上 voters、quorum、peer age、锁等待耗时。
- 非目标：不改 state.json 字段兼容性；不改 store 协议；不做跨版本滚动升级。

## 五、红线

- 不得把 token 写进日志/status。
- 单节点集群必须仍然能立即当选（不能一刀切要求 quorum≥2）。
- 不改变既有 `preferred_leader` 语义（仍是本机偏好，优先级高于 priority）。
- 新增行为必须有单测覆盖，且不影响既有 priority/no-preemption 用例。

## 六、验收

- 新增用例覆盖：成员>1 时 quorum>=2 且禁止自封；priority 最高者被推举；
  同 priority 随机退避只产生一个主；两人僵持能最终选出主；health 不被长操作阻塞。
- `python -m pytest -q tests/test_cluster.py -k "quorum or priority"` 全绿。
- 手工：三节点里停掉主控，剩余节点在秒级内选出一个主，且日志不再出现
  `（1/1 票）` 这种自封（单节点场景除外）。
