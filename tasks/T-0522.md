## 背景

新 main（`99d6165`）22 条遗留失败里，本卡负责**第三组：MCP 装配与技能清单渲染**。这两条都是**真逻辑缺陷**，且都会让「MCP 工具在生产路径上丢失」与「技能清单顺序不稳定」，与 T-0489 刚接好的上下文四段直接相关（MCP 段、技能段）。

## 缺陷清单

### D1 · `工具名到叶子` 缺 `mcp__*` 通配 → MCP 工具没有叶子依据

- 现象：
  - `tests/test_T0468_MCP挂载.py::test_standard预设下MCP工具有叶子且不被注销` 红
  - `tests/test_T0468_MCP挂载.py::test_预设挂载过滤有MCP通配规则` 红
- 断言：`MAP_MCP` 期望 `mcp__t0468__echo`，实际为空串；另一条报「工具名到叶子 没给 MCP 自持叶子」
- 根因：`src/总入口.light:188 段落 工具名到叶子(名字)` 只查 `工具面装配.叶子映射(名字)` 再走硬编码兜底，**没有 MCP 分支**。而 `src/工具面装配.light:341` 的注释明确写着「MCP 工具不进具体名表，用 `mcp__*` 通配 + HARNESS_MCP_TOOLS 开关决定」——即**设计上要求** `工具名到叶子` 对 `开头(名字, "mcp__")` 自持叶子，实现漏了。
- 影响：MCP 工具在装配层「无叶子依据」，会被当成未映射处理；虽然 `KEEP_FAKE_STD` 目前是 `True/True`（白名单通配保住了它），但 `MAP_MCP` 为空意味着**挂载集看不到它们**，真实会话里 MCP 工具可能挂不上。
- 修法方向：在 `工具名到叶子` 开头加：

  ```
  如果 开头(名字, "mcp__") == 真:
    返回 [名字]
  ```

  （自持叶子，与注释口径一致；注意 `tool-schedule` 的既有回落逻辑不能被影响。）
- 判据：`tests/test_T0468_MCP挂载.py` 全绿；`tests/test_T0489_收口.py` 仍全绿（MCP 段渲染不回归）。

### D2 · 技能清单顺序不稳定（beta 排在 alpha 前）

- 现象：`tests/test_T0478_技能段.py::test_技能段端到端_真发现与额外目录` 红
- 断言：期望顺序 `alpha, beta, gamma`，实际 `beta, alpha, gamma`（且额外目录的 `delta` 也在）
- 根因：`技能目录.发现技能` 的产出顺序依赖**目录遍历顺序**（`os.listdir` 不保证字典序），本地 FS 上 `beta` 恰好先返回 → 每次/每机结果不同。
- 影响：技能段是系统提示的一部分，顺序不稳定会让**提示缓存前缀漂移**（T-0469 明确要求「system 前缀稳定，避免打掉缓存」）。
- 修法方向：`发现技能` 返回前按技能名（或路径）**确定性排序**；主根与额外目录的合并顺序也要固定（主根优先，各组内按名排序）。
- 判据：该用例绿；`tests/test_T0478_技能段.py` 全绿；连续两次调用技能段逐字相同（可在新判据里钉住）。
