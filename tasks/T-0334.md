# Demo 验收与目标机实测

> **`state: blocked` —— 等 T-0332 出了 checkpoint 再改 `ready`。**
> 验收必须由**没有参与实现**的 agent 做（`needs: verify`）。

## 背景

Demo 计划书 (`docs/Demo开发计划.md` §2) 定了七条验收标准。本卡逐条验证并出报告。

## 七条标准（逐条贴命令与真实输出）

| # | 标准 | 判据 |
|---|---|---|
| V1 | 能加载模型并推理 | `lightprism chat --prompt "..."` 输出非空 |
| V2 | 输出语法合法 | 生成代码经 `light ai check` 无 error 级诊断（20 条抽样，≥ 80% 合法） |
| V3 | JSON 模式合法 | `--format json` 输出可被 `json.loads` 解析 |
| V4 | **速度 ≥ 200 tok/s** | `scripts/bench.py` 单线程口径，200 token 取平均 |
| V5 | 内存 ≤ 8GB | `/proc/self/status` 的 **VmHWM**（峰值），不是 ps 瞬时 RSS |
| V6 | **目标机实测** | 在真 5 代酷睿机器上跑 bench 达标 |
| V7 | 可复现 | `make demo` 从干净 clone 到出结果 ≤ 10 分钟 |

## 关键要求

### V4 的口径不许改

口径写死在 `scripts/bench.py`：单线程、贪心、prompt 32、生成 200、丢弃前 10 预热。
**如果想报别的口径，另开一列，不许覆盖这一列。**

### V5 用 VmHWM

```python
with open("/proc/self/status") as f:
    for line in f:
        if line.startswith("VmHWM:"):
            peak_kb = int(line.split()[1])
```

`ps` 的 RSS 是瞬时值，会漏掉峰值。

### V6 拿不到目标机怎么办

**标 `blocked` 并说明原因，不许拿本机数字冒充目标机。**

本机是 Xeon E5-2643 v2（2013 年 Ivy Bridge，**无 AVX2**），
目标机是第 5 代酷睿（Broadwell，**有 AVX2**）。本机数字是**保守下界**，
但「保守下界达标」不等于「目标机达标」—— 需要真机复现，否则承诺没被验证过。

报告里 V6 一栏允许写：

```
blocked：无第 5 代酷睿机器可用。
间接证据：本机（更老的 Ivy Bridge，无 AVX2）单线程 XXX tok/s，
目标机预计更快。但本条**未实测**，不作为通过依据。
```

### 反面证据要写

如果某条**没通过**，如实写没通过，并给出：测到的数字、与目标的差距、
最可能的原因（附证据）、建议的下一步。

**验收报告不许只报喜。**
