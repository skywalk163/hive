# brainstorm 只读在装配层落实：拆 tool-fs-read / tool-fs-write 叶子

## 背景

T-0403 新增了 4 个组合型模式，但 brainstorm（头脑风暴）"只给只读工具"目前只在**数据层**成立：
`头脑风暴组合行表` 删掉了 `tool-bash`/`tool-pwsh`/`tool-goal`/`delegation`，
可 `src/总入口.light:167` 仍把「读文件」和「写文件」同映到一个叶子 `tool-fs`：

```
如果 名字 == "读文件" 或 名字 == "写文件":
  返回 ["tool-fs"]
```

于是装配层 `预设保留工具` 按叶子过滤后，brainstorm 仍然挂出「写文件」——模型在"只读模式"里
可以真写盘。T-0403 用 `test_已知粒度缺口_写文件仍挂在tool_fs` 把这个现状钉住了，
T-0407 收口时没有拆这个叶子，T-0406 的模式规格也把它记为"已知粒度缺口，登记给后续卡"。

本卡负责真正拆开：`tool-fs-read` / `tool-fs-write` 两个过滤叶子，让 brainstorm 在**装配层**
就没有写文件工具，而不是只靠提示词约束。

## 要做什么

1. **拆映射**（`src/总入口.light` 的 `工具名到叶子`）：
   - 「读文件」→ `["tool-fs-read"]`；
   - 「写文件」→ `["tool-fs-write"]`；
   - 「搜索文件」仍 → `["tool-fs-search"]`；bash / 目标 映射不动。
2. **拆预设行**（`src/预设组合.light`）：
   - `标准组合行表` 里原来的单行 `{"id": "tool-fs", ...}` 改为**两行**
     `tool-fs-read` 与 `tool-fs-write`（`name` 都仍是 `@deepseek-ai/dsh-tool-fs`，
     `group`/`config`/`disabled` 与原行一致）；
   - `头脑风暴组合行表` 的删表追加 `tool-fs-write`（保留 `tool-fs-read`、`tool-fs-search`）；
   - 其余模式全部基于 `标准组合行表` 派生，自动继承两行，不做额外改动；
   - 同步改写 189～205 行那段"已知粒度缺口"注释，不要留下与新实现矛盾的说明。
3. **保证装配语义**：
   - `造条目表带映射` + `预设保留工具` 下，同一工具名只保留一次，不能因为两条叶子把
     「写文件」注册两遍；在 summary 里说明去重发生在哪一步。
   - `minimal` 不新增 fs 叶子（原本就只有 bash），行为不变。
4. **更新既有判据**（`tests/test_T0403_新模式预设.py`）：
   - 把 `test_已知粒度缺口_写文件仍挂在tool_fs` 改成正向断言「brainstorm 装配层没有 写文件」；
   - 8 预设对照表里被写死的"组合行(插件行/展平后)"、"叶子数"、"工具数"、
     `工具集按规格表_叶子层`、`工具集按规格表_装配层` 全部按新结果更新；
     建议改成按 `组合行表`/`装配挂载集` 推导，不要再写死数字快照。
5. **新增 `tests/test_T0419_工具叶子拆分.py`**，至少覆盖：
   - 映射层：读文件只有 `tool-fs-read`，写文件只有 `tool-fs-write`，两者不再共享 `tool-fs`；
   - 装配层 8 预设名单：standard/ptc/cordis/topdown/bottomup/lazy 同时有 读文件 + 写文件；
     brainstorm 只有 读文件 + 搜索文件，**没有 写文件、没有 bash**；minimal 仍只有 bash；
   - 组合行数变化后仍满足"删除项确实不在装配集、保留项确实在"；
   - 反证：把「写文件」映射改回 `tool-fs`，brainstorm 用例必须立红。
6. **examples 对账**：`examples/test_预设组合.light`、`examples/test_预设挂载过滤.light`、
   `examples/test_设置预设页.light` 里凡写死旧叶子集/行数/工具数的断言，按新结果修正；
   不得放松成"只判数量"，要保持"具体工具名在/不在"的语义。

## 红线

- 不改 `src/预设.light` 的模式提示文本；不改权限预设语义；不改 `webui/`。
- 不放松其它模式的工具集（standard 等必须仍有读+写+搜索+bash）。
- 不引入"按模式特判写文件"的后门；只通过叶子映射与组合行表解决。
- 不改 `examples/` 里与本次无关的期望值；不改 `tool-fs` 插件本身的实现。
- 不删除 `test_已知粒度缺口` 这条用例，只能把它改成正向断言（它正是这次要销的账）。
