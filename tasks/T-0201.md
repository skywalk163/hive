## 症状

写租约到期（`到期 = 现在 + 180 分钟`）和耗时统计（两个时刻差几秒）时发现：

- `解析时间("2026-10-28T15:00:00", "%Y-%m-%dT%H:%M:%S")` → **可用**，返回 `time.struct_time`；
- `时间加减(时刻, 分钟 = 180)` → **不存在**；
- `时间差秒(甲, 乙)` → **不存在**。

`time.struct_time` 也不能直接做算术，于是任何涉及时刻运算的业务（租约、超时、耗时、定时）
都得自己 FFI 直连 `datetime` —— lighthive 就是被逼着开了个 `src/时间工具.light` 才绕过去的。

## 期望

补三个（或至少前两个）内置，命名与现有 `时间管理` 的口径一致：

- `时间加减(时刻, 秒 = 0, 分钟 = 0, 小时 = 0, 天 = 0)` → 新时刻（入参可是 `struct_time` 或时间戳，出参与入参同型）
- `时间差秒(甲, 乙)` → float（甲晚于乙为正；负数也要支持）
- `时刻转戳(时刻)` / `戳转时刻(戳)`（可选，但能省掉大量 `time.mktime` 手工活）

边界要求：
1. **时区**：默认本地时间，行为与 `格式化时间` 一致；不要偷偷按 UTC 算。
2. **跨月跨年跨闰日**：`2026-02-28 + 1 天` → `2026-03-01`；`2028-02-28 + 1 天` → `2028-02-29`。
3. 解析失败返回 `空`（不抛），与「试探型转换」的约定一致。
