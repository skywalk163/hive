# T-0355 规模仿真压测与雪崩验证（节点多了不能炸）

## 背景

交办方最担心的一条：

> 尤其在节点多了、开发任务多了、repo 频繁改动的情况下，
> 不要造成整个系统的流量风暴和压力雪崩。

OSPF 当年之所以要在 CPU / 链路都远弱于现在的条件下设计 DR/BDR、Area、
LSA Pacing、MinLSInterval、SPF 节流，本质就是**给状态传播装上限流阀**——
拓扑一抖，不能让全网所有路由器同时重算、同时泛洪。本卡就是把这套上限
**用可复现的数字证明出来**，而不是靠感觉说「应该没问题」。

前两天的教训也说明必须量化：0.16.03 以为降频生效了，0.16.05 实测发现
远期租约把心跳永久钉在 1s、本地 `generation` 被误当跨机水位，
结果「优化了但流量没降」。**没有仿真的优化不算优化。**

规范见 `H-LSA-协议设计-借鉴OSPF.md` §4（七道闸）、§5（指标表）。

## 要做什么

1. **`tools/lsa_loadtest.py`**：纯仿真，可注入 `fake_clock` 与 `fake_transport`，
   **不连 Gitea、不真发组播、不启动集群进程**。可配参数：
   - 节点数 `N ∈ {5, 20, 50, 100}`；
   - 任务卡数 `M ∈ {200, 1000, 5000}`；
   - repo 变更频率：空闲 / 正常（1 次/分钟）/ 高频（10 次/秒）；
   - 运行时长：至少覆盖 **2 个完整的 1800s 对账周期**；
   - 场景开关：A 现状（每节点定时全量 `git pull`）、B H-LSA（T0+T1+T2）。
2. **采集两组对照指标**（每组都输出原始 JSON，报告只引用实测值）：
   - Gitea `ls-remote` / `fetch` / `pull` 总次数与**每节点**次数；
   - 控制面总字节、单节点峰值字节 / 周期；
   - 同一秒内同时发起 pull 的节点数（**同步风暴峰值**，用来验 jitter 是否生效）；
   - `state.json` 落盘次数与字节；CPU 侧用「LSA 处理次数 / 合并次数」近似；
   - 状态可见延迟 P50 / P95 / **max**（子节点变更 → 全集群可见）。
3. **必须通过的断言**（对应 §5 SLA，一条都不能放宽）：
   | 断言 | 阈值 |
   |---|---|
   | 状态变更 → 全集群可见 | max ≤ **300s** |
   | 全量对账周期 | 1800s ±20%，且**只发 digest** |
   | 场景 B 空闲期 Gitea 请求 | 0 次/节点/30min（Leader 兜底 ≤1 次） |
   | 空闲控制面带宽 | ≤ 0.16.05 基线（3 节点 ~9KB/s），**A/B 对比不得回退** |
   | 高频变更 + N=50/100 | 单节点 ≤64KB/周期、≤32 条 LSA/周期 |
   | 同步风暴峰值 | 同一秒 pull 节点数 ≤ `N × 20%`（jitter 生效证据） |
   | 切主 | 组播源恒 ≤1，无重复泛洪 |
   | 场景 B 总流量 vs 场景 A | 数量级下降，且 **N 越大优势越明显**（验证 O(N)→O(1)） |
4. **震荡场景**：制造同一个 `(repo, tid)` 连续 1000 次状态翻转，
   验证 Flap Damping 生效（通告次数被抑制、不是 1000 条 LSA），且状态最终不丢。
5. **`reports/H-LSA-压测报告.md`**：写实测数字表（A vs B、各 N、各频率），
   附复现命令与随机种子。**跑不出来的项写 `unavailable`，不许填估算值或编造数字。**
6. **`tests/test_lsa_loadtest.py`**：对上述断言做小规格冒烟（N=5、缩短时钟），
   保证压测脚本本身可信、断言不是摆设。

## 不要做什么

- 不在**生产集群**上跑压测，不向生产组播组发包，不连真实 Gitea；
- 不改 `hive.py` / `hive_cluster.py` / `hive_control/*` / `dashboard/*`（别的卡持有）；
- 不为让报告好看而调宽阈值、不算 idle 基线、只报 A 不报 B；
- 不用「理论估算」代替仿真输出，不编造历史数字；
- 不引入重型依赖（纯标准库，随机数可复现）。

## 完成标准

1. `python3 tools/lsa_loadtest.py --nodes 5,20,50,100 --duration 3600 --json ...`
   可一键跑完并产出 JSON，随机种子固定可复现。
2. 上表 8 项断言全部有对应实测结果，未达标项**如实记为 fail 并写明原因**，
   不允许通过改阈值消掉。
3. `N=100 + 高频变更` 场景下不出现同步风暴峰值 >20%，
   Flap Damping 把 1000 次翻转压到显著更少的通告数。
4. 报告数字与 JSON 原始输出逐项可核对。
