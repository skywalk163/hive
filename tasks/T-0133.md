## 背景

傍晚那次事故：4 张 `repo: light` 的卡（T-0002~T-0005）被派出去，hive 把代码推到了
`light` 项目（`http://192.168.1.5:3000/skywalk/light.git`）的 main 上，共 8 个 commit
（连同一条人工 CI 修复共 9 个）。用户明确说「咱们的 hive 项目在初期，不应该动 light 项目」，
那 9 个 commit 已经撤掉（light main 回到 `a02a9b2b`），5 张卡也已记作废。

但**"能推"的那根线还在**：四个 `agents/*.json` 的 `repos` 里都登记着
`"light": "/home/skywalk/src/light"`。

现在的安全状况是一分为二的：
- **自动路径安全**：T-0101 已让 `cmd_dispatch` 只派 hive 仓的卡，所以
  `dispatch` / `orchestrate` / watchdog 不会碰 light；
- **手工路径不安全**：`cmd_assign` 不校验仓库，`hive take` 也会建 light 的 worktree 并推分支。
  也就是说现在靠的是「没人手工派 light 卡」这个**约定**兜底，不是机制。

本卡把约定变成硬保证。

## 目标

1. 从 `agents/fb88-dsh.json`、`fb88-verify.json`、`raccoon.json`、`workbuddy.json` 四个文件里
   删掉 `"light": "/home/skywalk/src/light"` 这一项（`hive` 那一项保留）。
2. 效果（都由既有代码路径保证，不新增逻辑）：
   - `dispatch` / `hive next` / 领取判定 → 仓库不匹配，直接跳过；
   - 手工 `assign` 一张 light 卡 → `Worker.prepare` 报
     `agent X 没有配置仓库 'light' 的本地路径`，任务记 failed，**推不出去**；
   - `hive land` 需要 `code_repo('light')` → 报 `没有 agent 登记代码仓 'light' 的本地路径`。
3. **加回归守卫** `tests/test_repo_scope.py`：静态读 `agents/*.json`，断言
   - 每个 agent 的 `repos` 只含 `hive`（现阶段唯一允许被 hive 改动的代码仓）；
   - 不含 `light`；
   - 至少有一个 agent 登记了 `hive`（防止误删过头导致 dispatch 全废）。
   这样以后有人不小心把 light 加回来，测试立刻红。
4. `docs/操作手册.md`：在「第一次初始化 / 登记 agent」相关处写一句现阶段只登记 hive 仓，
   以及以后要管别的代码仓该怎么放开（把对应 repo 登记回 agents 即可）。

## 红线

- **只删 `light` 一项**，`hive` 必须保留，否则 dispatch 和所有自举流程直接废掉。
- **不改** `cmd_assign` / `_can_do` / `Worker.prepare` 的任何逻辑（报错文案保持原样）。
- **不改** 任何现有任务卡（T-0001~T-0005 仍是 `repo: light` + 已记作废，摘掉后它们变成
  不可执行，这与作废状态一致，不需要动）。
- **不引入** 任何第三方依赖。
- 测试只做静态检查，不联网、不改仓库状态、不依赖 `/home/skywalk/src/light` 是否真的存在
  （这样换台机器也能跑）。
