# 目标续跑：一个任务跑到底（不再反复键入「继续」）

## 背景

lightharness 现在「一轮完毕 = 请求返回」，用户得反复输入「继续」。DSH 的做法是 goal 模式
+ goal round driver：一轮结束后由驱动判断「目标还没完成」，自动把续跑提示作为下一轮
用户文本再驱动一次，直到目标标成 complete 或被栅栏拦下。

仓里**决策核心已经齐了，但一根线都没接**：

- `src/目标轮驱动.light`（305 行）：`推进一轮`(195) 返回 `wait/disarm/defer-round/block/reserve/queue-failed`；
  `轮次结束栅栏`(256) 把 `max-tokens` 映射成 disarm、`aborted` 映射成 keep-attempt/disarm；
  `可驱动`(128) / `检查点后就绪`(150) 五门；`渲染目标轮文本`(160) 是**逐字对齐上游**的续跑提示。
- `src/目标折叠.light`（590 行）：`折叠目标`(278) 从 `goal/change` 事件流重放投影，
  `造目标视图`(347) 出 `{id,revision,objective,phase,maxGoalRounds,roundsStarted,activation}`。
- 但这些**只被 `examples/` 导入，`src/` 内零导入**。

三个真实缺口（本卡要补）：
1. **没有 goal 工具**：`src/核心工具.light` 只注册 bash/读文件/写文件/搜索文件，
   所以 `指令段三` 里「mark it complete」模型无处可执行。
2. **没有 `goal/change` 事件写入者**：`src/会话日志增量.light:49` 与 `src/会话日志深化.light:47`
   的事件白名单里都有 `"goal/change"`，但全仓无 `记录事件("goal/change", …)` → `折叠目标` 永远折出空。
3. **没有目标持久化**。

## 要做什么

### 1) 新增 `src/目标续跑.light`（本卡独占）

纯逻辑，**零 IO、零线程、不导入 `代理.light`**。段落一律 `续` 前缀。至少提供：

- `续建续跑状态(目标视图, 选项)` → 状态字典（`{轮次, 最大轮数, 上次修订, 连续无进展, 已停}`）。
- `续续跑决策(状态, 轮次结果)` → `{"动作": "续跑"|"完成"|"停止", "理由": …, "提示文本": …}`。
  必须：
  - 轮次结果 `种类 == "completed"` 且目标 `phase != "complete"` → `续跑`，`提示文本` 取
    `目标轮驱动.渲染目标轮文本(目标, 轮)`（**复用，不要自己写一份提示**）；
  - `种类 == "max-tokens"` / `"aborted"` → 走 `目标轮驱动.轮次结束栅栏`，映射成 `停止`；
  - `种类 == "error"` / `"max-steps"` → `停止`，理由要能区分；
  - `轮次 >= 最大轮数` → `停止`，理由 `round-limit`；
  - **无进展检测**：连续 N（默认 2）轮 `completed` 且目标 `revision` 未变 → `停止`，理由 `no-progress`。
    （N 必须 > 1，否则该分支不可达 —— DSH 规格的硬要求。）
- `续合并目标变更(状态, 变更表)` → 新状态（`revision` / `phase` 推进）。
- `续目标工具规格()` → 目标工具的名字/描述/参数 schema（见下）。
- `续执行目标工具(参数表, 状态)` → `{"ok": …, "变更": {…}}`，纯函数：把
  `goal` 工具的 `update`/`complete`/`pause` 转成 `goal/change` 事件载荷 + 新状态。

**决策一律委托给 `目标轮驱动.推进一轮`**，不要在 `目标续跑` 里重新发明完成判定。

### 2) 新增 `src/目标工具.light`（本卡独占）

把 `续目标工具规格()` 落成可注册的工具：`段落 注册目标工具(注册表)`，
形状照抄 `src/核心工具.light` 里现有工具的注册方式。
工具名 `目标`（英文别名 `goal`），三个动作：`update`（改目标描述/上限）、`complete`、`pause`。

**关键**：新工具必须同步在 `src/总入口.light:158 工具名到叶子` 登记映射，
否则会被 `预设保留工具`(191-208) 注销 —— 但 `总入口.light` 是 T-0407 的热点，
所以本卡**只输出「需要往 `工具名到叶子` 里加哪一行」的精确说明**（贴代码 + 行号），
由 T-0407 落地。

### 3) 新增 `tests/test_T0401_目标续跑.py`

用 `附注 B` 的子进程驱动套路，覆盖：
- `completed` 且未完成 → 决策 `续跑`，`提示文本` 含 `<goal_round>` 与三段固定指令；
- 连续 2 轮 `completed` 且 `revision` 不变 → `停止`/`no-progress`；
- `max-tokens` → `停止`（栅栏口径）；
- `aborted` 且 `原因 == "user_abort"` → `停止`；
- 轮次到上限 → `停止`/`round-limit`；
- `goal` 工具 `complete` → 状态 `phase=complete`，下一轮决策 `完成`；
- **反证**：把 `无进展` 阈值从 2 改成 1，`连续 2 轮` 那条必须红（贴输出）。

## 附注 A：「光明」写法禁令（照抄现状规避写法，成本最低）

- 段落一律块形式：**禁 `段落 X: 返回 …` 单行函数**（生成器缩进会累积）。
- 字典/列表字面量一律**单行**；嵌套字面量内不写 `\n`（用 `chr(10)`）；字面量不直接当实参先 `设` 变量。
- **单字变量名全禁**（`若 则 否 是 段 出 导 遍 对 跳 过 试 捕 抛 终 返 配 己 自 设 为 从 当 空 长 首 末 余 父 常 并 与 且 或 的 在 到 现 例 步 断 新 接 承 引 掷 跃 非 真`）。
- 标识符不得被关键字序列完全切分（`错误己` 会炸，`错误甲` 正常）；不用「为」字入标识符；
  避开含 `等待` 的标识符；成员名避开 `模/模型/模式/工具/事件/类型/原因/取/生成/新建` 等词根。
- 成员赋值一律 `设 己.X 为 …`（裸 `己.X 为 …` 会编成 `==`）。
- 缺键 `d[k]` 直接抛 `键错误` → 用 `字典获取(d, k, 缺省)` 或 `字典包含键` 守卫。
- `空` 是 `None` 不是 `""`，判空串写 `x != "" 且 x != 空`（照抄 `web服务器.light:452/522/527`）。
- `/` 是浮点除法，切片/下标前先 `整数()`。
- **段落名会与依赖模块内联后冲突**（`src/代理循环.light:10-12` 已记）：新模块段落统一加 2 字前缀
  （本批约定：`续`=目标续跑、`压`=压缩升级、`模`不许用→用 `式`、`队`=会话队列、`时`=会话细节）。
- 循环依赖用 `导入 模块` + `模块.段落()` 点号调用，不要 `从 X 导入 名`。
- 新模块名全仓唯一（`src/` 与 `stdlib/` 都要查）。
