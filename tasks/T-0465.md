# 冷启动验收 + 公开 benchmark 报告（带数字才算数）

## 背景

R223 的全部改动（诊断自愈、strict、三层卡、发现入口、MCP、bench 扩容）最终只服务一个问题：
**一个从没听说过光明的 agent，能不能在 3 轮内写出能跑的光明代码？**

这个问题必须用数字回答，否则所有"AI 友好"的说法都是营销。本卡是收口之后唯一的对外产出。

## 要做什么

1. **冷启动实验**（核心）：
   - 新建一个干净 worktree，**只放** `AGENTS.md` + `skills/light/SKILL.md`（不给人提示、不给对话历史）
   - 从 `benchmarks/light_agent/tasks.jsonl` 抽 20 条（四类各 5 条），交给可用模型跑（`light harness run` 已有接口；没有 key 就走 `--model stub` 并明确标注"非真实模型"）
   - 记录：`pass@1`、平均轮数、每轮的诊断码、失败样本的"卡在哪一步"
   - **对照组**：同样的任务，不给 `AGENTS.md`（模拟 R223 之前）——两条曲线才有说服力

2. **报告** `docs/bench/AI友好度_20261126.md`，必须含四段：
   - 北极星四项：pass@1 / 自愈率 / 冷启动发现率 / `ai check` P50
   - 与 R222 基线对比（同一批 20 条任务的前后数字）
   - 错误码 Top10（说明每个码现在能不能自愈）
   - 结论段：**只写能由数据支撑的话**，写不了就写"本轮数据不足以判断"

3. **FAIL 清单**：把 20 条里没过的全部列出 + 归因（语言坑 / 卡信息不足 / 模型能力 / 判定器问题），交回主控转成下一轮卡。

## 不要做什么

- 不编数字。跑不了就写 `未跑（原因）`，**假数字比没数字危害大十倍**
- 不改 `benchmarks/light_agent/`（T-0462 独占）、不改 `cli/light.py`
- 不在报告里写"AI 原生""为 AI 而生"这类无定义的词
- 不把 20 条的任务清单直接外发（先内部评审一版）

## 完成标准

- `docs/bench/AI友好度_20261126.md` 存在，四个指标段齐全，**没有** `TODO` / `TBD` / `<待填>`
- `tests/test_T0465_bench_report.py`：
  - 报告存在且四段标题都在
  - 报告里每个数字后面都跟了来源（`bench` / `实测` / `stub`）
  - 若出现 `未跑`，必须同时出现原因括号
- verify：`python -m pytest -q tests/test_T0465_bench_report.py`
