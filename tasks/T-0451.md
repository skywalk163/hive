# 技能（Skills）：把 skills 目录做成可发现的 skill 工具与系统提示段

## 背景

- DSH 有 `packages/skill` + `tool-skill`：从 `skills/` 目录发现 `SKILL.md`，
  把「名字 + 描述 + 何时用」注入系统提示，模型按需用 `skill` 工具取正文。
- lightharness 的 `src/技能清单.light` 只有纯逻辑（名字 kebab-case 校验、调用策略、
  `<skill_content name="…">` 转义渲染），**全仓没有消费者**——
  没有任何地方扫 `skills/` 目录、没有 `skill` 工具、系统提示里也没有技能段。
- 结果：模型不知道有哪些技能可用，也无法按需取用。这是「不像 DSH」的第三大缺口。

## 要做什么

新增 `src/技能目录.light`（新文件；`src/技能清单.light` 只读导入，别改它）：

1. `发现技能(根, 额外目录表 = [])` —— 扫 `<根>/skills/*/SKILL.md` 与
   `<根>/.skills/*/SKILL.md`（两处都扫，同名去重取先出现的），返回技能表：
   `{名字, 描述, 路径, 正文长度}`。
2. `解析技能文件(文本)` —— 解析极简 frontmatter（`name:` / `description:`），
   正文取出 `---` 之后的部分；frontmatter 缺失/格式错 → 跳过该技能并在结果里记 `跳过原因`
   （**不许整体抛错**，一个坏技能不能拖垮发现）。
3. `渲染技能清单段(技能表, 上限条数 = 50)` —— 产出可直接拼进系统提示的文本：
   `- <名字>：<描述>` 一行一条，超长描述截断（按码点），转义走 `技能清单.转义文本`。
4. `造技能工具定义(发现函数, 根)` —— `skill` 工具：参数 `name`（DSH 同名 snake_case），
   返回 `技能清单` 渲染的 `<skill_content name="…">…</skill_content>` 文本；
   未知名返回 `isError=真` 且列出可用名字（截断到 20 个）。

## 判据（`tests/test_T-0451_技能目录.py`，新建，用临时目录造假技能树）

1. 两个根目录各放 1 个技能 → 发现 2 个，字段正确；
2. 同名技能两处都有 → 只留 1 个（先出现的那份）；
3. 坏 frontmatter（缺 `---` / 无 name）→ 跳过并给 `跳过原因`，好的仍然发现（不整体失败）；
4. `渲染技能清单段` 含两条 `- 名字：描述`，超长描述被截断，`<` 被转义；
5. `skill` 工具：已知 name 返回含 `<skill_content name="x">`；未知 name 返回 `isError=真` + 可用清单；
6. 工具定义过 `工具.校验工具定义形状`，名字恰为 `skill`；
7. **反跑**：把「同名去重」删掉，用例 2 立红。
