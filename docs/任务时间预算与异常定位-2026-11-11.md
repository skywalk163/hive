# 任务时间预算与异常卡定位（2026-11-11）

> 业主反馈两条：① 任务异常时看板「异常」列里尽量带上 agent 名字，方便定位；
> ② 按任务难度/复杂度制定超时，近期好几张卡只给了十来分钟，任务还在跑就被判异常。

## 先说一个顺带修掉的旧坑

上一批给 `hive status` 加了 `land_ready` / `land_block` / `local_stale`，看板
`classify()` 也据此把「只有结果、没有代码分支」的卡挪进异常列。但
`dashboard/app.js` 的 `normalize()` 是**白名单映射**——没列进去的字段前端一律
拿不到，于是 `t.land_ready` 永远是 `undefined`，那批看板改动实际没生效。
本轮把全部新字段补进 `normalize()`，并加了一条测试钉住白名单，避免再犯。

## 根因与改动

### 1. 异常卡看不出该找谁

- `status --json` 新增 `result_agent`（结果里记的交付 agent）和
  `abnormal_agent`（按 `claim.agent` → `owner` → `dispatched_to` → `result.agent`
  汇总的责任 agent），另有 `stale_suspected` 表示「租约过期但已按心跳豁免」。
- 看板 `cardInner()` 对异常卡固定显示一行「责任 agent：X」；没登记时明确写
  「未登记：卡面无 owner / claim / 派单对象」，不让人对着空卡猜。
- 详情面板增加「结果 agent」「责任 agent」两行；异常列 hint 也写明带 agent。

### 2. 超时不随难度变化

| 位置 | 旧行为 | 新行为 |
|---|---|---|
| `hive task new --timeout` | 固定 60 分钟 | 不传时按复杂度自动估算；`--complexity low/medium/high/xl` 可显式抬档 |
| `hive task new --lease` | 固定 180 分钟 | 不传时按复杂度估算，且至少 `timeout*1.5+30`（租约要覆盖派单等待+执行+验收+写结果） |
| `hive watchdog` 的 stale 回收 | `--minutes` 默认 0 = 租约刚过期立刻回收 | 不传 `--minutes` 时按卡的时间预算给宽限（至少 15 分钟）；显式传值（含 0）保留旧语义，兼容既有脚本 |
| watchdog / status 的租约过期判定 | 只看 `lease_until < now()` | 近期有 agent 进度上报（`status/<tid>` 的 `updated_at` 在 15 分钟内）就不判异常、不回收 |
| 派单未接单窗口 | 一律 10 分钟（accept 例外 180） | manual / verify 这类定时来接单的放宽到 60 分钟，只有常驻 exec worker 用 10 分钟 |
| 看板 `isStale()` | 租约过期即异常 | 前端也加一层「近期上报过进度就不进异常列」的兜底 |

**复杂度评分**（`task_complexity()`，只用于分档，不是耗时预测）：
`paths * 2 + verify * 3 + depends * 3 + needs(code/verify/docs: 3/2/1)
+ 正文长度(400/1000/2000/4000 字: 1/2/3/4 分) + P0: 1`，
显式 `complexity` 档次取 `max(自动分, 该档下限)`。

| 分数 | 档位 | timeout | lease |
|---|---|---|---|
| 0–2 | low | 60 | 180 |
| 3–6 | medium | 90 | 180 |
| 7–11 | high | 120 | 240 |
| 12–17 | high | 180 | 300 |
| ≥18 | xl | 240 | 360 |

### 3. 历史卡怎么办

新增 `hive task retime`（默认 dry-run）：按当前卡面重算预算，**只调大、不调小**，
跳过 done/closed/shelved；`--apply` 才写回并一次提交。输出里还会报「另有 N 张
已关闭卡当时预算低于复杂度建议」，只做复盘统计、不改历史卡。

`hive doctor` 对在飞卡增加「时间预算偏紧」告警，直接给出建议值与 `retime` 命令。
看板详情新增「时间预算」区块（当前超时/租约、复杂度评分、建议值、估算依据），
异常卡若超时偏紧会在卡片上直接标出来。

## 用法

```sh
# 新建卡：不传时间，按 paths/verify/depends/正文自动给
python3 hive.py --dir . task new --title "..." --repo light \
  --paths src/a.py src/b.py --verify "pytest -q tests/test_a.py" --body-file spec.md

# 明确知道是大工程：直接抬档
python3 hive.py --dir . task new --title "..." --repo light --complexity xl

# 看现有在飞卡哪些给短了（只读预演），再决定是否批量调大
python3 hive.py --dir . task retime
python3 hive.py --dir . task retime --apply

# 看门狗：不传 --minutes 就自动给宽限；要旧的「立刻回收」显式写 0
python3 hive.py --dir . watchdog
python3 hive.py --dir . watchdog --minutes 0 --apply

# 体检里会点名预算偏紧的在飞卡
python3 hive.py --dir . doctor
```

## 遗留

- 时间预算是启发式分档，不是基于历史耗时的统计预测；后续可以拿
  `results/*.json` 的 `duration_s` 按同类卡做校准。
- 163 张历史卡不改动是有意的（已完成卡不需要预算）；若想看逐卡明细，
  用 `status --json` 的 `budget_*` 字段即可。
- 多机并发写仍无机制性 single-writer；本轮只保证「还在跑的卡不因租约抖动被误判」。
