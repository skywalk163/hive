# 状态一致性与交付链路修复（2026-11-11）

> 背景：最近十余张卡反复出现「看板显示已完成但代码没合入」「显示待合入但任务根本跑不完」
> 「land 报分支不存在」「已合入的卡被改判作废」。诊断见工作区
> `/home/skywalk/dswork/任务状态逻辑诊断-2026-11-11.md`。本文记录这次落到代码里的修复。

## 修复映射（问题 → 根因 → 改动）

| 现象 | 根因 | 修复 |
|---|---|---|
| 结果 `done` 但 land 报「代码仓里没有 task/<tid> 分支」 | 交付侧 push 与回读都硬编码 `origin`；交付机的 `origin` 是本机路径裸仓（`g:\github\light`），自洽但协同服务器上没有分支 | 新增 `network_code_remotes()` / `push_task_branch()`：交付时把分支推到 origin **和所有网络远端**；`guard_result_head()` 增加网络远端回读，至少一个网络远端没有该 head 就把结果判 `failed`，并给出补推命令 |
| 已完成的卡被 `cancel` 成 `closed`（T-0324 的 424a99b） | `cmd_close()` 判定「有没有结果」只读 `origin/res/<tid>`，而 close 自己会删掉这个分支；第二次 close 必然读到 None → `done=False` | `cmd_close()` 改用 `result_info()` 统一口径 + **终态幂等**：`done`/`closed` 的卡重复 close 一律 no-op（不写卡面、不删分支、不动 store）。只保留 `--as-done` 纠正误判 closed 的例外 |
| 重复 land 越跑越坏 | `land_one()` 只拦 `done`，不拦 `closed`；已合入的卡再 land 会走空操作 merge → close → 又 cancel | `land_one()` 拦 `closed` 并提示先 `hive reopen` |
| 结果 head 与分支头对不上 / 零改动也能一路走到 merge | `guard_land_self_consistency()` 写好了但**生产从未调用**（只有测试在调） | 接进 `land_one()`；同时支持多远端 `task_ref`，并把「head 必须相等」放宽为「结果 head 必须是当前分支头的祖先」，兼容主控为解冲突又合了一次 main 的合法情形（T-0326） |
| 看板「待合入」列里是跑不完的卡 | 前端 `classify()` 只看 `result_status === 'done'` | `status` 增加 `land_ready` / `land_block` / `local_stale`；`land_ready === false` 的卡进「异常」列并在卡片上直接写出受阻原因 |
| 多机看到的状态不一样 | `cmd_status` 只 fetch 不 reset 本地工作区，`cards()` 读本地文件 | 输出 `local_stale` 标记 + CLI 醒目 WARN + 看板顶部横幅提示 `git pull`；不擅自替用户 merge 脏工作区 |
| 「N 个待合入结果」虚高、状态分叉没人报 | `doctor` 把 res 分支总数当待合入；缺四类一致性检查 | 按「结果 done 且卡面未关」计数；新增残留 res 分支、结果不可合入、store 状态分叉、Git 归档结果 vs store.results 四类告警 |
| store 漏写结果后提示「重跑 hive submit」 | 那条建议会被 `cmd_submit` 开头的 `result_info()` 闸门直接拒绝 | 改成准确说明：Git 结果可由 land 正常合入，视图不一致用 `doctor` / `repair` 对齐 |
| 分叉只能人工逐张修 | 没有自愈入口 | 新增 `hive repair`（默认 dry-run，`--apply` 生效）：清理残留 res 分支、用 `store/close` 对齐终态卡的 store 状态（走 oplog，不直接改 SQLite） |

## 代码改动清单

- `hive.py`
  - `remote_branch_head()` 支持指定远端名。
  - 新增 `network_code_remotes()`、`push_task_branch()`。
  - `guard_result_head()` 增加网络远端回读。
  - `guard_land_self_consistency()` 增加 `task_ref`，head 校验放宽为祖先关系。
  - `result_info()` 第三层（main 归档）只对终态卡生效，避免 reopen 后重跑 submit 被「已经有结果」挡死。
  - `cmd_close()` 统一结果口径 + 终态幂等。
  - `land_one()` 拦 `closed`、接入自洽校验、分支缺失提示带补推命令。
  - `cmd_submit()` / `Worker.run_task()` 改用 `push_task_branch()`；修正 store 失败后的补偿建议。
  - `cmd_status()` 新增 `_land_probe()` 与三个字段、本地滞后告警。
  - `cmd_doctor()` 新增四类检查并修正待合入口径；`_doctor_store_consistency()` 增加逐卡对账。
  - 新增 `Hive.cmd_repair()` + CLI `repair` 子命令。
- `dashboard/app.js`：`classify()`、列 hint、卡片受阻原因、`renderBanner()` 本地滞后横幅。
- `tests/test_state_consistency_repair.py`：新增 9 条回归测试。

## 新增的可观测信号

`hive status --json` 每条卡现在带：

| 字段 | 含义 |
|---|---|
| `land_ready` | 结果 done 且卡面未关时，是否真的可以 land（校验依赖、代码分支、结果 head、diff）；其余卡为 `null` |
| `land_block` | 不能合入的具体原因（如「代码仓没有 task/T-xxxx 分支（请交付机补推）」） |
| `local_stale` | 本机协调仓落后 `origin/main`，显示的卡面可能不是最新 |

## 用法

```sh
# 体检：会直接点名残留分支、store 分叉、结果不可合入
python3 hive.py --dir . doctor

# 预演修复（默认 dry-run，不动任何东西）
python3 hive.py --dir . repair

# 真正修复：删残留 res 分支 + 对齐终态卡的 store 状态
python3 hive.py --dir . repair --apply

# 交付侧无需改命令：worker / submit 会自动把 task/<tid> 推到所有网络远端
# 若某个网络远端没权限，结果闸门会要求「至少一个网络远端到位」，
# 否则结果判 failed 并给出补推命令，不会再写出一个「done 但合不了」的结果。
```

`repair --apply` 刻意**不动**：卡面内容、代码仓 main、结果 JSON、store.results 记录。
它只做安全可重放的两件事，且默认 dry-run。

## 遗留 / 建议

- `store.results` 与 Git 归档结果的历史差异数量较大（本机多为 follower 副本或结果已归档），
  `doctor` 只告警不自动补写；`repair --apply` 目前只对齐终态卡的 `tasks.state`。
- 本机 `repair` 预演检出 47 张 store 状态分叉，涉及批量 `store/close` 调用，
  建议在集群 leader 稳定、没有别的机器同时写卡面时再执行 `--apply`。
- 多机并发写仍无机制性 single-writer 约束（业主目前按指令逐次合入）。幂等与自洽校验
  已让「重复写」不再破坏状态，但要彻底消除竞态，仍需指定唯一的 land/close 写者或引入
  基于卡面 fence 的乐观锁。
