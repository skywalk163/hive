# 蜂巢（Hive）操作手册

> 面向：每天早上坐下来干活的你，和接在 dsh Web 里的总控 AI。
> 目标：用最短的命令完成「建卡 → 分派 → 看进度 → 验收 → 合并」。

## 1. 角色

| 角色 | 在哪 | 干什么 |
|---|---|---|
| 人 | 任意 | 定优先级、review 关键 diff、合并 `main` |
| 总控 Chief | fb88 的 dsh Web | 拆卡、`dispatch`、读结果、写验收卡 |
| worker | fb88 / win10 / GUI | 领卡、干活、跑 verify、推结果 |
| Gitea | fb5:3000 | 代码与任务真源、CI |
| `hive.py` | 每个 clone 的根目录 | 工具本体 |

## 2. 第一次初始化

```sh
# 开发机：把工具仓推到 Gitea（仓库名 hive，空仓即可）
cd ~/dswork/hive
git remote add origin http://192.168.1.5:3000/skywalk/hive.git
git push -u origin main

# 任意机器：clone 后补齐任务目录
git clone http://192.168.1.5:3000/skywalk/hive.git ~/hive
python3 ~/hive/hive.py --dir ~/hive init
```

`init` 会创建 `tasks/ inbox/ results/ agents/`，并保证 `hive.py` 在仓库根目录。

登记 agent：

```sh
python3 ~/hive/hive.py --dir ~/hive agent add \
  --name fb88-dsh --mode exec --command "dsh --profile headless -" \
  --capabilities freebsd python compiler pytest \
  --repo light=/home/skywalk/src/light \
  --worktrees /home/skywalk/.hive/wt
```

Windows 用 `windows/bootstrap.ps1`，见 `windows/README.md`。

## 3. 每天的命令

```sh
H="python3 ~/hive/hive.py --dir ~/hive"

# 看板
$H status

# 体检：任务卡、租约、结果、agent 配置
$H doctor

# 自动分派（先 dry-run，确认后 --apply）
$H dispatch
$H dispatch --apply --limit 3

# 单张卡
$H assign T-0101 --agent fb88-dsh
$H result T-0101
$H retry  T-0101            # 续用原分支
$H retry  T-0101 --fresh    # 从 main 重来
$H close  T-0101 --note "已并入 integration"

# 统计：成功率 / 中位耗时 / 按 agent / 按仓库
$H stats
$H stats --days 7
```

`dispatch` 的规则：

1. 只看 `state=ready` 且没有 owner 的卡；
2. 依赖必须都 `done`；
3. agent 必须声明了 `repo` 和任务卡的全部 `needs`；
4. `verify` 模式的 agent 不接带 `paths` 的卡（它不改代码）；
5. 已分派未领取也算负载，不超过 `max_concurrency`；
6. 默认 dry-run，`--apply` 才写。

## 4. 总控的一天

**早上**

```sh
$H doctor
$H stats --days 7
$H status
```

把失败/过期的卡拉出来：`$H result T-xxxx`。决定：改卡、`retry`、还是换 agent。

**拆卡**

一张卡只做一件事，写清楚：

- `paths`：允许改的路径（互斥，避免冲突）；
- `verify`：至少一条能自动判定的命令；
- `needs`：平台/能力标签（`windows`、`exe`、`freebsd`）；
- `depends_on`：前置卡。

**分派**

```sh
$H dispatch --apply
```

**验收**

```sh
$H result T-0101
git -C ~/src/light fetch origin
git -C ~/src/light diff main...origin/task/T-0101
```

跑 CI 或本地子集，绿了再合 `integration`。

**收口**

```sh
$H close T-0101 --note "已并入 integration"
```

`close` 会把结果归档到 `main:results/T-0101.json`，删掉 `claim/res` 分支。

## 5. 分支与合并

```
task/T-0101 ─┐
task/T-0102 ─┼─▶ integration ──CI 绿 + 人 review──▶ main（批量）
task/T-0103 ─┘
```

- 一卡一 worktree、一卡一分支；worker 不碰主 checkout。
- 共享文件（版本号、CHANGELOG）由总控在合并时统一改，或单独开“收口卡”。
- 冲突回给 owner 作为新卡，不要在 integration 上手工解半天。

## 6. 租约与故障

| 情况 | 处理 |
|---|---|
| VM 死机 / 机器断电 | 等 `lease_minutes` 到期 → `$H gc` → `$H retry T-xxxx` |
| 卡被占着但人想重派 | `$H retry T-xxxx --agent 别的agent` |
| agent 跑飞 | `timeout_minutes` 会硬杀；`--keep` 保留 worktree 排查 |
| 结果分支推不上去 | 看 `~/.hive/agents/<agent>/logs/T-xxxx.log` |
| 重复执行 | 只会发生在有人手工删了 claim 又没删 res；`doctor` 会报 |
| `unable to read sha1 file` | 服务端自动 gc 与并发 fetch 撞了；见 §8 |

## 7. 安全

- 每台机器一个 Gitea token，只授权需要的仓库；
- `main` 保护，worker 只推 `task/*`、`claim/*`、`res/*`；
- 任务卡不放密钥；
- GUI agent 用单独账号，出事能一键吊销；
- WorkBuddy 实测以 root 跑：不要给它宿主仓库写权限。

## 8. 已知坑：服务端自动 gc

240 次快速 push 后立刻 clone，复现过：

```
error: unable to read sha1 file of tasks/T-0222.md
fatal: unable to checkout working tree
```

原因是裸仓的 `receive.autogc` 默认开启，`gc --auto` 会后台跑，和并发的 clone/fetch 抢对象。
处理（在 Gitea 的仓库目录，或任意自建裸仓）：

```sh
git -C /path/to/hive.git config receive.autogc false
git -C /path/to/hive.git config gc.auto 0
# 夜间空闲时手动 gc
git -C /path/to/hive.git gc --prune=7.days
```

测试仓和 soak 已经默认关掉自动 gc；Gitea 仓建议在低峰期做一次。

## 9. 度量

看板：`PORT=8787 ./scripts/serve-dashboard.sh`，浏览器开 `http://127.0.0.1:8787`。

| 指标 | 命令 | 目标 |
|---|---|---|
| 周期时间 | `stats` 中位耗时 | < 45m |
| 一次通过率 | `stats` 成功率 | > 70% |
| 人工介入 | 手工记 | < 10m/卡 |
| 重复执行 | `doctor` | 0 |
| 冲突率 | 合并时统计 | < 10% |
