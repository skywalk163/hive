## 五、横向观察

1. **"卡 done" 与 "判据成立" 不是一回事**：16 张里 4 张（25%）卡说 done/shelved 但判据不成立，其中 3 张（T-0268/T-0276/T-0262）是**平台或环境造成的假绿**，1 张（T-0261）是全量基线本来就没绿就被关闭。
2. **假绿的成因高度集中**：大小写不敏感文件系统（Windows glob）、硬编码 Windows 绝对路径、把"单元测试绿"当"真判据成立"。三者都与"只在 Windows 上跑"有关。
3. **判据没有被改宽**：抽查 T-0261 / T-0262 / T-0268 / T-0276 的 `verify` 行历史，自创建卡（`895d2b7`）以来**没有出现过加宽**；问题出在"验证环境与判据前提不匹配"，不是"事后改判据"。
4. **六仓检出状态一致**：六仓 `git status --porcelain` 均为 0 行（干净）；但各机 HEAD 不完全同步（`light` 96 为 `33dbc22cf`、Windows 为 `4c7b15a35`；`lightharness` Windows 为 `602c27b` 而 96 为 `ce8a2ac`）。跨机验收需先对齐 HEAD，否则计数类判据会得出不同答案（T-0268 在 96 是 130/145 两种结果就依赖这一点）。
5. **间歇性挂死不只在 Windows**：`tests/test_watchdog.py`、`tests/test_dashboard_freshness.py` 在 FreeBSD 上出现过 4 次"打印 N passed 后进程不退出"（120s 被杀，exit=124），随后 8 次全部正常退出。与 T-0285 记录的"后代进程持有 stdout PIPE"一致，**不能当作已闭环**。
