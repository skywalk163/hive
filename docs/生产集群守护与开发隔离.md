# 生产集群守护与开发隔离（fb98）

> 背景：fb98 这台机器既是生产研发机，又跑着**整个团队**的 hive 控制面。
> 2026-11-10 之前它有两个隐患，都曾让全员训练/派单停摆：
>
> 1. 生产集群是 `nohup` 拉起的**孤儿进程**（PPID=1），没有守护。进程一退，
>    没有任何东西把它拉起来，集群就永久无主。
> 2. 改 hive 代码时要重启集群，而**本地集群就是生产集群**，一重启全团队停摆。

本文档给出这两件事的处理方式。**部署到独立机器（192.168.1.5）的方案暂不可行**，
原因见文末「为什么没有搬到 fb5」。

---

## 一、生产集群：交给 daemon(8) 托管

### 安装

```sh
sudo cp scripts/freebsd/hive_cluster.rc /usr/local/etc/rc.d/hive_cluster
sudo chmod 755 /usr/local/etc/rc.d/hive_cluster

sudo sysrc hive_cluster_enable="YES"
sudo sysrc hive_cluster_chdir="/home/skywalk/dswork/hive"
sudo sysrc hive_cluster_user="skywalk"
sudo sysrc hive_cluster_state="/home/skywalk/.hive/cluster"
sudo sysrc hive_cluster_name="fb98"
```

### 日常命令

```sh
sudo service hive_cluster start|stop|restart|status
```

`status` 用「端口在监听 + python 进程存在」组合判断，不依赖 pidfile
（daemon 模式下 pid 可能被回收复用，`kill -0` 会误判）。

### 行为

- **崩溃自动重启**：`daemon -f -r -R 5`，子进程异常退出后 5 秒拉起。
  实测 `kill -9` 后 **5 秒**恢复并重新当选主控。
- **开机自启**：`hive_cluster_enable="YES"`。

### 可调参数（`/etc/rc.conf`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `hive_cluster_port` | `8788` | HTTP 端口 |
| `hive_cluster_discovery_port` | `8789` | UDP 发现端口 |
| `hive_cluster_mcp` | `YES` | 是否起 MCP（127.0.0.1:8790） |
| `hive_cluster_store` | `YES` | 是否启用 sqlite store |
| `hive_cluster_extra_args` | 空 | 追加到 `serve` 之后的参数 |

### 两个踩过的坑（已在脚本里修掉，改脚本时别再退回去）

1. **路径**：rc 脚本里的启动包装是
   `scripts/freebsd/hive-cluster-run.sh`，不是仓库根的 `freebsd/`。
   写错会看到 `daemon: ... No such file or directory` 刷屏、集群完全起不来。
2. **HOME**：rc.subr 用 `su -m` 保留调用者环境，`HOME` 可能是 root 的 `/`，
   于是 `$HOME/.hive` 被展开成 `//.hive`（`mkdir: Permission denied`）。
   rc 脚本里必须显式 `export HOME="${hive_cluster_home}"`。

## 二、开发集群：完全隔离的第二套实例

改代码时**不要碰生产集群**，起一套开发用的：

```sh
scripts/dev-cluster.sh start     # 后台启动
scripts/dev-cluster.sh status
scripts/dev-cluster.sh logs      # tail -f
scripts/dev-cluster.sh restart
scripts/dev-cluster.sh stop

scripts/dev-cluster.sh start --foreground   # 前台跑，方便直接看 traceback
```

### 隔离矩阵（生产 / 开发逐项错开）

| 项目 | 生产 | 开发 |
|---|---|---|
| state_dir | `~/.hive/cluster` | `~/.hive/dev-cluster` |
| HTTP 端口 | `8788` | `8888` |
| 发现端口 | `8789` | `8889`（且**关闭广播**） |
| cluster_id | `hive` | `hive-dev` |
| store | 启用（`~/.hive/cluster/hive.db`） | **关闭** |
| MCP | 启用（8790） | **关闭** |
| 仓库同步 | 启用 | **关闭** |
| 监听地址 | `0.0.0.0` | `127.0.0.1` |

`cluster_id` 不同 + 关闭 UDP 广播，是**双保险**：即使广播意外触发，对端
也会因为 `cluster_id` 不匹配而丢弃（`hive_cluster.py` 的 discover/announce
都会校验 `msg["cluster"]`）。

### 已验证

- 连续 3 次 `restart` 开发集群 → 生产集群 `term` 不变、`peers=4` 完好。
- 开发集群日志中**没有任何**生产地址（`8788` / `192.168.0.x`）出现。
- 看板（8787）仍读生产集群，`cluster_id=hive`。

### 覆盖默认值

```sh
HIVE_DEV_PORT=9999 HIVE_DEV_STATE=~/tmp/dc scripts/dev-cluster.sh start
```

## 三、为什么没有搬到 192.168.1.5（fb5）

原计划：把主控迁到 fb5，`leader_priority=115`，让开发机彻底不参与生产。

**排查结论：网络单向不通，组不成集群。**

| 方向 | 结果 |
|---|---|
| fb98(`192.168.0.88`) → fb5(`192.168.1.5`) | 通（经 `192.168.0.1` 一跳） |
| fb5 → fb98 | **不通**（`192.168.1.1 → 100.120.0.1 → 公网`，`100.64/10` 是运营商 CGNAT） |

- fb5 上没有到 `192.168.0.0/24` 的回程路由。
- 手动在 fb5 加 `route add -net 192.168.0.0/24 192.168.1.1` 后仍不通 ——
  上游网关不知道怎么回 `0.x`（traceroute 显示流量进了公网）。该路由**已撤销**。
- fb5 的 `10.0.0.0/24`（cbsdbr0）与本机 `10.0.10.0/24`（bridge0）互不相通，
  都是各自主机内部的私有网桥。

hive 节点之间要互发心跳、拉票、同步 store，**全部要求双向可达**。单向通的
只有 fb98 主动连 fb5，fb5 发不回来，因此无法成集群。

### 要迁的话，先解决网络（二选一）

1. **路由器加回程路由**：给 `192.168.1.0/24` 加一条指向 `192.168.0.1` 的
   静态路由（最省事）。
2. **组网工具**：在两台机器上装 Tailscale / ZeroTier，走 overlay 互联。

打通后按此部署：

```sh
# 在 fb5 上
git clone http://192.168.1.5:3000/skywalk/hive.git ~/dswork/hive
cd ~/dswork/hive
python3 hive.py cluster serve --name fb5 --port 8788 --state-dir ~/.hive/cluster \
    --priority 115 --seed http://192.168.0.88:8788 --mcp --store --claim-backend store
```

`priority=115` 高于 fb98 的 20，按 T-0328 的四级择优链，无主时 fb5 会先当选；
但**non-preemptive**：只要 fb98 还活着当主，fb5 不会去抢。切主需要显式
`hive cluster promote --node fb5` 或让 fb98 先下线。

## 四、关联任务

- **T-0327**：主锁饥饿（持锁写盘 / 跨等 store 锁 / 补卡逐行 fsync），
  修好看板「集群：未启动」与周期性假死。
- **T-0328**：选主改「择优」（priority → link_speed → node_id），
  去掉「凑够多数票才能当选」，修长期无主。
- 本文档对应改动：`scripts/freebsd/hive_cluster.rc`、
  `scripts/freebsd/hive-cluster-run.sh`、`scripts/dev-cluster.sh`。
