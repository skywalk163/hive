## 三、四项问题逐项判定

### 3.1 `.103` 的「幽灵 leader」

**现状**：`laiweilideMacBook-Air-20c3af99` 是活跃 leader，`node.id` 前缀与它上报的
`hostname=laiweilideMacBook-Air.local` 一致，节点表里 id 与 URL 也自洽，**结构上不是幽灵**。
这是 T-0283 时期「Mac 身份出现在 Windows 节点上」遗留的历史标签，今天已不成立。
但工具仍如实报出一条治理项：该节点的**自身** `last_seen` 停在 `2026-11-08T12:08:24`（其启动时刻），
而 `/api/cluster/state` 对 leader 自身会回填当前时间——两者不一致，属于实现细节还是异常，
需要人工确认。

**影响**：不影响选主与读写；影响的是「幽灵/健康」口径与审计结论。

**路径 A：承认该身份为正式节点（推荐，零停机）**
- 做法：更新文档与审计口径，把「幽灵 leader」改述为「`.103` 的正式 leader 身份」；不需要碰运行时。
- 代价：历史审计记录里的「幽灵」措辞要一并更正。
- 前置：业主确认 `.103` 这台 Mac 就是集群的正式成员。

**路径 B：让 `.103` 换 node id 重新注册**
- 做法：停 hived → 改 `node.json` 身份 → 重新入群。
- 代价：需要停机窗口；会触发重新选主；旧 id 与新 id 可能短暂并存，存在双主/分裂风险；
  收益仅是「名字更干净」。**不建议**。

### 3.2 `.102` 的 dead 记录

**现状**：`DESKTOP-2NRDKF0-dfc32f1f` 的 last_seen 停在 `2026-11-03T23:51:43`，已 5 天。
**影响**：`peers/quorum` 口径偏大、看板出现死节点、调度仍可能把它算作候选。
**清理方式与风险**：
- 由 leader/controller 侧执行 `cluster leave`（软删除，事件与历史保留），不要手工改 `state.json`；
- 风险一：如果该机只是关机、之后会用同一 node id 回来，leave 后重入会重新注册（可接受）；
- 风险二：在非 leader 上执行会失败或被覆盖，必须确认目标节点的 leader 归属后再动；
- 前置：业主确认 `.102` 已退役；本卡**不执行**。

### 3.3 `.101` 的 id / name / IP 口径

**现状**：机器已改名 `WIN10`、DHCP 变为 `.101`，但节点记录仍是
`DESKTOP-6LFQUO8` / `DESKTOP-6LFQUO8-8a3bf94c`，上报 `hostname=win10`。
**影响**：看板与排障时按名字找不到机器；工具已将其列为 `identity_mismatch`。
**建议**：
- **保持 node id 不变**——换 id 等于新身份，会重复触发 3.1 的身份问题；
- 只把展示用 `name` 对齐为 `WIN10`（纯展示字段，逻辑零影响，但需要改配置并重启 hived，
  属运行时动作，本卡不执行）；
- 若重启窗口不允许，可先在文档与看板口径里注明「`DESKTOP-6LFQUO8` = `WIN10` = `.101`」。

### 3.4 过期验收脚本

`scripts/verify_104_readiness.py` 原来写死单个节点 IP 并断言「节点表恰好 2 个 URL」，
在当前 5 节点形态下必然全红。现已改为通用体检工具（文件名不变，避免断引用），
判据对照如下：

| 旧判据（已废） | 新判据 |
|---|---|
| 写死某个节点的 health 必须 1s 内回 | 从 `--leader-url` 动态采集，读不到就明确报错 |
| 节点表恰好 2 个不同 URL | 不再假设节点数，只查 id/URL 重复 |
| 断言「无幽灵 identity 字符串」 | `ghost_leader`：leader 是否在节点表/正式 roster 中且 URL 一致 |
| 无 dead 概念 | `dead_nodes`：`last_seen` 超过 `--dead-after`（默认 600s） |
| 只输出断言成败 | 输出结构化 JSON（term/role/peers/quorum/nodes/todos 等） |

复跑命令：

```bash
# 离线自检（不联网、不读真机 state）
python3 scripts/verify_104_readiness.py --self-test

# 只读体检本机集群（有 todos 也返回 0；--strict 时 todos 非空返回 1）
python3 scripts/verify_104_readiness.py
python3 scripts/verify_104_readiness.py --strict
python3 scripts/verify_104_readiness.py --leader-url http://192.168.0.88:8788 --state ~/.hive/cluster/state.json

# 判据单测（标准库，无需 pytest / 外网）
python -m unittest discover -s tests -p test_cluster_topology_check.py -v

# pytest 收集也不会因连不上真机而挂（只剩离线用例）
python3 -m pytest scripts/verify_104_readiness.py -q -o addopts=
```
