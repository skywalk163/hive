## 4. 夜里挖出来的四个坑（都已修）

1. **`verify: ["true"]` 被解析成布尔值**
   列表项走了标量转换，`true` 变成 `True`，传给 subprocess 直接
   `TypeError: 'bool' object is not iterable`。
   现在列表项一律按字符串解析。这个坑很隐蔽，任何 `verify` 命令叫 `true`/`false` 都会中招。

2. **多个 worker 共用 clone 时，claim 分支可能没有 `claims/T-xxxx.json`**
   原来的实现用工作区 index 做 `read-tree/update-index`，并发时会互相踩。
   现在用独立的 `GIT_INDEX_FILE` 构造提交，不碰工作区。顺带也不会再 `reset --hard` 掉你的本地改动。

3. **服务端自动 gc 和并发 clone 抢对象**
   240 次快速 push 后立刻 clone，复现了 `unable to read sha1 file`。
   原因是裸仓 `receive.autogc` 默认开启、`gc --auto` 后台跑。
   测试仓已默认 `receive.autogc=false` + `gc.auto=0`；Gitea 仓建议也这么设，夜间手动 gc。
   详见 `docs/操作手册.md` §8。

4. **`dispatch` 的负载统计漏了「已分派未 claim」**
   会把同一台机器塞爆。现在 claim 和 assigned 都算负载。

```powershell

powershell -ExecutionPolicy Bypass -File C:\hive\windows\bootstrap.ps1
```
