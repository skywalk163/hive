# 看板写操作：鉴权与审计

> 看板最早是**只读**的：点一下「复制派发指令」② 也不会写任何东西。
> 后来加了运维按钮（终止 / 重试 / 退回 / 重开 / 改派），本文讲它们**凭什么**能写、
> 写了之后**留下什么**。

---

## 1. 身份边界：绑定地址决定要不要 token

看板默认只听 `127.0.0.1`。**本机回环就是身份边界**——能打开页面的人，本来就能在
终端里跑 `hive`，所以写操作免鉴权（保持老体验，升级后按钮不会突然全部 401）。

一旦把看板暴露出去（`--host 0.0.0.0`、反向代理、隧道），就必须带 token：

| 绑定 | `HIVE_DASH_AUTH` | 写操作 |
|---|---|---|
| `127.0.0.1` / `localhost` / `::1` | `auto`（默认） | 免鉴权 |
| `0.0.0.0` / 其它地址 | `auto`（默认） | **要 token** |
| 任意 | `on` | 要 token |
| 任意 | `off` | 免鉴权（自担风险） |

```sh
# 本机看：按钮直接用
python3 dashboard/serve.py --status dashboard/status.json

# 让别的机器看：自动开启写操作鉴权
python3 dashboard/serve.py --status dashboard/status.json --host 0.0.0.0

# 显式覆盖
python3 dashboard/serve.py --auth on   # 本机也要 token
python3 dashboard/serve.py --auth off  # 内网试验田
```

## 2. token 从哪来、怎么登录

复用 **MCP 的本机 token 表**（`mcp_auth.py`，`~/.hive/cluster/mcp_tokens.json`，
SHA-256 存储、0600、不进协调仓）——同一个 agent 身份在看板和 MCP 里是同一个：

```sh
# 生成/轮换 token（一个 agent 一个；旧 token 自动吊销）
hive agent enroll board-ctrl --role controller
hive agent enroll win10 --role worker
```

拿到 token 后，看板右上角点「登录」，粘贴即可。服务端做三件事：

1. 校验 token（`mcp_auth.resolve`）；
2. 把 token 写进 **HttpOnly cookie**（`SameSite=Strict`，24h），页面里**不留明文**；
3. 记一条审计 `action=login`。

也支持请求头直连（脚本/CI 用）：

```sh
curl -s -X POST http://host:8787/api/task \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"retry","tid":"T-0100"}'
```

三种来源的取值顺序：`Authorization: Bearer` → `X-Hive-Token` → `hive_token` cookie。

## 3. 角色：谁能关、谁能退

| 操作 | 语义 | 需要的角色 |
|---|---|---|
| `retry` | 重新排队（同 agent 续跑或改派） | worker（自己的卡）/ controller |
| `unassign` | 退回待领取 | 同上 |
| `close` | 关闭：有结果记 done，没结果记作废 | **controller** |
| `reopen` | 已完成/作废的卡拉回 ready | **controller** |

`close`/`reopen` 是不可逆或半不可逆的运维动作，所以只给 controller；worker 的 token
也能看板、也能退自己的卡，但关不掉别人的。

## 4. 审计日志

每次写操作都往 `dashboard/audit.log` 追加一行 JSON（**append-only**）：

```json
{"ts": "2026-10-30T08:31:02+08:00", "action": "close", "task": "T-0100",
 "ok": true, "agent": "board-ctrl", "role": "controller",
 "note": "看板关闭：重复实现", "source": "127.0.0.1"}
```

- 失败也记：`ok: false` + `detail`（未鉴权 / 角色不足 / CLI 退出码 / 超时）。
- 有一次 `close` 被写成「看板操作」两个字、半年后谁也说不清为什么关（T-0181），
  这条日志加上**强制填原因**（前端 prompt）就是为了不再发生。
- 日志不进 git（`.gitignore` 已含 `dashboard/audit.log`），但要长期保留的话请自己备份。

```sh
# 最近 20 条
tail -n 20 dashboard/audit.log
# 谁关过卡
grep '"action": "close"' dashboard/audit.log
```

## 5. 请求清单

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/status` | 无 | 任务快照（含集群/HTTP 进度合并、`X-Snapshot-Mtime`） |
| GET | `/api/config` | 无 | 系统只读信息 + 共享看板配置 |
| GET | `/api/cluster` | 无 | 本机集群视图 |
| GET | `/api/dispatch-prompt` | 无 | 渲染可粘贴的派发指令（纯只读） |
| POST | `/api/login` | 无（凭 token 换 cookie） | 登录 |
| POST | `/api/task` | **要**（绑定回环可免） | close/retry/unassign/reopen |
| POST | `/api/push` | 无 | agent 上报进度（有意开放：只影响进度展示） |
| POST | `/api/config` | 无 | 共享看板配置/系统配置 |

> `/api/config` 的写入沿用旧行为（服务端共享默认）。如果看板要暴露到内网，
> 建议把 `--auth on` 一起用上，并在反代层再加一道。

## 6. 排障

| 现象 | 处理 |
|---|---|
| 按钮报 `写操作需要 token` | 右上角「登录」；或 `hive agent enroll <name>` 生成 |
| 登录后仍 401 | cookie 被清（隐私模式/换了主机名）；重新登录，或改用请求头 |
| `close 需要 controller 角色` | 用 controller 的 token；worker token 不能关别人的卡 |
| `找不到 hive.py` | 看板仓根要含 `hive.py`（`--dir` 指向协调仓根） |
| 想看谁动了什么 | `tail dashboard/audit.log` |

## 7. 实现位置

| 内容 | 位置 |
|---|---|
| 鉴权模式判定 | `dashboard/serve.py` 的 `_auth_mode` |
| token 校验 | `_resolve_dashboard_token`（包 `mcp_auth.resolve`） |
| 登录与 cookie | `serve_login` |
| 写操作闸门 | `require_write_auth` / `is_controller` |
| 审计 | `append_audit` / `_audit_log_path` |
| 前端登录 | `dashboard/app.js` 的 `loginWithToken`、`index.html` 的 `#login-btn` |

回归测试：`tests/test_dashboard_auth.py`（auto 模式判定、无 token 401、读接口永远可读、
登录换 cookie、worker 不能 close 但能 retry、controller close 落审计、`off` 保持旧行为）。
