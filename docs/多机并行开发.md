# 多机多 agent 并行开发

> 适用：一台机器发任务，多台机器（FreeBSD / Windows）上的多个 agent 并行干活，
> 全程文件不打架，最后自动验收、合流、push。
>
> 这是 `迁移指南.md` 的下一站：那篇讲「从聊天分发迁到任务总线」，本篇讲
> **把任务总线铺到多台机器上**。

---

## 1. 一句话模型

```
                    ┌─────────────────────────┐
                    │  中心仓 (Gitea)          │
                    │  tasks/  claims/  results/│  ← 唯一的真相
                    └───────────┬─────────────┘
              ┌─────────────────┼─────────────────┐
        ┌─────┴─────┐     ┌─────┴─────┐     ┌─────┴─────┐
        │ FreeBSD    │     │ Win10     │     │ Win10     │
        │ worker     │     │ worker    │     │ 手工 GUI  │
        │ fb88-dsh   │     │ raccoon-win│    │ workbuddy │
        │ 独立worktree│     │ 独立worktree│    │ 独立worktree│
        └───────────┘     └───────────┘     └───────────┘
```

- **任务卡**是文件，活在中心仓的 `tasks/`。
- **谁在干什么**由 `claims/T-xxxx` 这条 git ref 决定，**push 非快进被拒就是原子抢锁**。
- **每个任务一个独立 git worktree**（分支 `task/T-xxxx`），所以 agent 之间天然不碰同一份文件。
- 干完把结果推成 `results/T-xxxx.json`，`hive land` 串行合入 main。

多机之所以能成立，靠的就是这四条：**中心仓唯一真相、claim 原子锁、worktree 物理隔离、land 串行合流**。
这四条之上还有一层**可选的常驻集群**（§3.4）：git 是唯一真相，集群只把「等下一次
git fetch 才能看到别人进度」变成秒级，并在主节点退出后自动重选。

## 2. 五个核心概念

| 概念 | 在哪 | 作用 |
|---|---|---|
| `host` | `agents/<name>.json` 的 `host` | 标明这个 agent 属于哪台机器，默认取 hostname |
| `repos` | `agents/<name>.json` 的 `repos` | 这**台机器**上代码仓的本地路径（不同机器可以不同） |
| `paths` | `tasks/T-xxxx.md` 的 `paths` | 这张卡要动哪些文件；dispatch 用它判断两张卡会不会打架 |
| `claim` | `claim/T-xxxx` git ref | 租约锁；抢到才能干，过期自动回收 |
| `land` | `hive land T-xxxx --apply` | 把 `task/T-xxxx` 合进 main 并 push、close |

### host 与 repos 的关系（多机最容易踩的点）

同一个代码仓，在每台机器上的路径不同：

```jsonc
// FreeBSD 机的 agent
{ "name": "fb88-dsh", "host": "fb98",
  "repos": { "hive": "/home/skywalk/dswork/hive" } }

// Windows 机的 agent
{ "name": "raccoon-win", "host": "win10",
  "repos": { "hive": "G:/dswork/duan-light-merge/hive" } }
```

`hive` 解析代码仓路径时**优先取本机（host 匹配）且真实存在的那个**，
所以 `land` / `prune` 在你当前这台机器上永远找得到对的路径，不会被别的机器的
`G:/...` 顶掉。（这个 bug 在 T-0147 收尾时暴露并修复，见 commit `1dd373b`。）

## 3. 部署一台新机器（以 Windows 为例）

### 3.1 通用前置

1. Python 3.12+、git；
2. 能访问中心仓（`git ls-remote http://192.168.1.5:3000/skywalk/hive.git` 通）；
3. clone 一份协调仓：`git clone <中心仓> hive`。

### 3.2 登记 agent

```sh
# 在本机 clone 的协调仓里执行
python hive.py agent add \
  --name raccoon-win \
  --mode manual \
  --host win10 \
  --repo hive=G:/dswork/duan-light-merge/hive \
  --abilities code docs verify \
  --capabilities windows gui
```

- `--mode exec`：有命令行 LLM 的机器，worker 自动领卡跑；
- `--mode manual`：只有 GUI 聊天窗口的机器（小浣熊 / WorkBuddy），靠 MCP 或贴 prompt；
- `--mode verify`：只验收、不改代码的机器。

`--host` 不写就取当前 hostname。**多机时务必写清楚**，否则 `dispatch --host` 失效。

### 3.3 Windows 的两种接法

**A. MCP 自助（推荐，manual 也能闭环）**

按 `MCP接入.md` §11 配好 `mcp_server.py`，agent 在聊天里可以直接
`hive_claim` / `hive_submit`，不需要人贴 prompt。

**B. 贴 prompt（最朴素）**

```sh
# 在任意机器上领一张卡，准备 worktree
python3 hive/hive.py --dir hive take T-0148 --agent raccoon-win
# 把输出的 prompt 贴进小浣熊的聊天窗口
```

`take` 会把卡置为 assigned、建好 worktree，并打印一段可直接粘贴的 prompt。
你只负责粘贴，剩下的（claim、提交、verify、结果落库）由 agent + `hive submit` 完成。

### 3.4 起本机集群（建议，但可选）

> 以下命令在 hive 工作目录里跑（hive 仓 = `./hive`）；Windows 把 `/` 换成 `\`。

新机器接入后，顺手起一个常驻集群节点：自动发现同网段的其他 hive、向主节点注册，
这台机器的进度/租约立刻对其他机器秒级可见（不用等 `git push` → `git fetch`）。

```sh
python3 hive/hive.py --dir hive cluster start
python3 hive/hive.py --dir hive cluster status
```

- **不起也能用**：所有命令照常走纯 git 路径，只是跨机信息慢一拍。
- 主节点退出后自动重选；任期/化身号/租约宽限的取舍见 [`集群服务.md`](集群服务.md)。
- 端口（HTTP 8788 / UDP 8789）与防火墙见 [`端口与服务规划.md`](端口与服务规划.md)。

## 4. 日常怎么跑

### 4.1 写卡

```sh
python hive.py task new --id T-0150 --title "修 xxx" --repo hive \
  --paths src/a.py tests/test_a.py \
  --needs python pytest \
  --verify "python -m pytest tests/test_a.py -q"
```

**paths 是防冲突的第一道闸**：两张同时在飞的卡，只要 paths 有重叠，
dispatch 就不会把它们派到同一组。所以宁可按文件写细，也别写空。

### 4.2 分发

```sh
# 让所有机器的 agent 都可能接到（默认）
python hive.py dispatch --apply --limit 4

# 只派给某台机器（多机时最常用）
python hive.py dispatch --apply --host win10

# 只派给某个 agent
python hive.py dispatch --apply --agent fb88-dsh
```

不动 `--apply` 就是 dry-run，会打印每张卡"派给谁 / 为什么不派"。

### 4.3 agent 干活

- **exec**：本机 worker 轮询 inbox → claim → 建 worktree → 调 LLM → 改代码 → verify → push 结果；
- **manual**：你 `take` + 贴 prompt，或 agent 自己走 MCP；
- **verify**：只跑验收命令。

### 4.4 验收与合流

```sh
python hive.py status                 # 谁在跑什么
python hive.py result T-0150          # 单卡结果 + verify 输出
python hive.py audit T-0150           # 合入前：summary 与真实 diff 对不对得上
python hive.py land T-0150 --apply    # 合入 main + push + close
python hive.py land --all --apply     # 批量合入所有 done 卡
```

`land` 默认 dry-run，会先在临时 worktree 里真做一次 merge，冲突是真的冲突，
不是猜的。`--apply` 才推 main。

## 5. 为什么文件不会打架（三层保障）

| 层 | 机制 | 防的是什么 |
|---|---|---|
| **分支隔离** | 每卡一个 `task/T-xxxx` worktree | agent 之间物理上就看不到对方的未提交改动 |
| **租约锁** | `claim/T-xxxx` git ref，push 非快进即失败 | 同一张卡不会被两个 agent 同时干 |
| **路径互斥** | dispatch 检查 `paths` 重叠 + `HIVE_MAX_PER_REPO` | 两张不同的卡改同一片文件 |
| **合流串行** | `land` 一次合一张，冲突显式暴露 | 最后合并时的互相覆盖 |

注意：**分支隔离保证"干活时不冲突"，但不保证"合流时不冲突"**。两张卡改同一文件，
各自都能提交，land 时才冲突。所以 `paths` 写准 + 必要时 `depends_on` 串行，仍然重要。

## 6. 多机排障表

| 现象 | 原因 | 处理 |
|---|---|---|
| `dispatch` 不派给某台机器 | agent 没写 `host` 或写错 | `hive doctor` / `agent list` 看 host |
| `land` 报"本地代码仓不可用: G:/..." | 拿到别的机器的 repos 路径 | 已修（`1dd373b`）；确认本机 agent 的 `repos` 路径存在 |
| 卡一直是 assigned 没人干 | 那台机器没跑 worker / worker 挂了 | 看 `ps` 和 `logs/worker.log` |
| worker 说"没有配置仓库的本地路径" | 本机 agent 配置里 `repos` 缺该仓 | 补 `--repo name=path` |
| 验收恒过 | verify 命令本身有问题（如空命令） | 先手动跑一遍，确认它**该红的时候会红** |
| 两台机器同时改同一文件 | `paths` 没写或写太粗 | 拆细 paths，或加 `depends_on` |
| 中心仓不可达 | 网络 / Gitea 挂了 | 修网络；worker 会自动重试 |

## 7. 命令速查

```sh
# 机器 / agent
python hive.py agent add --name X --host <机器> --mode exec --repo hive=<本机路径>
python hive.py agent list
python hive.py doctor

# 任务
python hive.py task new --id T-xxxx --title "..." --repo hive --paths a.py b.py --verify "..."
python hive.py status
python hive.py result T-xxxx

# 分发
python hive.py dispatch                    # dry-run
python hive.py dispatch --apply --limit 4
python hive.py dispatch --apply --host win10
python hive.py dispatch --apply --agent fb88-dsh

# 手工领（manual / 贴 prompt）
python hive.py take T-xxxx --agent raccoon-win

# 验收 / 合流
python hive.py audit T-xxxx
python hive.py land T-xxxx --apply
python hive.py land --all --apply
```

## 8. 一条经验法则

> **并行度 = 你能同时审得过来的 diff 数，不是 agent 数。**

多机的价值在于"不同机器各自有本地环境（FreeBSD 编译、Windows GUI、不同模型）"，
不是无限堆并发。一开始 3–4 张并行、paths 互斥、每天 land 一次，比一上来开 20 张稳得多。
