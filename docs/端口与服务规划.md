# hive 端口与服务规划

> 一句话：**所有默认端口只在 `hive_ports.py` 定义一次**，文档、脚本、CLI、看板都从这里对齐；
> 要改端口，先改这个文件和本文档，再跑 `hive ports --check`。

---

## 1. 为什么单独做端口规划

2026-10-28 出过一次「手动跑 8787、服务起 8791」的错位：`serve.py`、`dashboard-service.sh`、
`hive.py` 各写各的默认值，文档全写 8787，实际访问却要换端口，看起来像被人偷偷改了。

集群上线后又多了两个端口（HTTP 8788 / UDP 8789）。如果继续散落，下一个人很容易：

- 把 UDP 8789 当成 TCP，防火墙只放 TCP；
- 把 8790 当成看板端口，和预留段撞车；
- 换个端口只改了 `--port`，忘了 `hive work` 自动拉起的集群还在用旧默认值。

所以现在的规则是：

1. **代码默认值** → `hive_ports.py`（唯一来源）；
2. **环境变量覆盖** → 每个服务一个名字，兼容项只保留看板的 `PORT`；
3. **运维说明** → 本文档；
4. **现场体检** → `hive ports [--check] [--json]`。

## 2. 端口分配表

| 端口 | 协议 | 服务 | 默认绑定 | 环境变量 | 说明 |
|---|---|---|---|---|---|
| **8787** | TCP | 看板 HTTP | `127.0.0.1` | `HIVE_DASHBOARD_PORT`（旧名 `PORT`） | 浏览器/看板；默认只绑本机，远程用 SSH 隧道 |
| **8788** | TCP | 集群 HTTP | `0.0.0.0` | `HIVE_CLUSTER_PORT` | 注册/心跳/投票/进度/租约；跨机需放行 |
| **8789** | **UDP** | 集群广播发现 | `0.0.0.0` | `HIVE_CLUSTER_DISCOVERY_PORT` | 只用于同网段自动发现；可关闭，静态 seed 不受影响 |
| 8790–8798 | — | hive 内部预留 | — | — | 后续服务分配前先改 `hive_ports.py` 和本文档 |
| **8799** | TCP | 测试/冒烟 | `127.0.0.1` | `SMOKE_PORT` | `scripts/ci-smoke.sh`、手工验证专用；不要跑生产 |

### 外部依赖（不归 hive 分配）

排障时这些端口也会出现，但不要把它们写进 hive 的默认值：

| 端口 | 服务 | 归属 |
|---|---|---|
| 3000 | Gitea（中心仓 / CI） | 外部 |
| 3080 | DSH Web | 外部 |
| 18443 | LightMem kernel | 外部 |
| 18444 | LightMem MCP | 外部 |

## 3. 常用命令

```sh
# 看完整规划（默认端口 + 当前环境变量生效值 + 外部依赖）
python3 hive.py --dir ~/dswork/hive ports

# 体检：尝试绑定本机端口，标出空闲/被占用
python3 hive.py --dir ~/dswork/hive ports --check

# 给脚本/看板消费
python3 hive.py --dir ~/dswork/hive ports --json
```

`hive ports --check` 用 `127.0.0.1` 探测：如果服务绑在 `0.0.0.0`，本机探测同样会显示
「被占用」，这是正常的，不是误报。

## 4. 防火墙 / 多机

最小可用（只有静态 seed、关闭 UDP 发现）：

```sh
# 每台机器放行集群 HTTP
# FreeBSD pf 示例
pass in proto tcp from 192.168.0.0/24 to any port 8788
```

想要「新机器零配置自动注册」，再放行 UDP：

```sh
# FreeBSD pf 示例
pass in proto udp from 192.168.0.0/24 to any port 8789
```

- 看板 8787 默认只绑 `127.0.0.1`，**不需要**对外放行；远程看用
  `ssh -L 8787:127.0.0.1:8787 user@host`。
- 集群 HTTP 8788 是节点间通信，建议只对可信局域网开放，并设置
  `HIVE_CLUSTER_TOKEN`。
- 8789 是 UDP，不是 TCP；只开 TCP 8788 仍然能用 `--seed` / `cluster join` 组网。

## 5. 改端口的正确姿势

### 5.1 临时覆盖（不改代码）

```sh
# 看板换 8887
HIVE_DASHBOARD_PORT=8887 python3 hive.py --dir ~/hive dash start

# 集群 HTTP 换 8888（所有节点必须知道这个端口）
HIVE_CLUSTER_PORT=8888 python3 hive.py --dir ~/hive cluster start
python3 hive.py --dir ~/hive cluster join 192.168.1.5:8888

# 关闭 UDP 发现（只用 seed）
python3 hive.py --dir ~/hive cluster start --no-discover
```

> `hive cluster start` 会把端口写进 `~/.hive/cluster/config.json`；
> 后续 `hive cluster status` / `hive work` 自动拉起都读同一份配置。
> 改端口时如果后台服务已经在跑，先 `hive cluster stop`，再改，再 `start`。

### 5.2 永久修改默认值

1. 改 `hive_ports.py` 里的常量（以及 `SPECS` 里的说明）；
2. 改本文档的端口分配表；
3. 搜一遍 `README.md` / `docs/` / `dashboard/` / `scripts/` 里旧端口的引用；
4. 跑：

```sh
python3 -m pytest -q tests/test_ports.py
python3 hive.py --dir ~/hive ports --check
```

`tests/test_ports.py` 会验证：端口不重复、预留段没被占用、`hive.py` / `hive_cluster.py` /
`dashboard/serve.py` 的默认值与 `hive_ports.py` 一致。

## 6. 多实例 / 冲突排查

同一台机器想跑两个看板或两个集群节点（测试/演示）：

```sh
HIVE_DASHBOARD_PORT=8887 python3 hive.py --dir ~/hive-a dash start
HIVE_DASHBOARD_PORT=8888 python3 hive.py --dir ~/hive-b dash start
```

集群同理，但要**同时改 HTTP 和发现端口，并使用不同 state 目录**：

```sh
HIVE_CLUSTER_PORT=8888 \
HIVE_CLUSTER_DISCOVERY_PORT=8889 \
HIVE_CLUSTER_STATE=~/.hive/cluster-a \
python3 hive.py --dir ~/hive-a cluster start --no-discover
```

常见冲突：

| 现象 | 原因 | 处理 |
|---|---|---|
| 看板打不开，但进程在 | 服务起在别的端口（旧脚本/旧环境变量） | `hive ports --check`；`hive dash status`；确认 `HIVE_DASHBOARD_PORT` |
| 集群 `status` 显示未运行，但进程在 | `status` 查的端口和 `serve` 绑的不一致 | 看 `~/.hive/cluster/config.json` 的 `port`；`curl 127.0.0.1:<port>/api/cluster/health` |
| 新机器不自动注册 | 8789/UDP 被防火墙挡；跨网段广播不到 | 放行 UDP，或 `--seed` / `cluster join` |
| `cluster start` 报端口占用 | 已有节点/旧进程占着 8788 | `hive cluster stop`；`lsof -i :8788` / `sockstat -4l | grep 8788` |
| 看板起在 8789，发现端口也是 8789 | 历史文档/手工命令混用 | 看板用 8787；8789 是 UDP 发现，不要拿它跑看板 |

历史备注：`scripts/dashboard-service.sh` 曾在 0.9.17 之前默认 8791，现已统一到
`HIVE_DASHBOARD_PORT`（默认 8787）。文档里若还看到 8791，按本文档为准。

## 7. 环境变量速查

| 变量 | 默认 | 归属 | 说明 |
|---|---|---|---|
| `HIVE_DASHBOARD_PORT` | 8787 | 看板 | 首选；`PORT` 是历史兼容覆盖项 |
| `HIVE_CLUSTER_PORT` | 8788 | 集群 | 节点 HTTP；`hive cluster start` 会持久化到 config.json |
| `HIVE_CLUSTER_DISCOVERY_PORT` | 8789 | 集群 | UDP 发现；`--no-discover` 时不绑定 |
| `SMOKE_PORT` | 8799 | 测试 | 只给 `scripts/ci-smoke.sh` / 手工冒烟 |
| `HIVE_CLUSTER_STATE` | `~/.hive/cluster` | 集群 | 状态目录，不是端口，但多实例时必须分开 |
| `HIVE_DASH_AUTOSTART` | 1 | 看板 | 设 0 关闭 hive 命令的按需自启 |
| `HIVE_CLUSTER_AUTOSTART` | 1 | 集群 | 设 0 关闭 `hive work/orchestrate` 的自动拉起 |
