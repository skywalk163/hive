# hive 使用指南：从一台机器到多机协同

> **第一次用先读这一篇。** 人照着命令能跑通，AI 照着工具序列能自己领卡干活。
> 更深的设计取舍看 [集群架构 v3.1](集群架构-v3.1.md)，命令全量看 [操作手册](操作手册.md)。

---

## 0. 一分钟模型

```
每台机器一个 hived（常驻）
  ├─ 127.0.0.1:8790   MCP HTTP：本机 agent 都连这里
  ├─ 8788/8789        集群：发现、选主、状态
  └─ 本地 SQLite      P2 可选 store；默认 claim 仍走 Git

Git（Gitea）= 任务卡 / 结果 / 代码的最终真相
```

三条规则：

1. **agent 永远只连 `127.0.0.1:8790`**，不配主控 IP；主控挂了自动选新主。
2. **默认 `claim_backend=git`**，和以前完全兼容；要试 P2 store 再显式切。
3. **人只做三件事**：写卡、看进度、land；其它交给 leader 的 orchestrate / worker。

## 1. 五分钟单机跑通

前提：Python 3.12+、git、能访问 Gitea。先进入工作目录（FreeBSD `~/dswork`，Windows `G:\dswork`），
下面命令都在里面跑；hive 仓就是 `hive/`，所以统一用相对路径：

```sh
H="python3 hive/hive.py --dir hive"
```

> Windows 把 `hive/hive.py` 写成 `hive\hive.py`，其余参数不变。

### 1.1 准备协调仓

```sh
git clone http://192.168.1.5:3000/skywalk/hive.git hive
$H init                     # 幂等：补齐 tasks/agents/inbox/results
```

### 1.2 登记本机 agent

```sh
$H agent add \
  --name my-agent \
  --mode manual \
  --repo hive="$PWD/hive" \
  --worktrees ~/.hive/wt \
  --capabilities python git
```

- `exec`：有 CLI 的 agent（`--command "dsh --profile headless -"`）；
- `manual`：GUI agent，人/工具把 worktree 交给它；
- `verify`：只验收，不写代码。

### 1.3 起 hived + MCP 入口

```sh
$H daemon start --mcp
$H cluster status           # 角色 / 主节点 / MCP / store
```

### 1.4 给 agent 发 token

```sh
$H agent enroll --name my-agent
```

输出里有 `token` 和一段 `mcpServers` 配置。把它写进 agent 客户端：

```json
{
  "mcpServers": {
    "hive": {
      "type": "http",
      "url": "http://127.0.0.1:8790/mcp",
      "headers": {"Authorization": "Bearer <token>"}
    }
  }
}
```

只支持 stdio 的客户端用桥：

```json
{
  "mcpServers": {
    "hive": {
      "command": "python3",
      "args": ["/home/you/dswork/hive/hive.py",
               "mcp", "connect", "--stdio", "--token", "<token>",
               "--dir", "/home/you/dswork/hive"]
    }
  }
}
```

### 1.5 建一张卡、让 agent 干

```sh
$H task new \
  --title "修一个文档错字" \
  --repo hive \
  --paths docs/ \
  --verify "python3 -m pytest -q tests/test_docs.py" \
  --body "只改 docs/ 下指定文件，完成后写 summary。"

$H dispatch --apply        # 分派给空闲 agent（默认 dry-run）
$H status                  # 看板
```

agent 侧的固定顺序见 §3。干完后：

```sh
$H land T-0001 --apply     # 合入 main + close
$H status
```

## 2. 多机（同一局域网）

### 2.1 每台机器

```sh
git clone http://192.168.1.5:3000/skywalk/hive.git hive
H="python3 hive/hive.py --dir hive"
$H agent add --name <本机唯一名> ...
$H daemon start --mcp
```

新机器启动后会自动发现同网段的主节点并注册；不需要填主控 IP。
跨网段/广播被挡时用 seed：

```sh
$H daemon start --mcp --seed 192.168.1.5:8788
```

建议所有机器设同一个 token：

```sh
export HIVE_CLUSTER_TOKEN='一长串随机值'
```

### 2.2 只验收 / GUI 机器

```sh
$H daemon start --mcp --no-elect
```

`--no-elect` 的机器是 observer：不参选、不投票、不会当 leader，但仍然提供本机 MCP。

### 2.3 换主

主节点退出后 followers 自动重选（通常 1–8 秒）。agent 不需要改任何配置，因为一直连本机 8790。
看状态：

```sh
$H cluster status
$H cluster peers
$H cluster watch
```

### 2.4 注意

- `daemon start` 发现**旧进程**在跑时不会热加载；改配置/升级后用：

  ```sh
  $H daemon restart --mcp
  ```

- 每台机器 agent 名必须唯一；token 只存本机，不跨机复制。
- 已有任务在飞时不要切 `claim_backend=store`（见 §5）。

## 3. AI agent 协议（照这个顺序做）

### 3.1 开工

1. 调 `hive_whoami`：确认自己是谁、能干什么、有哪些仓库。
2. 调 `hive_next` 或 `hive_list_pending`：挑一张能干的卡。
3. 调 `hive_claim(task_id=...)`：拿到 `worktree`、`task_md`、`summary_md`。
4. 只在这个 worktree 里改代码；只改卡上 `paths` 允许的路径。
5. 写 `<worktree>/.hive/summary.md`（做了什么、改了哪些文件、跑了什么验证、遗留风险）。
6. 调 `hive_submit(task_id=..., note=...)`。
7. 调 `hive_result(task_id=...)` 看验收结果。

### 3.2 硬规则

- **不要** `git push`、不要切 main、不要动 `land`（除非你是 controller）。
- 不要改别人的卡；写操作只作用在自己身上。
- 干不下去：`hive_block`（等资源）或 `hive_abort`（还回队列），不要干耗到租约过期。
- 任务卡 `verify` 是硬验收；`paths` 是修改边界。
- `HIVE_CLAIM` 失败会返回持有者；不要抢别人的租约。

### 3.3 controller（总控）额外工具

`hive_land` / `hive_close` / `hive_retry` / `hive_assign` / `hive_dispatch` /
`hive_gc` / `hive_watchdog`。都默认 dry-run，破坏性操作先不传 `apply` 看计划。

### 3.4 常见返回

| 返回 | 含义 | 下一步 |
|---|---|---|
| `E_NO_QUORUM` | store 模式多数不可用 | 重试 / 查集群 |
| `E_LEASE_LOST` | 租约过期/被抢 | 停手，重新 `hive_claim` |
| `T-xxx 已被 A 领取` | CAS 失败 | 换卡或找 A |
| `worktree 不存在` | 没 claim 或状态丢了 | 重新 claim |

## 4. 人怎么驱动

```sh
$H status                         # 全部任务
$H status --json                  # 机器读
$H dash                           # 本机看板
$H dispatch                       # dry-run
$H dispatch --apply --limit 3
$H land T-0001 --apply
$H doctor
$H watchdog --apply
```

常驻总控（leader 机器跑，或者只跑一台）：

```sh
$H orchestrate --interval 60
```

P0 起 `orchestrate` 有 leader gate：只有当前 leader 的写动作生效；也可以让 hived 代跑：

```sh
$H daemon restart --mcp --coordinator
```

> 不要同时开外部 `orchestrate` 和 `--coordinator`，否则会重复 tick。

## 5. P2 store 模式（可选）

### 5.1 什么时候用

- 想要 claim/lease 不写 Git、秒级 CAS；
- 想要 leader 挂了新主直接接上本机 store；
- 能接受 SQLite 本地文件 + 显式运维（备份/回滚）。

默认仍是 `git`，不需要 store 就完全不用看这一节。

### 5.2 切换（先 drain）

```sh
# 1) 确认没有 running/assigned 的在飞卡
$H status

# 2) 停旧进程，起 store 模式（start 不会热加载）
$H daemon restart --store --claim-backend store

# 3) 验证
$H cluster status
$H store
$H store check
curl 127.0.0.1:8788/api/cluster/store/state
```

切换后：

- `Worker.claim` / 续租 / 释放、`Hive.claim_info`、dispatch/assign、result accepted/archive
  走 store；
- Git 仍保存任务卡、结果和代码；
- hived 的 MCP 读缓存会用 store 覆盖 Git 卡面。

**Git 里已有的 claim 不会自动导入 store**。有在飞任务就先 `--claim-backend git` 等它落地，
或确认可以重新分派再切。

### 5.3 日常

```sh
$H store                 # tasks/claims/results/commit_seq/压缩点
$H store check           # SQLite integrity_check
$H cluster sync          # 代码仓同步游标（不是 store）
```

健康检查：`curl 127.0.0.1:8788/api/cluster/health` 会带 `store` / `archive` / `mcp` 状态。

### 5.4 备份/回滚

```sh
# 停机备份（最简单）
$H daemon stop
cp ~/.hive/cluster/hive.db ~/.hive/cluster/hive.db.bak
$H daemon start --store --claim-backend store

# 回滚到 Git claim
$H daemon restart --claim-backend git
```

store 文件默认 `~/.hive/cluster/hive.db`；可用 `HIVE_STORE_PATH` 改。

### 5.5 边界

- 极端网络分区没有完整混沌测试；commit 未达多数会返回 `E_NO_QUORUM*`，不会假成功。
- op log 有压缩（keep 1000）和 snapshot；新节点先 snapshot 再追增量。
- `--coordinator` 默认关；真实四客户端仍需现场各跑一遍全流程。

## 6. 代码同步

`land` 成功会发 `repo.updated` 事件；每台机器的 SyncAgent 按本机 `repos` 映射做
`fetch + merge --ff-only`：

- 只动主检出，不动 task worktree；
- dirty / diverged 跳过并在看板标红，绝不 reset；
- 游标 `~/.hive/cluster/sync_cursor.json`；漏事件 5 分钟内补偿；
- land 那台自己立即更新主检出。

查看：

```sh
$H cluster sync
```

## 7. 端口与常驻

| 端口 | 用途 |
|---|---|
| 8787 TCP | 看板（只绑 127.0.0.1） |
| 8788 TCP | 集群 HTTP（LAN） |
| 8789 UDP | 集群发现（LAN） |
| 8790 TCP | MCP HTTP（只绑 127.0.0.1） |
| 8791–8798 | 预留 |
| 8799 TCP | 测试/冒烟 |

`hive ports` 查看，`hive ports --check` 体检。

常驻用 `daemon serve`（前台，交给 init 守护）：

```ini
# Linux systemd user unit 示例
[Service]
ExecStart=/usr/bin/python3 /home/you/dswork/hive/hive.py --dir /home/you/dswork/hive daemon serve --mcp
Restart=always
```

FreeBSD rc.d / Windows NSSM 同理，命令都是 `daemon serve --mcp`。

## 8. 排障

| 现象 | 先看 | 处理 |
|---|---|---|
| `/api/cluster/store/state` 404 | `$H cluster status` | 8788 上还是旧进程；`daemon restart --store --claim-backend store` |
| `daemon start` 说“已在运行” | health | 配置没热加载；用 `daemon restart` |
| MCP 401 | `agent enroll` | token 错/被 revoke；重新 enroll 并更新客户端 |
| 8790 连不上 | `cluster status` 的 MCP 行 | 没起/端口被占；看 `~/.hive/cluster/cluster.log` |
| 没有可领的卡 | `hive_next` / `status` | 依赖/能力/仓库不匹配；或都被领走 |
| 卡一直 assigned | `hive watchdog --apply` | worker 没跑/租约过期 |
| 合并后本机代码旧 | `hive cluster sync` | SyncAgent 跳过 dirty/diverged；手动 `hive sync-repos` |
| store 写失败 | `hive store check` / health | 多数不可用/磁盘满/DB 损坏；先回滚 Git |
| MCP 工具报 `E_NO_QUORUM` | `cluster peers` | 等多数恢复；不要反复重试写 |

日志：

```sh
tail -f ~/.hive/cluster/cluster.log
```

## 10. 设计边界（为什么这样）

- **简单**：默认 Git claim，零新依赖；store 是显式开关。
- **实践优先**：agent 只连本机 127.0.0.1，换主不用改配置；干完自动同步。
- **类 OSPF**：发现/心跳/任期/选主/事件增量；临场拓扑自适应，不写死节点数。
- **低通讯/低内存**：不广播全量进度；store 只发 delta，落后才 snapshot；op log 压缩。
- **可信边界**：Git 仍是任务定义/结果/代码的最终真相；store 是运行时加速层。

更细的取舍、故障矩阵和验收标准见 [集群架构 v3.1](集群架构-v3.1.md)。
