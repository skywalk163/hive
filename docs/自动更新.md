# 自动更新：为什么以前总卡住，现在怎么自愈

> 2026-11-17。解决的问题：节点经常「本该自动更新却一直落后」，最后只能人工
> `git pull`；而人工 pull 又常撞上
> `无法创建 '.git/index.lock'：文件已存在`，于是一台机器可以被一个残留锁
> **永久**钉住，谁也不知道该等还是该动手。

## 一、四层根因（都在本机实测到过）

现场：`fb98` 协调仓落后 `origin/main` 9 个提交，`.git/index.lock` 是 09:23 留下的
0 字节文件，而 `git fetch` / `ls-remote` 一切正常 —— 只有 `merge` 每次失败。

| # | 根因 | 证据 / 机制 |
|---|---|---|
| 1 | **陈旧 `index.lock` 无自愈** | git 的互斥闸。进程被 SIGKILL / 重启看板 / 断电打断在写索引半路就留下 0 字节锁；此后所有**写索引**的操作（merge/checkout/add/reset）全失败，而 fetch 照旧成功。全仓原先只有 `tests/soak.py` 会 `unlink` 它，生产代码零处理。 |
| 2 | **合并失败被静默吞掉** | `_status_autosync` 里 `git(..., check=False)` 只看返回码，不记 stderr。结果 status 永远显示「落后」，没有横幅、没有原因，人只能去手动 pull 才看见真相。 |
| 3 | **脏工作区一律跳过** | 只要 `git status --porcelain` 非空就零写。但本机常年有别人/agent 的在途改动（当天 442 行），于是**永远**不自动更新——即使远端只改了完全无关的文件。 |
| 4 | **重启泄漏孤儿循环** | `serve-dashboard.sh` 前台跑 `serve.py`，POSIX sh 会等前台命令结束才执行 trap；`dashboard-service.sh` 10s 后 SIGKILL → EXIT trap 不执行 → `( while ) &` 刷新循环被孤儿化。实测积了 4 个（最老从周日跑到今天），它们每 20s 抢写 `status.json`、并发跑 git —— 正是根因 1 的来源。 |

附带一个可见性问题：`hive status --json` 默认输出**数组**，`sync_health` 只在
`--sync-health` 时才是顶层对象；而 `serve-dashboard.sh` 与 `serve.py` 的刷新循环都
没传这个标志。于是看板拿到的是 `degraded` 快照，**根本看不到落后/脏/分叉**。

## 二、现在怎么做

### 一条命令

```sh
hive autoupdate                     # 自愈一轮（修锁 → 快进 → 记账）
hive autoupdate --restart           # 顺带：看板代码比进程新时后台重启它
hive autoupdate --dry-run           # 预演，不写任何东西
hive autoupdate --status            # 看上一次的结论（不干活）
hive autoupdate --json              # 给脚本 / agent 读
```

退出码（cron 与外部 agent 的契约）：

| 码 | 含义 | 谁该动 |
|---|---|---|
| 0 | 已最新，或已快进 | 不用管 |
| 2 | **blocked**：脏改动与传入提交重叠，或本地分叉 | 人或 agent：提交/stash，或裁决分叉 |
| 1 | 出错（网络、仓库损坏等） | 看日志 |

一轮具体做什么：

1. **陈旧锁**：`index.lock` / `HEAD.lock` / `shallow.lock`，同时满足
   「无存活持有者」+「年龄 ≥ 120s（查不清持有者时 600s）」才动手；命中就
   **改名**成 `index.lock.stale-<epoch>` 留证据，随后重试一次写操作。
   活进程持有的锁一律不碰。
2. **fetch**：先 `ls-remote` 比对远端 SHA，没变就完全不 fetch。
3. **快进**：`merge --ff-only`。脏工作区先算「本地改动 ∩ 传入文件」：
   * 交集为空 → 允许 ff（**这就是自愈的关键**：本机 442 行在途改动与远端
     9 个提交完全不重叠，ff 不碰它们，本地改动逐字节保留）；
   * 交集非空 → 停下，结果里带 `blocked.files` 和原因，绝不 reset / stash。
4. **重启**（仅 `--restart`）：只比较 `dashboard/` 运行时代码与 PID 文件 mtime；
   代码新才重启，且用**独立会话**的 helper 延迟 2s 执行
   `dashboard-service.sh restart`，不打断正在跑的任务。
5. **记账**：`~/.hive/autoupdate/state.json`（含 head before/after、state、
   blocked、locks_repaired、restart），看板 / agent 直接读。

### 装成定时任务

```sh
hive autoupdate --install-cron              # 每 5 分钟一次
hive autoupdate --install-cron --every-min 10
hive autoupdate --uninstall-cron
```

写入用户级 crontab，行尾带 `#hive-autoupdate` 标记，重复执行幂等（换间隔不会
留旧行）。安装后这台机器不再需要任何人记得手动更新：

```
*/5 * * * * cd <repo> && <python> <repo>/hive.py --dir <repo> autoupdate --restart >> ~/.hive/logs/autoupdate.log 2>&1 #hive-autoupdate
```

### 看板

- `serve-dashboard.sh` 与 `serve.py` 的刷新循环都改用
  `hive status --json --sync-health`，快照顶层带上 `sync_health`：
  落后 / 脏 / 分叉 / blocked 都可见，`lsdb_seq` 节流也才真正生效。
- `sync_health` 新增诊断字段：`dirty_ff`、`dirty_files`、`overlap_files`、
  `sync_error`（以前被吞掉的合并失败原因）、`lock_repaired`、`blocked`。

## 三、安全边界（刻意保留的「不做」）

1. **不删锁**：只改名归档，可回溯；`HIVE_NO_LOCK_REPAIR=1` 一键关掉。
2. **不 reset / 不强推 / 不 rebase**：永远 `merge --ff-only`；分叉交人裁决。
3. **不 stash**：重叠时停下并列出文件名，要不要 stash 由改动主人决定。
4. **策略跟着入口走**：`hive status` 仍遵守 L5「脏工作区字节级不动」（默认
   `allow_dirty_ff=False`）；只有自愈入口 `hive autoupdate` 显式允许
   「不重叠则 ff」。想看 status 也自愈可 `HIVE_SYNC_DIRTY_FF=1`。
5. **不自动重启 hived**：autoupdate 只重启看板；集群节点进程的重启用
   `hive cluster restart` / `hive upgrade rollout --restart`（避免打断在跑任务）。

## 四、排障

| 现象 | 看哪里 | 处理 |
|---|---|---|
| `hive autoupdate` 退出 2 | `--json` 里的 `blocked[0].kind` | `dirty-overlap`：提交或 stash 列出的文件；`diverged`：人工裁决 |
| 一直落后、`sync_error` 有内容 | `state.json` / `--json` | 多半是锁或权限；先 `hive autoupdate` 再手动 `git pull` 复核 |
| 看板还提示「运行 dashboard-service.sh restart」 | `/api/config` 的 `system.service.restart_hint` | 说明进程确实比代码旧：`hive autoupdate --restart`（或 `hive dash restart`） |
| 看板刷新日志暴涨 / 多个刷新循环 | `pgrep -fl serve-dashboard.sh` | `sh scripts/dashboard-service.sh stop` 现在会按路径清孤儿，再 start |
| 不想让它自动更新 | — | `hive autoupdate --uninstall-cron`；临时停用 `HIVE_SYNC_NO_AUTOSYNC=1` |

## 五、测试

- `tests/test_autoupdate.py`（18 条）：陈旧锁归档 / 新鲜锁不碰 / 活进程持有不碰 /
  撞锁自愈重试 / 真冲突不重试 / 脏不重叠快进且改动保留 / 重叠 blocked /
  并发互斥 / 死进程锁抢占 / dry-run 零写 / 看板新鲜度 / 独立会话重启 / cron 幂等。
- `tests/test_status_autosync.py`：默认脏零写（L5）+ 显式 opt-in 的两条新用例。
- 现场验证：本机 `index.lock.stale-1794878610` 归档 → ff 到 `origin/main` →
  `hive autoupdate --restart` 清理 4 个孤儿循环并加载新代码。
