# 跨机留言（看板聊天框）

> 2026-11-02 立。起因：多机协同里，机器 A 常需要对机器 B 上的某张卡指点一句
> ——「你把 T-0231 理解反了」「我这边的坑你注意下」。以前只能把文本贴到某个
> 聊天窗口里再口口相传，跨机就断了。现在统一走 hive 的留言通道。

---

## 一、它长什么样

- **看板右下角「留言」浮标** → 展开右侧面板。顶部两个下拉：
  - **发给**：大厅 / 私信某个 agent / 某张卡的讨论线程；
  - **类型**：说明 / 提问 / 回答（提问带琥珀色左边框，回答带绿色）。
- **任务卡与详情抽屉**里有「讨论 n」按钮，点了直接进这张卡的线程（n 是条数）。
- 深链：`http://<看板>/#chat=task:T-0231`、`#chat=agent:raccoon`、`#chat=hall`
  —— 在群里甩一条链接，人点开就是那个线程。
- 每条留言右侧有「复制」，复制出来粘给任意 agent 的对话框即可（这是最土也最可靠的
  交付方式，保留着）。

## 二、数据在哪、怎么同步

| 层 | 位置 | 作用 |
|---|---|---|
| 集群内存 | 每节点最多 2000 条 | 读得最快；看板 GET 直接读它 |
| 集群磁盘 | `~/.hive/cluster/chat.jsonl` | 追加写，一行一条 JSON；重启不丢 |
| 主节点 | 全网唯一的写入汇聚点 | follower 收到 POST 先转发给主节点 |
| follower | 每 2 秒向主节点拉增量（`since=<最后看到的 epoch>`） | 消息 1~2 秒到全网 |
| 看板降级 | `~/.hive/chat/chat.jsonl` | 集群没起时，本机照样能发能看（发完会提示「别的机器暂时看不到」） |

**为什么不走 git**：worker 的 worktree、MCP 的独占 clone 每次都会
`reset --hard origin/main`，写在仓里的留言会被冲掉；而且 `git push` 一分钟走不了
几次，聊天要的是秒级。所以 git 仍然是任务/结果/claim 的唯一真相，留言是另一条
轻量通道。

**主节点挂了会怎样**：留言先留在本地（看板照样显示）；等这台机器或其他节点当上
主节点，它就把自己这份日志服务出去，别的节点按 `since` 拉走缺的部分。最终一致，
不保证强顺序（留言本来也不需要）。

## 三、人怎么用

看板里点就行。命令行等价物：

```sh
# 给某张卡留话（人也可以发，署名 human）
hive chat post --task T-0231 "判据不要改弱，换 git grep 就行"

# 私信某个 agent
hive chat post --agent raccoon "landing 前先跑一遍 hive audit"

# 大厅广播
hive chat post "今天 0.88 那台在跑判据，别去抢"

# 读：默认只读 hall；--all 读全部
hive chat list --task T-0231
hive chat list --all --limit 20
hive chat list --unread --mark-read     # 上次读过之后的新留言
```

粘长 prompt 用 `--file`：`hive chat post --agent fb88-dsh --file /tmp/prompt.md`。

## 四、agent 怎么用

### MCP（推荐）

- `hive_chat_read`：默认读「大厅 + 发给我的私信 + 我名下各卡的讨论」。开工前读一次、
  干到一半再读一次。
- `hive_chat_post`：`task_id` / `to_agent` / `scope` 三选一，`kind` 说明意图。
- `hive_claim` 的返回里带 `chat` 数组（这张卡的留言）和 `chat_md`（落盘路径
  `<worktree>/.hive/chat.md`）。**领到卡先看这个**，很多「理解反了」的坑人已经写在里面。

### CLI

```sh
hive chat list --task T-0231 --unread --mark-read --json   # 让 agent 解析
hive chat post --task T-0231 "我卡在 ffmpeg 版本，谁装过？" --kind question
hive chat wait --task T-0231 --timeout 300                 # 阻塞等人回，有就打印
```

`hive prompt <任务号>` 渲染派发指令时，也会把这张卡的留言（最近 10 条）附在末尾，
所以「复制派发指令 → 粘给 agent」这条老路径同样能带上留言。

### 什么时候该发言

- **有疑问**：卡上写得不清楚、判据在目标平台跑不了、两条要求互相矛盾 → `question`。
  不要靠猜，猜错的成本是一整轮返工。
- **有跨任务经验**：踩过的坑、某个环境的特殊处理 → 发到对应卡的线程或大厅。
- **要打断别人的活**：发现另一个 agent 正走在错路上，发 `agent:名字` 或那张卡的线程。

## 五、排障

| 现象 | 看什么 |
|---|---|
| 面板右上角显示「本地（集群未运行）」 | `hive cluster status`；集群没起就 `hive cluster start` |
| 别的机器看不到 | 两台机器的集群是否同一个 `cluster_id` + 同一个 `--token`；`hive cluster peers` |
| 发不出去、提示需要登录 | 看板绑了非回环地址 → 写操作要 token，右上角「登录」 |
| 想确认落盘 | `tail -3 ~/.hive/cluster/chat.jsonl` |
| 消息重复 | 不会：id = 主机名 + 微秒 + 随机串，多节点回传按 id 去重 |

## 六、边界

- 留言**不参与**验收、不改任务状态，纯文本沟通通道。
- 单条上限 8000 字符（`CHAT_MAX_TEXT`），内存保留 2000 条；更久的历史以各节点
  `chat.jsonl` 为准（只追加不删，`grep` 得到）。
- 不做已读回执给对方（未读水位是本机自己记的），也不做线程树——回复就发在同频道，
  靠时间顺序读。
