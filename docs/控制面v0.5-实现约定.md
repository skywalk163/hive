# Hive 韧性控制面 v0.5 · Agent 实现约定

> 本文件是母文档《Hive 韧性控制面升级（v0.5，Agent 实现规范）》的**落地契约**。
> 母文档规定“做什么”，本文件规定“代码放在哪、模块之间用什么接口、歧义怎么裁定、怎么测”。
> 实现任务（T-0302 起）以本文件为准；与母文档冲突时，先看本文件 §4 的裁定。
>
> 状态：契约 + 共享骨架已落在 main；各模块可并行开工。

## 0. 范围与分期

1. 新增独立包 **`hive_control/`**，实现母文档 §3–§9 的全部机制。
2. `hive cluster serve` 在启动时**附加启动**一个控制面实例（`hive_control.adapter`），
   与原 HTTP 集群面（`hive_cluster.py` 的注册/心跳/投票/store）**并存**。
   - 原 HTTP 面**一行都不改语义**；本期不删、不替换。
   - 组播下行只由“控制面 Leader”发送；原 HTTP Leader 不发组播。因此 I3 仍成立。
   - 第二个角色（控制面 Leader）在 `/api/cluster/status` 中以 `control_leader` 字段暴露，
     与旧 `leader` 并列；两者合并/最终切换是**后续卡**，不在本期。
3. Git 仍是唯一权威（I1）；控制面任何状态都只是提示通道。
4. 配置只允许母文档 §9 的 9 项。下面出现的窗口、容量、间隔等一律是
   `hive_control/config.py::Limits` 里的**内部常量**，不暴露给用户；测试可构造覆盖。

## 2. 数据与线格式

### 2.1 `StateEntry`（`model.py`，已实现）

```python
StateEntry(project: str, tid: str, version: int, incarnation: int,
           owner_agent: str, state: str, dna: bool, updated_at: int,
           urgent: bool = False)
```

- 状态枚举：`claimed | running | releasing | released | steady | expiring`。
  母文档 §4.1 的枚举漏了 `expiring`，§5.4 又用到；本契约把它收进枚举，
  但**只作为下行提示**（见 D4），不写回 Git/不参与租约裁决。
- 比较键：`(incarnation, version)` 字典序。`StateEntry.newer_than(other)` 为严格大于。
- 线格式：单行紧凑 JSON（UTF-8，`ensure_ascii=False`，`separators=(",",":")`）。
  `from_line()` 对未知字段宽容、对缺字段/非法状态抛 `ValueError`。
- `urgent` 是可选扩展（母文档 §5.2 提到 `urgent=true`），默认 `False`。

### 2.2 信封

所有控制面报文的一行是一个 JSON 对象，用 `type` / `kind` 区分：

| 报文 | 形状 | 传输 |
|---|---|---|
| 状态条目 | 条目对象本身，或 `{"type":"entry","entry":{...}}` | 上行 TCP / 下行 UDP / 拉取响应 |
| Hello | `{"type":"hello","router_id":...,"node":...,"address":...,"port":...,"priority":...,"bandwidth_factor":...,"interface_mbps":...,"leader_declaration":bool,"leader_epoch":int,"sent_at":ms}` | **UDP 单播**到已知节点 47899（D2） |
| LeaderHeartbeat | `{"type":"heartbeat","router_id":...,"leader_epoch":...,"downlink_sequence":...}` | **UDP 组播** 239.255.42.1:47899（回退时逐节点单播） |
| 过期提示 | `{"type":"expiring","project":...,"tid":...,"owner_agent":...,"incarnation":...,"version":...}` | 下行（事件触发） |
| 拉取请求 | `{"type":"pull","project":...,"mode":"incremental|full","from":{...}|null,"watermarks":{tid:[inc,ver]}}` | TCP 单播到 Leader `port+1` |
| 分页头 | `{"type":"page","page":K,"total_pages":T}` | 拉取响应 |
| 配额重试 | `{"type":"retry","after_ms":N}` | 拉取响应 |
| 空行 | 空字符串 | 拉取响应结束 |

接收方按 `type`/`kind` 分发；没有 `type` 且带 `project`/`tid` 的行按状态条目处理。

### 2.3 Worker ↔ serve（Unix socket）

- 路径：POSIX 为 `/tmp/hive-control.sock`；Windows 为 `%TEMP%\hive-control.sock`
  （D10，构造函数可传测试路径；不是用户配置项）。
- `SOCK_STREAM`，UTF-8 JSON 行。
- 客户端首行：`{"type":"worker","agent":"<名字>","pid":123}`。
- 上报：`{"type":"entry","entry":{...}}`。`version` / `incarnation` 可填 0，由 serve 统一盖号（D5）。
- serve → Worker：`{"type":"install","entry":{...}}`、`{"type":"expiring",...}`。
  **非阻塞写**：`send` 遇 `EAGAIN`/`EWOULDBLOCK` 直接丢弃该条通知并计数，不重试、不阻塞。
- 写路径保证（G1/I6）：`WorkerClient.report()` 只做内存入队，**不得**在调用线程做 connect/send。

### 2.4 上行 / 拉取 TCP

- 端口 = `serve` 的 HTTP 端口 + 1（默认 8788 → 8789；与 UDP 发现端口 8789 不冲突）。
- 上行连接：客户端把聚合后的条目逐行发出；服务端逐行 `entry` 安装，不回包。
- 拉取连接：首行 `{"type":"pull",...}`；服务端回条目行/分页头/重试行，
  以**空行结束**，然后关闭连接。全量分页每页 ≤ `pull_page_size`（默认 100）。
- 上行与拉取共用一个监听端口，服务端读首行分流。

### 2.5 下行 UDP

- 地址硬编码 `239.255.42.1:47899`；发送 `IP_MULTICAST_TTL=1`、`IP_MULTICAST_LOOP=0`。
- 周期包：待下行队列里的条目行；按 1400 字节上限分包，包间 1ms。
- 事件包：只装触发它的那一条（`claimed`/`releasing`/`urgent=true`）。
- 心跳是单独一个包，不与其他条目合并。
- 接收端 `SO_REUSEADDR` + `IP_ADD_MEMBERSHIP`；校验 TTL≠1 丢弃并记 `ttl_violation`。
  回退模式下同一 socket 也接收单播 UDP。

## 3. 模块接口（必须按签名实现，便于并行与替换）

> 所有 `now`/`clock` 参数可注入；默认 `time.monotonic`。所有 sleep 只在后台线程，
> 单测通过注入时钟或直接调 `tick_once()`，不要 `sleep` 等真实秒数。

### 3.1 `view.py`（T-0302）

```python
@dataclass(frozen=True)
class InstallResult:
    installed: bool
    reason: str          # "new" | "newer" | "stale"

class StateView:
    def install(self, entry: StateEntry, now: float | None = None) -> InstallResult
    def get(self, project: str, tid: str) -> StateEntry | None
    def entries(self, project: str | None = None) -> list[StateEntry]
    def watermarks(self, project: str) -> dict[str, tuple[int, int]]
    def changed_after(self, project: str,
                      watermarks: Mapping[str, tuple[int, int]] | None = None,
                      floor: tuple[int, int] | None = None) -> list[StateEntry]
    def mark_quiet(self, interval: float, now: float | None = None) -> list[StateEntry]
    def stats(self) -> dict

class DownlinkQueue:
    def put(self, entry: StateEntry) -> None      # 同 key 只留版本大者
    def drop(self, project: str, tid: str) -> None
    def drain(self) -> list[StateEntry]
    def __len__(self) -> int
```

- `install` 严格按 I5；`stale` 不记录日志、不回调。
- `changed_after`：优先用 `watermarks` 的逐条水位；没有时用 `floor` 作为全局下界（D3）。
- `mark_quiet`：`state=="steady"`、`dna is False`、距上次变化 ≥ `3*interval` 的条目
  置 `dna=True` 并返回；DNA 条目仍留在 `entries()`/拉取结果里。
- `DownlinkQueue` 不装 DNA 条目；`plane` 在 DNA 置位时调用 `drop`。

### 3.2 `election.py`（T-0303）

```python
@dataclass(frozen=True)
class SelfInfo:
    router_id: int; node: str; address: str; port: int
    priority: int; interface_mbps: float | None

class BandwidthProbe:
    def __init__(self, interface: str | None = None)
    def interface_mbps(self) -> float | None   # Linux SIOCETHTOOL/ETHTOOL_GSET；失败 None
    def router_id(self, address: str | None, hostname: str) -> int
    def factor(self, reference_mbps: float | None) -> float  # 自身/参考；无效→1.0

class Election:
    def __init__(self, self_info: SelfInfo, *, limits: Limits,
                 clock: Callable[[], float] = time.monotonic)
    def observe(self, message: dict, source: tuple[str, int] | None = None) -> str
        # 返回 "hello" | "heartbeat" | "ignored" | "adopted" | "leader_lost"
    def tick(self) -> str
        # "none" | "wait" | "declare" | "become_leader" | "leader_lost"
    def hello(self) -> dict
    def heartbeat(self) -> dict
    @property
    def leader_id(self) -> int | None
    @property
    def leader_epoch(self) -> int
    @property
    def is_leader(self) -> bool
    @property
    def reference_mbps(self) -> float | None
    def peers(self) -> list[dict]     # 存活邻居（address/port/priority/...）
    def status(self) -> dict
```

规则（严格按母文档 §3）：
- 比较顺序 `priority` → `bandwidth_factor` → `router_id`，都大者胜。
- `priority==0` 不参选；仍可被选/被承认。
- 启动先 Waiting `waiting_interval`；期间收到 `leader_declaration=true` 立即承认，不竞选。
- Waiting 结束仍无 Leader：存活节点中排名第一者发 `declare`（Hello 带 declaration），
  其余节点等它的声明/心跳；**非抢占**：现任 Leader 心跳有效时，排名更高也不发起。
- 心跳超时 `heartbeat_timeout`（6s）→ `leader_lost`；新 Leader epoch = 已知最大 epoch + 1。
- 参考带宽 = 存活节点（含自己）`interface_mbps` 最大值；单节点/全未知时自身值或 `None`，
  系数回落 1.0。`bandwidth_unavailable` 只记一次日志。
- Hello 间隔 2s、邻居 6s 过期（D11）；Hello **单播**给 `peers()`（D2）。

装配规则：

  `ControlTcpServer`、`DownlinkSender/Receiver`、`WorkerServer`。
- 本地 Worker 条目：盖 `incarnation`/`version`（D5）→ `view.install` → 若 Leader：
  入 `DownlinkQueue` + 瞬态立即事件下行；否则入 `Aggregator` → `UplinkQueue`。
- 收到上行/下行/拉取安装：`view.install` 成功才 `LeaseBook.note`、`WorkerServer.notify`。
- Leader 每 `heartbeat_interval` 发心跳；每动态 interval 发周期下行；切主时
  `LeaseBook.on_leader_change()` + 30s grace。
- 水位缺口：连续 3 个 interval 收到下行但 0 安装，且本机有 claimed/releasing 条目 →
  触发 `PullClient` 增量拉取（后台，不阻塞）。
- 人工拉取：独立队列（容量 64）+ 独立线程池（I7）；结果按安装规则合并并通知 Worker；
  **不触发下行**。

### 3.10 `adapter.py` + `hive_cluster.py`（T-0311）

```python
class ClusterControlAdapter:
    def __init__(self, cluster)     # duck-typed，不 import hive_cluster
    def start(self) -> None
    def stop(self) -> None
    def status(self) -> dict
    def request_pull(self, body: dict) -> tuple[int, dict]
    def pull_status(self, request_id: str) -> tuple[int, dict]
```

- `Cluster.start()` 创建并启动；`Cluster.stop()` 先停控制面。
- 新增路由：
  - `GET /api/cluster/status` → `{"ok":true,"control":{...}}`（含 `multicast_mode`、
    `control_leader`、`control_epoch`、队列长度、计数）。
  - `POST /api/cluster/pull` → 202 + request_id（体：`{"project":...,"mode":...}`）。
  - `GET /api/cluster/pull/status?id=...` → 结果/进行中。
- 旧 `GET /api/cluster/state` 不动；可在 payload 里追加 `control` 摘要（向后兼容）。
- 适配器从 `cluster.nodes` 生成 `peer_provider`（取 `url` 的 host + 控制端口），
  `local_agents` 从 `cluster._local_agents()` 取。

## 4. 母文档歧义与裁定（实现必须遵守）

- **D1 双面并存**：控制面 Leader 独立按 §3 选举；原 HTTP Leader 保持不变。
  只有控制面 Leader 向 `239.255.42.1` 发送（I3）。合并成单一 Leader 是后续卡。
- **D2 Hello 走单播**：I3 禁止非 Leader 向 AllNodes 组播地址发任何消息，因此 Hello
  用 **UDP 单播**发给已知节点（端口 47899）；bootstrap 的节点列表由适配器从原集群
  `nodes` 提供，单测可注入。LeaderHeartbeat 才走组播。
- **D3 增量水位按条**：母文档 §6.1 的 `from` 只有一个 `(incarnation,version)`，但条目
  的 `(incarnation,version)` 是各 owner 独立的，用单一全局水位会漏条目。裁定：
  请求保留 `from`（兼容母文档），另接受 `watermarks: {tid:[inc,ver]}` 逐条水位；
  有 `watermarks` 时优先，没有时 `from` 当全局下界。客户端（PullClient）默认发逐条水位。
- **D4 `expiring` 是提示不是状态**：§4.1 枚举没有 expiring，§5.4 又要求下发 expiring。
  裁定：`expiring` 只作为 `{"type":"expiring",...}` 信封下发（携带原 `(incarnation,version)`，
  不改版本）；接收方交给 watchdog 钩子，**不安装进视图**，避免与 I5 冲突。
- **D5 serve 盖号**：Worker 不持有可靠的 incarnation/version。Worker 上报时
  `version`/`incarnation` 可填 0；serve 首次见到某 `(project,tid)` 时用本 serve 的
  incarnation 盖号，之后每次本地更新 `version += 1`。跨 serve 的旧条目比较仍按 I5。
- **D6 DNA**：Leader 只在 `state=="steady"` 且连续 3 个下行周期无变化时置 `dna=True`；
  任何版本变化由 owner 发来的条目带 `dna=False`，自然复位。DNA 条目不进周期下行，
  但全量/增量拉取都返回。
- **D7 周期下行间隔**：`active = dna=False 且 state!="steady"`；>2000 → 500ms，
  >500 → 1000ms，否则 2000ms。启动首个周期用 2000ms。
- **D8 超长条目**：单条序列化后 >1400B 时独占一包发送（绝不把 JSON 行切断），
  计数 `oversize_packets` 并在日志告警。
- **D9 回退触发**：`IP_ADD_MEMBERSHIP` 失败，或连续 30s 没有有效下行且上行 TCP 仍能
  确认 Leader 存活 → `multicast_mode="fallback"`，逐节点单播到 47899；恢复不自动回切
  （避免抖动），进程重启后重试组播。
- **D10 跨平台**：`SIOCETHTOOL` 仅 Linux；其它平台 `interface_mbps=None` →
  `bandwidth_factor=1.0`，日志 `bandwidth_unavailable`。Unix socket 在 Windows 用
  `%TEMP%\hive-control.sock`。组播在无网卡/容器环境失败时走 D9。
- **D11 Hello/邻居时钟**：母文档未给 Hello 周期；取 2s，邻居 6s 未 Hello 视为过期
  （与心跳同窗，便于测试与收敛）。
- **D12 选举无需投票**：排序确定性 + leader_declaration；不做 quorum/投票，避免与
  原 HTTP 面的 term/quorum 混用。

## 6. 线程模型（非阻塞落点）

| 线程 | 职责 | 不允许 |
|---|---|---|
| `control-election` | Hello/心跳 tick、选举事件 | 不做 TCP、不碰 Git |
| `control-downlink-tx` | 周期/事件下行 | 不做拉取响应 |
| `control-downlink-rx` | 收包、安装、通知 | 不执行业务逻辑 |
| `control-uplink` | 聚合 flush + TCP 发送 | 不阻塞 Worker |
| `control-tcp` | 上行/拉取连接线程池 | 不占下行定时器 |
| `control-workers` | Unix socket 读 | 通知写不满不阻塞 |
| `control-pull` | 人工拉取队列（独立池） | 不碰下行队列 |
| `control-lease` | 续约/过期扫描 | 不碰 Git |

- Worker → serve 的 `report()` 只入内存队列（目标 <1ms）。
- 组播接收循环只做“校验→安装→非阻塞通知”。
- 任何网络 I/O 都有超时；不得在持有 `Cluster.lock` 时做控制面网络 I/O。

## 7. 测试与验收约定

1. 每个模块卡必须新增 `tests/test_control_<模块>.py`，用**注入时钟/假 transport/临时端口**，
   不依赖真实组播、不依赖外网、不 `sleep` 长于 2s。
2. 跨平台：Linux 专属断言（ioctl/TTL cmsg）用 `pytest.mark.skipif`；Windows 上
   Unix socket 测试用 `tmp_path`。

4. 验收命令形如 `python3 -m pytest -q tests/test_control_view.py`；集成卡再加
   `tests/test_control_plane_e2e.py`。
5. 不允许修改既有 `tests/test_cluster.py` 等基线用例来“变绿”；如确属基线冲突，卡里写明。
