## 1. 许可证：为什么我建议 MIT（你问的参谋部分）

你偏好 BSD，这个偏好本身没错。把三条摆在一起看：

| | MIT | BSD-2-Clause | BSD-3-Clause |
|---|---|---|---|
| 长度 | 最短（约 170 词） | 略长 | 多一条「不得用作者名义背书」 |
| 下游使用 | 无差别 | 无差别 | 无差别 |
| 专利条款 | 无 | 无 | 无 |
| 工具链识别 | 最好（SPDX、各种合规扫描默认认） | 好 | 好 |
| 常见误读 | 几乎没有 | 几乎没有 | 中文语境下常被当成商标限制，需要额外解释 |

**三条实质判断：**

1. **法律效果上三者几乎等价。** 都不提供担保、都要求保留版权声明、都允许商用与闭源再分发。差别在表述风格，不在权利范围。所以这不是一个"选错会出事"的决定，是一个"选哪个更省事"的决定。

2. **一致性比条款更有价值。** `light` 与 `lightharness` 已经是 MIT。如果 `hive`、`lightmem` 用 BSD，四个仓就是两种协议——下游做 SPDX 合规扫描、企业法务做入库审查时，每一份都要单独确认一遍，而这四个项目本来就是"一套东西"。混用带来的摩擦，大于 BSD 相对 MIT 的任何一点表述优势。

3. **BSD-3 那条"不得背书"条款听起来有用，实际很少被援引**，却最容易在中文语境里被读成"我不能说基于你的项目做了产品"。对一个正想让更多人用、包括商业使用的项目，这条的边际收益是负的。

**结论：统一 MIT。** 你的 BSD 偏好我理解——BSD 的免责表述确实更明确——但那是风格偏好，不足以抵消四仓分裂的成本。若哪天要整体换，四个一起换，别混。

> 顺带说清一件事：MIT 不阻碍你收费。你卖的是陪跑、验收、私有化交付这些服务，不是代码许可。许可证只决定别人能不能用代码，不决定你能不能收钱。

## 6. 一个待你确认的事

`github.com/skywalk163/lightmem` 从我这边访问，API 与网页都返回**干净的 404**（不是超时）。网络问题通常表现为超时或连接重置，而不是 404——所以更可能是**仓库当前是 Private**，或访问时你需要登录态。

请用一个**未登录的浏览器**（隐身窗口）打开一次：

- 能打开 → 是网络问题，我这边探测受限，按你判断继续。
- 打不开 → 仓库是 Private，公开链接对访客仍是死链。这时要么改成 Public，要么站点上 lightmem 只保留 GitCode 一个入口（其余三个项目仍保持双份）。

站点现在已做成双份，两种情况下都不会完全断路，但这一条值得确认清楚。
